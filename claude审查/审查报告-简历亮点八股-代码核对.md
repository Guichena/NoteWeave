## 1. HIGH 级问题（5 条，均已二次复核）

### H1 [亮点2] 旗舰指标是手写 fixture，不是实测
- **文档claim**：`02-场景化RAG` §9.3 / 面试 §1,§8：单路召回 33.3%–66.7%，融合链路 100%，Scope 违规 0。
- **实际**：数字只存在于静态 fixture `backend/src/test/resources/retrieval/qa-note-ablation-report-v1.json:13-18`（`recallAtK` 0.3333/0.6667/1.0 全部硬编码）。契约测试仅断言值落在 `[0,1]`、变体名存在，不验证"实测"：`retrieval/eval/FinalRetrievalGoldContractTest.java:60-67`。
- **加重**：唯一真实跑的 `RetrievalBenchmarkReplay.java:38` 用 `DeterministicBm25Baseline`，**不走 vector/RRF/rerank 融合链路**。
- **风险**：被追问"100% 怎么测"会翻车。口径必须改为"手工回归 fixture"。
- **状态**：☐ 待修（改口径 + 若要保留数字则补真实 pipeline 评测）

### H2 [亮点4] "MCP 内置、用户不能装任意插件"与代码矛盾
- **文档claim**：`04-Agent执行框架` §6,§22 / 面试 §5："用户能装自己的 MCP 吗？当前不能"。
- **实际**：`registry.register_custom_mcp_server`（registry.py:1581）接受任意 `launch_command/args/env/working_directory`；`custom_mcp_executor.py:94-132` 直接 `subprocess.run(command, cwd=working_directory, env={**os.environ, **launch_env})`，**无可执行文件白名单、无沙箱、无路径限制**；默认蓝图启动 `powershell.exe -ExecutionPolicy Bypass`（registry.py:58-65）。
- **缓解（限制真实爆炸半径）**：注册路由在 `/debug/register-custom-mcp-server`（main.py:804），默认 `debug_routes_enabled=False`（main.py:131-133）+ 内部 token 鉴权；`policy.py:60-63` 拦 `custom` 前缀除非 `allow_custom_mcp`。
- **风险**：安全叙事在代码层为假；插件执行机器完整存在。
- **状态**：☐ 待修（要么落实白名单/沙箱，要么改文档口径）

### H3 [亮点4] 运行时"并行图调度器"实为硬编码顺序循环
- **文档claim**：§16 Graph Scheduler（READY 状态机、并行节点投递）、§30、面试 §15。
- **实际**：真正 DAG（Kahn 拓扑 + 环检测）只在**编译期** `compiler.py:209-250`；运行时 `skill_graph.py:44` 就是 `for node_plan in plan.node_sequence` + if/elif 分发，无节点状态机、无就绪判定、无条件边、无并行。
- **状态**：☐ 待修（改口径为"编译期 DAG + 线性执行"，或实现运行时调度）

### H4 [亮点5] 删除被摘要覆盖的消息，派生内容仍存活可回放（隐私）
- **文档claim**：`05-Context与Memory` §31："删除 Ready Summary 时，受它覆盖的更早回放也必须降级"。
- **实际**：删消息只把覆盖它的 summary 标 `STALE`（`ConversationMessageDeletionService.java:46-53`），**不清空 `summary_text`**，也**不调用** `redactDeletedSummaryRevision`；快照按 message id 匹配 `snapshot_json LIKE '%messageId%'`（`RunReplayRedactionService.java:68-75`），若快照仅通过 summary revision id 引用则匹配不到 → 仍 `replay_availability='FULL'` → 回放渲染 summary 原文。
- **对比**：直接删 summary 才会 `summary_text=''` + `redactDeletedSummaryRevision`（`SegmentSummaryPromotionService.java:64-77`）。
- **状态**：☐ 待修（删覆盖消息时联动降级 summary + 快照）

### H5 [亮点1] Cell 状态机被夸大：CORRECTED/SCOPED 不存在，合并层不产 CONFLICTED
- **文档claim**：`01-Deep-Research` §15/§7.3：Accepted/Corrected/Scoped/Unresolved，`CONFLICTED→CORRECTED/SCOPED` 转换。
- **实际**：canonical 合并门只产 `VERIFIED` 或拒绝原因（`merge_gate.py:96-97`），冲突候选被 `VERIFIED_VALUE_CONFLICT` 拒绝；已 VERIFIED 再合并 `snapshotStale` 抛错（`ResearchAgentCompletionCommitter.java:398`）。全仓库 grep `CORRECTED|SCOPED` **零匹配**（已复核 workers/app 与 java/research 两处）。
- **状态**：☐ 待修（改口径为"冲突拒绝"，或补 scoped/corrected 状态）
