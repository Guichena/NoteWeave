# NoteWeave v2 Note 链路设计

## 1. 定位

`Note 链路` 是 NoteWeave 在统一聊天界面中的“回答 + 整理”链路。

它的实现重点直接参考 `Marginalia-style Structured Reading Funnel`：不直接对 chunk 做 top-k 问答，而是先通过资料标题、摘要、标签、历史笔记、结构化元数据和关系信号定位候选资料，再打开原文窗口读取可验证片段，抽取摘录卡片，并生成带引用的回答与结构化笔记。

- `Marginalia` 是 Note 链路的主要实现参考：系统先做资料级候选定位，再做原文窗口读取，最后生成可引用、可保存、可复用的结构化笔记。
- `NotebookLM` 只作为资料问答体验的辅助参考：用户在当前研究工作台资料集合里提问，系统围绕资料回答并给出来源依据。

一句话定义：

`Note 链路是面向资料整理的溯源式问答链路：用户仍然在聊天框里提问，系统先定位候选资料，再打开原文窗口读取可验证片段，抽取摘录卡片，并生成带引用的回答与结构化笔记。`

## 2. 核心原则

### 2.1 工作台是默认边界

Note 链路默认基于当前研究工作台内的全部可用资料工作。

用户不需要每次手动选择资料边界。系统内部根据问题自动缩小候选资料，回答链路之间的差异体现在检索组织方式、阅读方式和输出形态，而不是资料边界。

研究工作台内的资料包括：

- 用户上传文件
- 网页或文本导入
- 音视频转写
- 用户保存的笔记
- 已确认的研究报告
- 已确认的生成结果
- 已维护的 Wiki 页面

### 2.2 先定位候选资料，再读原文窗口

Note 链路不直接做简单向量召回问答，也不把离散 chunk 直接丢给模型生成答案。

它的核心动作是先通过结构化信号定位候选资料：

- 标题
- 摘要
- 标签
- 文件夹
- 文档类型
- 时间
- 来源
- 历史笔记
- 历史整理记录
- 资料之间的引用或主题关系

然后再选择少量关键资料打开原文窗口，读取可验证片段，抽取摘录卡片，并把回答中的关键观点绑定到具体证据。

这使 Note 链路更像“研究助理在翻资料、做摘录、整理结论”，而不是“模型在拼切片”。

### 2.3 具体技术路线

从工程实现上，Note 链路定义为：

`Marginalia-style Structured Reading Funnel + Windowed Evidence Reading + Citation-grounded Note Synthesis`

可以拆成五段：

1. `Workspace-bounded Retrieval`
   当前研究工作台是固定检索边界，先做工作台级过滤，不做全库开放召回。

2. `Structured Candidate Retrieval`
   先基于资料标题、摘要、标签、文件夹、时间、历史笔记、结构化元数据和关系信号做资料级候选召回，而不是直接 chunk top-k。

3. `Candidate Triage`
   对候选资料做轻量排序和筛选，优先选择最可能回答问题、最值得打开原文的资料。

4. `Windowed Evidence Reading`
   打开原文窗口读取可验证片段，保留页码、段落、行号、表格范围、音视频时间段等可回跳位置。

5. `Citation-grounded Note Synthesis`
   基于 `问题 + 候选资料 + 原文窗口 + 摘录卡片 + 来源定位` 生成带引用回答，并沉淀为结构化笔记。

这条路线的关键不是“RAG”三个字本身，而是：

- 先做资料级筛选，再做片段级召回
- 先做候选定位，再做原文阅读
- 先绑定证据位置，再做回答生成
- 回答之后继续沉淀为结构化笔记
### 2.4 笔记必须能回到证据

结构化笔记不是单纯总结。

每个关键观点都应尽量绑定：

- 原文摘录
- 来源位置
- 引用信息
- 是否存在冲突或待确认

这样保存后的笔记才具备后续复用价值，而不是另一段不可追溯的模型输出。

## 3. 产品体验

用户体验上，Note 链路仍然发生在聊天页面中。

用户选择 `Note` 链路后，聊天回答建议分为五块：

```text
直接回答
关键观点
候选资料
摘录卡片
结构化笔记
```

### 3.1 直接回答

先回答用户问题。

不能让用户感觉系统只是在整理资料，而没有解决当前问题。

### 3.2 关键观点

把回答拆成几个可理解的观点。

每个观点尽量绑定摘录或来源。

### 3.3 候选资料

展示系统认为最相关的资料。

候选资料卡回答四个问题：

- 哪些资料与问题相关
- 为什么相关
- 大概讲了什么
- 是否值得打开原文继续阅读

### 3.4 原文窗口

原文窗口负责把系统拉回真实资料。

它可以对应：

- PDF 页码范围
- Word / Markdown 段落
- 网页正文片段
- 表格行列范围
- 音视频转写时间段

原文窗口必须支持引用回跳，让用户能看到结论来自哪里。

### 3.5 摘录卡片

摘录卡片是结构化笔记的材料层。

每张摘录卡片建议包含：

- 原文摘录
- 对应观点
- 中文解释
- 来源位置
- 标签
- 相关原因
- 冲突或待确认标记

### 3.6 结构化笔记

系统基于回答、候选资料和摘录卡片生成一份可编辑笔记。

推荐默认结构：

```text
# 标题

## 直接结论

## 关键观点

## 证据摘录

## 来源对比

## 待确认问题

## 后续整理方向
```

用户确认后，笔记保存到当前研究工作台，后续可以继续参与问答、Note 整理、Wiki 页面生成和右侧产物生成。

## 4. 检索流程

Note 链路主流程定义为：

```text
用户在聊天框提问
  -> 系统读取当前研究工作台上下文
  -> 工作台级边界约束
  -> 通过资料标题、摘要、标签、历史笔记、结构化元数据和关系信号定位候选资料
  -> 对候选资料做轻量排序和筛选
  -> 生成候选资料卡
  -> 选择关键资料打开原文窗口
  -> 从原文窗口读取可验证片段
  -> 抽取摘录卡片
  -> 基于证据片段和来源定位生成带引用回答
  -> 基于回答、摘录和引用生成结构化笔记
  -> 用户确认保存到工作台
  -> 保存后的笔记继续参与后续检索
```

对应 Marginalia 思路，可以理解为：

```text
titles / summaries / tags / metadata / history notes / relations
  -> candidate entries
  -> candidate triage
  -> original reading windows
  -> verifiable evidence snippets
  -> excerpt cards
  -> cited answer
  -> structured reusable note
```

## 5. 与问答链路和 Wiki 链路的区别

### 5.1 问答链路

问答链路是 `答案优先`。

目标是：

- 快速回答
- 引用清楚
- 输出简洁
- 尽量少打断用户

典型输出：

```text
直接答案
关键依据
引用来源
```

### 5.2 Note 链路

Note 链路是 `回答 + 整理`。

目标是：

- 回答问题
- 找出关键资料
- 读取原文窗口
- 抽取摘录卡片
- 生成结构化笔记
- 保存到工作台后继续复用

典型输出：

```text
直接答案
关键观点
候选资料
摘录卡片
结构化笔记
保存到工作台
```

### 5.3 Wiki 链路

Wiki 链路是 `稳定知识优先`。

目标是：

- 优先读取已有 Wiki 页面
- 利用页面关系回答
- 内容不足时回到工作台资料补充
- 引导用户进入 Wiki 工作台维护长期知识

典型输出：

```text
基于 Wiki 的回答
相关知识页依据
进入 Wiki 工作台
```

## 6. 保存与复用

Note 链路的结果不静默进入长期记忆，也不自动发布为 Wiki 页面。

推荐规则：

- 用户确认后，结构化笔记保存到当前研究工作台
- 保存后的笔记可以被后续聊天检索
- 保存后的笔记可以继续被 Note 链路整理
- 保存后的笔记可以作为 Wiki 页面生成的参考材料
- 保存后的笔记可以作为右侧产物生成的上下文
- 是否进入长期记忆，由 `Graduated Memory` 单独门控判断

对外统一说法：

`保存到工作台`

## 7. 内部实现建议

对外产品词统一使用：

- 资料
- 候选资料
- 原文窗口
- 摘录卡片
- 结构化笔记
- 保存到工作台

内部实现可以保留英文实体或类名，但文档和汇报优先使用中文产品词。

建议内部对象关系：

```text
Workspace
  -> Material
  -> MaterialMetadata
  -> ReadingWindow
  -> 摘录卡片
  -> KnowledgeItem(type=NOTE)
  -> Citation
```

其中：

- `Material` 表示工作台内可检索资料
- `MaterialMetadata` 表示标题、摘要、标签、来源、时间等结构化信号
- `ReadingWindow` 表示可回跳的原文窗口
- `摘录卡片` 表示摘录卡片
- `KnowledgeItem(type=NOTE)` 表示用户保存后的结构化笔记

## 8. 落地范围

第一阶段只做最能体现差异的能力：

```text
工作台级检索
  -> 结构化候选资料卡
  -> 原文窗口读取
  -> 摘录卡片
  -> 直接回答
  -> 结构化笔记
  -> 保存到工作台
```

暂不做：

- 独立 Note 工作台
- 完整 journal 失效机制
- 复杂关系挖掘
- 自动知识图谱
- 多智能体协作
- 自动发布 Wiki 页面

## 9. 最终口径

`Note 链路是 NoteWeave 中面向资料整理的溯源式问答链路。它的实现重点参考 Marginalia-style Structured Reading Funnel：系统不直接对 chunk 做 top-k 问答，而是先通过资料标题、摘要、标签、历史笔记、结构化元数据和关系信号定位候选资料，再打开原文窗口读取可验证片段，抽取摘录卡片，并生成带引用的回答与结构化笔记。它和问答链路的区别在于更重视阅读、摘录和沉淀；和 Wiki 链路的区别在于不直接组织长期页面，而是先形成可保存、可复用的结构化笔记。`
