# GPT / Gemini 风格对照与改版建议

> 只读。不改代码。  
> **方向已更新：** 产品更接近 Google NotebookLM（来源 | 对话 | Studio），见 [NotebookLM风格对照与改版建议](./NotebookLM风格对照与改版建议.md)。本文保留作「和纯对话产品差在哪」的对照；其中「藏起来源、对话占满屏」**不要按这个方向落地**。  
> 架构问题（`App.tsx` 总编排、双 CSS、主题重复）仍然成立。

---

## 1. 目标气质

ChatGPT / Gemini 的共同点不是「再做一个研究后台」，而是：

1. **对话是唯一主舞台。** 打开就是聊天。别的能力是模式、工具或右侧画布，不是五个并列 App。
2. **空的时候很空。** 一句问候 + 几个 chip。没有架构图、没有「资料库 → 会话」说明、没有模式说明书。
3. **输入盒是视觉重心。** 大圆角、贴底、附件/工具收进盒子里，发送在盒内。
4. **消息几乎无框。** 用户一句、助手一篇 Markdown。引用是消息底下的小标记，不是另一张仪表盘。
5. **左栏是历史，不是导航墙。** 新对话、会话列表、账号。项目/工作台像 GPT 的 Project，收在顶部切换。
6. **右侧可有画布。** GPT Canvas / 产物是把主列劈开，不是全屏 modal，也不是永久三栏都亮着。
7. **一种强调色。** ChatGPT 绿或 Gemini 蓝，二选一。不要蓝钮 + 绿焦点环同时抢。

NoteWeave 已经有对话、模式切换、圆角输入盒、示例 chip、绿强调。差的是：**周围的研究后台外壳还没卸掉。**

## 2. 对照表

| 点 | ChatGPT / Gemini | 现在的 NoteWeave | 判断 |
| --- | --- | --- | --- |
| 打开后看见什么 | 问候 + 输入盒 | 左 rail 五入口 + 资料摘要 + 英文 label + 模式说明条 + 知识路径图 | 太满 |
| 信息架构 | Chat 为主，工具藏起来 | 对话 / 资料库 / 研究 / Wiki / 记忆平级 | 像套件，不像一个产品 |
| 左栏 | 会话历史，可收成图标 | 品牌 + 五导航 + 工作台切换 + 会话列表 + 账号 | 职责叠了三层 |
| 模式 | 标题旁一个下拉（模型） | 底部 `AnswerModeSelector` + 顶上一整条 `mode-context-line` | 下拉是对的，说明书是多余的 |
| 资料 | 回形针 / 文件抽屉 | 永久 `ChatSourcesPane` + 独立资料库页 | 资料常驻抢对话 |
| 产物 | 主列左右分屏 | `createPortal` 全屏 dialog，锁滚动 | 最不像 GPT Canvas |
| 输入 | 盒内工具 + 发送 | 盒下长文范围说明 + 模式 + Enter 提示 + 产物按钮 | 重心被拆散 |
| 空状态 | 「有什么可以帮忙的？」 | 「从工作台资料开始提问」+ 流程图 + 计数 | 在教产品，不是在开始对话 |
| 回答 | 正文 + 折叠引用 | lead 标题 + 多张 `details` 卡片（来源、漏斗、关系） | Note/Wiki 像报告封面 |
| 研究 | GPT 里是一次对话或 Deep Research 面板 | 三列：列表 / 报告 / 过程审计 | 运维台 |
| 颜色 | 一种 accent | token 蓝 primary + 绿 accent；规范还写了珊瑚海军 | 三套语言 |
| 字号 | 问候很大，正文约 16px | label 0.58rem，正文偏 14px | 辅助过小，问候不够大 |
| 文案 | 短、人话 | 中英混标签、范围叙事、流程 01 02 03 | 后台口吻 |

## 3. 现在已经像的部分（留下）

这些不要推倒：

- 白底 / 深色、圆角 composer、发送键圆形，方向对。
- `AnswerModeSelector` 已经是 GPT 式下拉，不是三个大 Tab。应上移到标题旁，当成「模型/模式」选择器。
- 示例 chip、生成中的三点动画、消息 `MarkdownSurface`。
- 左栏已有会话列表和新会话，这就是 GPT 左栏的核心。
- Artifact lazy 加载合理；缺的是出现方式（分屏而不是 modal）。
- 引用放进可折叠卡片，方向对；默认应只留「来源」一枚 chip，Journal/漏斗/图谱不要默认摊开。

## 4. 主要问题（按 GPT/Gemini 口径）

### 4.1 五个平级 App

rail 上：对话、资料库、研究、Wiki、记忆。GPT 不会把 Search、Canvas、Memory 和 Chat 并排放五个主按钮。Gemini 的工具是输入盒上方的 chip 或加号菜单。

结果：用户进门要先选「我现在用哪个子系统」，而不是直接问。

**建议：**

- 默认落地只有 **对话**。
- 左栏主列表 = 会话历史（可按工作台过滤）。
- 资料库、Wiki、Memory、Deep Research 放进：账号菜单、工作台菜单，或 composer 里的「+ / 工具」。
- Deep Research 更像 GPT 的 Deep Research：在对话里发起，过程用一条可展开的进度，报告仍在对话流或右侧画布出现。不要默认进三列监控页。

能力都还在，只是入口降级，不再和 Chat 抢一级导航。

### 4.2 对话区被说明书包围

Chat 主列从上到下：

1. 图标 + `Current conversation` + 标题 + 工作台/资料/会话计数  
2. 一整条模式说明（「基于工作台资料回答…」）  
3. 空状态：说明 + 资料库→会话流程图 + chip  
4. 输入盒外：QA 范围长文、模式、快捷键、产物  

GPT 空状态几乎只有问候和 chip。Gemini 问候可以大，但仍不解释产品架构。

**建议空状态：**

```text
        NoteWeave
        有什么想从资料里问的？

        [核心结论是什么？]  [有哪些矛盾观点？]  [用三条要点概括]
```

无流程图、无英文 label、无「N 个会话共用」。没资料时，输入盒左侧一个回形针，点开才进资料。

**建议进行中：**

- Header：会话标题（可改名）+ 右上角模式下拉（问答 / Note / Wiki）。
- 中间只有气泡。
- 底栏只有 composer。

`mode-context-line` 删掉。模式含义第一次可用 tooltip，不要常驻横条。

### 4.3 资料不该永远占一列

GPT/Gemini 的文件是附件。永久 `sources-pane` 让 Chat 永远少一列，还在重复「共享资料、绑定工作台」。

**建议：**

- Chat 默认两列都不要：左历史 + 中对话（GPT 默认）。
- 资料 = composer 内附件按钮，弹出当前工作台文件列表（可多选，作为 QA scope）。
- 完整上传/解析进度仍可留「资料库」页，但从工具菜单进入，不要和 Chat 平级。

QA 范围与后端一致：只在问答模式出现；Note/Wiki 不要露出「限定资料」以免打到 `ANSWER_SOURCE_SCOPE_UNSUPPORTED`。

### 4.4 产物应是 Canvas，不是对话框

GPT Canvas：对话还在，右边（或把对话挤窄）出现可滚动文档。Gemini 侧面板类似。

现在：全屏 modal、遮罩、锁 `body` 滚动，对话和资料全部消失。这是「另一个后台」而不是「边聊边看稿」。

**建议：**

- 桌面：主区 `grid` 为 `minmax(0,1fr) minmax(420px, 52%)`，仅当产物打开时变成两列。
- 不要同时再留资料列（GPT 也不会三栏常亮）。
- 移动：底部 sheet，高度约 85vh，仍能看到一点对话。
- 标题用「产物」，不要 `Workspace Studio` / `Artifact Studio`。

前一份报告里「必须永久三栏来源|对话|产物」**不再适用**。GPT 风格下，来源和产物都是按需面板，主列永远是对话。

### 4.5 回答气泡太「报告」

`MessageBubble` 会拆 lead 标题，再挂多张卡片（来源引用、Note 漏斗、Wiki 关系）。GPT 是一篇连着的 Markdown，引用是句末小标或底部 Sources。

**建议：**

- 问答：正文 + 一条「来源 · n」展开。
- Note：正文为主；「摘录 / 漏斗」默认折叠。
- Wiki：正文为主；图谱/反链给「在 Wiki 中打开」，不要在气泡里画网络。

### 4.6 Research / Wiki 页面不像对话产品

Research 空状态有 hero、四格 dl、01-02-03 流程、`Workspace research` 英文徽章。Wiki 空状态同样是流程条。这是控制台 onboarding。

若研究仍要独立页，也应像 Gemini 的长文档：左窄历史，中是问题输入 + 报告正文，过程是报告顶端一条可展开的 stepper，而不是第三列审计。

### 4.7 颜色：承认自己就是 GPT 系，选一个 accent

现码已经是白 + `#10a37f` + `#2563eb`。用户要 GPT/Gemini，就不要再往珊瑚海军扭。

**建议二选一：**

- **GPT 向：** 画布白/深灰，accent 只用绿（发送、选中会话、焦点环）。Primary 按钮也用绿或墨黑，去掉第二套蓝主色。引用链接可用中性下划线 + 小号 chip，不必另起「证据蓝」。
- **Gemini 向：** 画布更净，accent 只用蓝；问候可用极淡彩渐变，工作台里不再铺网格和光晕。

不要绿焦点 + 蓝按钮。认证页暖纸张也可以收掉，改成和 GPT 登录一样的中性底，进出同一产品。

### 4.8 排版：问候大、辅助少、正文偏大

GPT 空状态标题很大；正文舒适，接近 16px。现在辅助 0.58–0.66rem，问候不够大。

**建议：**

```text
问候      32–40px，字重 500–600，居中
会话标题  16px，header 里一行
正文      16px / 1.7
辅助      13px，能删就删
composer  16px 输入文字
chip      14px
```

中文 UI，专有名可留 Wiki、Note、Deep Research。删掉 `Current conversation`、`Research notebook`、`Workspace library` 这类装饰英文。

composer：圆角 24–28px 可以留（这正是 GPT 盒），但盒外不要再挂一段说明。阴影轻，不要大投影悬浮卡片。

## 5. 目标线框（Chat 默认）

```text
┌──────────┬──────────────────────────────────────┐
│ NoteWeave│  会话标题              [问答 ▾]  ··· │
│ [新对话] │                                      │
│ 会话 A   │           有什么想问的？               │
│ 会话 B   │     [chip] [chip] [chip]              │
│          │                                      │
│          │  ┌──────────────────────────── [↑] ┐ │
│ 工作台 ▾ │  │ 问一点…              📎   发送   │ │
│ 账号     │  └─────────────────────────────────┘ │
└──────────┴──────────────────────────────────────┘
```

产物打开时：

```text
┌──────────┬───────────────────┬──────────────────┐
│ 历史     │  对话继续可见      │ 产物标题    [x]  │
│          │  …                 │ 正文 / PPT / PDF │
│          │  [输入盒仍在左半]   │                  │
└──────────┴───────────────────┴──────────────────┘
```

Deep Research 进行中：对话里一条「正在研究…」进度卡，点开才看 checkpoint；完成后助手消息就是报告，需要时再推到右画布。

## 6. 建议顺序（按这个方向）

**P0 先让 Chat 像一个对话产品**

1. 空状态改成大问候 + 三个 chip；删除知识路径图和模式说明条。
2. 模式选择器移到 header，文案改成「问答 / Note / Wiki」（去掉「问答 RAG」这种内部名）。
3. composer 只保留输入、附件、发送；QA 范围进附件面板。
4. 左栏突出会话列表，五入口收到「工作台」或底部工具。
5. 中文标签；一种 accent（建议先用现有绿，去掉蓝主按钮）。

**P1 画布与资料**

6. Artifact 改为对话右侧分屏，去掉 modal。
7. Chat 默认不渲染 `sources-pane`；附件抽屉读同一份 `sources`。
8. 回答卡片默认只露来源 chip。
9. 正文 16px，问候 32px+。

**P2 其它表面同一语言**

10. Research 收成「历史 + 报告」，过程进报告内折叠。
11. Wiki / Memory 从工具进入，页面按文档而不是三列治理台排。
12. 认证页改中性底，与工作台同一 token。
13. 按视图懒挂 controller、整理双 CSS——这是工程债，视觉上用户无感，但仍应做。

## 7. 和仓库设计文档的冲突（写明）

| 仓库规范 | 若要 GPT/Gemini |
| --- | --- |
| 永久三栏：来源 / 主区 / inspector | 默认一列对话；面板按需 |
| 海军 + 珊瑚；蓝给 citation | 单 accent（绿或蓝） |
| 证据、状态、版本号视觉优先 | 证据在消息底部，不跟正文抢 |
| 工作台密度 7、领域色顶边 | 低 chrome，几乎无顶边装饰 |
| Research/Wiki 作为一级工作台 | 降为工具/画布 |

要以对话产品为准，应把上述规范标成「历史研究台方向」，避免实现时两套规范同时生效。`ui:check` 里锁死的品牌标题、`mode-context-line`、Chat 内资料区 class 会挡 P0，改 UI 时要同步改脚本。

---

## 8. 一句话

现在的前端是 **ChatGPT 的输入盒，套在研究套件的导航和说明书里。**  
要像 GPT/Gemini：把 Chat 做成几乎全屏的对话，资料变成附件，产物变成右侧画布，Research/Wiki/Memory 变成工具，只留一种强调色，把教学文案从主界面拿掉。
