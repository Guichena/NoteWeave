# NoteWeave v2 企业级视觉设计参考基线

> 研究日期：2026-08-10
>
> 适用范围：NoteWeave v2 的桌面浏览器研究笔记工作台，包括 Chat、Research、Wiki、Memory、Artifact、设置和认证入口。
>
> 本文只提炼视觉与交互设计原则，不复制参考产品的文案、业务术语、路由、信息架构或产品功能。本文是设计决策依据，不是前端实现变更记录。

## 1. 结论先行

NoteWeave v2 应该形成一种“证据优先的研究工作台”气质：

- 用中性的低对比画布承载长时间工作，用深色墨色 rail 固定导航和产品识别。
- 用 `canvas -> sunken -> default -> raised -> overlay` 表达空间层级，用分隔线和留白组织多数关系，阴影只保留给真正浮起的对象。
- 用一个稳定的主操作色表达可执行动作；Chat、Research、Wiki、Memory 的领域色只负责快速识别、选中线和状态，不应铺满页面背景。
- 用“索引/来源 -> 工作区 -> 检查或产物”的三段式工作台组织研究任务；右侧信息区可折叠，不能牺牲桌面端主任务宽度。
- 用高信息密度但有节奏的列表、标题和状态行服务重复操作；不把每个区域都做成相同的圆角卡片。
- 动效只解释进入、退出、状态变化和层级变化，并尊重 `prefers-reduced-motion`；不使用持续漂浮、发光或装饰性脉冲制造“AI 感”。

这组结论由本地 v1 / WeKnora 代码与官方设计系统的交集得出。NotebookLM 的官方产品说明支持三段式来源、对话、产物工作区；Linear 的官方重构文章支持“主任务获得注意力、导航后退、减少无意义边框”的界面策略；Carbon、Atlassian、Fluent 和 WCAG 为颜色、间距、层级、动效和可访问性提供了正式规范。

## 3. 适用于 NoteWeave 的色彩层级

### 3.1 颜色应该表达“角色”，不是装饰

Carbon、Atlassian 和 Fluent 都把颜色组织为语义角色或 alias，而不是让组件直接选择一组孤立的 hex。Atlassian 还明确区分 neutral、brand、information、success、warning、danger 角色及其 emphasis、hover、pressed、selected、focused、disabled 状态。[O6][O7][O12]

NoteWeave 的 token 应保持下面的语义边界：

| 层级 | 推荐职责 | 建议色相方向 | 禁止用途 |
| --- | --- | --- | --- |
| `canvas` | 页面和工作台外壳的最大面积背景 | 中性冷灰；认证页可用 v1 暖纸张 | 不用渐变、光斑或高饱和领域色铺满 |
| `surface-sunken` | 来源筛选、输入井、代码块、空态底座 | 比 canvas 略深/略暗 | 不再叠加第二张卡片 |
| `surface` | 侧栏、主内容平面、阅读区 | 与 canvas 只拉开有限明度差 | 不用同一套阴影制造所有层级 |
| `surface-raised` | 当前任务、可拖动卡片、聚焦表单 | 明度提升，暗色模式也应更亮 | 不把每个列表项都提升 |
| `surface-overlay` | 弹窗、菜单、抽屉、浮动工具条 | 最高层级，对比和阴影最明确 | 不作为普通页面 section |
| `ink` | 标题、正文、核心数据 | 近中性深色 | 不用领域色替代正文色 |
| `primary/action` | 保存、发送、开始研究、确认 | 稳定的蓝色或 NoteWeave 的主操作色 | 不与每个领域色争夺主按钮 |
| `domain` | 当前工作台识别、选中线、短标签 | Chat 珊瑚、Research 蓝、Wiki 绿、Memory 琥珀 | 不用于整块背景和长文本 |
| `status` | 成功、等待、警告、失败 | 绿、琥珀、红 | 不只用颜色表达状态，必须有文字、图标或形状 |

### 3.2 建议的 NoteWeave 颜色基线

下表是“适用于 v2 的候选基线”，不是声称来自任何参考产品的原始 token。它把本地 v1 的颜色语义、Carbon 的中性层叠、Atlassian/Fluent 的角色 token 和当前 v2 的领域色合并成一套可测试的方向。实施时应在现有 `tokens.css` 中保留语义名，再通过对比度工具校正实际值。

| 语义 | Light 候选 | Dark 候选 | 说明 |
| --- | --- | --- | --- |
| 画布 | `#F4F5F7` | `#17191C` | 中性工作台底色；不要把认证页的暖纸张扩散到业务工作台 |
| 画布深层 | `#E9EBEF` | `#111315` | sunken 区域和工作台间隙 |
| 普通面板 | `#FFFFFF` | `#202327` | 主工作表面 |
| 提升面板 | `#FFFFFF` | `#292D32` | 当前任务、浮起卡片；暗色模式通过明度而非黑色阴影表达 |
| 墨色 rail | `#1F2937` | `#101214` | v1 的 `bg-ink` 语义与 Carbon/WeKnora 的深导航共同支持 |
| 主正文 | `#1F2937` | `#F1F3F5` | 保证长时间阅读 |
| 次正文 | `#52606D` | `#B5BDC7` | 描述、元数据、辅助标签 |
| 主操作 | `#2F5BD1` | `#79A8FF` | v1 `signal-blue` 的交互语义；暗色值需实测对比度 |
| 品牌暖色 | `#C96A3D` | `#E69368` | Note 创建、认证页、少量品牌节奏；不作为全局大面积底色 |
| 成功 | `#2E7D61` | `#65C49B` | 完成、已索引、已写回 |
| 警告 | `#A56A17` | `#E2B25D` | 等待、待审核、需要处理 |
| 危险 | `#BA4A3C` | `#F08A82` | 失败、删除、不可用 |

推荐的默认比例是：中性表面和文字占绝大多数，主操作色只出现在可执行控件和焦点，领域色只出现在 active rail、标题标记、状态点和少量边线。这样能同时继承 v1 的识别力和 Carbon/Linear 的克制。[O3][O4][O6]

### 3.3 暗色模式不是“把白色换成黑色”

Carbon 说明暗色层级会随着层级变亮；Atlassian 说明暗色模式的 raised/overlay 表面仍需配合阴影，同时用更亮的表面区分提升；WeKnora 的暗色主题也采用 `#181818 -> #242424 -> #2c2c2c` 这类中性灰层，而不是蓝色渐变。[O6][O9][L2]

因此 NoteWeave 暗色模式应满足：

1. canvas 最暗，sunken 与 default 之间有可感知但不刺眼的明度差。
2. 主阅读/对话区域比侧栏亮一级，当前操作区再亮一级。
3. 边框只在需要分隔的地方出现，颜色不能成为连续网格。
4. 蓝、绿、琥珀、红都要在暗底上重新生成，不直接复用 light 的低明度值。
5. 任何状态都不能只依赖色相；同时提供文字、图标、形状、进度或位置变化。[O7][O11][O13][O14]

## 4. 三栏应用壳与工作台布局

### 4.1 结构模型

Google 对 NotebookLM 的官方描述把来源、对话、产物放在统一界面的三个区域，并允许根据任务扩展来源查看器或笔记编辑器。[O1] NoteWeave 可以把这个模型映射为自己的业务语义：

```text
┌────────────┬──────────────────┬──────────────────────────────┬──────────────┐
│ Global rail│ Context / source │ Main research canvas         │ Inspector    │
│ 导航与空间  │ 索引、来源、队列   │ 对话、报告、Wiki 页面、审阅工作区 │ 证据、版本、产物 │
└────────────┴──────────────────┴──────────────────────────────┴──────────────┘
```

这是空间模型，不是要求每个页面永远显示四列。推荐规则：

- Global rail 固定、可收缩，桌面展开宽度约 `240-260px`，收缩态保留约 `56-64px` 图标轨。
- Context/source 是任务索引，约 `240-288px`；它应能独立滚动或抽屉化，不压缩主阅读区。
- Main canvas 永远拿到最高视觉权重和剩余宽度；长文阅读宽度控制在约 `68-76ch`，数据/图谱可以例外。
- Inspector 是可选的辅助区域，约 `280-360px`；1280px 桌面默认收起或变为抽屉，1440px 以上才稳定展示三栏/四栏。
- 页面不应同时把 global rail、context rail、inspector 和大量浮动卡片都做成高对比容器；主任务只有一个 raised focal surface。

本地 v1 的 `60 / 288 / 360 / 720` 工作台变量、WeKnora 的 `260 -> 60` 主侧栏和 `56 -> 208` 空间侧栏，都支持“固定导航 + 可收缩上下文”的策略。[L1][L2] Atlassian 和 Fluent 的网格规范进一步要求主内容对齐列、gutter 和 margin，并在断点处重排，而不是让内容溢出或依赖横向滚动。[O8][O12][O14]

### 4.2 不要让每个区域都是一张卡片

Linear 官方 2026 refresh 直接指出边框和分隔线会无意义地增殖，应减少数量、降低对比，同时保持结构可感知。[O4] Atlassian 的 elevation 也建议 default 平面优先使用边界和留白，raised 只给真正需要聚焦或拖动的对象。[O9]

NoteWeave 的布局层级应改成：

- 外层：一个连续的 workbench canvas。
- 侧栏：以背景色阶、窄分隔线和 section 标题区分，不加重阴影。
- 主区：一个明确的工作表面，标题、内容和输入/操作区在同一平面内建立阅读顺序。
- 当前任务：最多一个到两个 raised surface，例如当前报告卡或 Memory 审阅卡。
- 抽屉/菜单：overlay，仅在交互期间出现。

这比“global rail + context rail + main + inspector 四个相同圆角白卡”更接近 Linear、Carbon 和 WeKnora 共同体现的企业级层级感，也能减少当前 v2 的视觉单调。

### 4.3 页面映射

| 页面 | 主任务 | 第一视觉焦点 | 次级区域 | 1280px 行为 |
| --- | --- | --- | --- | --- |
| Chat | 提问、阅读回答、回到证据 | 对话流和输入区 | 来源选择、产物 | 来源可见；产物/检查区抽屉化 |
| Research | 启动研究、观察过程、阅读报告 | 当前报告或运行状态 | 历史、过程、证据 | 历史和过程合并为上下文栏；详情抽屉化 |
| Wiki | 从索引进入页面、阅读、跳转关系 | Wiki 页面正文 | 页面索引、反链/图谱 | 正文与索引保留，关系区抽屉化 |
| Memory | 审阅候选、确认版本、处理队列 | 当前审阅任务 | 队列、版本差异 | 队列保留；版本详情抽屉化 |
| Artifact | 查看、复制、下载、回到来源 | 产物正文/预览 | 版本、运行追踪、来源 | 版本和追踪收进右侧抽屉 |

页面标题、主操作、状态和当前对象必须在同一条顶部对齐线上。不要让每个页面重新发明一套 header 高度、按钮位置或状态 badge。

## 5. 密度、间距与排版

### 5.1 密度不是把文字变小

Atlassian 用 8px 基础单位并把小间距、中间距和大间距区分用途；Fluent 用 4px ramp，同时强调邻近关系和留白共同表达群组与重点。[O8][O12] Linear 的官方重构也把“信息密度”与“视觉噪声”分开处理：可以保留信息，但减少不必要的图标、边框和同等权重。[O3][O4]

NoteWeave 的工作台建议：

| 场景 | 间距范围 | 规则 |
| --- | --- | --- |
| 图标与标签、列表行内 | 4-8px | 保持紧密关系；点击目标仍至少 24px，重要控件建议 40-44px |
| 列表项和小卡片内部 | 8-12px | 让重复信息可扫描，不用额外阴影分组 |
| section 内部 | 16-24px | 由标题、状态线、留白分组 |
| 主区与侧栏之间 | 16-32px | 在桌面网格中稳定，不随内容随机变化 |
| 页面标题与主内容 | 24-32px | 用留白建立页面级重点 |

### 5.2 字体层级

Atlassian 官方建议使用明确的 heading 层级，不跳级；其应用标题尺度以 16、20、24、28、32px 等为主要层次。[O8] 本地 v1 和 WeKnora 都优先使用系统无衬线字体，适合桌面应用的多语言和性能约束。[L1][L2]

NoteWeave 的候选排版阶梯：

- 页面标题：24-32px，行高约 1.2。
- 工作台标题：18-20px，配合状态和对象名。
- 正文/对话：14-16px，行高 1.5-1.65。
- 元数据/辅助信息：12-13px，不能低于可读对比度。
- 代码、ID、时间和计数：使用等宽或 tabular numbers，保持列对齐。
- 报告和 Wiki 正文：控制在 `68-76ch`，避免整屏横向长行。

不要用超大标题、字距压缩或装饰性衬线字体制造“高级感”；研究工作台的高级感来自稳定的层级、对齐和信息可预测性。[O8][O13]

## 6. 状态反馈与工作流反馈

### 6.1 每个异步区域都必须有完整状态集合

研究工作台的核心不只是成功态。来源索引、研究运行、Wiki 构建、Memory 审阅、Artifact 生成都至少需要：

1. `idle`：告诉用户可以做什么，但不抢主任务注意力。
2. `loading`：保留布局尺寸，显示正在进行的对象或阶段，不让页面跳动。
3. `partial/running`：显示已完成阶段、当前阶段和可执行的取消/返回操作。
4. `empty`：说明当前对象为空的原因，并提供唯一主要下一步。
5. `success/completed`：显示完成事实和下一步操作，而不是只显示绿色。
6. `warning/degraded`：说明降级、缺失或等待原因，不静默使用假数据或空结果。
7. `error`：说明影响范围、可恢复操作和是否需要重试。

Atlassian 明确要求状态不能依赖颜色 alone；Fluent 和 W3C 共同要求语义、焦点和文本反馈可识别。[O7][O11][O13][O14]

### 6.2 视觉规则

- loading 用局部 skeleton、进度线或阶段行，不能用全屏模糊遮罩覆盖可读内容。
- 空态优先使用真实布局中的短标题、原因和一个操作，不使用大面积插画占据研究内容区域。
- warning/error 采用图标 + 文本 + 状态色 + 可恢复动作；颜色只是冗余信号。
- 运行中状态应在 header、列表项和详情中保持同一命名和颜色角色。
- Toast 只用于短暂确认；需要用户处理的错误必须留在上下文中，不能只存在 3 秒。
- 异步完成后，焦点不应丢失；抽屉/对话框关闭后焦点回到触发控件。[O11][O13][O14]

## 7. 动效基线

### 7.1 只做解释性动效

Atlassian 将 motion 定义为解释“发生了什么、为什么发生、下一步是什么”；Fluent 将功能性、自然性、一致性作为基本原则，并提醒大面积内容移动会造成干扰。[O10][O13]

NoteWeave 候选时长：

| 动作 | 时长 | 推荐属性 |
| --- | --- | --- |
| hover、pressed、焦点反馈 | 50-150ms | background、border、color、opacity |
| tab/列表选中 | 120-180ms | opacity、background、窄线位置 |
| 侧栏/抽屉进入 | 150-250ms | translate + opacity，ease-out |
| 大面板重排 | 250-400ms | container transform 或 fade，避免整页飞入 |
| 数据流更新 | 尽量不连续动画 | 只标记新增或变化位置 |

禁止：无语义的漂浮球、无限渐变、持续发光、所有卡片同时上浮、打字机式阻塞阅读、以及在用户已经定位到主任务后仍持续运动的导航装饰。

### 7.2 reduced-motion

`prefers-reduced-motion: reduce` 下应取消页面进入、线条漂移、脉冲和大幅位移，只保留必要的颜色/可见性变化。这个要求来自本地 v1 已有的 media query，以及 Atlassian、W3C 和 Fluent 的可访问性原则。[L1][O10][O11][O13][O14]

## 8. 可访问性与真实浏览器验收

### 8.1 必测规则

- 普通正文与背景至少 `4.5:1`，大文本至少 `3:1`。
- 必要的边框、输入边界、图标、焦点指示和状态图形至少 `3:1` 对比度。
- 键盘可操作控件必须有持续可见的 focus indicator；不能用 `outline: none` 后不提供替代环。[O11][O14]
- 指针目标至少 `24x24px`；主操作、关闭、抽屉和移动端导航建议 `40-44px`。[O13][O14]
- 不依赖颜色传达 selected、running、success、warning、error；同时有文字、图标、位置或形状。
- 320px 宽度下，普通内容必须单向纵向重排；三栏只允许通过折叠、抽屉或顺序切换访问，不强迫非必要双向滚动。[O11][O13][O14]
- heading 语义顺序、landmark、按钮名称、输入 label 和对话框焦点顺序要能被屏幕阅读器理解。

### 8.2 NoteWeave 桌面浏览器验收矩阵

| 视口 | 必须看见 | 允许收起 | 不允许 |
| --- | --- | --- | --- |
| 1440x900 | global rail、context/source、主区、可选 inspector | 低频工具、版本详情 | 主标题/主操作换行遮挡；四区同权重 |
| 1280x720 | global rail、context/source、主区、主操作 | inspector、产物详情 | 主区少于可读宽度；横向页面滚动 |
| 1024x768 | 收缩 rail、主区、必要上下文 | inspector、低频 source filters | 侧栏覆盖主操作且没有返回/关闭 |
| 768x1024 | 顶部或抽屉导航、单列工作区 | context/source、inspector | 固定四栏挤压或内容截断 |
| 375x812 | 当前标题、当前内容、主要输入/操作 | 全部辅助栏 | 横向溢出、点击目标过小、焦点不可见 |

真实点击验证至少覆盖：登录/注册、四个工作台切换、source/context 打开和收起、主操作、错误/空态、设置抽屉、主题切换、键盘 Tab、Escape 关闭临时层，以及 reduced-motion 下的同一组路径。

## 9. 对当前 NoteWeave v2 的具体校准建议

以下是从证据推导出的实施顺序，不是本轮执行的代码改动：

1. **先重整 token。** 保留当前 `--nw-*` 语义名，删除组件中的散落色值；补齐 `surface-sunken/default/raised/overlay` 的 light/dark 对照和每个状态的 hover/pressed/focus/disabled 值。
2. **再统一壳。** 把 `WorkbenchShell` 变成连续工作台：深 rail、低对比 context、单一主 canvas、可选 inspector；让 1280px 默认收起右侧详情，1440px 再展开。
3. **再分配颜色。** Chat 使用珊瑚作为少量活动线，Research 使用蓝色作为证据/运行信号，Wiki 使用绿色作为知识完成/链接信号，Memory 使用琥珀作为待审阅；四种颜色不得同时成为页面背景。
4. **再改密度。** 统一标题、状态行、列表行高和 section 间距；减少同形卡片，使用行、分隔线和底色阶组织重复信息。
5. **再补状态。** 对每一个异步链路补齐 loading、empty、partial、degraded、error、completed，并保证错误不被空结果掩盖。
6. **最后做动效和可访问性。** 只保留进入/退出/反馈动效；统一 focus ring、目标尺寸、颜色对比度和 reduced-motion。

这条顺序与 Linear 官方“先验证环境、外观和层级，再小范围实施”的重构经验一致，也与 Atlassian 的 token -> layout -> component -> accessibility 依赖关系相符。[O3][O8][O10][O11]

## 10. 设计反模式清单

- 用大面积渐变、模糊玻璃、发光球和装饰网格代替信息层级。
- 同一屏幕上的每个面板都使用相同白底、相同圆角、相同阴影和相同顶部色线。
- 让领域色承担背景、按钮、正文、状态和插图的全部职责。
- 让侧栏比主任务更亮、更饱和或更宽，导致用户持续被导航吸引。[O4]
- 为了“密集”把正文缩到 12px 以下，或用过多图标、badge、分隔线填满空白。[O3][O4]
- 在暗色模式只把背景改成黑色，仍使用 light 主题的低对比边框和状态色。[O6][O9]
- 用空列表、静默 fallback 或无解释的 loading 伪装成正常结果。
- 用颜色单独传达成功、失败、选中和运行中。[O11][O14]
- 把页面切换做成大幅位移或连续动画，忽略 reduced-motion。[O10][O13]

## 11. 最终验收清单

在任何全站视觉优化合并前，必须逐项留下证据：

- [ ] 1440x900、1280x720、1024x768、768x1024、375x812 均完成截图审查。
- [ ] 每个页面存在唯一主视觉焦点；导航和辅助区对比度低于主任务但仍可读。
- [ ] 三栏/四栏在断点处收缩为抽屉或单列，没有非必要横向滚动。
- [ ] 所有颜色都通过语义 token 进入组件，没有组件级随机 hex/rgba。
- [ ] Light/Dark 的 canvas、sunken、default、raised、overlay 层级可辨识。
- [ ] 文本、非文本控件、焦点环完成对比度检查。
- [ ] 状态不依赖颜色，loading/empty/error/degraded/completed 都能被识别和操作。
- [ ] Tab、Escape、抽屉焦点回收、按钮名称和输入 label 完成真实浏览器验证。
- [ ] `prefers-reduced-motion: reduce` 下没有持续或大幅装饰动画。
- [ ] 只在设计基线验证后修改实现，避免用局部截图修补取代系统性调整。
