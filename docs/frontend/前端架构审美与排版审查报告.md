> 只读审查。对照 `frontend/src`、`docs/frontend` 设计文档和 `pnpm ui:check` 约束。不改源码。建议按优先级实施，实施时不得改 URL 语义、`/api/v2` 字段、表单字段或业务状态 owner。
>
> **产品方向：** 当前以 Google NotebookLM 式「来源笔记本」为准，见 [NotebookLM风格对照与改版建议](./NotebookLM风格对照与改版建议.md)。GPT/Gemini 对照仅作差异说明。本文「海军+珊瑚仪表盘」配色不要当目标；三栏空间语法与 Notebook 方向一致，应保留。架构问题（`App.tsx`、双 CSS、主题重复）仍共用。

审查对象：壳层、Chat / 资料库 / Research / Wiki / Memory / Artifact、认证页、token 与两套 CSS。  
对照文档：[工作台设计规范](./NoteWeave工作台设计规范-风格源v1-产品源v2.md)、[全站视觉基线](./NoteWeave-v2全站视觉基线.md)、[知识工作台视觉系统](./NoteWeave-v2-知识工作台视觉系统.md)、[前端现实基线](./前端现实基线-20260721.md)。

## 1. 结论

功能入口齐全：QA / Note / Wiki 同会话、资料库、Deep Research、Wiki 治理、Memory 审核、Artifact Skill。feature 目录也按领域拆开了。

真正的缺口在壳层和视觉所有权：

1. **编排仍集中在 `App.tsx`。** 视图切走后，Wiki / Research / Artifact 的 hook 还在跑。
2. **规范要三栏，产物做成了全屏弹层。** 来源、对话、产物无法同时看见。
3. **视觉规范写了三套主色，代码落地的是 ChatGPT 式白底蓝钮绿强调。**
4. **`styles.css` 与 `visual-refresh.css` 双重覆盖。** 同一选择器在两份文件里各写一遍，排版无法稳定收敛。
5. **中英标签混用、字号过碎、欢迎区说明过多。** 密度号称 7，实际被装饰和文案撑开。

下面分架构、审美、排版写清现状、问题和建议。建议按 P0 → P2 做，不要一次重写。

## 2. 当前结构（事实）

```text
AuthGate
  └── App.tsx                    认证后总编排：session、busy、全部 controller
        └── WorkbenchShell       左 rail + 顶栏上下文 + 主题/退出
              └── 当前视图
                    chat      ChatSourcesPane | ChatWorkbench | Artifact 弹层
                    library   SourceLibraryWorkbench
                    research  ResearchSidebar | Report | Status/Detail
                    wiki      Index | Overview/Page | Relations
                    memory    MemoryReviewWorkbench
```

- 无 React Router。`features/shell/viewRoute.ts` 用 `history.pushState` 解析 `/`、`/library`、`/research`、`/wiki`、`/memory/reviews`。
- URL 只表示视图。workspace、conversation、research run、wiki page 不进地址。刷新会丢当前对象。
- Chat / Wiki / Research / Memory / 资料库走 `React.lazy`；Artifact 在 Chat 内二次 lazy，打开才加载。
- HTTP 与 SSE 在 `shared/`，领域 API 在 `features/*/api.ts`。区域 busy 分 shell / chat / upload / research / artifact / wiki。
- 样式入口：`main.tsx` 先引 `styles.css`，再引 `styles/visual-refresh.css`。token 在 `styles/tokens.css`。

这套边界对答辩和模块所有权是清楚的。问题出在「谁在什么时候挂多少状态」和「屏幕上空间怎么分」。

## 3. 架构问题

### 3.1 `App.tsx` 是总控制室

`App` 同时创建：

- `useWorkspaceSession`
- `useExecutionRegistry`
- `useWikiWorkbenchController`
- `useChatSessionController`
- `useResearchWorkbenchController`
- `useArtifactWorkspace` + catalog + composer
- `useWorkbenchNavigation`

注释写「只给当前视图组 heavy props」，这只限制了 `build*Props`。hook 本身始终挂着。切到 Memory 时，Wiki 刷新、Research 状态、Artifact 目录仍在订阅 workspace。

后果：切换工作台时要靠 `scopeResetRef` 手动清五处状态；新增视图必须改 `App`；某一 controller 抛错会拖整棵树。

**建议：** 按路由拆 Provider 或懒挂 controller。`App` 只保留 session、busy、导航。Chat 视图再挂 chat + artifact；Research 视图再挂 research。Workspace 切换仍由 session 一层发出 reset 事件。

### 3.2 路径不是深链

`parseAppLocation` 能识别视图，但：

- `/research` 打不开某一 `run_id`
- `/wiki` 打不开某一 page
- `/` 打不开某一 conversation

Wiki 还兼容 `/wiki`、`/wikis/`、`/workspaces/:id/wiki` 多套历史形态。

**建议：** 第一期只把 `workspace_id` + 视图写入 URL（query 或 path）。第二期再加 conversation / run / page。不要继续扩正则兼容。

### 3.3 Artifact 空间语法错位

设计规范的默认布局：

```text
导航/来源 | Chat / Research / Wiki | Artifact / Inspector
```

实现：`ChatWorkbench` 用 `createPortal` 把 `ArtifactRail` 挂到 `document.body`，全屏 dialog，锁 `body.overflow`。产物按钮挤在 composer 发送栏。

CSS 里其实已经有三栏骨架：`styles.css` 的 `.layout.layout-with-inspector` 是「来源 | 对话 | 右栏」。`visual-refresh.css` 后写的同名规则把右栏打开时改成「对话 | 产物」，**来源列被挤掉**。弹层方案等于绕开了这份冲突。

**建议：** 桌面宽度恢复三栏，Artifact 作为右 inspector，不盖住对话。`layout-with-inspector` 必须是三列，不得吞掉 Sources。窄屏再用抽屉或底部面板。`ui:check` 仍可保留 `artifactRailOpen` 与 lazy 边界。

### 3.4 资料入口重复

Chat 左侧已有 `ChatSourcesPane`（摘要 + 跳转资料库）。导航另有「资料库」整页，负责上传、解析任务、完整列表。

规范写「左侧负责导航、来源和会话范围」。现在用户要猜：摘要算不算资料库、上传必须进另一页。

**建议：** 左栏继续做当前工作台资料摘要与范围；上传与处理状态只放资料库页。导航文案改成「资料」或「来源」，避免和左栏「共享资料」抢名。

### 3.5 样式双栈

| 文件 | 角色 | 问题 |
| --- | --- | --- |
| `tokens.css` | 语义色、间距、圆角 | 主色与设计文档不一致 |
| `styles.css` | 基础布局与控件 | 仍含旧 `.workspace-card`、居中单列 `.layout` |
| `visual-refresh.css` | 后加的工作台皮肤 | 数千行，重复覆盖 rail / layout / chat / composer / 渐变网格 |

同一选择器（`.layout`、`.global-rail`、`.composer-dock`、`.mode-context-line`）在两份 CSS 里都有，后加载的 refresh 获胜。改 spacing 时不知道改哪一份。

**建议：** 冻结 `visual-refresh.css` 不再加规则。新改动只进 token + 一份 layout 文件。随后按页面把 refresh 里的重复块删掉或内联回 `styles.css`。禁止第三份皮肤。

### 3.6 主题与认证状态重复

`AuthGate` 和 `WorkbenchShell` 各自 `useState(getInitialTheme)` + `applyTheme`。登录页改主题，进工作台可能对不上。`AuthGate` 还持有登录/注册全部表单字段，根组件偏重。

**建议：** 单一 `ThemeProvider`。认证表单留在 `AuthCard`，Gate 只做 session 校验。

### 3.7 Research / Wiki 组件过碎

Research 拆成 Launchboard、Sidebar、Report、Process、Audit、Checkpoint（Snapshot / Diff / Evidence / Provenance / Replay）、Timeline、Writeback 等。Wiki 把 filters / draft / selection / data / actions / helpers / derived 摊成超大 props，再 `...spread` 进子面板。

领域拆分是对的，页面结构像监控台：用户写报告或读一页 Wiki 时，过程/审计/关系同时抢宽度。

**建议：** 每个工作台只保留「主阅读列 + 一个可切换右栏」。Research 默认报告，过程/审计进 tab 或抽屉。Wiki 默认正文，关系/图谱进右栏开关（现有 `relationsOpen` 可沿用，不要默认三列全开）。

### 3.8 其它边界

- `ui:check` 用源码字符串锁品牌标题、lazy Artifact、若干中文文案。有利于防回退，也让布局实验必须先改脚本。
- Chat 的 QA 资料范围只在 composer 里；Note/Wiki 模式后端会拒绝显式 scope。前端若在非 QA 露出范围选择，会和后端不一致。
- Artifact 弹层文案仍有 `Artifact Studio`。与中文产品口吻不一致。

## 4. 审美问题

### 4.1 主色没有唯一答案

| 来源 | 结构色 | 行动色 | 证据色 |
| --- | --- | --- | --- |
| 工作台设计规范 | 深绿主操作 | 深绿 | 蓝 citation |
| 知识工作台视觉系统 | 海军蓝 | **珊瑚色**编织线索 | 蓝 signal |
| 全站视觉基线 | 冷白 + 深色 rail | 珊瑚 | 蓝 / 绿 / 琥珀分领域 |
| `tokens.css` 实际 | `#2563eb` 蓝 primary | `#10a37f` 绿 accent | 蓝 signal，焦点环却是绿 |

代码最像 ChatGPT：白画布、绿强调、蓝主按钮。焦点环 `--nw-focus-ring` 用绿色，主按钮用蓝色，焦点与行动不是同一色。

领域色规范（Research 蓝、Wiki 绿、Memory 琥珀）在 token 里没有强制映射，组件多用 `var(--nw-domain-color, var(--nw-color-primary))` 回落到蓝。

**建议（先做决策，再动 token）：**

- 选定一套：推荐视觉系统的「海军结构 + 珊瑚行动 + 蓝证据」。
- `--nw-color-primary` 只给导航/选中；`--nw-color-accent` 只给主按钮/发送；`--nw-color-signal` 只给引用链接。
- 焦点环跟 accent，不再跟另一套绿。
- 认证页可保留暖纸张；工作台禁止暖底。

未选定之前，不要同时改三份设计文档和 CSS，否则会继续分叉。

### 4.2 克制规范 vs 装饰落地

规范：少渐变、证据优先、动效只表达加载和层级。

`visual-refresh.css` 与 `body` 背景含：径向光晕、纸纹、网格、斜向双色渐变、rail 纵向渐变、认证页 repeating-linear-gradient。Chat 欢迎区还有「资料库 → 会话」示意图。

装饰在抢「来源、引用、状态」的注意力。`DESIGN_VARIANCE 5`、`MOTION_INTENSITY 4` 与文件体量不匹配。

**建议：** 工作台背景改为纯 `--nw-color-canvas`。最多保留 1px 网格且对比极低。删除欢迎区流程图。认证页纸纹可以留，不要进 Chat/Research。

### 4.3 中英混排

界面同时出现：

- `Current conversation`
- `Research notebook`
- `Workspace library` / `Workspace knowledge` / `Workspace Studio`
- `Wiki Index`
- `Artifact Studio`
- 中文导航：对话、资料库、研究、Wiki、记忆

这不像双语产品（没有语言开关），像未翻完的稿。section-label 还用 0.58rem 全大写气质，中文标题压在英文标签下，层级发虚。

**建议：** 产品 UI 默认中文。英文专有名可保留 Deep Research、Wiki、Memory、QA。section-label 改成中文短词：当前会话、资料、产物、知识网络。`ui:check` 里锁死的英文片段一并改脚本。

### 4.4 登录页与工作台气质分裂

认证页：暖纸、横纹、封面叙事（文档允许）。  
工作台：冷白 ChatGPT 风。  
进门和干活不像同一产品。

**建议：** 认证页保留纸感，但品牌锁与按钮色必须和工作台同一套 token。不要认证用珊瑚、工作台用蓝绿。

### 4.5 工作台偏仪表盘

Research / Wiki 默认多面板：小标签、过程、审计、checkpoint、关系、图谱。对面试展示状态机有利，对「读报告 / 写一页」噪音高。

Chat 则偏聊天产品：大欢迎卡、长范围说明、示例 chip。两边不是同一密度。

**建议：** Chat 欢迎区只留一句话 + 示例。Research/Wiki 默认主列阅读，次要面板折叠。状态色只出现在真正的成功/等待/失败，不要每块面板一条领域色顶边。

## 5. 排版与布局问题

### 5.1 字号阶梯过碎

实测常见档位大约：

| 用途 | 现状 | 问题 |
| --- | --- | --- |
| section-label | 0.58–0.72rem | 过小，英文标签发灰 |
| 辅助/meta | 0.59–0.66rem | composer hint、QA 范围说明几乎不可读 |
| 会话标题 | 1rem | 和工作台标题抢，又不够当页标题 |
| 正文气泡 | ~0.9–0.95rem | 尚可 |
| 导航标签 | 偏小 | rail 196px 时中文还能放，英文 title 靠 tooltip |

视觉系统写：页标题 24–32px，工作台标题 18–20px，正文 14px，辅助 12px。当前 Chat 会话标题约 16px，辅助低于 12px。

**建议字号（token 化，禁止组件内再写魔法数字）：**

```text
--nw-text-label: 12px / 600 / muted     区域名
--nw-text-meta:  12px / 400 / muted     时间、计数
--nw-text-body:  14px / 400 / ink       对话、报告、Wiki 正文
--nw-text-title: 18px / 650 / ink       当前会话、当前 Wiki 页、当前 Run
--nw-text-page:  24px / 650 / ink       空状态主标题、资料库页标题
```

辅助文字不要低于 12px。composer hint、QA 范围改成一行 12px，超出省略，详情放 details。

### 5.2 间距不统一

token 有 `--nw-space-1` … `--nw-space-8`，组件里仍大量 2px、3px、7px、9px、11px、15px、18px。Chat header padding `15px 18px 13px`，composer `10px 12px 11px`，rail gap `3px`。

**建议：** 组件间距只允许 space-2/3/4/5/6。新 CSS 禁止 奇数 px。现有页面按 Chat → Shell → Wiki 空状态分批收。

### 5.3 Chat 栏结构

当前垂直顺序：

1. 会话头（图标 + 英文 label + 标题 + 工作台/资料/会话计数）
2. 模式情境条（说明 + 范围 metric）
3. 消息区（空则欢迎卡 + 知识路径图 + 示例）
4. composer（隐藏的「问题」label、范围长文、模式切换、Enter 提示、发送、产物）

问题：

- 模式切换在底部，和发送抢一行；情境条在顶部，两处都在解释 QA/Note/Wiki。
- 产物是主路径之一，却是次按钮。
- 欢迎卡重复「共享资料库 / 当前会话」，左栏已经说了同一件事。
- 消息列 `max-width: 760px` 居中，三栏打开后对话区更窄，再居中会左右大片空白。

**建议布局：**

```text
┌ 会话标题（中文「当前会话」）          [QA | Note | Wiki] ┐
├ 一行状态：N 份可检索 · 未限定范围 / 已限定 k 份        ┤
│ 消息（左对齐填满主列，阅读宽 68–76ch）                  │
└ [输入]                              [发送]  [产物]     ┘
```

- 模式切换上移到 header，用 segmented control（规范允许胶囊用于 segmented）。
- composer 只留输入 + 发送；产物改为右栏开关，不进发送行。
- QA 范围放进左栏资料或 header 的「限定」，不要在输入盒里写整段叙事。
- 空状态：一句话 + 三个示例。去掉知识路径图。

### 5.4 三栏宽度

token：`--nw-rail-width: 196px`、`--nw-sources-width: 266px`、`--nw-inspector-width: 320px`。

refresh 在 inspector 模式改成两列，来源消失。Wiki 默认 252 + 主列 + 256，Research 默认三列含过程侧栏。窄于 ~1200px 时三列会挤爆正文。

**建议断点：**

| 宽度 | Chat | Research / Wiki |
| --- | --- | --- |
| ≥ 1280 | 来源 + 主列 + 产物/关系 | 索引 + 主列；右栏可选 |
| 768–1279 | 主列；来源/产物为切换侧栏 | 主列 + 一个侧栏 |
| < 768 | 底栏导航；来源/产物抽屉 | 单列 |

桌面 Chat 打开产物时必须仍能看见来源摘要，这是「边看资料边生成」的最低条件。

### 5.5 行宽与阅读

视觉系统要求长文 68–76ch。Chat 气泡、Wiki 正文、Research 报告应设 `max-width: 72ch`，左对齐于主列，不要在已经很窄的三栏里再水平居中整列。

代码块、表格、图谱可以满主列，不受 72ch 限制。

### 5.6 圆角与阴影

规范：控件 8px、卡片 12px、面板 16px。token：control 8、card 10、panel 14。composer 被 refresh 写成 18px 大胶囊，阴影 `0 12px 34px`，像浮动聊天盒，不像工作台输入槽。

**建议：** composer 用 panel 圆角、1px `--nw-color-border`、无大阴影。raised 阴影只给对话框和认证卡。

### 5.7 中英与标题层级

空状态标题「准备工作台知识网络」上面是 `Workspace knowledge`。会话 `h2` 上面是 `Current conversation`。rail 副标题 `Research notebook`。

英文 label 既不参与检索，又占一行垂直空间，把真正标题挤到 16px。

**建议：** 删掉英文 section-label，或改成中文 12px。每个面板只保留一个标题元素。

## 6. 分页面建议

### Chat

P0：产物改右栏；中文标签；模式切换上移。  
P1：压缩欢迎区；QA 范围离开 composer；阅读宽 72ch。  
P2：左栏与资料库职责文案对齐。

### 资料库

保持上传与任务流在本页。列表密度可以提高（行高、状态点、少卡片阴影）。不要再做一套欢迎流程图。

### Research

默认：左 Run 列表 + 中报告。过程/审计/checkpoint 用页内 tab。空状态 Launchboard 保留，但去掉重复的「打开资料库」叙事（导航已有入口）。

### Wiki

默认：索引 + 正文。关系面板继续按需打开。空状态中文标签；流程三步可改成右侧「下一步」清单，不必做成横向流程图。

### Memory

审核队列本身适合三列（队列 / 正文 / 版本）。保持，但字号拉到 12/14/18，避免 label 小于 12px。

### Artifact

作为 Chat 右栏：上为 Skill 目录，中为当前 Job 状态，下为写回/Note 入库。不要用 `Workspace Studio` 当标题，用「产物」。

### 认证

保留纸感。按钮、输入、焦点环与工作台共用 token。主题状态与工作台同源。

## 7. 建议实施顺序

不要同时改主色、三栏和路由。

**P0 排版（不动路由、不动 API）**

1. 统一中文 UI 标签（Chat / Wiki 空状态 / rail 副标题 / Artifact 加载态）。
2. 字号 token：label/meta ≥ 12px，body 14px，title 18px。
3. Chat 打开产物时使用三列 `来源 | 对话 | 产物`，修正 refresh 里吞掉来源列的规则。

## 8. 明确不建议做的

- 不要引入新的设计体系或第三份 CSS 皮肤。
- 不要为了「好看」加更多网格、光晕、斜线。
- 不要把 Artifact 做成独立顶级导航页；它应留在当前工作台上下文。
- 不要在未定主色前把所有领域色铺到顶边装饰条。
- 不要把本次审查写成「前端不能用」。能用；缺的是壳层所有权和一种视觉语言。

## 9. 与后端审查的关系

后端审查里「QA 范围只支持 QA 模式」「产物 Worker 常见第一段样本」会直接反映在 UI：范围选择必须随模式隐藏；Artifact 预览不要假装引用了全文。前端排版优化解决不了这两条，但错误展示可以更诚实（例如资料「仅可阅读 / 未索引」已经有文案，应保持，不要改成模糊的「处理中」）。
