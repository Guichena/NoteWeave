# 前端现实基线

> 本文记录当前 `frontend/src` 的结构和可验证行为。文件名保留以兼容既有链接，内容不代表 2026-07 的阶段计划。

## 1. 工具链与入口

- React 19、TypeScript 5.6、Vite 5、pnpm 11.7。
- `main.tsx` 挂载 `AuthGate`，认证通过后渲染 `App`。
- 不使用 React Router。`features/shell/viewRoute.ts` 解析 `/`、`/research`、`/memory/reviews` 等路径，导航通过 `history.pushState` 和 `popstate` 协同。
- 主要命令是 `pnpm dev`、`pnpm build`、`pnpm test`、`pnpm e2e`、`pnpm ui:check` 和 `pnpm smoke`。

## 2. 当前结构

当前 `frontend/src` 有约 160 个文件。`App.tsx` 约 342 行，负责认证后的工作台编排、视图选择、controller 连接和 lazy 视图；业务代码位于 `features/*`，共享 HTTP、认证错误和 SSE 位于 `shared/*`。

| 区域 | 现行入口 | 责任 |
| --- | --- | --- |
| shell | `WorkbenchShell`、`useWorkbenchNavigation` | 全局导航、上下文条、区域 busy、视图切换 |
| chat | `ChatWorkbench`、`useChatSessionController` | QA/Note/Wiki 模式、消息流、资料、Note 入库 |
| research | `ResearchWorkbenchView`、`useResearchWorkbenchController` | 研究列表、报告、过程、checkpoint、导出 |
| knowledge | `WikiWorkbench`、`useWikiWorkbenchController` | Wiki 首页、索引、图、问题、重建 |
| memory | `MemoryReviewWorkbench`、`useMemoryReview` | canonical review 队列和决策 |
| artifact | `ArtifactRail`、artifact API/model/controller | Skill、Job、Version、状态和写回 |
| shared | `api`、`event-stream`、错误和 util | `/api/v2` 客户端、SSE、统一错误 |

`ResearchWorkbenchView`、`MemoryReviewWorkbench` 和部分 Artifact 组件通过 `React.lazy` 按视图加载。App 仍是编排根，不应描述成只有 provider/router 的空壳。

## 3. 视图与 URL

| 视图 | 路径习惯 | 说明 |
| --- | --- | --- |
| chat | `/` | 同一会话切 QA、Note、Wiki；Sources 在左侧，Artifact 可在右侧 rail |
| research | `/research` | 报告、过程和审计的研究工作台 |
| wiki | 由 `viewRoute` 与 history state 解析 | Wiki 查询和治理操作 |
| memory | `/memory/reviews` | Memory 审核队列，不是普通聊天页 |

URL 只是视图入口，workspace、conversation、run 和任务 id 仍从状态与 API 数据获得。页面切换不能清空未完成 SSE 或把其他 workspace 的数据复用到当前页。

## 4. API 与状态边界

前端 API 模块与后端 `/api/v2` Controller 对齐，返回字段使用 `snake_case`。SSE 客户端保留 event id，断线时按最后游标恢复。区域 busy 分为 shell、chat、upload、research、artifact、wiki，避免一个请求锁死全站；错误必须保留后端业务 code 和可读提示。

Memory review 只读取 canonical review endpoint；Artifact 侧栏只创建系统 Skill Job；Research 页面展示后端持久化的 checkpoint、evidence 和 delivery 状态，不自行推断 worker 完成。

## 5. 测试门禁

仓库包含 Vitest 单测、DOM 测试、shell smoke 和 Playwright 配置。`pnpm build` 进行 TypeScript/Vite 构建，`pnpm ui:check` 检查三模式、资料区、Artifact lazy 入口和文案约束。E2E 覆盖范围以当前测试文件为准，不能沿用旧文档中的通过数量。

## 6. 维护要求

修改路由、API 字段、SSE 事件或 view state 时同步 `features/*` model/API、DOM/smoke/E2E 测试和本文件。不要把设计方向、未接入路由或历史阶段验收写成当前实现。
