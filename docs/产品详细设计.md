# NoteWeave v2 产品详细设计

## 1. 产品定位

NoteWeave v2 的目标产品形态不是传统“聊天机器人”，而是更接近 NotebookLM 的知识工作台：

- 以资料为中心，而不是只以对话为中心
- 以当前工作上下文为中心，而不是让用户每次重新组织 Prompt
- 以可生成、可回写、可沉淀的产物为中心，而不是只给一次性回答

产品最终要承接四类典型工作：

1. 快速问答与理解
2. 长期知识整理与 Wiki 维护
3. 资料调查与跨文件比较
4. 基于当前上下文生成结构化产物
5. 将高价值上下文和已确认产物晋升为可复用长期记忆

## 2. 主界面形态

推荐采用三栏式工作台：

```text
左侧：导航与资料区
中间：主工作区
右侧：产物栏与结果抽屉
```

### 2.1 左侧区域

左侧承载“工作范围选择”和“资料组织”：

- Workspace 切换
- Topic Scope / 研究主题列表
- Source 列表
- 标签 / 文件夹 / 最近使用
- Notes / Wiki / Artifacts 快捷入口

左侧解决的问题是：

- 用户当前在处理哪一批资料
- 当前上下文边界是什么
- 哪些内容属于同一个主题

### 2.2 中间区域

中间区域是当前主要工作界面，根据模式切换展示不同主视图：

- 问答模式：对话与引用
- Wiki 模式：页面与关系
- 调查模式：资料卡、原文窗口、调查结论
- Deep Research 结果查看：研究进度、表格、报告

中间区域必须始终围绕“当前上下文”工作，而不是变成多个完全割裂的页面系统。

### 2.3 右侧区域

右侧区域是 v2 很关键的产品特征，类似 NotebookLM 的 Studio / 输出动作区。

它承担两种职责：

1. 展示当前上下文下可触发的产物按钮
2. 展示最近生成的产物结果、进度和可回写动作

这一区域也是 `Artifact Agent` 的主要产品入口：

- 用户不需要自己写 Prompt
- 系统围绕当前上下文自动选择 `Production Action`
- 生成结果既可以回写为 Note / Wiki，也可以进入 `Graduated Memory` 晋升链路

推荐形态：

```text
Artifact Actions Rail
  - 生成报告
  - 生成测验
  - 生成学习指南
  - 生成 FAQ
  - 生成时间线总结
  - 生成 Wiki 草稿
```

## 3. 三种工作模式

### 3.1 问答模式

核心目标：

- 围绕当前资料做快速问答
- 结合当前会话保持上下文连续性
- 快速生成 Note 或派生产物

典型界面元素：

- Chat 输入框
- 回答区
- 引用来源卡片
- 相关 Note / Wiki / Artifact 推荐
- 右侧产物栏按钮
- 顶部 Deep Research 按钮

典型问题：

- 这个文件讲了什么？
- 这个概念是什么意思？
- 这个结论的来源在哪？
- 根据这些材料生成一个测验

### 3.2 Wiki 模式

核心目标：

- 维护长期稳定知识
- 组织页面、关系、缺口与覆盖度
- 将调查或生成结果沉淀成更规范的知识页

典型界面元素：

- Wiki 页面列表
- 页面详情编辑区
- 关系图 / 页面关系侧栏
- Citation 覆盖提示
- 缺口分析入口
- 右侧产物栏按钮
- 顶部 Deep Research 按钮

典型动作：

- 从调查结果生成 Wiki 草稿
- 检查某页面来源是否完整
- 发起“扩展研究”补某个主题页面

### 3.3 资料调查模式

核心目标：

- 先找资料，再读资料，再形成调查结论
- 让系统工作在 source-first 而不是 chunk-only 的层次
- 支持跨文档、跨来源的比较和证据整理

典型界面元素：

- 调查问题输入框
- SourceCard 候选资料卡列表
- SourceWindow 原文阅读窗口
- 已阅读资料轨迹
- Investigation Note 面板
- 右侧产物栏按钮
- 顶部 Deep Research 按钮

典型动作：

- 找与某主题相关的所有资料
- 比较几份方案的异同
- 标出支持和反对某个观点的来源

## 4. Deep Research 独立入口

Deep Research 必须是一个独立功能入口，而不是某个模式内的隐藏流程。

推荐触发入口：

- 顶栏全局按钮：`深度研究`
- 问答结果卡片中的“升级为深度研究”
- 调查模式中的“启动深度研究”
- Wiki 页面中的“围绕本页扩展研究”

### 4.1 发起方式

用户可以从以下上下文发起：

- 当前聊天问题
- 当前调查主题
- 当前 Wiki 页面
- 当前选中的多个资料

系统发起时需要自动生成 `UI Context Snapshot`，把当前上下文冻结下来，供后续 `Research Run` 使用。

### 4.2 研究结果页

Deep Research 结果页建议单独呈现，至少包括：

- 研究问题
- 当前状态与进度
- Research Table
- 候选资料与已访问资料
- 低置信 / 冲突项
- 最终研究报告
- 回写操作按钮

### 4.3 结果回流

研究完成后，用户可以显式选择：

- 回到问答继续追问
- 保存为 Investigation Note
- 保存为 Note
- 生成 Wiki 草稿
- 保留为 Artifact

## 5. 右侧产物栏设计

### 5.1 按钮分组

建议把右侧动作分成三组：

1. 总结类
2. 学习类
3. 沉淀类

示例：

```text
总结类
- 报告
- 时间线总结
- 对比总结

学习类
- 测验
- 学习指南
- FAQ

沉淀类
- Wiki 草稿
- Note 草稿
```

### 5.2 按钮的本质

按钮不是直接绑定一段 Prompt，而是绑定一个 `Production Action`。

也就是说，用户点击“生成测验”时，系统内部执行的是：

- 识别当前上下文
- 选择 Quiz Action
- 装配 Skill / Prompt Recipe
- 调用所需 MCP / 读取能力
- 创建 Artifact Job
- 异步执行并产出 Artifact Version

### 5.3 上下文识别

按钮触发时系统需要判断当前上下文属于哪种类型：

- Chat Context
- Source Reading Context
- Multi-Source Context
- Investigation Context
- Wiki Page Context

这个判断会直接影响：

- 选用哪个 Action
- 如何抽取内容
- 输出结构长什么样

### 5.4 产物结果形态

右侧生成的结果不应只是一段临时文字，而应支持：

- 查看版本
- 查看生成依据
- 再次生成
- 编辑草稿
- 回写为 Note / Wiki / Investigation Note
- 加入检索

## 6. 关键用户流程

### 6.1 问答到产物

```text
用户提问
  -> 得到回答与引用
  -> 点击右侧“生成测验”
  -> 系统基于当前问答上下文创建 Artifact Job
  -> 生成测验
  -> 用户保存或继续追问
```

### 6.2 调查到研究

```text
用户进入调查模式
  -> 浏览 SourceCard
  -> 阅读 SourceWindow
  -> 形成初步 Investigation Note
  -> 点击 Deep Research
  -> 生成 Research Run
  -> 输出研究报告
```

### 6.3 研究到 Wiki

```text
Deep Research 完成
  -> 生成 Artifact 报告
  -> 用户点击“生成 Wiki 草稿”
  -> 产出 Wiki Draft
  -> 用户编辑后发布
```

### 6.4 阅读到学习产物

```text
用户打开 PDF / 视频转写
  -> 点击右侧“学习指南”
  -> 系统识别当前阅读上下文
  -> 运行对应 Production Action
  -> 输出学习指南 Artifact
```

### 6.5 产物到长期记忆

```text
用户在右侧生成报告 / FAQ / 测验 / Wiki 草稿
  -> 用户确认内容有效
  -> 系统抽取 Context Signal / Memory Candidate
  -> 通过 Novelty Gate
  -> 通过 Task Neighborhood Validation
  -> 晋升为可复用长期记忆
```

## 7. 状态与反馈设计

### 7.1 Deep Research 状态

前端建议展示以下状态：

- 已创建
- 规划中
- 搜索中
- 阅读中
- 抽取中
- 验证中
- 冲突处理中
- 写作中
- 已完成
- 部分完成
- 失败

### 7.2 Artifact Job 状态

右侧产物任务建议展示：

- 已创建
- 排队中
- 运行中
- 等待外部能力
- 校验中
- 提交中
- 已完成
- 失败

### 7.3 用户反馈原则

- 用户始终能看到任务现在在做什么
- 用户能看到结果来自哪些资料
- 用户能知道为什么失败或停在等待状态
- 用户能知道哪些内容低置信、哪些需要人工确认

### 7.4 Memory 反馈原则

- 用户能区分“聊天上下文”“研究轨迹信号”“已晋升长期记忆”
- 用户能看到某条长期记忆来自哪些产物或研究过程
- 用户能知道为什么某个内容被晋升，或为什么被拒绝
- 长期记忆默认增强问答与产物生成，不默认改写 Deep Research 过程

## 8. 默认按钮与默认产物

第一版建议锁定以下默认按钮：

- 报告
- 测验
- 学习指南
- FAQ
- Wiki 草稿

这样足够覆盖：

- 总结
- 学习
- 沉淀

而不至于第一版按钮过多导致认知负担。

## 9. 产品设计边界

第一版产品不应追求：

- 把所有 AI 能力都塞进右侧产物栏
- 让 Deep Research 变成无约束的自治系统
- 自动把所有生成结果直接写入正式知识
- 一开始就支持非常复杂的多人协作

第一版更重要的是：

- 入口清晰
- 上下文清晰
- 任务状态清晰
- 结果去向清晰

## 10. 产品总结

NoteWeave v2 的产品详细设计可以概括为一句话：

`以 NotebookLM 风格的三栏工作台为外壳，以三种工作模式承接日常知识工作，以 Deep Research 按钮和右侧产物栏承接重型智能任务，并通过显式回写与 Graduated Memory 门控晋升机制把结果沉淀为可维护、可复用的知识。`
