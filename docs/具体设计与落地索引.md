# NoteWeave v2 具体设计与落地索引

## 1. 目的

这份文档只回答两个问题：

1. 哪些设计文档可以作为后续落代码依据
2. 后续实现时应该优先读哪些文档，避免被历史口径和重复方案干扰

它默认产品边界、功能亮点和工程方向已经在主文档中收敛，不再重新定义系统形态。

当前正式口径是：

- `Java` 主系统负责研究工作台、三种聊天回答链路、业务真源、任务状态和结果回写
- `Python Research Worker` 负责 Deep Research 智能执行循环
- `Python Artifact Worker` 负责右侧产物生成智能执行循环
- `MySQL + MinIO + Elasticsearch + Kafka + Redis` 分别承担业务真源、大对象、检索索引、异步任务和短期运行态

### 2.4 三种聊天回答链路

这些文档负责回答“用户在聊天框里选择不同模式时，背后的检索和生成逻辑有什么区别”：

1. [问答RAG链路设计](D:/java-projects/NoteWeave-v2/docs/问答RAG链路设计.md)
2. [Note链路设计](D:/java-projects/NoteWeave-v2/docs/Note链路设计.md)
3. [Wiki模式设计](D:/java-projects/NoteWeave-v2/docs/Wiki模式设计.md)

统一边界：

- 三条链路都默认基于当前研究工作台内的资料集合工作
- 三条链路都必须给出可回溯来源
- 三条链路不默认互相依赖，也不把其他链路的产物当成默认检索对象
- 只有被用户明确保存为资料的系统生成内容，才会按普通资料进入解析、索引和引用流程

### 2.5 两条智能体执行链路

这些文档负责回答“独立长任务如何执行、验证、产出和回写”：

1. [深度研究智能体编排升级设计](D:/java-projects/NoteWeave-v2/docs/深度研究智能体编排升级设计.md)
2. [深度研究智能体工程落地设计](D:/java-projects/NoteWeave-v2/docs/深度研究智能体工程落地设计.md)
3. [受控式异步产物生成Agent编排升级设计](D:/java-projects/NoteWeave-v2/docs/受控式异步产物生成Agent编排升级设计.md)

统一边界：

- Deep Research 是独立研究任务，默认最终产出研究报告
- 研究报告可以像用户上传文件一样被保存为资料，再进入工作台资料底座
- Artifact Agent 是右侧产物生成能力，面向报告、FAQ、测验、学习指南、Wiki 页面草稿、Note 文档等产物
- Artifact Agent 默认绑定当前研究工作台，原材料是工作台资料池和已保存为资料的系统产物；产物类型与风格配置属于生成要求，不属于原材料
- 两条 Agent 链路都由 Python Worker 执行，但任务创建、状态管理、权限边界和结果回写由 Java 主系统负责

## 3. 后续落代码阅读顺序

推荐按下面顺序阅读，不再按历史讨论顺序翻文档：

1. 先读 [系统总体设计与功能总表](D:/java-projects/NoteWeave-v2/docs/系统总体设计与功能总表.md)，确认产品形态、功能全貌和冻结口径
2. 再读 [系统架构设计](D:/java-projects/NoteWeave-v2/docs/系统架构设计.md)，确认模块分层、执行引擎和链路边界
3. 再读 [技术架构详细设计](D:/java-projects/NoteWeave-v2/docs/技术架构详细设计.md) 与 [技术栈与数据库设计](D:/java-projects/NoteWeave-v2/docs/技术栈与数据库设计.md)，确认后端、数据和中间件落地方式
4. 开始建工程前，先读 [代码落地路线与开工清单](D:/java-projects/NoteWeave-v2/docs/代码落地路线与开工清单.md)，确认模块顺序、冻结对象和第一阶段不做事项
5. 紧接着读 [数据库迁移与建表顺序](D:/java-projects/NoteWeave-v2/docs/数据库迁移与建表顺序.md) 与 [最小接口契约](D:/java-projects/NoteWeave-v2/docs/最小接口契约.md)，直接冻结第一批建表和接口边界
6. 再读 [阶段计划总入口](D:/java-projects/NoteWeave-v2/docs/阶段计划/README.md) 与 [TDD与迁移总则](D:/java-projects/NoteWeave-v2/docs/阶段计划/TDD与迁移总则.md)，确认阶段树、迁移优先级与测试优先顺序
7. 然后只读取当前阶段对应的阶段文档，不跨阶段大面积开发
8. 写资料上传、解析、切片、索引和生成成果资料化时，阅读 [资料基础设施详细设计](D:/java-projects/NoteWeave-v2/docs/资料基础设施详细设计.md)
9. 写三种聊天链路时，分别阅读问答 RAG、Note、Wiki 三份专项文档
10. 写 Deep Research 或右侧产物生成时，分别阅读对应 Agent 专项文档

## 4. 清理原则

后续文档维护遵守以下规则：

1. 不保留过渡方案、历史方案和历史演进说明
2. 不在多个文档重复定义同一套表结构、同一条链路或同一组亮点
3. 总体文档讲边界，专项文档讲实现，简历文档统一汇报亮点
4. 如果发现某份文档只是在重复其他文档，直接合并或删除
5. 如果发现某个概念没有进入正式设计，不在文档中提前写成已有能力
