# NoteWeave v2 具体设计与落地索引

## 1. 目的

这份文档只回答两个问题：

1. 哪些设计文档可以作为后续落代码依据
2. 后续实现时应该优先读哪些文档，避免被历史口径和重复方案干扰

它默认产品边界、功能亮点和工程方向已经在主文档中收敛，不再重新定义系统形态。

当前状态补充：

- Phase 1 ~ 3 的 Java + React 原型已经跑通
- `问答RAG链路设计`、`Note链路设计`、`Wiki模式设计` 已同步到现有代码契约
- 后续继续写代码时，不再把 Note / Wiki 当作“待讨论概念”，而是以现有接口、测试和页面行为为准继续扩展

## 3. 后续落代码阅读顺序

推荐按下面顺序阅读，不再按历史讨论顺序翻文档：

1. 先读 [系统总体设计与功能总表](D:/java-projects/NoteWeave-v2/docs/系统总体设计与功能总表.md)，确认产品形态、功能全貌和冻结口径
2. 再读 [系统架构设计](D:/java-projects/NoteWeave-v2/docs/系统架构设计.md)，确认模块分层、执行引擎和链路边界
3. 再读 [技术架构详细设计](D:/java-projects/NoteWeave-v2/docs/技术架构详细设计.md) 与 [技术栈与数据库设计](D:/java-projects/NoteWeave-v2/docs/技术栈与数据库设计.md)，确认后端、数据和中间件落地方式
4. 开始建工程前，先读 [代码落地路线与开工清单](D:/java-projects/NoteWeave-v2/docs/代码落地路线与开工清单.md)，确认模块顺序、冻结对象和第一阶段不做事项
5. 紧接着读 [数据库迁移与建表顺序](D:/java-projects/NoteWeave-v2/docs/数据库迁移与建表顺序.md) 与 [最小接口契约](D:/java-projects/NoteWeave-v2/docs/最小接口契约.md)，直接冻结第一批建表和接口边界
6. 再读 [阶段计划总入口](D:/java-projects/NoteWeave-v2/docs/阶段计划/README.md) 与 [TDD与迁移总则](D:/java-projects/NoteWeave-v2/docs/阶段计划/TDD与迁移总则.md)，确认阶段树、迁移优先级与测试优先顺序
7. 进入具体开发前，只读取当前阶段对应的阶段文档；阶段文档内部已经内嵌函数清单和中间件接入，不再跳到平行文档
8. 写资料上传、解析、切片、索引和生成成果资料化时，阅读 [资料基础设施详细设计](D:/java-projects/NoteWeave-v2/docs/资料基础设施详细设计.md)
9. 写三种聊天链路时，分别阅读问答 RAG、Note、Wiki 三份专项文档
10. 写 Deep Research 或右侧产物生成时，分别阅读对应 Agent 专项文档

## 4. 清理原则

后续文档维护遵守以下规则：

1. 不保留过渡方案、历史方案和历史演进说明
2. 不在多个文档重复定义同一套表结构、同一条链路或同一组亮点
3. 总体文档讲边界，专项文档讲实现，阶段文档讲函数与中间件，简历文档统一汇报亮点
4. 如果发现某份文档只是在重复其他文档，直接合并或删除
5. 如果发现某个概念没有进入正式设计，不在文档中提前写成已有能力
