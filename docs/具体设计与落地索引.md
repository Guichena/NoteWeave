## 1. 目的

这份文档只回答两个问题：

1. 现有哪几份文档可以直接指导落代码
2. 应该按什么顺序实现

它默认整体设计已经确定，不再重复讨论产品边界。

## 2. 具体设计范围

具体设计关注的是：

- 后端模块划分
- 前后端接口边界
- Deep Research 编排细节
- Artifact Runtime 编排细节
- 中间件职责与边界
- MySQL 与任务链路落地

具体设计不负责：

- 再重新定义产品模式
- 再重新争论亮点是什么
- 再重新发散成平台化产品

## 4. 推荐落代码顺序

### 4.1 P0：先把骨架搭起来

1. Workspace / Topic Scope / Source 基础对象
2. 文件上传、MinIO、解析任务、ES 索引基础链路
3. Ask 基础接口与检索闭环
4. Artifact Runtime 最小链路
5. Research Run 最小链路

P0 的模型接入原则：

- 直接基于 `OpenAI SDK` 或 `OpenAI-compatible SDK` 落地
- 只写一层薄的 `ModelClient` 封装
- 不先做独立模型网关

### 4.2 P1：补核心亮点

6. `Style Profile + Production Action + Prompt Recipe`
7. `Skill Graph Template`
8. `Evidence-Gated Branchable Research Harness`
9. `Schema-Gated Skill Graph Runtime`
10. Research / Artifact 进度反馈

### 4.3 P2：补增强能力

11. `Graduated Memory`
12. 用户自有 MCP 连接
13. 更完整的观测与日志
