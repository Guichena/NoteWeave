## 2. 本批新增行为与边界

### 2.1 来源产品、分支和时间

- 来源检查按事实簇执行，输入使用归档窗口、标题、URL、引文及冻结范围。产品、分支或时间无法确认时保留未知，不能提升为合格事实。
- 发布或更新日期必须有可定位的原文字面依据，日期与原文均由 Java 复核；抓取时间不替代更新时间。截止日期沿用 Run 冻结值。
- 指定历史版本、当前支持状态和历史事件分别处理，历史资料不会仅凭版本号正确就满足当前状态要求。
- 目录阅读最多跟进 2 个相关页面，深度为 1，限制同站点及相关目录/版本范围；每次获取仍申请阅读预算并归档。链接去重、锚点上下文和路径规范化都受限额约束。
- 独立语义核验指独立调用和冻结输入，本批没有更换为其他模型。其判断准确性仍需真实来源与人工抽查验证。

### 2.2 报告缺项返回研究流程

- 报告核验区分 `EXPRESSION`、`MISSING_FACTS` 和 `NOT_CHECKED`。无预算或没有核验结果时不能编造补查请求。
- `MISSING_FACTS` 只能引用冻结需求。跨对象比较的缺项映射回原对象和维度，不能临时增加另一个问题。
- 每个需求最多反馈 2 次，每个 Run 最多 12 条，每次协调器处理最多 3 格；补查还受角色预算、总预算和停止条件限制。
- 有待处理反馈时，旧覆盖观察不能自动结束补查。新合格事实与完整覆盖观察到达后才解除对应缺项；重复旧事实不能解除。
- 预算不足、范围不可用或补查仍未解决时记录明确状态，保留可靠事实和部分报告。反馈状态参与新的成文输入摘要，避免重复使用旧报告。

### 2.3 成文恢复、消耗与保留期

- 状态版本 5 的报告统一使用不可变分段登记；小型完成信封只提交引用，Java 重组后继续执行正文、事实、引用、覆盖和快照校验。
- 跨租约只恢复同一任务、同一冻结输入的生成内容。片段顺序、长度、分段摘要和总摘要全部核对，恢复后的引用绑定当前租约和 fencing token。
- 成文模型请求先向 Java 获取顺序授权。调用授权在生成正文前持久化，即使 Worker 中断、没有登记报告，重新领取也会扣除已授权次数。
- 同一租约已经授权调用但没有生成登记时，禁止直接再次生成，交由重新领取恢复；授权回执重放保持幂等。
- 任务失败或取消时，已授权尝试计入消耗，只释放未花费部分。调用授权数代表计入预算的尝试；实际 Provider 请求数单独记录，无法确认时为 `null`。
- 自动保留期清理默认关闭。启用后默认保留 7 天，每批最多 100 个任务，按 Run → Task 顺序加锁，保护当前活动租约；生成和调用元数据在 Run 结束前保留，防止预算被重新获得。
- 完成信封仍受既有 256 KiB 上限保护；报告每段 64 KiB，总大小最多 4 MiB，超限明确失败。

### 2.4 调度、规划和指标

- 调度前先冻结所有适用单元格需求，避免尚未建立需求的首轮候选得到错误低分。显式缺项优先，再结合近期新增事实、满足需求、解决冲突与调用/阅读成本排序。
- 连续无增益按单元格、规划修订和对象集合计算，合并任务不再把一个单元格的收益分配给其他格。
- 总预算为成文、事实审计和反证补查保留额度；关闭宽搜索时仍使用冻结总预算，不能因此绕过全局限制。
- 规划复核检查原问题分句到显式需求的映射，最多进行一次完整计划修订。未知或遗漏会阻止完整定义判定。`COMPARISON` 同时保留跨对象需求及各对象所需事实。
- 需求修订记录稳定血缘、前序需求和修订原因；历史记录继续保留。
- 运行接口提供轮次、逐格增益、查询、阅读、调用、已知 token、耗时、重复文档、过滤原因、冲突与停止原因。前端使用服务端统计，研究覆盖和报告覆盖分别展示。
- 每个新增满足需求的调用成本包含已完成任务结算与失败/取消成文的未提交授权。缺少调用结果时，总 token 保持未知，不把缺失值当作零。
- 标题、章节标题和表头使用中性模板或冻结标签，防止未经事实核验的断言出现在报告元数据中。

## 5. 评测与回放工具

正式回放代码位于 `scripts/deepresearch/replay/`，入口为 `replay_mechanisms.py`，共登记 28 个场景。生产代码不读取评测答案。回放使用预设来源、模拟模型或受控数据库，不调用外部 Provider。

Python 单独运行时执行 18 个场景，其余 Java 和跨语言场景标为 `NOT_RUN`；结果同时包含 `passed_count`、`scenario_count`、`all_scenarios_passed`，不能把单个驱动成功解释为全部场景通过。具备 JDK、Python 和后端依赖的环境可通过 `--java-classpath` 与 `--backend-classes` 一次执行全部驱动；分镜像环境另提供 `run_java_replays.sh` 和 `check_contract_v4.py`。

真实评测入口新增源码、配置、模型、数据集和容器身份记录。运行中发现变更时标记 `INVALID`；无法捕获运行镜像身份时明确标记不可比较。评分缓存包含评分模型和端点身份，研究模型的角色路由也纳入独立性检查。

留出集工具要求至少 20 道新题、四类各至少 4 题、唯一题目及编号、预先固定的评分要求，拒绝与开发集完全相同的规范化题目。工具不能判断语义近似题是否泄漏，需要人工检查。真实留出集尚未创建和冻结；留出评分要求不同于研究角色的模型标识且至少三次评分，模型标识检查也不能替代对底层模型身份的人工确认。
