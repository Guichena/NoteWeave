# 非 Research 模块审查与修复计划

日期：2026-10-24。范围：当前工作树中的全部非 Research 模块，以及它们与 Research 的交互边界。

本文是修复清单和验收记录。审查发现不等于修复完成；只有实现、针对性回归和实际行为均有证据后，才能将对应条目标记为完成。既有 Research 改动由原工作保持，不在本轮重构范围内。

## 1. 目标与执行规则

1. 消除可绕过权限、泄露已删除内容、写入错误工作台和破坏持久状态的问题。
2. 让用户发起的操作能够完整到达最终结果，包括异步恢复、文件导出、引用展示及失败结束。
3. 统一同一资源的身份、作用域、生命周期和读取规则，避免继续增加相互矛盾的状态与抽象。
4. 按本清单逐项修复；每项记录实现、测试、剩余限制。发现原结论不成立时保留证据并更正，不能为满足清单而修改正确行为。
5. 不重置既有工作树，不自动提交或部署。新增注释与文档使用简体中文。

严重程度：P1 优先处理，涉及安全、数据归属或主要流程中断；P2 近期修复。疑点先验证，再决定实现。

## 2. 审查基线与证据边界

审查沿前端、Controller、Service、异步投递、Worker、数据存储及最终展示检查。覆盖认证、工作台、会话、三种回答模式、引用、资料上传与四阶段处理、检索、Wiki、记忆、产物、执行观察、配额、对象存储和内部回调。

审查时现有测试结果：后端选定 91 项、前端排除 Research 目录后 273 项、Artifact Worker 665 项、Parse Worker 133 项全部通过。这些是基线，不能证明下述边界场景已经正确。

已执行的额外验证包括：真实 Spring/Tomcat/H2 路径绕过复现；当前业务类与 H2 的记忆拒绝、已删除生成资料再保存复现；前端并发刷新、作用域切换、引用快照及轮询故障注入；Worker 幂等键、异常漏报及进度顺序验证。临时验证文件位于系统 TEMP，正式回归需要纳入仓库。

本轮未完成真实外部模型、MCP 服务和完整生产中间件联调。涉及这些环境的结论要明确区分本地契约验证与外部集成验证。

## 4. 已确认问题与验收条件

### R01 / P1：路径解析不一致导致认证与授权绕过

- 位置：`security/ApiRequestIdentityFilter.java`、`security/WorkspaceAuthorizationInterceptor.java`、`config/InternalServiceAuthFilter.java`、`knowledge/KnowledgeCommandService.java`。
- 触发及影响：安全层用原始 requestURI，Spring 路由会处理分号参数；真实应用中匿名普通删除返回 401，分号等价路径返回 200 并把知识页从 ACTIVE 改成 DELETED。内部过滤器存在同类路径判断，应一并检查。
- 根因：认证与授权各自解析路径，未匹配规则时直接放行，关键资源写入依赖外围拦截器。
- 修复方案：安全层共享确定的路径处理规则，拒绝歧义路径或与 MVC 一致地解析；资源授权使用 MVC 已解析的变量和匹配模式，避免重复解析原始 URI。补充关键资源边界检查，保持正常公开认证接口与内部令牌受众隔离。
- 验收：匿名、外部用户、EDITOR、OWNER 的普通及分号/编码路径权限一致；拒绝请求不改变数据库；内部路径不能借变体跳过令牌；正常注册、登录、刷新和有效资源操作通过。
- 状态：已修复并通过回归。RequestPaths 统一分段解码，授权采用 MVC 资源变量，未配置的资源规则默认拒绝。新增 12 项真实 HTTP 路径与受众测试，相关权限契约也通过。

### R02 / P1：删除与来源撤销后，运行接口仍可返回正文

- 位置：`conversation/ConversationMessageDeletionService.java`、`answer/AnswerRunService.java`、`chat/ChatAnswerGenerationAdapter.java`、回答与会话 SSE。
- 触发及影响：删除清空 conversation_message，但 message_revision 正文仍被运行详情和快照返回；生成中删除后还可能被无条件持久化重新写回。
- 根因：消息列表、运行读模型、历史事件和生成写入没有共同遵守内容可读性与删除状态。
- 修复方案：统一运行读取和事件回放的删除/来源撤销门禁，清理应删除的派生正文；生成落库在事务内检查消息状态，删除或取消后不得恢复正文；保留不含正文的审计元数据。
- 验收：删除完成回答后，消息、运行详情、两种 SSE、历史重放均不含原文；删除来源后的可见性一致；生成与删除两种先后顺序都不会重新暴露内容；普通回答完成流程不受影响。
- 状态：已修复并通过回归。AnswerContentReadPolicy 统一消息、运行、证据与事件可见性；删除清理派生正文，生成写入检查删除状态，缓存流回放逐事件检查。6 项新增契约覆盖删除顺序、来源撤销和两种 SSE；保留来源编号及空内容摘要等审计元数据。前端显式 REDACTED 快照会清空旧正文且不会被旧快照恢复。

### R03 / P1：多阶段视频进度共用幂等键

- 位置：`workers/artifact-worker/app/callback.py`、`runner.py`、`worker/WorkerTaskCallbackService.java`。
- 触发及影响：普通视频讲义的不同采集操作都上报 WAITING_FOR_PROVIDER，键只包含 task 与 phase；第二个不同 payload 被后端判冲突，下一个 provider 操作未派发。MATERIAL_ONLY 父任务不受同一路径影响。
- 修复方案：进度事件使用稳定操作或事件身份生成幂等键；相同事件重投保持键不变，不同操作互不冲突。消费者按错误码识别投递失效，不能把所有 409 视为过期消息。
- 验收：至少两个连续异步阶段经过真实幂等摘要校验并成功推进；相同事件重复回调不重复变更，不同内容复用同键仍被拒绝。
- 状态：已修复并通过回归。进度幂等键包含规范化 payload，三个视频操作分别落回执，相同事件重投仍复用。消费者只跳过 WORKER_CALLBACK_DELIVERY_STALE 与 WORKER_INPUT_DELIVERY_STALE，其他冲突保留恢复机会。

### R04 / P1：完成阶段的本地异常漏报

- 位置：`workers/artifact-worker/app/callback.py`、`video_deck_preview.py`、`artifact_kafka_consumer.py`。
- 触发及影响：渲染、文件准备、冻结素材校验抛出本地异常时不上报失败，消息重放可持续续租并重复生成。
- 修复方案：生成与完成准备共用异常分类；确定性错误上报终态失败，传输故障按有界策略重试；重试复用已生成候选，避免重复调用模型。
- 验收：ValueError、缺失文件、渲染超时、网络错误分别进入正确分支；已上报失败只处理一次；后端任务不长期停留 RUNNING。
- 状态：部分完成。普通完成及等待恢复阶段的本地异常已统一上报失败，ValueError、FileNotFoundError、TimeoutExpired 均有回归；传输异常保留重试，Artifact Worker 全量 672 项通过。尚需验证并落实传输重试的上限及普通完成结果复用，不能将整个条目标记完成。

### R05 / P1：并发刷新凭证清除新会话

- 位置：`frontend/src/shared/api/auth.ts`、`client.ts`、`security/AuthService.java`。
- 触发及影响：多个 401 独立刷新同一旧 token，后返回的轮换失败清除已刷新的有效登录。
- 修复方案：共享进行中的刷新 Promise，基于会话版本或旧 token 比较决定是否清理；用户退出或切换账号后旧刷新不得覆盖新状态。
- 验收：多个 401 只发一次刷新且原请求正确重试；刷新失败一致退出；刷新中退出、重新登录、旧失败延迟返回均不破坏新会话。
- 状态：已修复并通过回归。刷新共享 Promise 并使用会话版本防止旧结果覆盖；较晚的旧 401 复用已更新凭证；退出、重新登录和账号切换不会被旧操作撤销。8 项新增并发用例及现有客户端测试通过。

### R06 / P1：旧 Note 草稿在新工作台下保存到旧工作台

- 位置：`useChatSessionController.ts`、`useChatSourceActions.ts`、`ArtifactRail.tsx`、`chat/NoteAnswerSourceService.java`。
- 修复方案：草稿绑定 workspace/conversation/message；切换时清理或按作用域存取，保存前核验作用域，异步草稿完成不得污染新工作台。
- 验收：A 生成草稿后切 B 无法误存到 A；A 草稿晚返回不会显示于 B；正常编辑和保存保留完整正文。
- 状态：已修复并通过回归。Note 草稿绑定工作台与会话作用域，切换立即隐藏并清理；旧保存函数及晚到草稿都失效。新增草稿切换与延迟返回测试通过。

### R07 / P1：旧异步操作覆盖新工作台状态

- 位置：`useChatSourceActions.ts`、`useMemoryItems.ts`、`features/knowledge/state.ts`、聊天降级流。
- 触发及影响：上传、记忆写操作、Wiki 刷新或旧回答流在切换后写共享状态，导致 B 显示 A 内容。该结论不等同于后端权限绕过。
- 修复方案：异步操作持有不可变作用域令牌，所有状态写入核验当前作用域；旧请求不得主动改变当前门控；流事件按 run 身份更新消息，辅以取消旧订阅。
- 验收：上传、记忆审核/添加、Wiki 刷新、回答流分别在 A→B 切换并反转完成顺序，B 状态始终来自 B；快速 A→B→A 也能正确恢复。
- 状态：已修复并通过本地回归。useOperationScope 按一次作用域生命周期隔离回调，覆盖资料、记忆、Wiki 门控、回答流、App 资料刷新及产物保存/回滚状态。旧请求不能改变当前门控，降级流按 run 更新并在切换时取消。新增 A→B、A→B→A、延迟审核及产物入库测试通过。

### R08 / P1：拒绝新记忆提案删除整个记忆项

- 位置：`memory/CanonicalMemoryReviewService.java`、`CanonicalMemoryRuntime.java`。
- 触发及影响：同 slot 已有 ACTIVE 版本，再拒绝 PROPOSED 版本，会使 item=DELETED，旧生效版本及其他提案不可见。
- 修复方案：拒绝只更新目标 revision；保留有效头，按剩余提案计算审核状态；仅无有效头及其他提案时回收空项。
- 验收：已有生效版本、多个提案、首次提案三类拒绝结果正确；召回与列表一致；重复审核的状态保护仍生效。
- 状态：已修复并通过回归。只拒绝目标 revision；保留生效头及其复核状态，无生效头时保留其他提案，最后一个空提案才回收。新增 3 项契约通过，MemoryRuntimeContractTest 合计 22 项通过。
