## 2. 研究在主链路里的位置

1. 问答输入框打开深度研究后，这一轮以 `DEEP_RESEARCH` 提交。`ConversationTurnModule` 创建研究运行，用 Context v2 冻结对话上文，研究运行与对话、提问消息、回答消息互相关联。
2. 对话里按研究运行显示进度和报告，可以进入完整报告页。研究完成后，`ConversationResearchProjectionService` 把去掉证据编号的报告正文写进回答消息，供之后的问答理解上文。
3. 追问时，问答默认依据这段对话里的研究报告作答，走 `REPORT` 检索通道：报告引用过的网页原文作为证据，和工作台资料一样进入统一证据契约，回答里的引用可以直接打开网页原文。
4. 研究回合的消息被删除后，这份报告不再参与自动取证；研究的输入上下文被脱敏后，报告不能再作为当前证据。

`REPORT` 通道原先已经出现在检索配置里，但在 NR21 修复时以 409 明确拒绝，修复记录写的是真实实现留待产品排期。这次补上了实现。

| 环节 | 工作台资料（QA） | 研究报告（REPORT） |
|---|---|---|
| 证据单位 | 资料的 source chunk | 报告正文实际引用过的 `source_evidence` 摘录 |
| 身份 | 资料、快照、chunk | 研究运行编号、证据键 |
| 资格 | 资料当前可用，快照是最新版本 | 研究已完成，输入上下文没有被脱敏，依赖闭包全部满足当前证据用途（与报告保存、导出共用一套判断） |
| 排序 | 检索器内的 MMR 或选择策略 | 与问题的词项重合数，同分时保持报告里的引用顺序 |
| 预算 | 公共预算按计划步骤顺序取证 | 同左；REPORT 步骤最多 6 条，排在工作台检索之前 |
| 范围校验 | `workspace-source:{资料}`，在显式资料范围内 | `workspace-research:{研究运行}`，必须是本轮声明的报告 |
| 归属校验 | 当前快照里的 chunk | 研究运行已完成，证据键在该运行的证据表里 |
| 引用落库 | `citation` 记资料、快照、chunk | `citation` 记研究运行编号和证据键，资料字段为空 |

证据正文由两部分组成：报告依据这条摘录写出的结论（作为说明），以及核对过的网页原文；引用卡片只显示网页原文。问答提示里研究证据标注为研究报告引用的网页，回答照常按编号引用。

## 4. 接口与数据

- 发送消息（`POST /api/v2/conversations/{conversationId}/messages`）：依据研究报告时传 `retrieval_strategy: AUTO`、`retrieval_channels: ["REPORT"]`（工作台有可检索资料时为 `["WORKSPACE", "REPORT"]`）、`grounding_refs: [研究运行编号]`。前端取这段对话里最近 3 次研究的编号；AUTO 不传编号时，后端取这段对话最近完成的 3 次研究。
- 错误：`grounding_refs` 里有不属于本工作台的研究，返回 404 `RETRIEVAL_GROUNDING_REF_INVALID`；只用 REPORT 通道、没有指定编号且对话里没有已完成的研究，返回 409 `RESEARCH_REPORT_NOT_FOUND`；笔记、Wiki 模式使用 REPORT 或任何模式使用 WEB，返回 409 `RETRIEVAL_CHANNEL_UNSUPPORTED`。
- 降级原因：研究未完成记 `RESEARCH_REPORT_NOT_COMPLETED`，研究上下文已脱敏或依赖资料撤销记 `RESEARCH_REPORT_NOT_USABLE`，随证据快照保存在回答运行上。
- 检索计划版本在 QA 计划版本后加 `+research-report-v1`。QA 检索器会严格核对计划只有一个步骤、版本号是它认识的配置；同时检索工作台时，它先用 `ResearchReportGrounding.workspacePlan` 还原出工作台检索的原计划再核对，严格校验本身不变。
- 证据键与 `source_evidence.evidence_key` 相同，带 `evidence:` 前缀，与报告正文里的 `[evidence:...]` 标记、报告引用核对使用同一匹配规则。
- 读取对话消息时，资料引用照旧按资料资格判断，研究引用按报告正文能否展示判断（`reportBodyAllowed`）；报告依赖被合规删除等情况下，引用它的回答同样隐藏。
- V222：`citation.source_id`、`source_snapshot_id` 改为可空，`location_info` 放宽到 1000 字符，新增 `research_run_id`、`research_evidence_key`。资料引用的写入和外键不变。
- 回答保存为笔记时，研究引用按所属研究报告的依赖闭包校验；资料引用照旧按资料资格校验。笔记召回统计只读有资料编号的引用。

## 5. 已知限制

- 研究证据按词项重合排序，没有模型重排。候选只是一份报告引用过的几十条摘录，影响有限；追问改写较多时排序可能不准。
- 笔记读取时不再复核其中研究引用的报告资格，资料引用照旧复核。
- 研究证据的原文来自研究时抓取的网页存档，不随网页更新。
- 删除回答消息时，研究引用与资料引用一样，仍有复核文档 C04 所说的副本清理缺口。
- 回答回合的回执在检索之前生成，不含降级原因，需要从回答运行的证据快照读取。
- 充分性判断是模型调用，同一问题、同一批证据可能一次判为依据不足、一次判为部分充分。端到端验证里，问怎样避免固定这一类报告没有直接回答的追问出现过这种情况；依据不足时按拒答处理，不登记引用。
