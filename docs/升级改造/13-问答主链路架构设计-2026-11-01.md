## 2. 设计原则

1. 对话是统一交互入口，三种回答模式与研究回合共享会话身份，但不共享一个无差别检索器。
2. 区分当前任务、会话理解材料、用户要求与前提、可引用证据。只有证据可以产生事实引用；前提明确标为用户陈述、未经资料核实。
3. 同一运行只确定一次最终证据正文和顺序。Judge、生成、引用绑定、清单消费同一份结果，展示预览可以缩短，不能被当成另一份事实来源。
4. 输入冻结与当前授权复核各司其职：冻结保证可回放，复核保证现在允许使用。哈希一致不能替代授权与版本资格。
5. 删除、来源撤销、运行取消均有明确生命周期，新增持久化展示文字同时具备清理路径。
6. 生成与规划调用失败按明确规则降级并记原因；判定调用失败记 `NOT_RUN`，不自动判为通过。
7. 业务正确性不依赖 token 分块、查询返回顺序、页面标题唯一性、日志错误码后缀或测试替身的默认行为。
8. 数据权限是硬边界，偏好是任务参数或表达要求。偏好不能覆盖工作台权限、来源撤销或显式资料范围。

## 3. 目标主链路

```text
接收回合并分配运行身份
  → 在确定的 cutoffSeq / 消息版本边界冻结会话输入
  → C1 提取本轮要求与前提，记录来源和操作版本
  → C2 改写为独立问题、查询关键词、问题类型和 refers_to
  → C3 在冻结边界内按需回忆
  → 按独立问题选择一次长期记忆并执行层级覆盖
  → 各模式独立检索，工作集只提供合格信号和候选
  → 生成最终证据集合、正文与顺序，完成资格检查和预算
  → C5 充分性判断，基于相同最终证据
  → C6 组装提示、校验、登记引用、冻结生成契约
  → 调用模型前复核运行状态与证据资格
  → evidence.ready → 规范化正文增量
  → 同一完成事务校验并写回
  → 异步话题摘要、记忆候选和效果反馈
```

网络模型调用不得放在长事务或持锁区间内。冻结快照内的身份和版本在本次运行保持稳定；当前资格发生变化时取消或失败本次运行，不静默换用新版材料继续完成旧运行。

研究回合在冻结之后进入 R0 简报编译，再由规划、单元格和成文角色分别消费自己的输入。

## 4. 证据、评分与生成契约

### 4.1 最终证据

最终证据至少保留：稳定 evidenceId、证据种类、已有来源与版本身份、最终 excerpt、正文 hash、选择顺序、实际预算成本、评分来源。顺序以最终有序列表和已有 rank 表达，不为了改名另加 selectionRank。

- QA：source / snapshot / chunk；邻块若进入正文必须成为独立证据，否则只保留诊断身份。
- Note：source / snapshot / chunk / window；无正文的窗口不能占候选、角色或预算名额。
- Wiki：item / knowledgeVersion 及该版本完整来源依赖；目录导航不作为事实证据。
- 研究：researchRunId / evidenceKey。现有证据 ID 和访问范围已携带研究编号，不得再以缺编号为理由跳过复核。

正文裁剪在选择阶段完成。Judge 和 compose 不再分别截取不同长度或从 metadata 取另一份正文。完整依赖与展示预览分离，展示上限不能裁掉资格检查需要的依赖。

### 4.2 评分来源

`ScoreInfo` 由实际生产者创建，至少含 origin、model 或方法标识、可空 value。来源为 `PROVIDER_MODEL`、`LLM_FALLBACK`、`FUSION_FALLBACK`、`LEXICAL`、`GRAPH`；旧数据缺失时为明确的 `LEGACY_UNKNOWN`，不伪造为融合或模型分数。

- 0 是有效真实分数，未知才用 null。
- 模型后备、未评分尾部、纯词法和图分不进入提供方门槛。
- 提供方分数也必须声明量纲和可用门槛策略；保留已知策略的 0.15/0.35，不把任意供应商分数或 LLM 自评分当成已校准概率。
- 从 `RerankResult` 到各模式命中、最终 Evidence、持久化 snapshot 全程保留来源，不能在下游根据错误码或分值反推。
- JSON 在数值转换之前校验字段存在、类型、有限性、索引整数性、实际提交范围和重复项。非法响应触发现有后备，不转换成合法零分。

### 4.3 资格复核

调用生成前对最终允许集合执行类型化复核：

- 资料：工作台、来源、绑定快照、chunk/window 归属、当前可用性及生成来源依赖。
- Wiki：工作台、页面有效状态、版本政策、全部依赖的当前资格和绑定快照。版本存在只是必要条件。
- 研究：研究身份与完成状态、输入上下文是否可用、来源依赖、证据键归属，以及当前引用入口所要求的会话关联资格。

复用现有来源政策和研究门禁，不在新 Guard 里另起宽松政策。来源批量评估遵守上限，同一 source 的不同 snapshot 不得因映射键覆盖而误通过。未知种类、缺失必要身份和缺少校验结果均不得默认放行。

### 4.4 生成与引用

新协议所有模式统一输出 `[n]`。`CitationBinding(number, evidenceId, citationIds)` 来自最终编号，不由页面标题或引用行排序推断。QA 的提示不得再要求写 evidence ID；Wiki 的提示不得再要求以 `[[页面名]]` 作为事实引用。

`GenerationContract` 冻结模式、提示版本、拒答状态、允许身份、编号绑定与正文摘要。拒答的允许集合为空。公共规则与模式提示显式合并，不能把用户偏好原文直接升级为不受限制的系统指令。

新协议不以页面标题作为引用白名单。历史 `[[页面名]]` 可以保留为明确的普通导航，但不能冒充冻结证据或替代版本定位。

## 5. 流式协议、删除与可回放性

### 5.1 流式解析与客户端协议

引用规范化必须满足切片不变性：同一完整字符串以任意 chunk 分割，规范化正文、非法计数和绑定解释相同。解析器区分普通正文、代码块、行内代码、转义字面量和 Markdown 链接；只处理约定位置的引用标记。

越界引用转成不再触发角标的普通文字，记录原因和计数，不中止整段回答。最大暂存长度、超长标记及流结束未闭合的规则必须确定且有测试；不能因缓冲上限不同输出另一份正文。

所有实时、重新订阅、游标恢复、过期游标重建和已完成回放，都先得到该运行的冻结引用协议，再解释正文。协议未知不等于旧协议：只有显式确认历史协议时才进入旧解析，新运行未知时禁用证据角标。

主正文、折叠章节、表格与其他用户可见回答区域使用相同绑定。来源详情可延迟加载，但编号身份不可等生成完成后再猜。

### 5.2 引用的归属与共享

`owner_message_id` 表示生命周期归属，不自动证明当前独占。

推荐落地策略是：新消息创建自有引用；保存为知识版本或交给另一消息时，对消息自有引用执行 copy-on-bind，创建目标生命周期的引用副本，保持源身份和版本不变。知识版本自有或共享来源引用继续按其既有政策管理。

存量已经共享的引用不得批量清空或盲目回填 owner。删除消息先解除消息关联、清理该运行自有副本；只有证明仍由该消息独占的中央引用才能清正文。所有引用绑定入口遵守一致的并发保护，不能仅靠一次无锁计数判断独占。来源合规撤销另按全依赖传播处理，不被历史保留策略绕过。

### 5.3 删除与完成事务

准备、生成、完成三个时段都必须处理删除。删除关联用户消息或助手消息后，运行不能继续提交新的正文；生成中后续批次停止发送，已发出的字节不宣称能够收回。

删除与完成入口采用一致锁序或等价的持久化状态仲裁。完成事务校验运行、stream owner、用户消息、助手消息、必要的撤销状态，再原子写入主消息、revision 与运行终态。任何条件写回为零都必须作出明确结果，不能继续标为成功。

清理范围包含该运行的草稿、revision、manifest 展示正文、消息专属引用、契约展示字段、相关事件和缓存。保留身份、版本、hash 与必要计数。必须区分用户删除、来源更新、合规撤销和历史展示政策，不能一律清空仍合法共享的知识材料。

### 5.4 审计

实际采用的评分来源、视图、回忆引用、提示版本、规范化计数、资格复核结果和终止原因可追踪。`ANSWER_EVIDENCE_REVOKED` 等业务错误不得在编排层被统一覆盖为无意义的流错误。合法的历史无契约记录和损坏的新契约必须区别处理，损坏的新契约不能降级成旧协议继续生成。

### 6.2 预算裁决

模型上下文窗口为最终硬上限，需同时计入系统提示、问题、上下文、前提、证据、协议包装、输出预留和安全余量。表内数值是各层目标或上限，不能分别装满后再拼成超预算请求。

按渲染后实际文本估算，记录估算器版本。分层选择先满足明确的必带信息，再分配可选材料；原文转摘要属于有记录的选择，不能在 renderer 内偷偷截字。

必带信息本身超预算时，不伪称完整保留。给出明确输入过长或控制信息过多的结果，或使用已经约定并记录的降级；不静默丢掉当前问题、关键约束和来源标识。

## 7. 分层压缩、回忆与会话前提

### 7.1 消息形态

原文、确定性消息摘要、异步话题摘要、句柄四种形态均保留来源消息 ID、序号和版本/hash。摘要属于派生视图，不能替代原始账本。

最近一轮优先原文；较早内容按预算逐级使用摘要或话题摘要。助手输出超过原文目标时，使用结构化摘要并记录降级。对于明确要求展开旧回答某一点的追问，优先取对应原文或可定位片段，不用首句摘要冒充完整恢复。

### 7.2 冻结与按需回忆

回合冻结时记录 `cutoffSeq`、可用消息版本、摘要版本、要求与前提版本及工作集身份。回忆可以超出默认视图的窗口，但不能超出这份冻结边界，不能读到本轮之后新写入的消息或研究状态。

`refers_to` 只能指向本运行允许的句柄。无效句柄记录原因并丢弃或采用受控回退；存在的句柄仍需检查会话、工作台和当前可读资格。

无明确指代时，在有界候选中用 BM25 检索旧回合。需要正相关最低条件与校准数据；不能只用最高分的一半作为可拒绝噪声的阈值。候选上限、命中上限、召回预算与遗漏原因全部记录。

缓存若引入，键必须覆盖身份、截止点、内容/约束版本和资格变化；删除与撤销有主动失效或版本校验。第二期默认先不加缓存，测量后再优化。

### 7.3 用户前提

采用独立的 `conversation_premise` 语义模型，第二期实现。建议字段包括 premiseId、workspaceId、conversationId、subjectKey、用户陈述文本、sourceMessageId、sourceSeq、scope、topicId、有效区间、状态、supersededBy、抽取版本。

- subjectKey 描述被陈述的实体及属性，数据库版本、预算与团队人数不能互相替换。
- 确定的更正覆盖同主体同作用域的旧前提，跨话题或指代不明时不自动撤回。
- 操作按来源消息和抽取版本幂等；已有 scope、时序和撤销基础设施可以复用，前提值不得伪装成固定偏好槽位。
- 前提以未经资料核实的条件渲染，不登记 citation，不晋升成长期事实记忆。
- 删除来源消息同时撤销前提与派生展示文本，冻结视图同步脱敏。

### 7.4 非完成消息

按消息类型和状态定义投影：研究 PENDING 消息在任何历史位置均可以形成冻结句柄；已删除消息保留必要账本位置但不提供正文；失败、取消和普通回答 PENDING 的处理单独定义。

不能简单删除整条前缀一致性检查，也不能只放行末尾一条研究占位。话题投影、摘要覆盖、序号连续性和正在完成的研究必须一起验证。

## 8. 深度研究的输入与对话投影

### 8.1 研究简报

R0 先从冻结上下文生成独立研究问题、带来源的 contextNotes、focusEntities 与必要前提。确定独立问题之后只选择一次记忆，再由确定性编译器合并 outputRequirements、sourcePolicy、priorResearch 和 seedSources，避免 R0 依赖尚未完成的记忆编译而形成循环。

保留 originalQuestion，规划和成文使用 researchQuestion。模型失败时按有来源的上下文要点生成受控简报并记录降级，不把无法消解的指代当作已经理解；必要时明确请求澄清。续跑与恢复读取同一份简报版本。

来源排除、日期和授权范围由实际任务参数执行，不能只写在规划提示里。单元格输入虽短，也不能截掉决定研究含义的任务条件。

### 8.2 P0/P1/P2 投影

- P0：身份、标题、状态和简短结论；进行中计数必须冻结到本回合可见时刻。
- P1：执行摘要、需求覆盖状态、对象和维度名，目标不超过 800 token；不足、部分核实、未能核实明确区分。
- P2：单元格结论、状态与通过资格检查的证据，经会话证据通道参与回答。

规划、抓取窗口、失败候选、修复历史和完整报告不进入日常对话视图。保存完整报告供研究详情使用，历史研究消息的兼容转换不修改原始研究证据。

### 8.3 入口与增量研究

对话内创建研究；研究记录页的新建入口先建立对话。旧独立研究按已有权限提供报告查看，不擅自删除历史数据。

第七期开始前询问用户。获得同意后才检查现有 checkpoint/resume 是否真的支持保留旧单元格并只重开指定格，不把已有续跑字段当作增量研究已实现的证据。

## 9. 会话工作集与会话证据

冻结时从最近回答清单、显式来源选择和研究运行派生工作集，不新增权威工作集表。初始上限沿用资料 20、知识页 20、研究 3、最近引用证据 30，但渲染和检索还必须受各自总预算限制。

工作集记录贡献回合、身份、版本与权重；删除回合只去掉其贡献，同一资料仍被其他有效回合使用时可保留。显式资料范围、通道关闭、当前权限优先于所有会话信号。

QA 接入会话证据候选；Note 增加来源信号；Wiki 将合格知识页加入 PPR 重启分布，归一化并限制总权重；研究接收可选种子和已有覆盖。不得把这些信号解释成可绕过各模式资格的事实。

研究对象和维度定位只提供选择线索。单元格未核实时，即使存在相关网页，也不能把相关网页解释成该格已核实。最终统一去重按规范证据身份，不按标题或 URL 粗暴合并不同快照。

## 10. 偏好分层与结构化编译

覆盖顺序为本轮要求 → 适用的会话/话题要求 → 合格长期记忆。只在同一语义维度冲突时覆盖，不能把整个粗粒度 family 清空；例如本轮术语 A 的要求不能删除长期术语 B。

编译输出分为结构化任务参数与受限表达文本。语言、长度、表格、结构、术语等在支持的调用方生效；来源偏好只能在允许的研究策略中转成实际可执行参数，不能越过硬范围或权限。

记忆只选择一次，运行快照记录实际采用、被覆盖及排除的条目身份与版本。冻结的原始会话状态不重复塞入全部记忆，但最终调用的决策和参数必须可审计。

确认卡片区分已自动生效与待确认。记住、只用于本对话、忽略、撤销都要有幂等后台语义；只用于本对话必须产生会话要求并阻止候选进入长期记忆，不能只是换一个按钮文案。

第五期同时覆盖回答、研究和设计中声明的产物参数接入，不因前端入口完成就宣称记忆编译完成。

#### 与设计的差异及理由

1. 生成契约的冻结位置：第 10 节写的是提示校验和引用落库之后冻结，实现放在 `ChatService.finalizePreparedAnswer` 中，与引用落库在同一事务内。理由是编号绑定需要 `citationId`，落库之后才有。
2. `CitationBinding.number` 取提示里 `[n]` 的顺序，也就是 `referencedEvidenceIds` 的下标加一，没有使用 `selectionRank`。理由是模型看到的就是这个顺序，换用别的编号方式会让绑定与正文对不上。
3. 契约里额外保存 `allowedPageTitles`。设计只写了编号绑定，而 `[[未选页面]]` 的规范化需要一份允许的页面名集合；冻结时从 `KNOWLEDGE_VERSION` 证据的标题取出，避免前端或流式层按标题猜。
4. `CitationMarkerNormalizer` 把越界标记改成全角括号（例如 `［7］`），没有删除。理由是视觉不变、语义不丢，同时不再被引用解析器匹配。
5. 非对话入口 `AnswerSubmissionService.createPreparedRun` 暂不冻结契约，传 `null`。理由是这条路径目前只有测试在用，二期统一到同一份契约。
6. 证据资格复核的覆盖面：资料与知识版本都复核，研究报告证据只校验清单存在与正文摘要，没有复核研究运行状态。理由是证据身份里没有稳定的研究运行键，补齐这项复核需要新的血缘字段，放到第六期与 W03 一起做。
7. 流式绑定事件是前端成员指出缺口后补做的，属于复核文档 7.3 的必改项，本来应当在第一期一次做完。
