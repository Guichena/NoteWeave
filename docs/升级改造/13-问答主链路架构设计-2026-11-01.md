# 问答主链路架构设计：证据、上下文、记忆与研究

日期：2026-11-01。基线：GitHub main `e2f72e39`（研究功能已并入，见 [12 号文档](12-研究功能并入主链路-2026-10-31.md)）。状态：已确认，按第 5 节分期实施。

本文评估《NoteWeave 三种检索链路复核与修改实施文档》（以下简称复核文档）的改动项，补上上下文和记忆层的问题，给出目标结构。原则是只做设计上必要的部分。

## 1. 一轮回答的四类输入

| 输入 | 作用 | 能否引用 | 负责模块 |
|---|---|---|---|
| 当前问题（原文、独立问题、主题锚点） | 检索查询和生成的主语 | 否 | `QueryRewriteService` |
| 会话上下文（最近原文、消息摘要、研究摘要、话题摘要、会话约束） | 理解指代和省略，延续会话约束 | 否 | `conversation`（上下文冻结） |
| 长期记忆（偏好、术语、禁用项） | 控制表达方式 | 否 | `memory`（`MemoryCompilerService`） |
| 证据（资料片段、笔记窗口、知识页版本、研究报告引用的网页原文） | 唯一的事实来源 | 是 | 各模式检索器和 `answer.strategy` |

规则：

1. 只有证据进入引用编号。
2. 每类输入只选择一次。
3. 选择结果就是渲染内容，预算按实际渲染的文字计算。
4. 每类输入的身份写进运行快照，删除和撤销按身份处理。

## 2. 复核文档评估

在 `e2f72e39` 上抽查了四项，都还存在：

- W01：Wiki 步骤候选数是 5，`RetrievalOrchestrator` 先截到 5，扩展页全部丢掉；
- Q01：QA 主块拼接邻块正文，引用仍绑定主块；
- C02：充分性判断按 0.05 下限猜分数来源，知识页分数一律除以 100；
- C03：生成只用一段固定系统提示，模式策略的系统提示没有传到模型。

N03 的排序部分已在 12 号文档中修复。

**采纳**：

- 公共契约：3.1 最终正文、3.3 评分来源与 C02、3.4 与 N04 元数据不带事实、3.5 生成前资格复核；
- 生成与引用：C03 生成契约、7.2 引用绑定；
- 三条链路：Q01 到 Q03、N01、N02、W01 与 W07（一起上线）、W02、W03、W04；
- 其他：C05。

**调整**：

- **引用标记**：模型继续写 `[n]`，生成契约冻结编号到证据的绑定，服务端按绑定校验。复核文档建议模型直接写证据 ID，长 ID 容易抄错。
- **流式非法引用**：越界编号改成普通文字并计数，不中止生成，否则用户拿到半截回答。流式内容、返回值和落库文本经过同一个规范化器，三者一致。
- **删除消息时清理引用**：问答引用本来就是每条消息新建的。`citation` 增加 `owner_message_id`，按归属清理，不做加锁判断。

**推迟**：

- N05 跨块续读；
- N06 关系查询分批；
- Q04 多分支融合；
- W05 资格前移；

## 4. 目标结构

**证据契约。**

- `EvidenceBundle.Evidence` 增加以下字段，`metadata` 只放诊断信息：
  - `selectionRank`：模式内最终选择顺序；
  - `role`：`QA_PASSAGE`、`NOTE_WINDOW`、`WIKI_SEED`、`WIKI_EXPANDED`、`REPORT_EVIDENCE`；
  - `ScoreInfo(origin, stage, model, value)`：`value` 为空表示没有模型分数。
- 充分性判断只读 `ScoreInfo` 和最终 `excerpt`。

**生成契约。**

- `GenerationContract` 在提示校验之后生成，写入 `answer_run`，内容包括：
  - 模式系统提示；
  - 是否拒答；
  - 编号绑定 `CitationBinding(number, evidenceId, citationIds)`。
- 生成调用使用契约里的系统提示。
- 模型调用前复核所选证据的资格，失效就终止本次运行并给出原因。
- 流式输出经过 `CitationMarkerNormalizer`。
- 正文、版本和状态在一个带条件的完成事务里写入，消息已删除时不写回。
- 前端从证据清单读取绑定，只为绑定里的编号生成角标。

**上下文压缩。**

- 规划器输出带最终渲染文本的条目，渲染器只负责拼接，删除按角色截断的逻辑。
- 分层如下：
  - 最近一轮问答保留全文，预算允许时最多 4 轮；
  - 更早的消息用消息摘要（回答完成时确定性生成：标题行、每节首句，不调用模型）；
  - 再往前用现有的话题摘要；
  - 会话约束照旧。
- 某条原文放不下时改用它的摘要，不再按字数截断。
- 记忆不计入上下文预算。

**研究融入。**

- 研究完成时，对话消息写入研究摘要：
  - 内容取报告结构的 `executive_summary` 和最多 5 条 `key_findings`；
  - 限 800 token，带研究运行编号；
  - 完整报告留在研究页。
- 追问时的事实来自 REPORT 通道。REPORT 通道扩展为会话证据通道：候选除了最近 3 次研究的引用证据，还包括最近 2 轮回答引用过的证据（解决 X5），按原身份重新校验资格。
- 同一次研究已经走会话证据通道时，工作台检索排除这次研究生成的资料，回答引用原始网页。
- 研究按研究问题选记忆（X6）。

**记忆。**

- 选择只保留一个入口，就是现有的 `MemoryCompilerService` 按问题编译。问答、研究、产物共用。
- 运行快照和效果反馈归因读同一份结果。
- 上下文冻结不再调用 `CanonicalMemoryRuntime.recall`。
- `MemorySlots` 映射到 `ConstraintSlot`，同一槽位上会话约束优先，这条记忆本轮不渲染，并记录原因。

**代码组织。** 不搬动现有类。新增的生成契约、引用绑定、引用规范化放在新包 `answer.generation`，其余改动留在原包。

**不做**：包结构整体调整、约束抽取与记忆抽取合并、新的向量库、通用 Agent、跨模式统一检索器。
