## 1. 现状

| 功能 | 现在的入口和行为 | 主要问题 |
|---|---|---|
| 回答模式 | 对话输入框切换问答、精读、Wiki 问答，三条链路各自检索 | 模式的系统提示没有传到模型（C03）；Wiki 扩展页被截掉（W01）；引用编号与证据靠标题猜测对应 |
| 深度研究 | 两个入口：对话里的深度研究开关，以及导航里独立的深度研究页 | 独立页创建的研究不属于任何对话，之后无法追问；对话里的研究完成后把 6000 字报告正文写进消息（X4） |
| 追问研究报告 | 问答模式下的依据研究报告开关（默认打开），走 REPORT 通道 | 由前端拼检索通道和研究编号；精读、Wiki 问答不能用；研究证据只按词项重合排序 |
| 会话上下文 | Context v2 冻结：原文窗口、话题摘要、会话约束 | 预算按全文计算，渲染时每条历史消息截到 120 或 180 字（X1）；研究进行中继续提问会导致冻结失败（X7） |
| 会话约束 | 冻结时同步抽取，比如这次别用表格 | 用户看不到当前生效的约束，也不能撤销；和长期记忆用两套槽位（X3） |
| 长期记忆 | 异步抽取，候选进入记忆页审核队列；回答依据区显示参照的记忆；点赞点踩、重新生成会回流效用 | 用户在对话里看不到新记下的偏好；记忆在一轮里选两次（X2）；研究按空查询选记忆（X6） |

## 2. 设计原则

**对话是唯一入口。**

- 资料问答、精读、Wiki 问答、深度研究都是对话里的回合。
- 记忆和上下文压缩在后台为每个回合服务；用户能在对话里看到它们用了什么，也能控制它们。
- 独立的深度研究页改为研究记录，新建研究一律落在对话里（3.4 节）。

**一轮回答只有四类输入**，各自由一个模块负责：

| 输入 | 作用 | 能否引用 | 负责模块 | 用户在哪里看到 |
|---|---|---|---|---|
| 当前问题（原文、独立问题、主题锚点） | 检索查询和生成的主语 | 否 | `QueryRewriteService` | 依据区显示改写后的问题（已有） |
| 会话上下文（最近原文、消息摘要、研究摘要、话题摘要） | 理解指代和省略 | 否 | `conversation`（上下文冻结） | 依据区显示参照的上文 |
| 会话要求和长期记忆 | 控制表达方式 | 否 | `conversation.constraint`、`memory` | 输入框上方的要求标签；依据区显示参照的记忆（已有） |
| 证据（资料片段、笔记窗口、知识页版本、研究报告引用的网页原文、上一轮回答用过的证据） | 唯一的事实来源 | 是 | 各模式检索器、`answer.strategy` | 正文角标和引用卡片 |

**四条规则：**

1. 只有证据进入引用编号。上下文和记忆即使含有事实性文字，也只帮助理解问题。
2. 每类输入只选择一次，选择结果就是渲染内容，预算按实际渲染的文字计算。
3. 会话要求只在本对话内生效，立即生效，不需要确认；长期记忆跨对话生效，需要确认。同一类偏好上，会话要求优先。
4. 每类输入的身份写进运行快照。删除或撤销时按身份处理，被删除的内容不再进入之后的回合。

## 3. 一个对话里的功能设计

### 3.1 回合类型

| 回合 | 发起方式 | 产出 | 之后的回合怎么用它 |
|---|---|---|---|
| 回答回合 | 选择问答、精读或 Wiki 问答后发送 | 带引用的回答 | 作为上文；它引用过的证据进入会话证据，供追问使用 |
| 研究回合 | 打开深度研究开关后发送；或者在依据不足的回答下点击用深度研究查这个问题 | 对话里的研究卡片（进度、摘要、主要结论），完整报告在报告页 | 研究摘要作为上文；报告引用过的网页原文进入会话证据 |

产物生成（侧栏的产物面板）和保存为笔记，作为对话的后续操作保留，不新增回合类型。

### 3.2 一段对话的完整流程

下面用一段对话说明各功能如何配合，括号里是负责的模块。

1. **用户在问答模式问资料里的问题。**
   - 冻结上下文（`conversation`）→ 改写问题（`QueryRewriteService`）→ 选记忆（`memory`）→ 工作台检索与会话证据（`answer.strategy`）→ 生成契约（`answer.generation`）→ 带引用的回答。
   - 依据区显示：引用证据、参照的上文、参照的记忆、生效的会话要求。
2. **用户说：以后回答简短一点，这次先别用表格。**
   - 冻结时的约束抽取得到两条：这次别用表格是会话要求，回答简短是长期偏好。
   - 会话要求立即生效，输入框上方出现标签不用表格，可以点叉撤销。
   - 长期偏好先作为这一轮的会话要求生效，同时进入记忆候选。回合结束后，这条用户消息下方出现一张小卡片：要记住这条偏好吗？按钮为记住、只用于本对话、忽略。
     - 选记住：候选晋升为长期记忆，以后的对话都会参照；
     - 选另外两项：候选被拒绝，会话要求照常生效。
3. **用户追问：第二点展开说说。**
   - 上下文里有上一轮回答全文，改写模型能把第二点解析成具体内容。
   - 会话证据通道把上一轮引用过的证据作为候选，追问能拿到原来的片段，不依赖重新检索碰巧命中。
4. **用户问资料里没有的问题。**
   - 充分性判断为依据不足时，按现有规则拒答。
   - 回答下方出现按钮：用深度研究查这个问题。点击后，以同一个问题发起研究回合，并带上本对话的上下文、会话要求和记忆。
5. **研究进行中。**
   - 对话里显示研究卡片和进度（已有）。
   - 用户可以继续问别的问题。上下文冻结把进行中的研究显示为一条状态：研究进行中，加上研究问题，不再因为它没有完成而冻结失败（X7）。
6. **研究完成。**
   - 卡片显示研究摘要和最多 5 条主要结论，入口是打开完整报告。
   - 对话消息里存研究摘要，不存报告全文。
7. **用户追问：按报告，哪种情况影响最大？**
   - 后端默认的检索策略看到本对话有已完成的研究，自动加上会话证据通道，用户不需要打开开关。
   - 输入框上方的依据标签显示：研究报告 1 份，加工作台资料；点击可以关掉研究报告。
   - 回答引用报告核对过的网页原文。
8. **用户把回答或报告保存为笔记、资料，或者在侧栏生成产物。**
   - 报告保存为资料后，同一次研究的追问仍然引用原始网页，不引用这份资料里对网页的转述。
9. **用户删除某一轮。**
   - 这一轮的消息、它产生的会话要求、它引用过的会话证据都不再进入之后的回合。
   - 删除研究回合后，这份报告不再自动作为依据（已有）。

### 3.3 对话界面的变化

| 位置 | 变化 |
|---|---|
| 输入框上方 | 新增依据标签：显示本轮会用到的来源，如工作台资料、研究报告 N 份，可以逐项关闭。替代现在的依据研究报告开关 |
| 输入框上方 | 新增会话要求标签：显示当前生效的会话要求，点叉撤销 |
| 用户消息下方 | 新增记忆确认卡片（3.2 第 2 步）。只在识别到长期偏好时出现，确认或忽略后收起 |
| 回答依据区 | 增加参照的上文（如最近 2 轮原文、话题摘要 1 段、研究摘要 1 份）。已有引用证据和参照的记忆 |
| 回答下方 | 依据不足时出现用深度研究查这个问题 |
| 正文角标 | 只为生成契约里的编号生成可点击角标，点击打开对应证据；越界编号显示为普通文字 |
| 研究卡片 | 完成后显示研究摘要和主要结论（已有进度和报告入口） |

### 3.4 入口调整

- **导航里的深度研究页**改为研究记录：列出本工作台的研究，每条显示所属对话和报告入口。
  - 在这里新建研究时，创建一个新对话并提交研究回合，然后跳到这个对话。
  - 历史上不属于任何对话的研究，继续可以查看报告，但不能追问。
- **记忆页**保留为管理页：查看、编辑、撤销记忆，处理冲突复核。对话里的确认卡片调用同一个审核接口。
- **知识库、资料库**不变。

## 4. 各功能设计

### 4.1 回合编排与检索通道

- **默认检索策略由后端决定。** 请求不带 `retrieval_strategy` 时，后端按以下规则选通道：
  - `WORKSPACE`：问答模式下，工作台有可检索资料时加入；精读、Wiki 问答始终加入；
  - `CONVERSATION`：问答模式下，本对话有已完成的研究，或最近 2 轮回答有引用时加入。
- 回执和回答运行返回实际使用的通道和研究编号。前端的依据标签按回执显示，用户关掉某项后，下一轮请求显式传 `retrieval_channels`。
- 前端现在用 `researchReportRefs` 自己拼通道和研究编号，改为只在用户手动调整时传，默认交给后端。
- `CONVERSATION` 通道这一轮只开放给问答模式。
  - 原因：精读和 Wiki 问答的证据单位是工作台资料和知识页，研究证据要先保存为资料，才进入这两种模式。
  - 精读、Wiki 问答显式请求这个通道时，沿用现有的 409 `RETRIEVAL_CHANNEL_UNSUPPORTED`。
- 显式的资料范围对会话证据同样生效：用户把范围限定在资料 A 时，上一轮来自资料 B 的证据不进入候选。

### 4.2 会话证据

由现有 REPORT 通道扩展而来，渠道名从 `REPORT` 改为 `CONVERSATION`。为兼容已有请求，`REPORT` 作为别名保留。

**候选来源，不新建表：**

- 研究：本对话最近 3 次已完成研究的报告正文引用过的 `source_evidence`（现有逻辑）；
- 上一轮回答：当前活跃路径上最近 2 条助手消息的 `message_citation` 与 `citation` 行：
  - 资料引用按 `source_id`、`source_snapshot_id`、`source_chunk_id` 回到 `source_chunk` 读取正文；
  - 研究引用按 `research_run_id`、`research_evidence_key` 回到 `source_evidence`；
  - 知识页引用这一轮不进入候选。Wiki 问答本身不开放这个通道，问答模式的回答也不会引用知识页。

**身份与资格：**

- 资料片段沿用 `passage:{chunkId}` 的证据编号和 `workspace-source:` 访问范围，经过现有归属校验：快照不是当前版本就丢弃，新版本由工作台检索去找。
- 研究证据沿用 `research-evidence:` 的编号和 12 号文档的资格规则。
- 同一证据同时来自会话证据和工作台检索时，编排器按证据编号去重，保留排在前面的一条。现在编排器没有去重，需要补上。

**排序：**

- 用 QA 的重排服务给候选打分。候选通常只有几十条，开销很小。
- 重排不可用时退回词项重合，同分保持原顺序。此时分数不参与充分性门控（4.7 节的评分来源）。

**预算：**

- 排在工作台检索之前，最多 6 条。
- 检索计划版本后缀由 `+research-report-v1` 改为 `+conversation-evidence-v1`，`workspacePlan()` 两种后缀都能去掉，旧运行照常解码。

**研究资料去重：** 同一次研究已在本轮候选里时，工作台检索排除 `generated_by = research_agent` 且 `generated_ref_id` 为这次研究的资料。

### 4.3 上下文压缩

**分层与预算。** 上下文总预算沿用 12000 token（`ContextV2ShadowSnapshotService.CONTEXT_BUDGET_TOKENS`），不再包含记忆。按以下顺序放入：

| 顺序 | 层 | 内容 | 规则 |
|---|---|---|---|
| 1 | 会话要求 | 当前生效的会话约束 | 必带 |
| 2 | 最近一轮 | 上一轮用户消息和助手回答的全文 | 必带；助手回答超过 3000 token 时改用它的摘要形式 |
| 3 | 更近的原文 | 再往前最多 3 轮 | 合计不超过 6000 token；放不下的改用摘要形式 |
| 4 | 研究摘要 | 当前话题段内最近 2 次研究 | 每份不超过 800 token |
| 5 | 消息摘要 | 原文窗口之外、仍在当前话题段内、话题摘要尚未覆盖的消息 | 每条不超过 300 token |
| 6 | 话题摘要 | 当前话题更早部分和同话题的旧段（现有） | 预算不足时记 `SUMMARY_BUDGET_EXCEEDED`（现有） |

**消息摘要**在冻结时用确定性规则从消息正文生成，不调用模型，也不落新表：

- 用户消息不超过 200 token 时用原文，超过时取前 200 token；
- 助手回答取标题行、每节第一句和列表各项的第一行，限 300 token。

快照记录每个条目的身份、形式（原文或摘要）、内容哈希和 token 数，所以不需要单独存摘要。

**研究摘要**在研究完成时生成，直接作为研究回合助手消息的正文，替代现在的 6000 字报告：

- 内容取报告结构里的 `executive_summary`、最多 5 条 `key_findings`、未解决的问题（`closed_loop_state` 或 `next_actions`），最后附研究运行编号；
- 不调用模型；
- 正文里的证据编号标记照旧去掉。

旧研究消息超过 800 token 时，冻结时取前 800 token。

**进行中的研究**（X7）：研究回合的助手占位消息是 `PENDING`。冻结时把它当作一条状态条目（研究进行中：研究问题），不再要求前缀里的消息全部是 `CURRENT`。其他 `PENDING` 消息（正在生成的回答）仍按现有规则处理。

**预算与渲染一致**（X1）：

- 规划器输出条目列表，每个条目带最终渲染文本和 token 数；
- 渲染器按用途拼接：
  - 改写：最近原文和摘要，不带会话要求；
  - 生成：全部条目；
  - 研究简报：全部条目。
- 删除 `ConversationRetrievalContextAssembler` 按角色截到 120 和 180 字的逻辑。
- 检索查询仍然只用独立问题和主题锚点，不带对话窗口（保持 `ConversationWindow` 现有约定）。

**冻结失败**时只用最近一轮原文并记降级原因。统计 `context_v2_fallback_code` 确认回退很少后，删除 Context v1 编译、影子对比和灰度开关。

### 4.4 会话要求

- 抽取不变：冻结时同步调用 `ConstraintOpsExtractor`，按现有合并规则写入 `conversation_constraint_v2`。
- 新增两个接口：
  - `GET /api/v2/workspaces/{ws}/conversations/{conv}/constraints` 返回当前生效的会话要求：编号、文字、作用范围、来源消息；
  - `DELETE .../constraints/{constraintId}` 撤销一条：写 `invalid_after_seq` 为当前最大序号，状态和合并规则沿用现有字段。之后的冻结不再包含它。
- 删除来源消息时，由它产生的会话要求一起失效（检查现有 `ConversationMessageDeletionService` 是否已经覆盖，没有就补上）。

### 4.5 长期记忆

**选择只有一个入口。**

- 问答、研究、产物都调用 `MemoryCompilerService` 按问题编译，返回入选记忆的版本身份、每条的入选或落选原因、渲染文本和 token 数。
- 调用时机：
  - 问答在改写之后；
  - 研究在创建研究运行时，用研究问题选择（X6）；
  - 产物沿用现有调用。
- 上下文冻结不再调用 `CanonicalMemoryRuntime.recall`。`ContextProjectionV2.memoryRevisions` 为了能读旧快照而保留，新快照写空列表。
- 运行快照的 `memory_revision_refs`、`logPackUsage`、效果反馈归因读同一份编译结果（快照现在已经读控制包，保持不变）。

**会话要求优先**（X3）：

- 新增 `PreferenceSlotFamily`（语言、长度、表格、结构、引用、代码、术语、风格）。`ConstraintSlot` 和 `MemorySlots` 各自映射到这组类别。
- 编译记忆时传入本轮生效的会话要求所属类别。同一类别的记忆本轮不渲染，记录原因 `OVERRIDDEN_BY_CONVERSATION_CONSTRAINT`。
- 删除 `ChatService` 里按归一化文字去重的逻辑。

**对话里确认记忆：**

- 记忆抽取仍是回合后的异步任务。产生候选后，消息列表接口为对应的用户消息带上 `memory_suggestions`：候选编号、展示文字、状态。
  - 候选通过信号的来源（`memory_signal.source_type`、`source_id` 指向消息）找到。
- 前端在用户消息下显示确认卡片，按钮调用现有的 `POST /memory/reviews/{reviewKind}/{reviewId}/decisions`：
  - 记住：批准；
  - 只用于本对话、忽略：拒绝。
- 已经按策略自动生效的记忆（明确表达且没有冲突）显示为：已记住，可以撤销。撤销调用现有的 `revoke` 接口。

**效果反馈**不变：点赞点踩、重新生成、下一轮追问按现有规则回流，作用于这一轮实际注入的记忆。

### 4.6 深度研究回合

- **发起**：对话里的深度研究开关（已有）；依据不足回答下的按钮（新增，前端以同一问题提交 `DEEP_RESEARCH` 回合）；研究记录页的新建按钮（新增，先建对话再提交回合）。
- **输入**：与回答回合共用冻结上下文、会话要求和记忆选择。研究简报由 `ResearchContextV2Question` 用研究用途渲染。
- **进行中**：研究卡片显示进度（已有）；对话可以继续（4.3 节进行中的研究）。
- **完成**：
  - 写研究摘要到对话消息（4.3 节）；
  - 卡片显示摘要和主要结论；
  - 报告引用的证据通过会话证据进入之后的追问（4.2 节）。
- **在同一对话里再次研究**：新的研究简报带上之前研究的摘要（来自上下文），以及之前研究的编号 `prior_research_run_ids`，供规划时避开已经查过的方向。
  - 复用之前研究的证据作为种子，这一轮不做。
- **删除**：删除研究回合后，摘要不再进入上下文，报告不再进入会话证据（已有后者）。

### 4.7 生成与引用契约

**评分来源 `ScoreInfo(origin, model, value)`。** 新增到 `EvidenceBundle.Evidence`，`value` 为空表示没有模型分数，0 是有效分数。`origin` 的取值按链路如下：

| 链路 | origin 取值 | 依据 |
|---|---|---|
| 问答 | 重排成功且有分数为 `PROVIDER_MODEL`；`RerankResult.model` 为 `llm-listwise-v1` 时为 `LLM_FALLBACK`；未评分尾部和全部降级为 `FUSION_FALLBACK` | 来自 `QaRerankService.RankedHit.fallbackScore`。需要在 `QaHybridRetriever.OwnedHit` 和 `QaPassageRetriever.RetrievedChunk` 里传递 |
| 精读 | 窗口重排同上；重排失败为 `FUSION_FALLBACK` | 来自 `NoteReadingRetriever` 的窗口重排结果 |
| Wiki 问答 | 种子页有模型重排分为 `PROVIDER_MODEL`，否则为 `LEXICAL`；扩展页为 `GRAPH` | `KnowledgePageHit` 现在只有百分制整数分，需要另带原始分和来源 |
| 会话证据 | 重排成功为 `PROVIDER_MODEL`，否则为 `LEXICAL` | 4.2 节 |

**充分性判断：**

- 只取 `PROVIDER_MODEL` 的最高分，应用 0.15 和 0.35 两个门槛；其他来源只看模型结论，并记 `RERANK_SCORE_ABSENT`。
- 删除 `MODEL_SCORE_FLOOR` 的来源猜测、知识页除以 100、按降级原因后缀跳过评分。
- `OpenAiCompatibleRerankClient.parse` 校验响应：分数字段存在且为有限数值，下标为整数、在范围内且不重复。不合法时抛出异常，让 `FallbackRerankClient` 转到 LLM 后备。

**生成契约 `GenerationContract`。** 放在新包 `answer.generation`，在提示校验和引用落库之后生成，写入 `answer_run.generation_contract_json`。内容：

- 契约版本、模式、提示版本；
- 模式系统提示（来自 `PromptSpec.systemPrompt`）；
- 是否拒答；
- 编号绑定 `CitationBinding(number, evidenceId, citationIds)`。

编号规则：

- 问答、精读、会话证据按证据在最终证据集里的顺序从 1 编号。现有提示已经这样编号，预算器保持选择顺序，所以最终顺序就是选择顺序，不另加排名字段。
- Wiki 问答保留 `[[页面名]]` 写法，绑定里记录页面标题和知识版本。
- `EvidenceCitationAssembler.persist` 改为返回每条证据对应的引用行编号。

**生成调用：**

- `ChatAnswerGenerationAdapter` 使用公共规则加契约里的模式系统提示，替换现在固定的润色草稿提示。
- 调用模型前复核绑定证据的资格。现在 `citationLines` 遇到撤销来源会静默过滤，改为让本次运行失败，错误码 `ANSWER_EVIDENCE_REVOKED`，避免旧草稿继续生成。

**引用规范化 `CitationMarkerNormalizer`：**

- 位置：在 `AnswerGenerationOrchestrator` 中，包在 `BufferedAnswerDeltaEmitter::accept` 外面。
- 规则：
  - 合法编号和已选页面名原样输出；
  - 越界编号、未选页面名改为普通文字并计数；
  - 跨 token 的未闭合标记先暂存，超过 16 个字符按普通文字放出；
  - 代码块和行内代码里的内容不处理。
- 流式内容、返回值和落库文本都经过它。非法标记次数写入 `answer_run.citation_marker_invalid_count`。

**带条件的完成事务**（C04 晚到写入部分）：

- 把 `persistContent` 并进 `AnswerRunService.complete` 的同一个事务。
- 只有回答消息不是 `DELETED`、运行仍属于当前 stream owner 时，才写消息正文、`message_revision` 和状态。
- 消息已删除时，完成结果为 `DELETED`，不写正文。

**前端：**

- `AnswerEvidenceManifestResponse` 增加 `protocol_version` 和 `citation_bindings`。
- `buildCitationViews` 有绑定时按编号对应，没有时走旧逻辑并标为旧协议。
- `MessageBubble` 只为绑定内的编号生成角标。

### 4.8 删除与撤销

| 操作 | 影响 |
|---|---|
| 删除一条回答消息 | 消息正文清空（已有）；它产生的会话要求失效（4.4）；它引用过的证据不再进入会话证据；按 `citation.owner_message_id` 清理这条消息自己的引用行，共享的知识页引用只解除绑定；进行中的生成按带条件的完成事务不写回 |
| 删除研究回合 | 研究摘要不再进入上下文；报告不再自动作为依据（已有）；报告页保留 |
| 资料被撤销 | 引用它的回答隐藏（已有）；它的片段不再进入会话证据；生成前复核失败的运行终止 |
| 撤销会话要求 | 之后的冻结不再包含它 |
| 撤销长期记忆 | 召回排除（已有）；运行快照里的展示文字脱敏（已有） |

| 多轮上下文 | 30 组多轮对话，包含第 N 点展开、刚才那个、按报告追问、话题切换后回到旧话题、研究进行中提问 | 指代解析正确率（改写后的独立问题是否包含正确实体）；平均输入 token | 第二期前后 |
| 记忆与会话要求 | 02 号文档第 5 节的构造集，加会话要求覆盖长期记忆的用例 | 应注入记忆的命中率、误注入率、覆盖规则的正确率 | 第二期结束 |

评分模型会跨天漂移，在研究评测里观察到约 2 题，对比的两个版本要在同一时段评分。

## 8. 不做的事

- 包结构整体调整：新增的类放进新包 `answer.generation`，现有类不搬动；
- 约束抽取与记忆抽取合并成一次调用；
- 精读、Wiki 问答使用会话证据；
- 研究复用之前研究的证据作为种子；
- 新的向量库、通用 Agent、跨模式统一检索器、全局命题图、事实核验 Agent。
