# 一个对话里的三种模式与深度研究：上下文、压缩与记忆设计

日期：2026-11-01。基线：GitHub main `e2f72e39`（研究功能已并入，见 [12 号文档](12-研究功能并入主链路-2026-10-31.md)）。

状态：设计已定，按第 12 节分期实施，执行说明见 [协作/AI执行提示词-对话链路改造](协作/AI执行提示词-对话链路改造-2026-11-01.md)。复核文档全文见 [协作/检索链路复核与修改实施文档](协作/检索链路复核与修改实施文档-605f2c58.md)。

本文以一个对话为单位，设计问答（QA）、精读（Note）、Wiki 问答三种模式和深度研究如何共存，以及支撑它们的上下文、压缩、记忆机制。

核心约束是每次模型调用只拿它需要的东西，研究过程、检索中间结果、记忆原文都不整段塞进提示。文末给出分期计划、评测，以及与简历条目的对应。

## 0. 设计要点

| 设计 | 解决的问题 | 一句话说明 |
|---|---|---|
| 按调用方的上下文契约 | 同一段对话窗口被塞给改写、生成、研究规划、单元格抽取等所有调用 | 回合开始时冻结一份会话快照，每次模型调用按自己的契约从快照里取视图，记录取了什么、多少 token |
| 可回溯的分层压缩 | 窗口加摘要会丢细节，追问早先的内容答不上 | 每条消息有原文、摘要、话题摘要、句柄四种形态，默认用压缩形态；改写识别出指代后，按需把被指的旧回合还原成原文 |
| 钉住用户前提 | 用户说过的前提（用的是 MySQL 8、预算 10 万）在压缩中丢失 | 约束抽取同时抽取前提，前提和要求一样常驻上下文，标明未经资料核实 |
| 会话工作集 | 三种模式各自检索，对话里提过的资料、知识页、研究彼此不知道 | 从本对话的引用和研究派生一份工作集，作为 QA 的会话证据、Note 的来源信号、Wiki 的 PPR 种子、研究的已有覆盖 |
| 研究状态分级投影 | 研究过程很长，整份报告或过程放进对话既贵又干扰 | 研究以表格状态存在，对话里只放句柄或结论卡；追问时按研究对象和维度定位到具体单元格，取它核实过的证据 |
| 研究输入编译 | 研究规划和成文用的是用户原话，单元格任务却带着整段对话 | 研究开始前把问题解析成独立研究问题和少量上下文要点，规划、单元格、成文各取所需 |
| 偏好分层与就近覆盖 | 会话要求与长期记忆冲突时只靠文字去重 | 本轮指令、会话要求、长期记忆按层级覆盖，同一类偏好离当前回合近的生效 |
| 记忆编译为任务参数 | 记忆只能以一段文字进提示，研究和产物用不上 | 语言、长度、表格、来源偏好等编译成各任务的结构化参数，其余才作为提示文字 |
| 生成契约与引用绑定 | 模式提示没传到模型，引用编号靠标题猜 | 来自复核文档，作为以上设计的可靠性基础 |

## 1. 现状与问题

### 1.1 一轮回答的现状

| 环节 | 现状 | 问题 |
|---|---|---|
| 上下文冻结 | Context v2：原文窗口（最多 8 条、6000 token）、话题摘要、会话约束、全部已批准记忆 | 预算按全文算，渲染时每条消息截到 120 或 180 字（X1）；记忆占预算但不渲染（X2）；研究进行中提问会冻结失败（X7） |
| 改写 | 输入当前问题、话题锚点、话题摘要、截断后的窗口 | 看不到上一轮回答的大部分内容；只输出改写文本，不说明问题指的是哪一轮、哪份资料 |
| 记忆 | 取证前按问题编译控制包，以表达控制段进入提示 | 与会话约束两套槽位（X3）；只能作为提示文字 |
| 取证 | 三种模式各自检索；追问研究走 REPORT 通道 | 上一轮用过的证据不参与追问（X5）；Note 和 Wiki 不知道对话里提过哪些资料和页面 |
| 生成 | 固定的润色草稿系统提示加模式的用户提示 | 模式系统提示没有传到模型（C03） |

### 1.2 深度研究的现状

| 环节 | 现状 | 问题 |
|---|---|---|
| 研究问题 | 对话里发起时，`ResearchContextV2Question` 把话题摘要、原文窗口、约束和当前问题拼成一段，作为研究的 `query`，最长 12000 字 | 见下面两条 |
| 规划 | 规划模型收到 `planning_input.question`（用户原话）和话题摘要（4000 字以内） | 追问式问题（那 Java 21 呢）在规划阶段丢掉主语，因为最近原文窗口没有给规划模型（R2） |
| 单元格 | 每个单元格的核验提示带 `research_question = query_policy.query` | 整段对话上下文进入每个单元格调用，单次研究有几十个单元格（R1） |
| 成文 | 成文模型收到 `run.question()`（用户原话） | 与规划同样丢上下文（R2） |
| 写回对话 | 报告去掉证据编号后截 6000 字写进对话消息 | 问答里只剩前 180 字；同一对话再研究时占掉大半预算（X4） |
| 记忆 | 研究控制包按空查询编译，以文字列表进入单元格任务 | 按需记忆不注入（X6）；来源偏好之类的记忆没有变成研究参数 |

## 2. 设计原则

1. **对话是唯一入口。** 三种模式和深度研究都是对话里的回合；独立的深度研究页改为研究记录，新建研究落在对话里。
2. **四类输入，边界清楚：**
   - 当前问题；
   - 会话上下文：理解问题用；
   - 偏好：要求、前提、长期记忆，控制表达和任务参数；
   - 证据：唯一可引用的事实来源。
3. **按需取用。** 默认用压缩形态，模型指出需要哪一段时再还原；研究只投影结论，过程留在研究页。
4. **一次选择、一处渲染、全程可追溯。** 每次模型调用的输入都能从运行快照还原，删除和撤销按身份生效。
5. **模型调用失败有确定的退路。** 生成类调用退回规则，判定类调用记 `NOT_RUN`，与升级计划的通用约定一致。

## 3. 总体结构

### 3.1 会话状态

一个对话维护五类状态，前四类已有，第五类由已有数据派生：

| 状态 | 内容 | 存储 |
|---|---|---|
| 消息账本 | 每条消息的原文、角色、模式、序号、状态 | `conversation_message`（已有） |
| 话题结构 | 话题段、增量话题摘要、边界复核 | `conversation_topic_segment_v2`、`segment_summary_revision`（已有） |
| 要求与前提 | 会话要求（格式、语言、长度等）和用户前提 | `conversation_constraint_v2`（已有，前提为新增的一类） |
| 研究状态 | 研究表格（对象、维度、单元格）、需求覆盖、报告 | `research_run`、`research_row`、`research_cell`、`research_cell_evidence`（已有） |
| 会话工作集 | 本对话最近用到的资料、知识页、研究、证据 | 不建表，冻结时从引用、证据清单、研究运行派生（第 6 节） |

### 3.2 回答回合的流程

```
提交
  冻结会话快照   消息、话题、要求与前提、工作集、研究投影（不含记忆、不含证据）
  改写          视图 C2 → 独立问题、关键词、问题类型、指代（refers_to）
  回忆          按指代和独立问题，把快照外的旧回合、话题摘要、研究单元格补进生成视图
  选记忆        按独立问题，经过偏好层级覆盖 → 结构化参数 + 提示文字
  取证          模式检索器 + 会话证据通道；工作集作为先验信号
  充分性判断     视图 C5：独立问题 + 最终证据
  组装与契约     视图 C6 → 提示；冻结生成契约（编号绑定）
生成            按契约生成，流式规范化引用
完成            带条件写回
回合后（异步）   话题切分与摘要、记忆抽取
```

研究回合在冻结后改走第 7 节的研究输入编译，再进入研究 Agent。

## 4. 上下文契约：每次模型调用看到什么

### 4.1 视图

每个调用方声明一份上下文契约：取哪些层、各层用什么形态、预算多少、按什么顺序渲染。所有视图来自同一份冻结快照，渲染器只有一个，按契约拼接。

| 编号 | 调用 | 取用的内容 | 不取的内容 | 上下文预算 |
|---|---|---|---|---|
| C1 | 约束与前提抽取（冻结时，同步） | 当前用户消息；上一条助手回答的摘要；当前生效的要求与前提 | 其他历史、记忆、证据 | 1500 token |
| C2 | 问题改写 | 当前问题；最近一轮原文；前 2 轮摘要；当前话题摘要；其他话题句柄；工作集句柄（资料、知识页、研究的标题）；研究结论卡的对象和维度名 | 要求、记忆、证据正文 | 3000 token |
| C3 | 回忆（不调用模型） | 改写的独立问题和指代；快照外的旧回合 | 无 | 预留 2000 token 给结果 |
| C4 | 检索查询（不调用模型） | 独立问题、关键词、模式过滤条件；工作集作为先验 | 一切对话文字 | 无 |
| C5 | 充分性判断 | 独立问题；最终证据正文 | 对话、要求、记忆 | 由证据预算决定 |
| C6 | 回答生成 | 系统提示：公共规则、模式提示、表达参数。用户提示依次为：上下文（标明只用于理解问题）、前提（标明未经核实）、编号证据、原问题与独立问题 | 研究过程、未选中的检索候选、记忆原文 | 上下文 12000 token；证据按模式预算 |
| C7 | 话题摘要（异步） | 已有摘要；新增消息原文，研究消息用结论卡 | 证据原文、引用卡片 | 现有 |
| C8 | 记忆抽取（异步） | 用户消息；上一条助手回答的摘要 | 证据、其他历史 | 现有 |
| R0 | 研究输入编译 | 与 C2 相同；另加当前话题已有研究的结论卡 | 记忆原文、证据正文 | 4000 token |
| R1 | 研究规划 | 研究简报（第 7.1 节）；记忆编译出的研究参数；探测检索结果 | 对话原文 | 简报 1500 token |
| R2 | 单元格检索、抽取、核验 | 独立研究问题；研究对象；维度与需求；日期 | 对话、记忆、其他单元格 | 200 token |
| R3 | 证据审核与反证 | 待核结论和证据 | 对话、记忆 | 现有 |
| R4 | 报告成文 | 独立研究问题；用户原话（判断语言）；输出要求；已核实的单元格 | 对话原文、过程记录 | 500 token 加单元格 |

### 4.2 实现

- **类型**：新增 `ContextContract`（调用方、层、形态、预算）和 `ContextView`（条目列表、渲染文本、token 数、决定）。
  - `ContextWindowPlannerV2` 改为两步：先产出快照（条目全集与各形态），再按契约选出视图。
- **记录**：每个视图的条目身份、形态、token 数，写进运行快照的 `context_views`。回放和排查时能看到每次调用实际拿了什么。
- **渲染**：全部通过 `ContextRenderer`，删除 `ConversationRetrievalContextAssembler` 按角色截断的逻辑和 `ResearchContextV2Question` 的整段拼接。
- **检索查询**：继续不含对话文字，保持现有 `ConversationWindow` 的约定。

## 5. 可回溯的分层压缩

### 5.1 四种形态

| 形态 | 生成方式 | 大小 | 用途 |
|---|---|---|---|
| 原文 | 消息正文 | 不限 | 最近一轮；被回忆命中的旧回合 |
| 摘要 | 冻结时用确定性规则生成，不调用模型 | 用户消息不超过 200 token；助手回答取标题行、每节首句、列表各项首行，不超过 300 token；研究消息用结论卡 | 窗口内较早的回合 |
| 话题摘要 | 已有的异步增量摘要 | 现有 | 当前话题更早的部分 |
| 句柄 | 话题锚点加话题摘要第一句 | 不超过 40 token | 其他话题，让改写知道有哪些旧话题可回 |

每种压缩形态都保留来源消息编号，可以还原。

### 5.2 默认视图（C6）的装配顺序

1. **要求与前提**：必带。
2. **最近一轮原文**：必带。助手回答超过 3000 token 时用摘要形态，这种情况很少，三种模式的回答输出上限是 1200 到 2400 token。
3. **预留回忆空间**：2000 token。
4. **当前话题更早的回合**：从近到远，原文放得下就用原文，否则用摘要，合计不超过 6000 token；再往前由当前话题摘要覆盖。
5. **当前话题内的研究**：最多 2 份结论卡。
6. **其他话题句柄**：最多 5 个。

预算按渲染后的文字计算，任何条目都不再按字数截断。放不下的条目记录原因，比如 `DIGEST_FOR_BUDGET`、`SUMMARY_BUDGET_EXCEEDED`。

### 5.3 按需回忆

改写模型额外输出 `refers_to`：当前问题指向的对象，类型为回合、话题、研究、资料、知识页，引用快照里的句柄编号。没有明确指向时为空。回忆步骤据此补全生成视图：

| 指向 | 补进生成视图的内容 |
|---|---|
| 回合 | 该回合原文；超过 1500 token 用摘要 |
| 话题 | 该话题最新的话题摘要 |
| 研究 | 该研究的结论卡；若问题对应到单元格，交给会话证据通道（第 7.4 节） |
| 资料、知识页 | 不补上下文，交给取证环节作为先验（第 6 节） |

没有明确指向时，用独立问题对快照外的旧回合做 BM25 打分。范围是本对话最近 200 条消息，按回合计。取最高的 2 个回合，分数要过阈值。阈值用评测集校准，校准前取 BM25 最高分的一半。

回忆结果写进运行快照的 `context_recall_refs`。改写失败时不回忆，记录 `CONTEXT_RECALL_SKIPPED`。

### 5.4 钉住用户前提

- `ConstraintOpsExtractor` 的输出增加一类 `PREMISE`：用户陈述的事实前提，比如我们用的是 MySQL 8、团队只有 3 个人、预算 10 万。
  - 作用范围沿用现有的本轮、本话题、本对话；
  - 同一主题的新前提替换旧前提，合并规则复用 `ConstraintOpMerger`。
- 前提和要求一样常驻上下文，渲染为：用户说明的前提（未经资料核实）。
- 前提不进入证据和引用。生成提示要求依据前提的结论写明是按用户说明。
- 意义：压缩不会丢掉用户亲口说过的关键事实，这也是关键事实检查评测的主要对象（第 13 节）。

### 5.5 进行中的研究

研究回合的助手占位消息是 `PENDING`。冻结时把它作为句柄：研究进行中，加上研究问题和已核实单元格数。不再要求前缀消息全部是 `CURRENT`，用户可以在研究进行中继续提问（X7）。

## 6. 会话工作集：三种模式共享的状态

### 6.1 内容与派生

冻结时从以下数据派生，不建新表：

| 成员 | 来源 | 上限 |
|---|---|---|
| 资料 | 最近 6 个回答运行的证据清单（`answer_run_evidence_manifest`）中的资料编号；最近回合显式选择的资料范围 | 20 |
| 知识页 | 同一批证据清单中的知识版本 | 20 |
| 研究 | 本对话的研究运行，排除回答消息已删除的 | 3 |
| 证据 | 最近 2 个回答引用过的证据身份 | 30 |

每个成员带权重 `0.7^距离`，距离是成员最近一次被使用的回合距当前的回合数。成员都要通过当前资格检查，失效的不进入工作集。

### 6.2 各模式怎么用

| 使用方 | 用法 |
|---|---|
| 改写（C2） | 工作集句柄列出标题，模型能把那份资料、刚才那个页面、那次研究解析成具体对象，写进 `refers_to` |
| QA | 会话证据通道：候选是工作集里的证据和研究证据，重新校验资格后参与选择（第 7.4 节）；`refers_to` 指向的资料作为软范围，排序时加分，不做硬过滤 |
| Note | `NoteRecallRetriever` 的来源级召回增加一路会话信号，分数取工作集权重；`refers_to` 指向的资料作为锚点来源 |
| Wiki | PPR 的种子加入工作集里的知识页，权重为最高种子权重的 0.3 乘工作集权重。不占种子名额，只影响随机游走的重启分布，让扩展偏向本对话讨论过的页面 |
| 研究 | 研究简报带上工作集里的资料作为可选种子来源，带上已有研究的覆盖情况 |
| 界面 | 输入框上方的依据标签：工作台资料、研究报告 N 份、本对话资料 N 份，可以逐项关闭 |

### 6.3 边界

- 工作集只提供信号和候选，最终证据仍由各模式的选择和预算决定。
- 显式资料范围优先于工作集：用户限定范围后，范围外的成员不参与。
- 删除回合后，该回合贡献的成员在下一次冻结时自然消失。

## 7. 深度研究在对话里

### 7.1 研究输入编译（R0）

`ResearchBriefCompiler` 在研究开始前调用一次模型（用途名 `research.brief.compile`），输出研究简报：

| 字段 | 内容 |
|---|---|
| `research_question` | 独立、完整的研究问题，语言与用户一致 |
| `context_notes` | 最多 5 条来自对话、限定研究范围的要点，每条带来源消息编号 |
| `premises` | 当前生效的用户前提 |
| `output_requirements` | 报告的语言、格式、长度要求，来自会话要求和记忆 |
| `focus_entities` | 对话中已经点名的研究对象 |
| `prior_research` | 当前话题已有研究的编号、标题、已覆盖需求、未解决需求 |
| `seed_sources` | 工作集里的资料（`WEB_PLUS_SEEDS` 时作为种子） |

使用方式：

- 研究的 `query` 和 `planning_input.question` 都改为 `research_question`，成文的 `question` 也用它（解决 R2）。
- 用户原话另存为 `original_question`，只用来判断报告语言。
- 模型不可用时退回规则：`research_question` 用原话，`context_notes` 取最近 3 条用户消息的摘要，记 `RESEARCH_BRIEF_COMPILE_FALLBACK`。
- 简报冻结进研究运行，续跑和恢复都读同一份。

### 7.2 研究各角色的输入

- **规划**：收到完整简报和记忆编译出的研究参数。`prior_research` 让规划避开已覆盖的需求；`focus_entities` 是研究对象的候选。
- **单元格任务**：只收到 `research_question`、对象、维度和需求，不再收到对话上下文和记忆文字（解决 R1）。现在给单元格任务的控制包改为只给规划和成文。
- **成文**：收到 `research_question`、`original_question`、`output_requirements` 和已核实的单元格。

### 7.3 研究在对话里的分级投影

研究状态是一张表：对象乘维度的单元格，每格有值、状态、置信度、证据，另有需求覆盖和报告。对话只看它的投影：

| 级别 | 内容 | 用在哪里 |
|---|---|---|
| P0 句柄 | 研究标题、一句话结论、状态（进行中时为已核实单元格数） | 其他话题的研究；同一话题超过 2 份时较早的研究 |
| P1 结论卡 | `executive_summary`；每条需求一行（结论、状态：已核实、部分核实、未能核实，来自 `research_requirement` 与单元格状态）；表格的对象名和维度名；不超过 800 token | 当前话题的研究；研究消息的正文就是结论卡 |
| P2 单元格 | 某个单元格的值、状态和它核实过的证据原文 | 追问定位到这个单元格时，经会话证据通道进入证据 |

**永远不进入对话上下文的内容**：

- 规划和重规划记录、任务和检索词；
- 抓取和阅读窗口、被驳回的结论；
- 审核与修复历史、反证过程；
- 完整报告正文。

这些都留在研究页。

结论卡在研究完成时用确定性规则从报告结构（`executive_summary`、需求覆盖、表格结构）生成，不调用模型，作为研究回合助手消息的正文。它替代现在的 6000 字报告（解决 X4）。

### 7.4 按单元格定位的追问

会话证据通道收到追问后，先尝试把问题定位到研究表格：

1. 对象匹配：独立问题里出现研究对象的名称或别名（规划记录 JSON 里 `rows` 的 `label` 与 `aliases`）。
2. 维度匹配：独立问题与维度标签和说明（`research_column`）的词项重合，或 `refers_to` 指向的研究给出了维度。
3. 两者都命中时定位到单元格；只命中对象时取该对象的全部已核实单元格；只命中维度时取该维度的全部单元格。

定位后的处理：

- 单元格的证据（`research_cell_evidence` 到 `source_evidence`）排在会话证据的最前面，其余研究证据按重排结果排在后面。
- 单元格状态随证据进入提示。状态是部分核实或未能核实时，回答必须说明研究没有核实这一项。
- 界面在回答下方给出补查这一项（第 7.5 节）。
- 没有定位到单元格时，按现有方式在研究引用过的全部证据里重排选取。

### 7.5 增量研究

**发起方式**：

- 对研究未核实的单元格点击补查这一项；
- 在同一对话里提出对已有研究的扩展，比如再加上 Go 的对比。

**做法**：

- 以已有研究为基础发起新的研究回合，复用现有的检查点续跑：`resumed_from_research_run_id` 加最终检查点。
- 简报里写明 `focus_cells`（要补查的单元格）或新增的需求。
- 规划只对新增需求做重规划，增加行或列；已核实的单元格保留，只重开指定的单元格；成文基于更新后的表格重写报告。
- 新研究链接到原研究，对话里的结论卡更新为新版本，原研究保留在研究记录里。
- 意义：追问驱动的局部补查，代价远小于重跑整个研究。这是 Table-as-State 和检查点设计在对话里的直接延伸。

### 7.6 研究入口

- 对话里的深度研究开关（已有）。
- 依据不足的回答下方：用深度研究查这个问题。
- 研究记录页新建：先建对话再提交研究回合。
- 历史上不属于任何对话的研究只能查看报告。

## 8. 记忆：分层与结构化编译

### 8.1 偏好层级

| 层级 | 生效范围 | 来源 | 是否需要确认 |
|---|---|---|---|
| 本轮指令 | 当前回合 | 约束抽取，作用范围为本轮 | 否 |
| 会话要求 | 本话题或本对话 | 约束抽取，作用范围为本话题或本对话 | 否，可以在输入框上方撤销 |
| 长期记忆（用户级、工作台级） | 跨对话 | 记忆候选，经过门控晋升 | 明确表达且无冲突时按现有策略自动生效，否则在对话里确认 |

- 新增 `PreferenceSlotFamily`：语言、长度、表格、结构、引用、代码、术语、风格、来源偏好。`ConstraintSlot` 和 `MemorySlots` 各自映射到这组类别。
- 同一类别上离当前回合近的层级生效，被覆盖的记忆本轮不使用，决定记为 `OVERRIDDEN_BY_CONVERSATION_CONSTRAINT`。
- 删除 `ChatService` 里按归一化文字去重的逻辑。

### 8.2 编译为任务参数

记忆编译的输出分两部分：结构化参数，以及没有对应参数的提示文字。

| 偏好类别 | 回答 | 研究 | 产物 |
|---|---|---|---|
| 语言 | 输出语言 | 报告语言（`output_requirements`） | 技能参数 |
| 长度 | 长度要求；简短时把 `maximum_output_tokens` 降到 600 | 报告篇幅 | 技能参数 |
| 表格 | 允许或禁止表格 | 是否需要对比表 | 技能参数 |
| 来源偏好（如优先官方文档、不要用某站点） | 不适用 | 规划的权威域名提示和排除域名 | 不适用 |
| 术语 | 术语表 | 报告术语 | 术语表 |
| 其他 | 表达控制段文字 | 规划提示文字 | 现有 |

### 8.3 防止记忆污染事实

- 记忆只进入生成的表达控制、研究规划的参数和成文要求。改写、检索、充分性判断、单元格核验都不读记忆。
- 记忆不进入证据和引用。
- 记忆抽取只接受偏好类陈述；对世界的事实性陈述不进入记忆，在对话里提示可以保存为笔记，成为资料后才能作为证据。
- 依据资料产生的记忆，在资料撤销后召回时排除（已有 `MemorySourceReadGate`）。

### 8.4 选择与反馈

- **选择只有一次**：
  - 问答在改写之后按独立问题编译；
  - 研究在研究输入编译后按 `research_question` 编译（解决 X6）；
  - 冻结快照不再包含记忆（解决 X2）。
- **对话里确认**：
  - 记忆抽取产生候选后，消息列表接口为来源用户消息带上 `memory_suggestions`；
  - 前端在消息下方显示确认卡片：记住、只用于本对话、忽略，调用现有审核接口；
  - 已自动生效的显示为已记住，可以撤销。
- **效果反馈**：点赞点踩、重新生成、下一轮追问按现有规则回流，归因到本轮实际使用的记忆。

## 9. 三种模式的分工与切换

| 模式 | 适合的问题 | 证据单位 | 上下文侧重 | 会话工作集的作用 |
|---|---|---|---|---|
| QA | 资料里的具体事实、出处 | 资料片段 | 最近原文和回忆，追问指代多 | 会话证据通道 |
| Note（精读） | 整理、总结、对比几份资料 | 资料的连续阅读窗口 | 工作集里的资料比对话原文更重要 | 来源级召回的会话信号和锚点 |
| Wiki 问答 | 概念、关系、长期知识 | 知识页版本 | 话题摘要和工作集里的页面 | PPR 种子 |
| 深度研究 | 资料里没有、需要联网核实的开放问题 | 网页原文摘录（研究证据） | 研究简报 | 种子来源和已有覆盖 |

- **切换**：用户在输入框选择，切换模式不清空会话状态，下一轮照常使用上下文、要求、记忆和工作集。
- **模式建议**：改写已经输出问题类型，不额外调用模型。界面根据问题类型和充分性给出提示，由用户决定，不自动切换：
  - 问答模式下的整理、总结类问题，建议精读；
  - 概念与关系类问题，建议 Wiki 问答；
  - 依据不足时，建议深度研究。
- **会话证据**这一轮只开放给 QA。精读和 Wiki 问答的证据单位是工作台资料和知识页，研究证据保存为资料后才进入这两种模式。

## 10. 证据与生成契约

来自复核文档，作为上面各项的可靠性基础。

**评分来源。** `EvidenceBundle.Evidence` 增加 `ScoreInfo(origin, model, value)`，`value` 为空表示没有模型分数。各链路的取值：

- 模型写 `[n]`。`CitationMarkerNormalizer` 在流式输出时把越界编号和未选页面名改成普通文字并计数，流式、返回、落库三者一致。

**完成与删除：**

- `persistContent` 并入 `AnswerRunService.complete` 的同一事务，消息已删除时不写回；
- `citation.owner_message_id` 标记消息自有的引用，删除时只清理自有引用。

### 13.2 与简历条目的对应

简历第 5 条现在写的是 Topic-aware Window 加增量摘要、候选提取与门控晋升、偏好与证据分层隔离，Token 降低 34%，关键事实检查通过率 92%。本设计实施后，可以讲清楚的部分：

- **按调用方的上下文契约**：同一冻结快照派生改写、生成、研究规划、单元格等视图，每次调用的输入可回放；Token 降低按调用方分别统计。
- **可回溯的分层压缩**：原文、摘要、话题摘要、句柄四种形态，改写识别指代后按需还原原文；用户前提常驻。关键事实检查有对照实验。
- **偏好分层与就近覆盖**：本轮、会话、长期三层，按偏好类别覆盖；记忆编译为任务参数，只进入表达和规划，不进入取证和核验。

第 1 条可以补充研究与对话的衔接：研究输入编译，表格状态分级投影到对话，按单元格定位的追问和增量补查。

第 2 条可以补充会话工作集：同一对话的资料、知识页、研究作为 QA 会话证据、Note 来源信号、Wiki PPR 种子。

具体措辞等对应阶段实施并跑完评测后再改，数字以评测结果为准。

#### 与设计的差异及理由

1. 生成契约的冻结位置：第 10 节写的是提示校验和引用落库之后冻结，实现放在 `ChatService.finalizePreparedAnswer` 中，与引用落库在同一事务内。理由是编号绑定需要 `citationId`，落库之后才有。
2. `CitationBinding.number` 取提示里 `[n]` 的顺序，也就是 `referencedEvidenceIds` 的下标加一，没有使用 `selectionRank`。理由是模型看到的就是这个顺序，换用别的编号方式会让绑定与正文对不上。
3. 契约里额外保存 `allowedPageTitles`。设计只写了编号绑定，而 `[[未选页面]]` 的规范化需要一份允许的页面名集合；冻结时从 `KNOWLEDGE_VERSION` 证据的标题取出，避免前端或流式层按标题猜。
4. `CitationMarkerNormalizer` 把越界标记改成全角括号（例如 `［7］`），没有删除。理由是视觉不变、语义不丢，同时不再被引用解析器匹配。
5. 非对话入口 `AnswerSubmissionService.createPreparedRun` 暂不冻结契约，传 `null`。理由是这条路径目前只有测试在用，二期统一到同一份契约。
6. 证据资格复核的覆盖面：资料与知识版本都复核，研究报告证据只校验清单存在与正文摘要，没有复核研究运行状态。理由是证据身份里没有稳定的研究运行键，补齐这项复核需要新的血缘字段，放到第六期与 W03 一起做。
7. 流式绑定事件是前端成员指出缺口后补做的，属于复核文档 7.3 的必改项，本来应当在第一期一次做完。
