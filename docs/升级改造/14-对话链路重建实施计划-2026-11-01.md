## 3. 阶段门禁与工作方法

### 3.1 一期的完成条件

只有下列条件同时满足，才能汇报一期完成：

1. 该期必改任务与用户确认的设计差异全部关闭。
2. 每条安全或一致性结论有生产路径测试；不能只测试新值对象或人工拼接的理想输入。
3. 全量后端、前端、研究 Worker、跨运行时词汇检查完成；CI 中其他验证项执行或有明确说明。
4. 新字段的历史兼容、删除、撤销和迁移有验收；有并发需求的路径测试实际竞争顺序。
5. 需要真实模型的端到端验证已执行，或确有环境阻碍且记录为未验收项目并获得用户接受；不能自行把缺项隐藏为完成。
6. 13 号文档第 15 节记录准确的提交、命令、结果、差异和未完成项。
7. 工作分支提交并推送，未改 main。汇报区分代码完成、测试通过、部署完成、阶段验收。

### 3.2 日常实施顺序

先读涉及生产调用链与现有测试 → 建反例 → 修生产逻辑 → 跑定向回归 → 复核 diff → 固定测试提交/快照 → 跑全量 → 写实施记录 → 推送并汇报。

允许阶段内提交作为固定测试基线，但中间提交不能被标为阶段完成。最后代码提交发生变化，必须重新验证受影响项目并在最终门禁上使用准确代码版本。

### 3.3 进度状态

任务使用 `NOT_STARTED / IN_PROGRESS / IMPLEMENTED_UNVERIFIED / VERIFIED / ACCEPTED / DEFERRED_APPROVED`，不可混用。测试环境故障记在执行记录，不当作产品 bug 已修。延期必须写原验收项、影响、理由和用户确认，不能仅由 Agent 在文档里单方面宣布。

**对应 A01、A09。** 涉及 `RerankClient`、`FallbackRerankClient`、QA/Note/Wiki 评分结果类型、四个 EvidenceRetriever、`EvidenceBundleSnapshot`。

实施要求：

### F1-06 流式引用解析与规范正文

**对应 A06。** 涉及 `CitationMarkerNormalizer`、适配器返回值与回调处理、编排器、前端 Markdown 有效位置规则。

实施要求：

验收：

- 至少包含合法/越界/0/超长编号、相邻引用、页面名双括号、代码块、不同长度行内 backtick、转义反斜杠、数组下标、Markdown 数字链接、流末尾未闭合。

## 6. 第二期：上下文契约与压缩，完整交付

验收：上一轮第 N 点位于旧 180 字之后，改写与生成都能看到；必须保留信息超过预算时返回明确结果；prompt、snapshot、计数记录一致。

验收：早期前提、编号列表尾部、跨话题返回、无关追问、错误句柄、改写失败、删除后回忆、运行开始后新消息到达等场景；不同工作台/会话绝不进入候选。

| 迁移与生命周期 | 隔离 MySQL 与 H2；升级、存量兼容、删除/并发反例 | 数据库前后断言，不使用生产库 |
| 真实端到端 | 三模式回答、研究追问、真实 SSE/恢复、引用版本与删除 | 环境、deployedCommit、运行 ID、接口与浏览器证据 |

不修改既有失败断言来消除红灯。若旧断言与已确认的新契约冲突，先解释契约差异、建立新用例，再调整旧断言；测试替身必须跟随真实 schema，而非另造一个让错误实现通过的表。

### 11.2 insta4 后端验证示例

仅在确认测试副本干净、无运行中的构建后切换到明确提交。不要把 `git reset --hard` 当作同步默认命令；使用新隔离检出或确认干净后的 `checkout --detach <sha>`。

测试 ES 独立于业务 ES，版本 8.15.3、无鉴权、只绑定 loopback。启动前检查同名容器用途，不能无条件 `docker rm -f` 删除别人的实例。

```bash
# 在 insta4 的 shell 中执行；先核对这些目录、镜像和测试端口。
cd /data/workspace/nw-pipeline
TESTED_COMMIT=$(git rev-parse HEAD)
git status --porcelain
# 若上面不是空输出，先确认快照和归属，不继续宣称测试针对干净提交。
mkdir -p /data/m2/repository
RUN_DIR=$(mktemp -d /tmp/nw-verify-XXXXXX)
printf 'HEAD=%s\nSTART=%s\n' "$TESTED_COMMIT" "$(date -u +%FT%TZ)" > "$RUN_DIR/meta"

rc=0
docker run --rm --network host \
  --user "$(id -u):$(id -g)" -e HOME=/tmp \
  -v /data/workspace/nw-pipeline:/src -w /src \
  -v /data/m2:/m2 -e MAVEN_CONFIG=/m2 \
  maven:3.9-eclipse-temurin-17 \
  mvn -B -f backend/pom.xml -Dmaven.repo.local=/m2/repository clean test \
  > "$RUN_DIR/backend.log" 2>&1 || rc=$?
printf 'EXIT=%s\nEND=%s\n' "$rc" "$(date -u +%FT%TZ)" >> "$RUN_DIR/meta"
printf 'REPORT=%s EXIT=%s\n' "$RUN_DIR" "$rc"
exit "$rc"
```

示例不自动下载密钥、不接业务数据库。正式记录镜像实际 digest 和 Java 版本；tag 不视为永远不变。用工具管理后台进程并保留 job/PID/容器 ID，定期读取日志不忙轮询。

若仍受内存限制，先查当前 surefire 配置。旧配置硬编码 argLine，单纯传 `-DargLine` 不保证生效，应查看实际 fork 参数。可以分批，但必须列出完整测试类清单、保证无遗漏、不把重复跑的用例累加成总数。OOM/被杀与断言失败分开记录。

### 11.3 端到端环境核查

参考 12 号文档第 6.1 节核查 insta2 现有隔离评测目录、数据库备份方案、模型接线与执行脚本。读取配置时不打印密钥、不把 `.env` 提交进仓库。需要消费真实模型额度、迁移现有评测库或影响他人环境时先说明范围并确认。

先使用受控模型/固定证据验证协议与状态机，再跑真实模型评测。服务健康检查通过只能证明可启动，不能替代引用、研究与删除流程验证。

### 11.4 测试证据格式

每次运行保留独立目录，不覆盖上一轮失败日志。最少包括：

```text
meta: commit、dirty 状态、机器、路径、runtime、镜像 digest、完整命令、时间、退出码
reports: surefire XML / pytest / vitest 原始报告
summary: 总数、失败、错误、跳过及逐项原因
failures: 重现方式、期望与实际、归因、修复提交、复跑结果
```

不要用包含 `EXIT=` 的任意日志行判断进程结束，数据库 URL 的 `DB_CLOSE_ON_EXIT` 也可能误命中。使用独立退出状态文件或精确行格式。不要把 `mvn ... | grep ...` 的 grep 退出码当作 Maven 结果。

## 12. 数据迁移、兼容与部署

- V223/V224 已被执行过，不回改。新迁移号由当前权威工作树统一分配，先检查所有分支内的最大编号。
- schema 扩展、数据兼容、清理/回填分开说明。无法证明的历史身份不得回填为已验证；使用 LEGACY_UNKNOWN 或明确不可取证状态。
- 引用/前提/快照等字段需要索引与约束，但删除敏感正文时应保留必要审计身份，不随意增加阻止合法清理的强外键。
- 旧完成回答允许历史协议展示；旧进行中运行的恢复必须保留当时契约，或明确结束并新建运行，不用新策略偷偷解释旧草稿。
- 部署使用独立 compose project、端口、数据库/schema、索引名和运行目录。不能直接复用业务库跑破坏性测试。
- 迁移前备份，记录恢复步骤。应用回退与数据库向前兼容分开说明，不把回退镜像等同于回退迁移。

## 13. 文件分工与并发规则

默认由用户选定的执行模型主导；使用子智能体/团队前遵守用户最新授权。即使允许并行，Lead 仍负责逐项审查与最终 diff。

推荐按真实写范围拆任务：评分生产与透传、资格/生命周期、流式协议、前端展示、独立验证、文档记录。共享值对象、DTO、schema、ChatService/AnswerRunService 等交叉接口由一位负责人先定契约，依赖任务等待接口稳定。

- 不在同一个工作树同时编译相同 target。
- 不在成员编辑时切分支、reset 或全量覆盖文件。
- 不用 `git add -A` 把他人半成品带入提交；提交前逐项看 diff 与暂存区。
- 不用宽泛 `pkill -f java/mvn/surefire` 清理未知进程；按记录 PID/容器 ID 精确终止自己启动的任务。
- 每个任务输出生产路径、测试证据、未完成项和具体提交/差异；另一个成员说完成，不代替 Lead 的核验。
