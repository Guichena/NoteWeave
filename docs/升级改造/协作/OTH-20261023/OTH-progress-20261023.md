## 本轮复核发现与处理

逐提交核对了文件范围、迁移内容、向量批次与检索通道实现，并重跑了测试。发现并修复两个回归：

1. 约束输出解析收得过严。原实现允许数组前后带说明文字与代码围栏，收紧后这类正常输出会被判失败。改为保留说明文字容错，仍然拒绝截断、重复键和根之后拼接第二个 JSON 值，嵌套数组与字符串里的方括号按语法解析。
2. 回答冻结把模型不可用当成状态不一致。约束抽取不可用时，任何未配置抽取模型的环境都无法冻结回答，既有 10 个用例失败。改为只核对已提交状态的一致性，抽取不可用按降级处理，回答照常进行，最新一条消息的约束下次再补。

两处都在 `f6b48a58` 与 `e35474de` 修正，并调整了按旧语义编写的用例。
