# 记忆系统重设计（简化版，2026-10-23）

上一版设计铺得太大，把综述里的五个研究方向都塞了进来。这一版收回到产品本身：NoteWeave 是一个个人知识工作区，记忆只需要解决三件事，做法参考 Mem0 的写入管线和 Letta 的两层记忆。

## 一、项目背景与记忆要解决的问题

NoteWeave 的典型使用流程是：上传资料，解析切分建索引，然后围绕资料做问答、写笔记、生成 wiki、跑研究、产出幻灯片或文档。用户会连续使用几周甚至几个月，反复处理同一批项目资料。

记忆在这个产品里只承担三个用途：

1. 记住表达偏好。回答用中文还是英文，要不要先给结论，引用要不要带出处，篇幅偏长还是偏短。
2. 记住当前项目上下文。用户正在写哪份报告、关注哪个主题、已经否决过哪些方向。
3. 记住约束与决定。不要用某种格式，某个结论已经确认，某份资料不可信。

超出这三类的记忆，例如跨用户的知识图谱、参数化记忆、隐式风格迁移，这个项目不需要。

## 二、参考的两个样板

Mem0 的做法：

- 从对话里抽取候选事实。
- 取最相似的若干条已有记忆。
- 让模型在 ADD、UPDATE、DELETE、NOOP 里选一个。
- 写入向量库，检索时按语义取 top-k。

Letta 的做法：

- 核心记忆块常驻上下文，数量有限，Agent 可以直接编辑。
- 归档记忆放在外部存储，需要时检索。
- 后台 dreaming 定期整理，合并重复、刷新核心记忆。

我们各取一半：

- 写入用 Mem0 的抽取加模型裁决。
- 读取用 Letta 的核心加归档两层。
- 整理用 Letta 的后台任务，但只做合并与衰减，不做复杂演化。

## 三、两层记忆

### 3.1 核心记忆

常驻在每次回答的上下文里，上限 20 条、约 600 token。放大模型从对话里确认过的偏好、约束、当前项目。核心记忆按重要度和最近使用时间排序，满了就挤掉最久没用的一条。

### 3.2 归档记忆

不常驻。回答前按问题检索 top-8，和资料片段一起进上下文。存的是具体决定、历史偏好、项目事实。

### 3.3 记忆类型

| 类型 | 例子 | 默认层 |
| --- | --- | --- |
| 偏好 | 回答先给结论，控制在 300 字以内 | 核心 |
| 约束 | 不要用表格，引用必须带页码 | 核心 |
| 项目上下文 | 正在写第三季度的调研报告 | 核心 |
| 决定 | 已经确认采用方案 B | 归档 |
| 事实 | 这份资料讲的是 2025 年的市场 | 归档 |

## 四、写入

### 4.1 来源

- 用户在对话里明确说出的偏好、约束、决定。
- 用户对回答的反馈，例如指出回答太长、引用不对。
- 用户修改产物时体现出的稳定偏好。

### 4.2 流程

```text
抽取候选
  -> 规范化文本
  -> 精确去重（文本哈希）
  -> 向量召回 top-5
  -> 模型裁决 ADD / UPDATE / DELETE / NOOP
  -> 写入并更新核心记忆
```

裁决规则：

- ADD：新建记忆。
- UPDATE：在目标记忆上新增版本，旧版本保留。
- DELETE：目标记忆标记为已删除，不物理删除。
- NOOP：已有等价记忆，直接结束。

### 4.3 自动与复核

用户明确说出的内容自动生效。从反馈或产物修改里推断出来的内容进入复核队列，用户在记忆页面确认后生效。

### 4.4 幂等

候选 id 作为幂等键，裁决结果落库后不再重算。同一段对话重放不会产生第二条记忆。

## 五、读取

```text
核心记忆（常驻，上限 20 条）
  + 归档检索（BM25 加向量，取 top-8）
  -> 合并去重
  -> 按 800 token 预算裁剪
  -> 注入提示词
```

三个接入点：

- 问答：核心记忆加与问题相关的归档记忆。
- 研究：核心记忆里的项目上下文与约束，研究计划生成时注入。
- 产物：核心记忆里的格式偏好，生成幻灯片或文档时注入。

提示词里的记忆带类型标签，例如 `[偏好] 回答先给结论`，不要求模型引用记忆 id，减少复杂度。

## 六、整理

每天凌晨跑一次，按 workspace 执行：

1. 合并重复：同类型、文本相似度高的记忆合并，保留最新版本。
2. 刷新核心：把最近频繁使用、置信度高的归档记忆提升到核心，把长期不用的核心记忆降回归档。
3. 衰减：超过 90 天没有被使用的归档记忆，置信度减半；低于阈值后不再参与检索，但不删除。

单次改动设上限，改动写审计日志，不执行物理删除。

## 七、数据模型

只动三张表，尽量复用现有结构。

```text
memory_item        记忆当前状态：类型、文本、层级、状态、置信、来源
memory_revision    版本历史：每次 UPDATE 新增一行
memory_candidate   候选与裁决：抽取结果、动作、目标、复核状态
```

关键列：

```sql
alter table memory_item
  add column memory_layer varchar(16) not null default 'ARCHIVAL',
  add column memory_type varchar(16) not null default 'PREFERENCE',
  add column source_ref_json json null,
  add column last_used_at timestamp null,
  add column use_count int not null default 0;

alter table memory_candidate
  add column decision varchar(16) null,
  add column decision_target_id varchar(64) null,
  add column decided_at timestamp null;
```

来源信息放在 `source_ref_json`，记录来源类型与来源 id，不做单独的证据表。

## 八、界面

记忆页面提供四件事：

- 按类型和层级列出记忆。
- 查看每条记忆的来源对话或产物。
- 编辑文本，编辑后生成新版本。
- 删除记忆，软删除。

复核队列单独一个标签页，展示待确认的推断记忆。

## 九、评测

自建 100 条用例，覆盖三类：

| 类型 | 例子 | 指标 |
| --- | --- | --- |
| 偏好召回 | 问一个普通问题，看是否遵守篇幅偏好 | 遵守率 |
| 更新 | 用户改了偏好后再问 | 更新准确率、陈旧率 |
| 约束 | 用户说不要用表格 | 违反次数 |

基线两条：无记忆、全量注入。指标看遵守率、更新准确率、注入 token 数。不追求论文级 benchmark，能证明记忆确实改善了回答即可。

## 十、实施

| 阶段 | 内容 | 工作量 |
| --- | --- | --- |
| 一 | 表结构、写入裁决、核心记忆注入 | 1 周 |
| 二 | 归档检索、三个接入点、记忆页面 | 1 周 |
| 三 | 后台整理、评测集、指标 | 1 周 |

三周可以完整演示：说一次偏好，下一次回答自动遵守；改一次偏好，旧版本保留、新版本生效；记忆页面能看到来源并手动删除。

## 十一、简历怎么写

- 为个人知识工作区设计两层记忆系统，核心记忆常驻上下文，归档记忆按需检索，接入问答、研究、产物三条链路。
- 实现 Mem0 式写入管线，模型在新增、更新、删除、忽略四种动作间裁决，配合精确去重、版本保留与幂等键。
- 实现每日后台整理，合并重复、调整核心与归档、衰减长期未用记忆，并用 100 条用例量化偏好遵守率与更新准确率。

技术难点讲三点：写入幂等与并发、核心记忆的预算控制、更新后的陈旧记忆清理。这三点和产品直接相关，也比堆概念更容易讲清楚。
