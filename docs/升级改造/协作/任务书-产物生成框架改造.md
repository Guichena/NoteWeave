## 3. 新增目录与位置

```
skills/                                   # 仓库根目录，每个产物一个目录
  <name>/SKILL.md
schemas/                                  # 仓库根目录，每种产物形态一份
  doc.v1.json  quiz.v1.json  cards.v1.json  tree.v1.json  table.v1.json  deck.v1.json  script.v1.json
workers/artifact-worker/app/pipeline/     # 新流水线
  skills.py          # 读取与校验 SKILL.md
  schemas.py         # 读取 kind Schema 并校验内容
  rules.py           # 契约规则注册表
  evidence.py        # 素材包：切句、编号、时间戳与关键帧 ID
  stages/            # gather.py  plan.py  draft.py  check.py  render.py
  renderers/         # markdown.py  pdf.py  pptx.py  interactive.py  table.py
  prompts/<kind>/<stage>.md
  runner.py          # 串联五个阶段
  projection.py      # 投影成现有 artifact-content-v1，供现有阅读页使用
workers/artifact-worker/templates/lecture-notes.tex   # 已放入：PDF 讲义的 LaTeX 模板
workers/artifact-worker/tests/pipeline/
workers/media-mcp/                        # M2 新建：音视频解析 MCP 服务
  pyproject.toml  Dockerfile  media_mcp/  tests/
frontend/src/features/artifacts/views/    # M4 新建：按形态的阅读视图
```

`skills/` 和 `schemas/` 由 Java 与 Worker 共同读取：

| 读取方 | 配置项 | 本地默认值 | 容器内 |
|---|---|---|---|
| Backend | `noteweave.artifact.skills-dir`（环境变量 `NOTEWEAVE_SKILLS_DIR`） | `../skills`（测试时工作目录为 `backend/`） | `docker-compose.yml` 把 `./skills` 只读挂载到 `/app/skills` |
| Worker | `NOTEWEAVE_SKILLS_DIR`、`NOTEWEAVE_SCHEMAS_DIR` | 按 `app/` 位置推算到仓库根目录的 `skills/`、`schemas/` | 同上，挂载到 `/app/skills`、`/app/schemas` |

## 5. 里程碑任务

### M1 SKILL.md 与五段流水线

1. 在 `schemas/` 写 `doc`、`quiz`、`cards`、`tree`、`table` 五份 Schema，事实性文本字段带 `anchors`。
2. 在 `skills/` 写 M1 的 11 个产物：`briefing`、`study-guide`、`blog-post`、`faq`、`timeline`、`custom-report`、`course-notes`、`quiz`、`flashcards`、`mind-map`、`data-table`。旧产物名写进 SKILL.md 头部的 `aliases`，例如 `briefing` 的 `aliases: [report_draft, structured_note, reading_digest, video_summary, audio_minutes]`，保证旧版本再生成能找到新 Skill。对应关系见 12 号文档第 9.1 节。
3. 实现 `app/pipeline/` 的加载、校验、五个阶段、渲染器（Markdown、交互数据、表格）、投影和提示词模板。规则注册表实现 12 号文档第 4.4 节中 M1 用到的规则。
4. `app/runner.py` 入口按 `NOTEWEAVE_ARTIFACT_PIPELINE` 路由。完成载荷新增 `ir`、`evidence`、`pipeline_stats`，同时给出 `artifact-content-v1` 投影。
5. Backend：`ArtifactSkillCatalogService` 改读 `skills/`，`/api/v2/skills` 返回 `kind`，创建任务时校验 Skill 名称、别名与选项；`ArtifactCandidateVerificationPolicy` 增加新载荷分支。补对应测试。
6. Frontend：产物按钮来自 `/api/v2/skills`；思维导图改按 `kind` 判断。

验收：新流水线产物能在现有阅读页显示；在 `skills/` 新增一个 SKILL.md 后不改代码即可在前端出现并生成，这一过程写成一条自动化测试；三端测试通过。

### M2 音视频解析 MCP 服务

1. 新建 `workers/media-mcp/`，用 MCP Python SDK 以 Streamable HTTP 方式提供 `get_video_info`、`parse_video`、`parse_media`，输入输出见 12 号文档第 7 节。
2. 转写：B 站有官方字幕时用字幕（迁移 `get_bilibili_subtitle` 的逻辑），否则用 `faster-whisper`。
3. 关键帧：ffmpeg 场景检测粗筛，`imagehash` 计算感知哈希，与上一张保留帧的汉明距离小于阈值则丢弃，阈值走配置 `MEDIA_MCP_PHASH_THRESHOLD`；对保留帧做 OCR 和画面描述，迁移 `observe_staged_frame` 的实现。
4. 转写与关键帧两条线并行，最后按时间轴对齐，输出带 `stats`（候选帧数、保留帧数、转写来源）。
5. `docker-compose.yml` 新增 `media-mcp` 服务，挂载 whisper 模型卷，只接入它需要的网络。
6. Backend：`SourceController` 新增 `POST /api/v2/workspaces/{workspaceId}/sources/links/preview`（返回标题、时长、分 P）和 `POST /api/v2/workspaces/{workspaceId}/sources/links`（提交链接和所选分 P）；解析任务沿用转写派发和回调链路；回调保存关键帧到 MinIO，按段生成带时间字段的 `DocumentElement`，再进入现有切片与索引流程。需要的表结构变化用 V200 起的迁移。链接只接受 B 站域名。
7. Worker：`source_transcription.py` 改为通过 HTTP 调用 `parse_media`；新增视频链接解析任务的处理，调用 `parse_video`。
8. Frontend：资料栏增加粘贴链接，先调用预览接口，多 P 视频显示分 P 选择。

验收：B 站链接解析成图文文档并入库，问答能检索到视频内容；解析结果中有去重前后的帧数；上传音视频走新服务后原有转写测试通过。

### M3 幻灯片、视频 PPT 与 PDF 讲义

1. 写 `schemas/deck.v1.json`，以及 `skills/slide-deck`、`skills/video-deck`、`skills/lecture-notes-pdf` 三个 Skill。
2. Backend 新增内部接口 `GET /internal/worker/artifact-tasks/{taskId}/frames/{frameId}`，校验投递令牌与任务资料范围后返回关键帧图片，写法参照 `ArtifactTaskRetrievalController`。
3. PPTX 渲染器：改造 `render_original_video_deck` 读取 DECK 内容，配图通过上一步接口获取；没有配图的页面使用版式模板。
4. PDF 渲染器：使用 `workers/artifact-worker/templates/lecture-notes.tex` 和 Worker 镜像中已有的 XeLaTeX 编译，插入关键帧图片，图片下方注明视频时间区间。

验收：普通资料能生成幻灯片；同一视频能生成带原帧的 PPT 和插图 PDF 讲义，文件可在前端下载。

### M4 前端按形态展示

1. 版本详情接口返回 `ir`，对应 Backend 的版本详情响应类增加字段。
2. 在 `frontend/src/features/artifacts/views/` 新增测验作答、闪卡翻面、数据表、幻灯片预览视图；思维导图沿用现有组件。
3. `ArtifactReader.tsx` 按 `kind` 选择视图，DOC 继续使用现有渲染。

验收：每种形态都有对应的阅读视图，前端测试和 `tsc -b` 通过。

### 7.1 两条线之间的接口约定

1. **视频片段的时间与关键帧字段**：B 在资料切片上保存 `part`、`start_ms`、`end_ms`、`frame_ids`，以及来源链接；关键帧的说明和 OCR 文字写进切片正文，保证检索能命中。A 在 `/internal/worker/artifact-tasks/{taskId}/retrieve` 的返回中带出这些字段，供素材包使用。
2. **关键帧读取**：B 提供 Java 服务方法，按工作台、资料 ID、帧 ID 读取关键帧图片，返回图片内容和类型；A 在 M3 用它实现 `/internal/worker/artifact-tasks/{taskId}/frames/{frameId}`。
3. **旧文件的删除**：B 迁移 `video_frame_capture.py`、`video_frame_observation.py`、`bilibili_render_pdf_server.py` 中的逻辑时只复制不删除，旧文件统一由 A 在 M5 删除。
4. 接口细节有变化时，由提出方在 12 号文档实施记录自己的小节里写明，并通知用户。

### 7.2 共享文件
