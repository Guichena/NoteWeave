## 问答与检索（C 线实现，A 线前端）


`INSUFFICIENT` 时前端在回答上方提示资料中没有足够信息，`PARTIAL` 时提示只能回答一部分。

Wiki 模式的证据项新增 `graph_path: ["种子页标题", "中间页标题", "扩展页标题"]`，只有通过图扩展得到的页面才有，状态：已实现。空路径省略该字段。

### 后端内部接口：供产物素材检索调用（C 线提供，B 线调用）

B 线 4B 的 `POST /internal/worker/artifact-tasks/{taskId}/retrieve` 不直接依赖 `QaHybridRetriever` 的内部细节，而是调用 C 线提供的服务。接口状态：已实现。实现类是 `com.noteweave.chat.HybridScopedPassageSearch`，放在 chat 包是为了避免 `retrieval.qa` 和 `QaHybridRetriever` 循环依赖。query 必须已经是独立自然语言。Provider 不可用时返回 `degraded`，不抛异常。

```java
package com.noteweave.retrieval.qa;

public interface ScopedPassageSearch {
    /** 在给定资料范围内检索片段；query 是一句独立的自然语言查询，不需要对话改写。 */
    Result search(String workspaceId, java.util.Set<String> sourceIds, String query, int limit);

    record Passage(String chunkId, String sourceId, String sourceSnapshotId, int chunkNo,
                   String title, String location, String content, double score) { }

    record Result(java.util.List<Passage> passages, boolean degraded, java.util.List<String> degradationReasons) { }
}
```

C 线在 3A 中先提供一个基于现有混合检索的实现；B 线开始 4B 时如果 3A 还没合并，可以先写一个临时实现放在 B 自己的目录里，3A 合并后删除。

## 产物（B 线实现，A 线前端）

### 4A 意图编译诊断

现有产物详情的 `runtime_trace` 新增 `intent_compilation_trace`（`purpose / method / status / llm_calls / degradation_reasons / validation_errors`）与 `llm_usage`（当前、检查点既有和累计调用次数、总调用上限、token 计数），状态：已实现。意图诊断用于通用执行计划；专用视频入口仍读取宿主冻结的知识计划。旧结果或未发生模型调用的专用结果缺少这些字段时返回空对象。token 计数来自当前客户端收到的实际响应，不含检查点恢复前未保存的 token。契约检查仍在 `output_contract_trace.action_checks`，每项的 `metadata` 增加 `rule_name / level / backtrack_to`；`ASSERT` 失败阻止提交，`SUGGEST` 失败记警告。`backtrack_to` 本阶段记录诊断，实际生成修复在 4D 实现。公开 Skill 列表不返回输出契约或规则实现。

### 4B 任务范围内素材检索

`POST /internal/worker/artifact-tasks/{taskId}/retrieve`，状态：已实现。该路径不加工作区 API 前缀，使用内部服务认证与当前 outbox 投递令牌。请求 `{query: string, limit: int}`，query 为 1 至 2000 字符的独立查询，limit 为 1 至 20；资料及快照范围由宿主任务提供，请求不能扩大范围。

响应使用 `ApiResponse`，data 为 `{task_id, input_snapshot_id, passages: [{chunk_id, source_id, source_snapshot_id, chunk_no, title, location, content, score}], degraded, degradation_reasons}`。只返回冻结快照内仍可读的片段；正文从对应数据库快照读取，单次正文总字节上限为 65536。没有资料时返回空列表，不执行全工作区检索。索引不可用、仅覆盖新快照或片段超出预算时返回降级原因，Worker 使用本地冻结内容做 BM25 检索。认证失败、旧投递、资料撤权及不可重放任务必须停止执行，不允许以本地内容绕过。

Worker 对每个大纲章节执行 `RETRIEVE`，查询由用户要求、重点及章节组成，正文预算按章节分配，片段去重；完成结果的 `generation_trace.retrieval` 保存查询、方法、预算、命中标识和降级原因。专用视频产物沿用冻结知识计划，不另查工作区索引。现有 QA 通道最多提供 6 条候选及 8000 字符；limit 是响应上限。旧恢复入口缺少当前投递令牌时只做本地冻结内容检索，最终发布仍由宿主完整资格门控。

### 4C 类型化节点诊断

现有产物详情的 `runtime_trace.node_traces[]` 新增 `node_kind / purpose / prompt_recipe_id / llm_calls / validation_errors / input_fields / output_fields / execution_trace`，状态：已实现。`node_kind` 为 `LLM_STEP / RETRIEVE / VERIFY / REPAIR / TOOL`；`purpose` 是实际模型调用标识，普通生成节点使用 `artifact.node.<runtime_skill_key>`，无模型调用的节点为空字符串。`llm_calls` 记录该节点实际请求次数，包含一次输出校验重试；缺少模型、调用失败或两次输出不合规时停止执行，不能返回成功候选。

`input_fields` 与 `output_fields` 只列实际投影和返回的图状态字段名，节点无法读取未声明字段。`validation_errors` 保留输出校验的路径和约束诊断；`execution_trace` 保存执行状态、失败原因和节点信息，不包含完整宿主权限输入。旧节点记录缺少新增字段时，字符串为空字符串、次数为 0、列表和对象为空。

Worker 完成结果中的 `generation_trace.mode` 为 `LLM_NODE_GRAPH`，新增 `purposes / llm_calls / state`，保留 `provider / model / generated_section_count / source_count / retrieval`。`source_count` 为去重后的检索片段数；图调用总数不含独立的 `artifact.compile_intent`，累计预算仍由 `llm_usage` 记录。`state` 可包含 `facts / normalized_facts / bullets / verification / repair_trace`，用于核对简历事实、连续原文引文和要点引用的事实 ID，不包含完整任务或权限输入。现有版本详情的类型化 `generation_trace` 沿用既有字段，扩展检索和图状态保存在完成 payload 中。

`verification_status` 表示真实节点结果：普通执行为 `PASS`，检索降级可为 `WARN`，`VERIFY` 按契约为 `PASS / WARN / FAIL`。当前 `REPAIR` 没有失败项时为 `SKIPPED`，有失败项时为 `NOT_RUN` 并阻止候选提交；`repair_trace` 保存 `status / reason / failed_checks`。本阶段不生成修复正文、不补齐数量，实际修复轮次和陈述级证据指标按 4D 约定实现。专用视频产物保持冻结执行入口，通用图未绑定的 `TOOL` 必须拒绝。公开 Skill 目录仍只返回元数据，不暴露提示词或完整节点 Schema。

### 4D 校验与修复

产物版本详情顶层 `verification` 与 `runtime_trace.verification` 使用同一份最终校验结果，状态：已实现。保留原 `status / passed_checks / repaired_checks / failed_checks / warnings`，新增字段如下：

```json
{
  "verification": {
    "status": "PASS",
    "contract_status": "PASS",
    "evidence_status": "PASS",
    "statement_verification_version": "artifact-statement-verification.v1",
    "verification_mode": "TYPED_GRAPH_STATEMENTS",
    "llm_calls": 2,
    "repair_rounds": [],
    "citation_recall": 1.0,
    "citation_precision": 1.0,
    "sections": [{
      "heading": "章节标题",
      "support": "SUPPORTED",
      "chunk_ids": ["真实片段标识"],
      "statements": [{
        "statement_id": "statement-标识",
        "text": "待核对的完整陈述。",
        "label": "SUPPORTED",
        "sufficiently_supported": true,
        "assessment_status": "ASSESSED",
        "term_coverage": 0.9,
        "failure_reasons": [],
        "citations": [{
          "chunk_id": "真实片段标识",
          "label": "SUPPORTED",
          "quote": "对应片段中的连续原文",
          "assessment_status": "ASSESSED"
        }]
      }]
    }]
  }
}
```

陈述标签为 `SUPPORTED / CONTRADICTED / UNSUPPORTED / NON_FACTUAL / UNDETERMINED`；逐引用标签另含 `PARTIAL`，章节 `support` 为 `SUPPORTED / PARTIAL / UNSUPPORTED / NOT_RUN`。`assessment_status` 区分模型完成的 `ASSESSED`、受限的原文复制判断 `EXACT_COPY` 和未完成的 `NOT_RUN`。仅 `SUPPORTED` 可以声明 `sufficiently_supported=true`，且必须至少有一条充分支持的真实引用；多个 `PARTIAL` 引用不能自动合并为充分支持，含明确矛盾引用的陈述也不能充分支持。

Worker 按章节批量调用 `artifact.node.statement_support_judge`，模型必须完整返回请求中的全部陈述及每条陈述声明的全部引用，不能遗漏、重复或新增标识；每条返回引文必须是对应片段的非空连续原文。未知引用、标题与片段 ID 的歧义、同一 ID 对应不同正文、超出章节素材范围、模型缺失、调用失败或两次不合规均保留未完成诊断。必需证据的任务不能据此提交成功候选。通用生成的共同 IR 继续以 `source_refs` 展示资料标题，真实片段 ID 与逐陈述引用保存在本段诊断中，不增加共同 IR 字段。

`citation_recall` 为充分支持的事实陈述数除以全部事实陈述数；无法判断的陈述保留在分母，`NON_FACTUAL` 不计入该分母。`citation_precision` 为有效支持引用对数除以全部声明的陈述与引用对数，`SUPPORTED / PARTIAL` 引用计有效支持，未知引用及非事实性陈述的引用保留在分母，后者不计有效支持。没有对应分母时指标为 `null`。`term_coverage` 仅作词项覆盖诊断，不替代证据判断。

`repair_rounds[]` 最多两项，全图共享轮次预算。每项保存 `round / status / failed_checks / repaired_sections / backtrack_nodes / remaining_failed_checks / validation_errors`，其中 `repaired_sections` 只列实际改动或补入的必需章节，不代表该轮已经通过。`artifact.node.section_repair` 只接收失败章节、具体陈述诊断、分配给这些章节的原文及生成约束；输出须恰好覆盖全部失败或缺失必需章节，不能修改已通过章节。简历亮点失败时必须同时返回与既有事实一致的要点；其他章节失败时不能改写已通过的要点。每轮重新验证，后置变换也只能使用剩余轮次；模型输出校验的单次重试与实际判断、修复调用均计入现有预算。无失败项为 `SKIPPED`，通过修复为 `REPAIRED`，两轮仍失败为 `FAILED`，模型不可用或预算耗尽为 `NOT_RUN` 并拒绝提交。

冻结视频产物使用 `verification_mode=FROZEN_VIDEO_STATEMENTS`，以冻结字幕和帧观测条目执行同一陈述判断；失败时拒绝候选，不改知识计划、原帧或正文。当前目录的通用 Candidate 必须携带完整新诊断，Backend 在版本提交前校验最终状态、全部正文章节、陈述状态、引用指标及连续的最多两轮修复记录。历史结果和旧专用 Candidate 保持兼容读取或提交规则，但主动携带 4D 字段时仍须通过相应校验。旧结果缺失的指标及新增标量为 `null`，集合为空，不生成虚假的 `PASS`。语义判断和局部修复不新增 HTTP 路径或数据库迁移。

### 4E 按章节生成

状态：已实现，自动化全量验证结果由阶段交接记录汇总；不新增 HTTP 路径、数据库迁移或生产配置。

Skill 目录顶层 `generation_mode` 为 `SINGLE / SECTIONED`，只控制执行策略，与配方中的同名元数据分别保留。模式固化在 Worker 的 `execution_plan.generation_mode`；旧目录发布缺模式时默认 `SINGLE`，非法模式拒绝。新自定义动作继承章节图时固化 `SECTIONED`，显式选择旧单次生成图时保留 `SINGLE`。内置 `study_guide / quiz_pack / wiki_page` 使用 `SECTIONED`，其他产物保留 `SINGLE`，三个专用视频产物仍使用原冻结入口。学习指南采用独立章节图，测验与 Wiki 保留原图标识及契约回退节点。

章节图顺序为 `digest → outline → write/design → consistency → cite → guard → repair`。模型生成的 `chapter_plan` 必须完整保留冻结标题与顺序，各章记录 `section_id / heading / key_points / chunk_ids`；片段标识限于本章素材包。章节写作只接收这些片段在 `selected_chars` 范围内的真实原文前缀，不能读取其他章节素材或公共源表中的更长内容。缺失、歧义或原文冲突会停止执行。

章节写作和独立引用采用有界的在途并发任务，按冻结章节顺序组装结果。已知客户端记录线程独立的实际调用数，累计预算通过原子请求预留限制；未知客户端缺少此计数能力时串行执行，并在对应节点诊断的 `degradation_reasons` 中记录 `ARTIFACT_SECTIONED_THREAD_CALL_ACCOUNTING_UNAVAILABLE`。失败后停止派发、取消未开始的任务并等待已开始请求结算，部分结果不作为成功产物提交。每次结构校验的单次重试及后续引用、判断、修复调用均计入现有预算。

写作节点只生成正文，`cite` 节点只选择真实片段引用并更新 `source_refs`，不能改正文。独立的 `citation_assignments` 按章节保存 `heading / chunk_ids`；证据判断明确使用 `CHUNK` 解释这些标识，避免同名资料标题造成歧义。共同 IR 保留现有结构，`source_refs` 仍展示资料标题，精确片段标识保存在分配与逐陈述诊断中。

全文一致性按段落执行检查、一次局部修改和复查，只处理 `TERM_INCONSISTENCY / DUPLICATE` 对应的问题段落，未判定有问题的段落保持原样。模型未执行或输出不合规时停止生成；完成判断但复查仍有问题时进入已有 4D 最多两轮的共享修复闭环。纯一致性失败仍不得改动未判问题段落和原空行分隔，可删除已判重复的段落正文。每个实际修复轮显式刷新失败章节引用，即使正文未变也不能使用该章旧引用缓存，随后重做一致性与陈述证据判断。已通过章节保持缓存，正文或素材变化后重新判断。

Worker 完成载荷的 `generation_trace.state` 新增 `chapter_plan / citation_assignments / consistency_trace`；对应节点诊断保存实际子步骤、调用次数、失败章节及串行降级原因。最终 `verification` 与版本详情读取沿用 4D 约定，图状态扩展保存于完成载荷。公开 Skill 目录继续只返回元数据，不暴露生成策略的完整图、提示词或节点 Schema。

已接受的旧 4D LF、CRLF 目录摘要及旧学习指南默认图可以显式迁移到章节图，保留冻结意图、输入、权限、等待状态和既有调用预算。自定义图和配方保持原声明；内置 Provider 仅增加新学习指南图支持，不扩大自定义能力权限。质量评测按本次用户要求暂缓，自动化验证继续执行。

## 资料上传与解析（B 线实现，A 线前端）

### 5A 断点续传、秒传、多格式

| 接口 | 说明 | 状态 |
|---|---|---|
| `GET /api/v2/uploads/{uploadId}` | 返回 `{upload_id, status, total_chunks, chunk_size, uploaded_chunk_indexes: [int]}`。`status` 沿用现有取值：`UPLOADING` 时前端只补传不在 `uploaded_chunk_indexes` 中的分片；`COMPLETED` 时前端直接调用完成接口取结果（完成接口对已完成的会话幂等返回）；会话不存在或已过期返回 404，前端重新上传 | 已实现 |
| `POST /uploads` 请求体新增可选 `sha256`（小写十六进制，对整个文件计算） | 同一工作台已有同样内容的资料时响应新增 `instant: true`、`source_id`，以及与完成接口相同的 `task_id`、`parse_status`、`index_status`；资料已处理完成、没有新任务时 `task_id` 为空字符串。前端收到 `instant` 后不再上传分片 | 已实现 |
| `GET /uploads/formats` | 返回 `[{extension: "pdf", mime_type: "application/pdf"}]`，扩展名不带点、小写。前端据此生成文件选择器的 accept、校验文件和展示格式名；接口不可用时使用前端内置列表 | 已实现 |

内部结构解析使用独立 Parse Worker 的 `POST /internal/parse`，请求体为 `application/octet-stream`，查询字段为 `workspace_id / source_id / snapshot_id / file_name / mime_type / sha256 / max_chars`，内部鉴权头为 `X-NoteWeave-Internal-Token`。服务只解析本次上传的本地文件，不接收URL，不获取文件声明的外部资源。默认单文档并发，超额请求返回429；请求流超过大小上限或真实哈希不匹配时拒绝。Java发送已下载的原件文件流，响应必须与冻结身份、哈希和MIME一致。

响应使用 `schema_version=1`，包含原请求身份、`sha256 / mime_type / markdown / page_count / elements / parser / truncated / warnings`；`parser` 为 `DOCLING`。每个元素包含 `element_type / text / page / bbox / heading_level`，类型为 `TITLE / SECTION_HEADER / TEXT / TABLE / CAPTION / FORMULA / CODE / LIST_ITEM / FOOTNOTE / PICTURE`。未知页码、坐标或标题级别为 `null`，坐标记录 `left / top / right / bottom / coord_origin`，原点为 `TOPLEFT / BOTTOMLEFT`，不填虚构零值。多个真实定位的原子元素保留首个页码和坐标并告警，全文只保留一次。

字符或元素数量达到上限时只在完整元素边界截断并返回 `truncated=true` 和告警，表格、图注与公式不能截半；若没有任何可用正文则返回错误。Java在同一快照下保存结构结果，切片沿用真实结构与坐标。解析服务不可用或响应无效时，PDF与纯文本采用已有解析器降级并记录原因；其他格式真实失败。按页OCR来源标记留到5D，真实质量评测按用户要求暂缓。

### 5D OCR 来源标记

资料片段和引用定位新增 `text_origin: TEXT_LAYER | OCR`，OCR 时附 `ocr_confidence`（0 到 1），状态：约定。前端目前在回答证据接口 `GET /answer-runs/{runId}/evidence` 的每条证据上读取这两个字段，置信度低于 0.8 时提示用户核对原文。
