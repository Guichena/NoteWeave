# NoteWeave v2 名词口径与汇报词表

## 1. 用途

这份文档用于统一 NoteWeave v2 在架构设计、产品汇报、简历表达和后续开发中的核心名词，避免同一概念在不同文档里出现多套说法。

原则：

- 对外汇报优先用中文主名词，必要时补英文关键词
- 产品名、能力名、技术模块名分开表达
- 同一个对象只保留一套正式术语

## 2. 产品层

- `研究工作台`
  对外主口径。表示一个用户围绕某个研究主题建立的资料、聊天、Wiki、Note、产物与研究任务容器；内部实体可叫 `Workspace`。

- `问答模式`
  对外可继续使用的产品名，更准确的架构口径是 `问答链路`。英文可写 `Ask Mode`。

- `Note 模式`
  对外可继续使用的产品名，更准确的架构口径是 `Note 链路`。它是在同一聊天界面中面向“边问边整理”的回答逻辑，不单独强调另一套 Note 资料库。

- `Wiki 模式`
  对外可继续使用的产品名，更准确的架构口径是 `Wiki 链路`。它是在同一聊天界面中优先调用 Wiki 页面、页面链接、索引和来源回链的回答逻辑；历史文档中的 `Full Wiki` 统一收敛到这里。

- `三种聊天回答链路`
  架构主口径。表示 `问答 / Note / Wiki` 是同一聊天前端背后的三套回答逻辑，而不是三个割裂页面或三个独立产品。

- `溯源式 Note 问答链路`
  Note 链路的对外解释口径。强调它仍然回答用户问题，但会额外通过候选资料卡、原文窗口和摘录卡片把答案沉淀成可编辑的结构化笔记。

- `结构化检索增强的 Note 链路`
  Note 链路的推荐汇报口径。用于说明其参考 NotebookLM 式 Source-grounded RAG：以当前资料集合为检索边界，将召回片段、原文定位和问题共同交给模型生成带引用回答；同时结合 Marginalia 的结构化检索漏斗：先定位候选资料，再读取原文窗口，最后沉淀为可追溯的结构化笔记。

- `深度研究`
  产品入口名。英文可写 `Deep Research`。它是独立系统能力，不是第四种日常模式。

- `右侧产物栏`
  产品入口名。英文别名 `Artifact Actions Rail`。对外不优先使用“按钮栏”“动作栏”等多套说法。

- `共享项目级资料池`
  对外主口径。表示用户上传文件、被确认的研究报告与被纳入的高价值来源，共用同一套研究工作台资料底座。

## 3. 能力层

- `Deep Research 智能体`
  用于项目亮点、面试和架构讲解。

- `Deep Research Engine`
  用于技术架构中描述后端执行引擎，不直接作为产品名。

- `TAS-Informed Verification-Centric Research Harness`
  用于深度研究能力升级后的主亮点和架构表述，强调系统以 TAS 思路组织研究对象，以验证驱动研究推进，以受控分支和停止契约保证长任务可靠性。

- `Interaction-Scaled Research Loop`
  用于深度研究详细讲解，表示系统提升的重点不是单纯拉长推理链，而是提高每一次 `Search / Read / Extract / Verify` 交互的有效性。

- `Table-as-State`
  用于深度研究详细讲解，表示 `Research Table` 不只是结果展示表，也是执行状态层。

- `Dual Verifier`
  用于深度研究详细讲解，表示系统同时具备局部结论验证和全局研究进度验证两层 verifier。

- `Counterfactual Branching`
  用于深度研究详细讲解，表示当主路径过强或来源过于单一时，系统会主动开反向分支做反证探索。

- `Evidence-Gated Progress`
  用于深度研究详细讲解，表示研究推进由证据和验证状态门控，而不是由模型主观完成感驱动。

- `Stop Contract`
  用于深度研究详细讲解，表示研究 run 从开始就显式声明完成条件、部分完成条件和停止条件。

- `Premature Commitment Guard`
  用于深度研究详细讲解，表示系统避免过早锁死到单一路径或单一来源的保护机制。

- `受控式产物生成 Agent`
  用于项目亮点和能力描述，表示右侧产物栏背后的生成能力。

- `Artifact Runtime`
  用于技术架构中描述受控式产物生成的执行平面，不直接替代产品名。

- `Production Action`
  正式术语，表示“报告生成”“测验生成”“FAQ 生成”等统一产物动作抽象。

- `Schema-Gated Skill Graph Runtime`
  用于产物生成能力升级后的亮点和架构表述，强调执行前先形成结构化计划，再按技能子图和能力策略受控执行。

- `Style Profile`
  用于产物生成详细讲解，表示用户可配置的写作风格、结构偏好、篇幅和受众约束。

- `Skill Graph`
  用于产物生成详细讲解，表示 Skill 不再只是平铺列表，而是可展开的技能子图。

- `Capability Union Policy`
  用于产物生成详细讲解，表示用户自定义 MCP 时，对能力组合风险做统一权限判断的策略层。

## 4. 资料与记忆层

- `研究过程资产`
  正式术语。表示搜索结果、网页快照、抓取文本、证据片段、检查点与运行轨迹，默认只服务当前 Research Run，不直接进入主检索链路。

- `确认后资料成果`
  正式术语。表示最终研究报告、被引用的关键网页快照、被用户确认纳入的来源等高价值内容，可以进入共享资料池。

- `记忆晋升机制（Graduated Memory）`
  对外主口径，强调长期知识不是直接堆积聊天历史，而是经过门控晋升。

- `上下文信号（Context Signal）`
  正式术语，表示来自会话、研究轨迹、反馈等的弱信号。

- `记忆候选（Memory Candidate）`
  正式术语，表示待判断、待晋升的记忆对象。

- `长期记忆对象（Memory Object）`
  正式术语，表示通过门控晋升后进入长期复用层的记忆对象。

- `新颖性门控（Novelty Gate）`
  正式术语，表示是否值得写入长期记忆的第一道门。

- `任务邻域验证（Task Neighborhood Validation）`
  正式术语，表示候选内容是否能在相邻任务簇中复用的第二道门。

## 5. 实现层

- `Java 主系统`
  正式术语，用于描述承接研究工作台、三种聊天链路、业务真源、任务编排与结果回写的主系统。

- `Python Research Worker`
  正式术语，用于描述承接 `Deep Research` 执行循环的独立研究执行器。

- `Python Artifact Worker`
  正式术语，用于描述承接右侧产物栏背后生成执行链路的独立产物执行器。

推荐统一表述：

- `模式层在 Java，智能执行层在 Python`
- `Java 负责业务真源，Python 负责智能执行循环`

## 6. 推荐替换

- `Full Wiki` -> `Wiki 模式`
- `Workspace` -> 对外写 `研究工作台`，内部实体可保留 `Workspace`
- `三种主模式` / `用户可见工作模式` -> `三种聊天回答链路`
- `右侧产物按钮栏` / `右侧产物动作栏` -> `右侧产物栏`
- `长期 Memory` -> `长期记忆`
- `Promoted Memory` -> `长期记忆对象（Memory Object）`
- `Artifact Memory` -> `记忆候选` 或 `已确认产物形成的稳定记忆来源`

## 7. 一句话总口径

`NoteWeave v2 是一个参考 NotebookLM 形态的研究工作台：用户可以在同一工作台中上传资料、进行多次聊天，并在每个聊天里选择问答、Note、Wiki 三种回答链路；深度研究和右侧产物栏作为独立任务能力存在，正式产物可以回流资料池，并通过记忆晋升机制沉淀为可长期复用的知识。`
