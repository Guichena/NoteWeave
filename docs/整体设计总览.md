# NoteWeave v2 整体设计总览

## 1. 目的

这份文档只回答两个问题：

1. NoteWeave v2 整体上要做成什么
2. 整体设计文档应该先看哪些

它不负责落代码细节，不展开表结构、接口细节、任务编排实现。

## 2. 整体设计范围

整体设计关注的是：

- 产品形态
- 系统边界
- 聊天链路与执行引擎划分
- 核心对象关系
- 能力边界
- 亮点叙事
- 汇报与面试口径

整体设计不负责：

- controller / service / repository 如何写
- MySQL DDL
- Kafka topic 细节
- Redis key 设计
- MinIO bucket 设计
- ES index 设计
- 具体类名与包结构

## 4. 这套整体设计的最终口径

当前统一口径如下：

- 1 个基本产品单位：`研究工作台`
- 3 个聊天回答链路：`问答`、`Note`、`Wiki`
- 1 个全局重型功能入口：`Deep Research`
- 1 个右侧产物栏：`Artifact Actions Rail`
- 1 个受控异步执行平面：`Artifact Runtime`
- 1 套门控式长期记忆机制：`Graduated Memory`
- 1 套能力扩展方式：`内置能力层 + 用户自有 MCP 连接`

在工程实现上，再补一条关键口径：

- `Java` 主系统承接研究工作台、三种聊天链路、业务真源、任务编排与结果回写
- `Python Research Worker` 承接 `Deep Research`
- `Python Artifact Worker` 承接右侧产物栏背后的生成执行链路

其中两个核心升级是：

1. `TAS-Informed Verification-Centric Research Harness`
2. `Schema-Gated Skill Graph Runtime`
3. `共享项目级资料池 + 门控式资料回流`
