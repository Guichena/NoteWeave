# NoteWeave v2 最小接口契约

## 1. 定位

这份文档只锁定“开始写代码必须先统一的接口边界”。

它不追求把所有未来接口一次写完，而是只覆盖三类最小契约：

1. 前端到 Java 主系统
2. Java 主系统到 Python Worker
3. 前端任务进度与结果回写

它承接：

- [系统总体设计与功能总表](D:/java-projects/NoteWeave-v2/docs/系统总体设计与功能总表.md)
- [技术架构详细设计](D:/java-projects/NoteWeave-v2/docs/技术架构详细设计.md)
- [代码落地路线与开工清单](D:/java-projects/NoteWeave-v2/docs/代码落地路线与开工清单.md)

## 2. 契约总原则

### 2.1 三种聊天链路共用一套聊天接口

前端虽然有 `问答 / Note / Wiki` 三种回答链路，但不拆成三套完全独立 API。

统一使用：

- 一个会话创建接口
- 一个消息发送接口
- 一个流式结果接口

链路差异只体现在 `answer_mode`。

### 2.2 Deep Research 与右侧产物栏统一走异步任务

这两类能力都必须：

1. 立即返回 `task_id`
2. 通过任务状态接口或 SSE 查看进度
3. 完成后由 Java 主系统写入正式业务对象

### 2.3 Worker 不直写业务真源

Python Worker 负责执行，不负责直接改 MySQL 主业务表。

最小实现约束：

1. Java 主系统通过 Kafka 下发任务
2. Worker 通过内部 HTTP 回传进度和结果
3. Java 主系统负责最终落库、建版本、建引用、回写资料池

### 2.4 保存为资料必须显式触发

Research 报告和 Artifact 结果都不能静默进入资料池，必须走显式接口。

## 3. 前端到 Java 主系统

### 3.1 创建工作台

`POST /api/v2/workspaces`

请求体最小字段：

- `name`
- `description`

返回最小字段：

- `workspace_id`
- `name`
- `status`
- `created_at`

### 3.2 创建上传事务

`POST /api/v2/workspaces/{workspaceId}/uploads`

请求体最小字段：

- `file_name`
- `file_size`
- `mime_type`
- `chunk_size`
- `total_chunks`

返回最小字段：

- `upload_id`
- `status`
- `chunk_size`
- `total_chunks`

### 3.3 上传分片

`PUT /api/v2/uploads/{uploadId}/chunks/{chunkIndex}`

请求：

- 二进制分片
- 请求头带 `Content-MD5`

返回最小字段：

- `upload_id`
- `chunk_index`
- `accepted`

### 3.4 完成上传

`POST /api/v2/uploads/{uploadId}/complete`

返回最小字段：

- `source_id`
- `task_id`
- `parse_status`
- `index_status`

说明：

- 这里返回的是“资料已建档 + 解析任务已创建”
- 不是“资料已经可检索”

### 3.5 创建会话

`POST /api/v2/workspaces/{workspaceId}/conversations`

请求体最小字段：

- `title`
- `conversation_type`

返回最小字段：

- `conversation_id`
- `title`
- `conversation_type`
- `created_at`

### 3.6 发送聊天消息

`POST /api/v2/conversations/{conversationId}/messages`

请求体最小字段：

- `content`
- `answer_mode`
- `client_request_id`

`answer_mode` 取值：

- `QA`
- `NOTE`
- `WIKI`

返回最小字段：

- `message_id`
- `assistant_request_id`
- `stream_url`

说明：

- 聊天结果默认通过流式接口返回
- 三种链路只改 `answer_mode`，不改整体交互模型

### 3.7 聊天流式结果

`GET /api/v2/chat/requests/{assistantRequestId}/stream`

协议：

- `SSE`

事件类型最少包含：

- `chat.delta`
- `chat.citation`
- `chat.completed`
- `chat.failed`

### 3.8 启动 Deep Research

`POST /api/v2/workspaces/{workspaceId}/research-runs`

请求体最小字段：

- `question`
- `profile`
- `context_snapshot_id`

返回最小字段：

- `research_run_id`
- `task_id`
- `status`

### 3.9 启动右侧产物生成

`POST /api/v2/workspaces/{workspaceId}/artifact-jobs`

请求体最小字段：

- `action_key`
- `style_profile_key`
- `context_snapshot_id`

返回最小字段：

- `artifact_job_id`
- `task_id`
- `status`

### 3.10 查询任务状态

`GET /api/v2/tasks/{taskId}`

返回最小字段：

- `task_id`
- `task_type`
- `task_status`
- `progress_phase`
- `progress_message`
- `result_ref`
- `error_message`

### 3.11 任务流式进度

`GET /api/v2/tasks/{taskId}/events`

协议：

- `SSE`

事件类型最少包含：

- `task.status`
- `task.progress`
- `task.completed`
- `task.failed`

### 3.12 Research 报告保存为资料

`POST /api/v2/research-runs/{researchRunId}/save-report-as-source`

返回最小字段：

- `source_id`
- `task_id`
- `status`

### 3.13 Artifact 保存为资料

`POST /api/v2/artifacts/{artifactId}/versions/{versionNo}/save-as-source`

返回最小字段：

- `source_id`
- `task_id`
- `status`

## 4. Java 主系统到 Python Worker

## 4.1 下发方式

Research 和 Artifact 统一通过 Kafka 下发。

Topic 最小约定：

- `noteweave.research.run`
- `noteweave.artifact.job`

### 4.2 任务消息信封

Kafka 消息最小字段：

- `task_id`
- `task_type`
- `workspace_id`
- `target_type`
- `target_id`
- `payload_version`
- `trace_id`
- `created_at`

约束：

- Kafka 里只放轻量任务信封
- 大 payload 不直接塞进消息体
- 详细输入由 Worker 再向 Java 主系统拉取

### 4.3 Worker 拉取任务输入

Research Worker：

`GET /internal/worker/research-tasks/{taskId}/input`

Artifact Worker：

`GET /internal/worker/artifact-tasks/{taskId}/input`

返回最小字段：

- `task_id`
- `workspace_id`
- `target_id`
- `source_scope`
- `context_snapshot`
- `control_pack`
- `input_payload`

说明：

- `control_pack` 对应 `Research Control Pack` 或 `Artifact Control Pack`
- Worker 只拿当前任务被授权的资料范围，不自己拼全工作台权限

### 4.4 Worker 心跳

`POST /internal/worker/tasks/{taskId}/heartbeat`

请求体最小字段：

- `worker_type`
- `worker_instance_id`
- `phase`
- `heartbeat_at`

### 4.5 Worker 进度回传

`POST /internal/worker/tasks/{taskId}/progress`

请求体最小字段：

- `phase`
- `progress_percent`
- `message`
- `metrics`

Research 常见 `phase`：

- `PLANNING`
- `SEARCHING`
- `READING`
- `VERIFYING`
- `WRITING`

Artifact 常见 `phase`：

- `RESOLVING`
- `ACQUIRING`
- `COMPOSING`
- `VERIFYING`
- `EXPORTING`

### 4.6 Worker 完成回传

`POST /internal/worker/tasks/{taskId}/complete`

请求体最小字段：

- `result_type`
- `result_title`
- `result_payload`
- `trace_summary`
- `citations`

约束：

- Worker 回传的是结构化结果，不是直接写库
- Java 主系统收到后负责更新 `research_run`、创建 `artifact_version`、写引用关系和结果快照

### 4.7 Worker 失败回传

`POST /internal/worker/tasks/{taskId}/fail`

请求体最小字段：

- `phase`
- `error_code`
- `error_message`
- `retryable`

## 5. 最小返回对象约定

为了前后端先跑通，不需要一开始定义特别重的 DTO，只先统一下面几类返回壳子。

### 5.1 Chat Response Envelope

字段最小集合：

- `assistant_request_id`
- `conversation_id`
- `user_message_id`
- `answer_mode`

### 5.2 Task Response Envelope

字段最小集合：

- `task_id`
- `task_type`
- `task_status`
- `target_type`
- `target_id`

### 5.3 Citation Item

字段最小集合：

- `citation_id`
- `source_id`
- `title`
- `quote_text`
- `page_no`
- `location_info`

## 6. 第一阶段先不写进契约的东西

下面这些现在可以先不冻结成正式接口：

1. 用户自定义 MCP 管理后台
2. 通用 Skill 可视化编排接口
3. 多人实时协作接口
4. 批量资料权限管理接口
5. 全量多模态解析接口
6. Wiki 工作台的复杂图谱操作接口

原因很简单：

- 这些都不是第一批代码闭环的阻塞项
- 先冻结它们只会拖慢主链路落地

## 7. 开工建议

当前最值得立刻照着写的，是下面这一组接口：

1. `创建工作台`
2. `上传资料`
3. `完成上传并创建解析任务`
4. `创建会话`
5. `发送消息并按 answer_mode 返回 SSE`
6. `启动 Research / Artifact 任务`
7. `查询任务进度`
8. `保存系统结果为资料`

只要这组接口跑通，前端、Java 主系统、Python Worker 三边就能真正开始并行写代码。
