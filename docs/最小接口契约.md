# NoteWeave v2 最小接口契约

## 1. 定位

这份文档只锁定开始写代码必须统一的接口边界。

它不追求一次写完所有未来接口，而是先覆盖四类最小契约：

1. 前端到 Java 主系统。
2. Java 主系统到 Python Worker。
3. 前端任务进度与结果回放。
4. Note / Wiki 阶段3链路的最小保存与版本接口。

## 2. 总原则

### 2.1 三种聊天链路共用一套聊天接口

前端有 `问答 / Note / Wiki` 三种回答链路，但不拆三套聊天 API。

统一使用：

1. 创建会话接口。
2. 发送消息接口。
3. SSE 流式结果接口。

链路差异只体现在 `answer_mode`。

### 2.2 Note 和 Wiki 的链路边界

`NOTE` 参考 `shenmintao/marginalia`：

```text
资料级元数据候选
  -> 原文窗口
  -> 摘录卡片
  -> 带引用结构化笔记
```

`WIKI` 参考 `WeKnora`：

```text
Wiki Index / 页面列表
  -> Wiki 页面
  -> 页面链接与来源回链
  -> 默认 Wiki 工作台入口
```

### 2.3 Deep Research 与右侧产物栏统一走异步任务

这两类能力都必须：

1. 立即返回 `task_id`。
2. 通过任务状态接口或 SSE 查看进度。
3. 完成后由 Java 主系统写入正式业务对象。

### 2.4 Worker 不直接写业务真源

Python Worker 负责执行，不直接改 MySQL 主业务表。

最小约束：

1. Java 主系统通过 Kafka 下发任务。
2. Worker 通过内部 HTTP 回传进度和结果。
3. Java 主系统负责最终落库、建版本、建引用、回写资料池。

## 3. 前端到 Java 主系统

### 3.1 创建工作台

`POST /api/v2/workspaces`

请求字段：

- `name`
- `description`

返回字段：

- `workspace_id`
- `name`
- `status`
- `created_at`

### 3.2 创建上传事务

`POST /api/v2/workspaces/{workspaceId}/uploads`

请求字段：

- `file_name`
- `file_size`
- `mime_type`
- `chunk_size`
- `total_chunks`

返回字段：

- `upload_id`
- `status`
- `chunk_size`
- `total_chunks`

### 3.3 上传分片

`PUT /api/v2/uploads/{uploadId}/chunks/{chunkIndex}`

请求：

- 二进制分片。
- 可选 `Content-MD5`。

返回字段：

- `upload_id`
- `chunk_index`
- `accepted`

### 3.4 完成上传

`POST /api/v2/uploads/{uploadId}/complete`

返回字段：

- `source_id`
- `task_id`
- `parse_status`
- `index_status`

说明：

- 当前实现会同步完成解析和切片，后续可替换为 Kafka 异步解析。
- 完成解析后会写入 `source.summary`、`source.tags_json`、`source.metadata_json`，供 Note 链路做资料级候选定位。

### 3.5 创建会话

`POST /api/v2/workspaces/{workspaceId}/conversations`

请求字段：

- `title`
- `conversation_type`

返回字段：

- `conversation_id`
- `title`
- `conversation_type`
- `created_at`

### 3.6 发送聊天消息

`POST /api/v2/conversations/{conversationId}/messages`

请求字段：

- `content`
- `answer_mode`
- `client_request_id`

`answer_mode` 取值：

- `QA`
- `NOTE`
- `WIKI`

返回字段：

- `user_message_id`
- `assistant_message_id`
- `assistant_request_id`
- `stream_url`

说明：

- 聊天结果默认通过流式接口返回。
- 三种链路只改 `answer_mode`，不改变整体交互模型。

### 3.7 聊天流式结果

`GET /api/v2/chat/requests/{assistantRequestId}/stream`

协议：

- `SSE`

事件类型：

- `chat.delta`
- `chat.citation`
- `chat.completed`
- `chat.failed`

### 3.8 保存助手回答为 Note

`POST /api/v2/messages/{messageId}/save-as-note`

请求字段：

- `title`

返回字段：

- `item_id`
- `item_type`
- `latest_version_id`
- `latest_version_no`

说明：

- 只允许保存助手回答。
- 保存后会把该回答对应的引用绑定到 `knowledge_version_citation`。

### 3.9 创建 Note / Wiki 对象

`POST /api/v2/workspaces/{workspaceId}/knowledge-items`

请求字段：

- `item_type`
- `title`
- `content`
- `source_message_id`

`item_type` 取值：

- `NOTE`
- `WIKI`

返回字段：

- `item_id`
- `item_type`
- `title`
- `latest_version_id`
- `latest_version_no`

### 3.10 追加 Note / Wiki 版本

`POST /api/v2/knowledge-items/{itemId}/versions`

请求字段：

- `content`
- `source_message_id`
- `citation_ids`

返回字段：

- `item_id`
- `item_type`
- `latest_version_id`
- `latest_version_no`
- `summary`

说明：

- Wiki 页面追加版本后，Wiki 模式必须读取最新版本。
- Wiki 页面内容中的 `[[页面名]]` 会更新页面链接关系。

### 3.11 获取默认 Wiki 工作台入口

`GET /api/v2/workspaces/{workspaceId}/wiki-home`

返回字段：

- `workspace_id`
- `wiki_url`
- `pages`
- `links`

说明：

- 聊天中只保留一个默认 Wiki 工作台入口。
- 页面浏览、编辑和维护都从这个入口进入。

### 3.12 启动 Deep Research

`POST /api/v2/workspaces/{workspaceId}/research-runs`

请求字段：

- `question`
- `profile`
- `context_snapshot_id`

返回字段：

- `research_run_id`
- `task_id`
- `status`

### 3.13 启动右侧产物生成

`POST /api/v2/workspaces/{workspaceId}/artifact-jobs`

请求字段：

- `action_key`
- `style_profile_key`
- `context_snapshot_id`

返回字段：

- `artifact_job_id`
- `task_id`
- `status`

### 3.14 查询任务状态

`GET /api/v2/tasks/{taskId}`

返回字段：

- `task_id`
- `task_type`
- `task_status`
- `progress_phase`
- `progress_message`
- `result_ref`
- `error_message`

### 3.15 任务流式进度

`GET /api/v2/tasks/{taskId}/events`

协议：

- `SSE`

事件类型：

- `task.status`
- `task.progress`
- `task.completed`
- `task.failed`

### 3.16 Research 报告保存为资料

`POST /api/v2/research-runs/{researchRunId}/save-report-as-source`

返回字段：

- `source_id`
- `task_id`
- `status`

### 3.17 Artifact 保存为资料

`POST /api/v2/artifacts/{artifactId}/versions/{versionNo}/save-as-source`

返回字段：

- `source_id`
- `task_id`
- `status`

## 4. Java 主系统到 Python Worker

### 4.1 下发方式

Research 和 Artifact 统一通过 Kafka 下发。

Topic：

- `noteweave.research.run`
- `noteweave.artifact.job`

### 4.2 任务消息信封

Kafka 消息字段：

- `task_id`
- `task_type`
- `workspace_id`
- `target_type`
- `target_id`
- `payload_version`
- `trace_id`
- `created_at`

约束：

- Kafka 只放轻量任务信封。
- 大 payload 不直接塞进消息体。
- 详细输入由 Worker 再向 Java 主系统拉取。

### 4.3 Worker 拉取任务输入

Research Worker：

`GET /internal/worker/research-tasks/{taskId}/input`

Artifact Worker：

`GET /internal/worker/artifact-tasks/{taskId}/input`

返回字段：

- `task_id`
- `workspace_id`
- `target_id`
- `source_scope`
- `context_snapshot`
- `control_pack`
- `input_payload`

### 4.4 Worker 心跳

`POST /internal/worker/tasks/{taskId}/heartbeat`

请求字段：

- `worker_type`
- `worker_instance_id`
- `phase`
- `heartbeat_at`

### 4.5 Worker 进度回传

`POST /internal/worker/tasks/{taskId}/progress`

请求字段：

- `phase`
- `progress_percent`
- `message`
- `metrics`

Research 常见 `phase`：

- `PLANNING`
- `SEARCHING`
- `READING`
- `VERIFYING`
- `WRITING`

Artifact 常见 `phase`：

- `RESOLVING`
- `ACQUIRING`
- `COMPOSING`
- `VERIFYING`
- `EXPORTING`

### 4.6 Worker 完成回传

`POST /internal/worker/tasks/{taskId}/complete`

请求字段：

- `result_type`
- `result_title`
- `result_payload`
- `trace_summary`
- `citations`

### 4.7 Worker 失败回传

`POST /internal/worker/tasks/{taskId}/fail`

请求字段：

- `phase`
- `error_code`
- `error_message`
- `retryable`

## 5. 当前先不冻结的接口

以下接口不是第一批代码闭环的阻塞项：

1. 用户自定义 MCP 管理后台。
2. 通用 Skill 可视化编排接口。
3. 多人实时协作接口。
4. 批量资料权限管理接口。
5. 全量多模态解析接口。
6. Wiki 工作台复杂图谱操作接口。

## 6. 开工建议

当前最值得立刻照着写的是：

1. 创建工作台。
2. 上传资料。
3. 完成上传并创建解析任务。
4. 创建会话。
5. 发送消息并按 `answer_mode` 返回 SSE。
6. 保存 Note / 创建 Wiki / 追加 Wiki 版本。
7. 查询默认 Wiki 工作台。
8. 启动 Research / Artifact 任务。
9. 查询任务进度。
10. 保存系统结果为资料。
