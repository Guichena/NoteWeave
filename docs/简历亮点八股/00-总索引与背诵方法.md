## 1. 这套文档怎么用

这套材料先用一篇总叙事把项目从同步原型讲到当前架构，再围绕简历中的 5 个核心亮点展开。开始准备前，先读[系统演进与面试叙事主线](00-系统演进与面试叙事主线.md)，建立“问题出现、方案比较、做出选择、承担代价”的因果链，并先练其中的全项目 4 到 5 分钟标准回答。

完成五个亮点后，再读[面试官八维度审计与横切系统设计](06-面试官八维度审计与横切系统设计.md)。这篇补充业务抽象、数据与一致性、并发与容量、安全、可观测性、成本、测试证据和演进边界，专门处理跨模块追问。

项目不使用“几成完成”作为面试口径。面试主回答按证据标签逐项说明：当前仓库能证明主要用户链路、状态模型、异步投递、检索、长任务、Memory、前端交付和测试保护；签名 Release Bundle、完整生产对账、真实 SLO、容量、成本和长期质量仍属于目标设计或生产待验证。先说明当前证据，再展开规模、并发、任务时长、数据量和运行约束下的演进路线。

指标题统一查阅[全项目指标体系与面试计算手册](07-全项目指标体系与面试计算手册.md)。其中 EVO 以 Evaluation、Verification、Observation 三层解释任务质量、安全不变量和失败定位，配合[质量、评测、测试与发布门禁](../测试与评测/NoteWeave-评测指标报告.md)中的权威数据契约，以及[行为面试与现场系统设计](13-行为面试与现场系统设计题.md)中的故事母稿使用。它是项目内部记忆法，不是行业标准。本文仍区分源码已埋点、可从业务数据计算和建议补充三种成熟度，覆盖公式、计算例子、Dashboard、告警与常见面试计算题。

大厂面试补充材料按以下顺序阅读：[项目事实卡与 Ownership](08-项目事实卡与Ownership面试口径.md)、[真实缺陷排查与复盘](09-真实缺陷排查与复盘案例.md)、[Java/JVM/并发与网络](10-Java-JVM并发与网络基础下钻.md)、[MySQL 索引事务与 SQL](11-MySQL索引事务与SQL专项.md)、[发布迁移灰度与回滚](12-发布迁移灰度与回滚专项.md)、[行为面试与现场系统设计](13-行为面试与现场系统设计题.md)、[大厂常见基础八股与项目映射](14-大厂常见基础八股与项目映射.md)、[项目真实配置参数与容量口径](15-项目真实配置参数与容量口径.md)。Research Agent 还要单独阅读[真实案例、消融实验与 Ownership 答辩](17-Research-Agent真实案例消融实验与Ownership答辩.md)；场景化 RAG 还要阅读[演进取舍专项](18-场景化RAG演进与技术取舍专项.md)和[案例、消融与 Ownership 答辩](19-场景化RAG真实案例消融实验与Ownership答辩.md)。专项用于回答“为什么这样演进”“具体案例如何走完整链路”“每一层机制贡献多少”“AI 参与后怎样证明是你的判断”。事实卡中的个人经历字段必须由本人填写，其他文档不能替候选人虚构经历。

涉及线程池、连接池、超时、重试、缓存、配额、Lease、SSE 和 Worker 并发的数字，以 15 为统一参数真源。文档严格区分代码默认值、Compose 覆盖值、校验约束和压测结果。默认参数只能解释资源保护与失败语义，不能直接推出生产 QPS、在线用户数或 RTO/RPO。

08 到 13 不再只讲项目专项。项目事实卡补了项目介绍、技术选型、难点与结果类八股；故障复盘补了 CPU、OOM、死锁、P99、Kafka Lag 和 Redis 故障；Java 篇补了集合、泛型、类加载、ThreadLocal、代理与 Spring；MySQL 篇补了日志、Buffer Pool、复制、连接池、分片与 Online DDL；发布篇补了滚动、蓝绿、金丝雀、配置和兼容性；行为与系统设计篇补了常见行为题、容量估算、一致性、稳定性与幂等。14 负责 Redis、Kafka、操作系统、网络、分布式理论、安全和微服务等横切基础。

项目背景统一使用“学校资料服务原型，后续做工程化重构与面试向扩展”。先读[项目事实卡](08-项目事实卡与Ownership面试口径.md)中的学校原型边界和 90 秒演练回答，再读[指标手册](07-全项目指标体系与面试计算手册.md)中的学校场景理想数据卡，最后使用[行为面试与现场系统设计](13-行为面试与现场系统设计题.md)中的八个 STAR 母稿、考试周容量、资料版本与课程归档题。`[演练假设-待本人确认]` 只用于把回答练完整，不能替代日志、评测 Manifest、提交记录或真实用户数据。

每个亮点原来按架构和面试题拆成多篇。现在先按“一体化主入口 + 深挖附件”阅读，一体化手册把演进、架构、契约、案例、指标和连续追问串起来，旧文档保留源码级细节和历史链接。

1. **一体化面试手册**：先建立 30 秒主回答，再按演进、架构、契约、案例、指标和连续追问展开。
2. **深挖附件**：旧的面试题、详细架构、演进取舍、案例消融和契约文档继续保留，用于源码、算法和具体反例下钻。

两类文档都增加了源码级隐藏设计。它们不是对接口链路的重复描述，而是从当前实现和测试中提炼候选仲裁、版本门禁、旧 Owner 晚到防护、能力等待恢复、不可变快照、失败语义和批量查询等内部机制。

问答篇中较短的 H3 回答定位为“打断式追问速查”，用于面试官只问一个机制时快速回应，不要求单独讲满 3 分钟。每篇末尾的“面试官八维度母题长回答”才是默认的 3 到 5 分钟准备材料，分别从业务抽象、数据与一致性、并发与容量、安全、可观测性、成本、测试证据和演进边界展开，并能承接至少三层连续追问。

不要逐字硬背整篇。建议按四层准备：

- 第一层先能讲清 V0 原型为什么不够，以及五个亮点按什么因果顺序出现。
- 第二层背“30 秒回答”，用于面试官刚看到项目时快速建立主线。
- 第三层练“4 到 5 分钟标准主回答”，把业务问题、方法、项目实现和工程设计连续讲清楚。
- 第四层按八个评分面练母题长回答，主动讲失败窗口、证据边界和演进触发条件。
- 第五层理解详细架构篇中的原理、替代方案和 Trade-off，用于继续下钻源码与中间件细节。
- 第六层按常见基础八股做随机跳转训练，从底层原理回答到 NoteWeave 的真实机制，再回到失败窗口和测试证据。

每个亮点建议按下面的口述节奏练习：

```text
30 秒：项目解决什么，最核心的方法是什么
2 分钟：核心链路与两个关键机制
4 到 5 分钟：原理、实现、工程保障、评测与边界
继续追问：算法细节、替代方案、故障场景和 Trade-off
```

五段标准主回答按约每分钟 280 个中文字符估算，目前都超过 5 分钟。实际面试不需要一口气全部说完，可以在每个机制后停一下，让面试官选择继续追问的方向。

## 4. 回答项目题的通用结构

项目主回答推荐使用八段式：

1. **业务起点**：用户在什么场景遇到了什么问题。
2. **V0 方案**：最小实现是什么，它为什么在早期合理。
3. **失效条件**：规模、时延、正确性或安全约束变化后，旧方案在哪里失败。
4. **候选对比**：至少比较两个方向，也承认未选方案的优点。
5. **选择依据**：当前约束为什么更适合这一种，不用“更先进”代替判断。
6. **落地机制**：讲数据结构、状态机或算法，再说明中间件如何承载。
7. **验证与故障**：说明测试、观测、降级和恢复。
8. **代价与边界**：主动说明维护成本、生产化边界和架构扩展判据。

详细知识点使用六段式理解：

1. **概念**：它是什么，解决哪类问题。
2. **原理**：数据结构、算法或中间件机制如何工作。
3. **项目应用**：在 NoteWeave 的哪个对象和状态中体现。
4. **替代方案**：还能使用哪些方法。
5. **Trade-off**：当前方案得到了什么，又承担了什么成本。
6. **选择依据**：为什么当前业务约束更适合这一种，而不是其他方案。

外部笔记中的 MySQL、Redis、Kafka、连接池、RAG 和 Agent 知识点只作为分析镜头，不作为项目事实来源。蒸馏时不问“还能把哪个名词写进文档”，而按下面的顺序追问当前项目：

1. **它保护什么不变量**：例如 RRF 保护异构分数不可直接比较，Fencing 保护旧 Owner 不能覆盖新结果。
2. **它在哪个入口被消费**：必须落到当前类、方法、配置键、表字段或事件，而不是只写组件作用。
3. **它依赖什么假设**：数据规模、错误分布、Provider 能力、租户边界和任务时长一旦变化，结论是否仍成立。
4. **最小反例是什么**：构造一个能推翻当前判断的 Bad Case，例如精确错误码被语义候选淹没、Rerank 返回重复下标、最后一次 Claim 后进程退出。
5. **怎样区分症状与根因**：先列候选原因、支持证据和反证，再把能够稳定复现并被修复消除的原因称为根因。
6. **参数怎样联动**：TopK、Batch、线程池、连接池、Timeout、Retry 和 Lease 必须沿同一资源链解释，不能逐个背默认值。
7. **证据能证明到哪一层**：源码证明机制存在，单测证明受控输入，集成回放证明组件协作，只有真实工作负载才能形成容量或业务结论。

## 5. 统一安全口径

- Research 的分支恢复是有界顺序执行，不说成大规模并行搜索。
- Gold Set 是内部确定性评测，不等同于外部 Benchmark 领先。
- 检索消融只有 6 条内部样本；仓库中的 33.3%/66.7%/100% 是手工固化回归 fixture，现有自动 Replay 走 BM25 Baseline，不能说成融合链路实测结果。
- MCP 由系统注册并受能力白名单、内部认证和 Host 写回约束；工具数量、并发或副作用范围增长时，再按输入 Schema 和审批策略细化边界。
- Redis Lua 确实用于 Workspace + Actor + Workload 速率令牌桶和 Workspace + Workload 并发租约，不与 MySQL Outbox Lease 混用。
- 多存储一致性采用最终一致，不说 MySQL、MinIO、Elasticsearch 之间存在分布式强事务。
- Memory 保留来源，但不参与资料召回、Citation 或 Evidence Rerank。
