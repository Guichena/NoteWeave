# 统一领域模型

## 1. 目标

这份文档定义 v2 的统一对象模型，用来把三种工作模式、两个执行引擎和统一回写链路收拢到同一个业务世界里。

它要解决的问题不是“对象够不够多”，而是：

- Ask、Wiki、调查是否共享同一套 Source / Evidence / Version
- Deep Research 与 Artifact Runtime 是否建立在相同领域对象之上
- 临时会话、中间沉淀、稳定知识、生成产物是否拥有清晰边界

## 2. 顶层边界

### 2.1 Workspace

所有用户知识工作的顶层边界。

职责：

- 归属关系
- 可见性边界
- Source / Knowledge / Artifact / Run 容器

### 2.2 Topic Scope

Topic Scope 是工作区内围绕某个主题的组织边界，对应上游设计中的 `Research Process` 思想。

它的作用是把以下内容按主题收拢：

- Conversations
- Sources
- Notes
- Wiki Pages
- Investigation Notes
- Research Runs
- Artifacts

它不是新的顶层产品，而是工作区内部的主题型组织单元。

## 3. 核心持久化对象

### 3.1 Source

导入系统的原始资料对象。

示例：

- PDF
- Word
- Markdown
- 网页
- 图片 OCR 文本
- 音频转写
- 视频转写

关键字段：

- source id
- workspace id
- topic scope id
- source type
- raw object reference
- parsed text reference
- metadata
- import status
- parse status

### 3.2 Conversation

用于问答模式的轻量交互会话。

职责：

- 保存用户与助手消息
- 记录附加 Source
- 记录会话摘要
- 记录本轮使用的 Citation

Conversation 负责连续性，但不直接承担长期知识沉淀。

但它可以作为 `Graduated Memory` 的上游信号来源，用于抽取偏好、表达习惯与任务意图。

### 3.3 Knowledge Item

统一的用户知识内容对象。

初始类型：

- `NOTE`
- `WIKI_PAGE`
- `INVESTIGATION_NOTE`

共享字段：

- knowledge item id
- workspace id
- topic scope id
- type
- title
- content
- status
- source origin
- latest version

这个抽象的意义是：

- Note、Wiki、Investigation Note 属于同一知识世界
- 它们生命周期不同，但不应拆成三套互不兼容的数据模型

### 3.4 Knowledge Version

任意 `Knowledge Item` 的版本对象。

职责：

- 保存标题与内容快照
- 记录编辑者或生成者
- 保存变更说明
- 记录发布 / 晋升链路

### 3.5 Citation

可复用的证据引用对象。

职责：

- 指向 Source 或生成快照
- 标识引用片段、页码、时间戳或位置
- 保留对应版本信息

### 3.6 Artifact

生成型交付对象，默认不等同于长期稳定知识。

示例：

- 研究报告
- 对比分析
- 学习指南
- FAQ
- Wiki 草稿
- 课程笔记
- 会议纪要

### 3.7 Artifact Version

Artifact 的版本化内容对象。

职责：

- 内容快照
- Source 列表
- Citation 列表
- 生成链路
- 父版本关系
- Run / Job 关联

### 3.8 Research Run

Deep Research 的核心长任务对象。

职责：

- 保存研究问题
- 保存研究计划
- 保存运行状态
- 保存预算配置
- 关联表格状态、证据和最终输出

### 3.9 Research Table

Research Run 的外显状态容器。

职责：

- 候选行
- 研究列
- cell 状态
- 置信度
- evidence binding
- conflict markers

Research Table 是 Deep Research loop 的外部状态，不是临时内存。

### 3.10 Research Trace

Deep Research 的审计日志对象。

职责：

- plan events
- search events
- read events
- extraction events
- verification events
- revision events
- writeback events

### 3.11 Artifact Job

Artifact Runtime 的异步任务对象。

职责：

- 保存输入快照
- 保存触发来源上下文
- 保存 Production Action
- 保存 Prompt Recipe 版本
- 记录运行状态、校验结果与重试信息

### 3.12 Production Action

产物能力配置对象。

它描述：

- UI 展示名称
- 所属按钮分组
- 输入类型
- 目标产物类型
- 内容获取策略
- 默认 Prompt Recipe
- 输出结构要求
- 是否允许外部能力
- 是否允许回流检索

它既可以被右侧产物栏直接触发，也可以被 Agent 选择后触发。

### 3.13 Prompt Recipe

可配置生成模板对象。

它描述：

- 输出风格
- 章节结构
- 长度要求
- 表格 / 行动项 / 练习题等开关
- 目标场景

### 3.14 Skill Binding

Skill Binding 表示某个 Production Action 绑定到哪类 Skill 能力。

它描述：

- action id
- skill id
- 默认参数
- 输出结构契约
- 可选校验规则

### 3.15 MCP Capability Binding

MCP Capability Binding 表示某个 Action 或 Skill 依赖的外部能力声明。

它描述：

- capability name
- provider
- input contract
- output contract
- permission scope

### 3.16 Context Signal

从 Conversation、Research Trace、用户反馈中抽取出的弱记忆信号对象。

它描述：

- signal id
- workspace id
- topic scope id
- source type
- source object id
- signal kind
- signal content
- confidence
- decay policy

这类对象默认可衰减，不直接等同于长期记忆。

### 3.17 Memory Candidate

待判断的记忆候选对象。

它描述：

- candidate id
- workspace id
- topic scope id
- candidate type
- source lineage
- normalized statement
- evidence set
- novelty score
- neighborhood validation status
- review status

它的来源可以是：

- 被确认的 Artifact Version
- 人工整理后的 Note / Wiki
- 高价值 Context Signal 聚合结果

### 3.18 Memory Object

通过门控晋升后的长期记忆对象。

它描述：

- memory id
- workspace id
- topic scope id
- memory type
- memory scope
- canonical content
- supporting evidence
- source lineage
- promotion record
- freshness
- retrieval policy

Memory Object 是跨任务可复用的长期记忆对象，而不是原始聊天或原始产物的直接拷贝。

## 4. 运行时派生对象

以下对象对系统很重要，但更适合作为运行时视图或中间对象，而不是顶层业务世界：

### 4.1 SourceCard

资料调查模式中的候选资料卡片视图。

它来自 Source metadata、摘要、标签、文件夹信息和相关度排序结果。

### 4.2 SourceWindow

资料调查模式中的原文阅读窗口视图。

它指向具体 Source 的某个原文片段、页码、段落或时间戳范围。

### 4.3 Canonical Content Object

Artifact Runtime 用于归一化不同输入的标准内容对象。

它统一承接：

- 文档文本
- 视频 / 音频转写
- 网页正文
- Card 上下文
- 混合输入

这层对象既可持久化为快照，也可作为运行时中间态。

### 4.4 UI Context Snapshot

UI Context Snapshot 是前端当前上下文的运行时快照，专门服务于右侧产物栏和 Deep Research 按钮。

它可以来自：

- 当前聊天会话
- 当前阅读 Source
- 当前调查主题
- 当前 Wiki 页面
- 当前多选资料集合

## 5. 对象关系

推荐的第一层关系如下：

- 一个 `Workspace` 拥有多个 `Topic Scopes`
- 一个 `Workspace` 拥有多个 `Sources`
- 一个 `Workspace` 拥有多个 `Conversations`
- 一个 `Workspace` 拥有多个 `Knowledge Items`
- 一个 `Workspace` 拥有多个 `Artifacts`
- 一个 `Workspace` 拥有多个 `Research Runs`
- 一个 `Workspace` 拥有多个 `Artifact Jobs`
- 一个 `Workspace` 拥有多个 `Production Actions`
- 一个 `Workspace` 拥有多个 `Context Signals`
- 一个 `Workspace` 拥有多个 `Memory Candidates`
- 一个 `Workspace` 拥有多个 `Memory Objects`

- 一个 `Topic Scope` 可以聚合多个 `Sources`
- 一个 `Topic Scope` 可以聚合多个 `Conversations`
- 一个 `Topic Scope` 可以聚合多个 `Knowledge Items`
- 一个 `Topic Scope` 可以聚合多个 `Research Runs`
- 一个 `Topic Scope` 可以聚合多个 `Artifacts`
- 一个 `Topic Scope` 可以聚合多个 `Context Signals`
- 一个 `Topic Scope` 可以聚合多个 `Memory Objects`

- 一个 `Research Run` 读取多个 `Sources`
- 一个 `Research Run` 维护一个 `Research Table`
- 一个 `Research Run` 记录多条 `Research Trace`
- 一个 `Research Run` 产出一个或多个 `Artifacts`
- 一个 `Research Run` 也可能产出一个或多个 `Investigation Note`
- 一个 `Research Run` 可以抽取多个 `Context Signals`

- 一个 `Artifact Job` 产出一个 `Artifact Version`
- 一个 `Artifact Job` 由一个 `UI Context Snapshot` 触发
- 一个 `Artifact Job` 对应一个 `Production Action`
- 一个 `Artifact Version` 可引用多个 `Citations`
- 一个 `Artifact Version` 可以生成多个 `Memory Candidates`
- 一个 `Knowledge Version` 可引用多个 `Citations`
- 一个 `Knowledge Version` 可以生成多个 `Memory Candidates`
- 一个 `Citation` 反向指向具体 Source 或 Source Snapshot
- 一个 `Production Action` 可绑定一个或多个 `Skill Binding`
- 一个 `Production Action` 可声明一个或多个 `MCP Capability Binding`
- 一个 `Context Signal` 可以被聚合为一个或多个 `Memory Candidates`
- 一个 `Memory Candidate` 最终可能晋升为一个 `Memory Object`

## 6. 生命周期边界

### 6.1 Conversation

特征：

- 短周期
- 面向对话连续性
- 不等同于知识沉淀
- 但可提供可衰减的 `Context Signal`

### 6.2 Note

特征：

- 临时或中间态
- 可手动编辑
- 面向个人理解沉淀
- 可晋升

### 6.3 Wiki Page

特征：

- 稳定
- 可链接
- 可维护
- 适合长期导航

### 6.4 Investigation Note

特征：

- 面向调查过程
- 强调来源、候选资料和结论链路
- 可以进一步整理为 Note 或 Wiki 草稿

### 6.5 Artifact

特征：

- 生成型输出
- 带版本
- 带来源
- 不自动成为规范知识

### 6.6 Research Run

特征：

- 长任务过程对象
- 异步
- 可中断
- 可恢复
- 可审计

### 6.7 Context Signal

特征：

- 弱信号
- 可衰减
- 来源广
- 不直接进入长期记忆

### 6.8 Memory Object

特征：

- 经门控晋升
- 可跨任务复用
- 需保留来源链路
- 不等同于原始产物全文

## 7. 不应重新引入的旧问题

避免通过隐藏字段或重复模块，把旧拆分重新带回来：

1. 不再出现独立的 `team wiki` 与 `personal wiki` 世界
2. 不为不同工作模式重复建设 Source 系统
3. 不为不同模式定义互不兼容的 Evidence / Citation 规则
4. 不允许生成内容静默自动晋升为稳定知识
5. 不把 Deep Research 和 Artifact Runtime 建成两套彼此割裂的长任务框架
6. 不把 Conversation 全量历史直接当作长期记忆

## 8. 可选结构化层

`Claim / Entity / Concept` 更适合作为增强型结构化层，而不是当前架构锁定的前置条件。

建议状态：

- 架构感知
- 增强扩展项
- 对后续推理层友好

## 9. 最小稳定模型总结

从目标架构的稳定骨架看，v2 的核心对象集合可总结为：

`Workspace + Topic Scope + Source + Conversation + Knowledge Item + Citation + Research Run + Artifact + Artifact Job + ContextSignal + MemoryObject`

在这个模型之上，三种工作模式、两个执行引擎和统一回写链路都可以成立。
