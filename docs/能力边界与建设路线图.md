# 能力边界与建设路线图

## 1. 目的

这份文档用于锁定 NoteWeave v2 的目标能力边界、系统建设路线和设计取舍。

目标不是只定义一个最小原型，而是先把完整产品形态设计清楚，再决定实现顺序。

## 2. 总体使命

NoteWeave v2 要成立，核心要证明的一件事情是：

`一个研究工作台可以同时承载资料上传、多次聊天、问答 / Note / Wiki 三种回答链路，并通过深度研究、右侧产物栏与任务邻域个性化记忆机制，把复杂任务沉淀为可追溯、可复用、可持续演化的知识结果。`

因此这里要设计的不是一个脱离业务场景的“大而全 Agent 平台”，而是一个围绕真实知识工作流程组织起来的统一知识工作台。

在工程实现上，当前统一口径进一步明确为：

- `Java` 主系统承接研究工作台、三种聊天回答链路、业务真源、任务编排与结果回写
- `Python Research Worker` 承接 `Deep Research`
- `Python Artifact Worker` 承接右侧产物栏背后的生成执行链路

## 2.1 设计收敛原则

虽然文档采用目标态口径，但实际设计必须围绕少数高价值亮点收敛，不追求把所有能力都做成完整平台。

当前真正需要成立的主线只有五个：

1. `Deep Research 智能体`
2. `右侧产物栏 + 受控式产物生成 Agent`
3. `RAG / Wiki / Note 一体化知识工作流`
4. `Graduated Memory + Task-Neighborhood Memory Compiler`
5. `文件上传 + Kafka + MinIO` 资料基础设施

除此之外的能力都应该服务这五条主线，而不是反过来要求主线去迁就平台复杂度。

## 3. 目标能力范围

### 3.1 研究工作台底座

- Workspace 作为顶层归属边界
- Topic Scope 作为主题组织边界
- 统一权限、归属、导航与对象索引
- 统一 Evidence / Citation / Version 规则

### 3.2 资料导入与证据底座

- 文件导入
- URL 导入
- 文本导入
- 对象存储映射
- 解析文本保存
- 原文定位与 原文窗口
- Citation / Evidence 统一引用能力

### 3.3 问答链路

- 基于工作台资料池的检索问答
- 当前会话连续性
- 回答级引用展示
- 一键保存为结构化笔记
- 与深度研究、右侧产物栏天然联动
- 默认采用 `Workspace-bounded Conversational RAG`
- 第一阶段检索对象以当前工作台已解析资料 chunk 为主
- 其他链路产生的内容只有在用户明确保存为资料后，才按普通资料参与问答召回
- 聊天历史只用于理解上下文，不作为事实证据
- 支持关键词检索、向量检索、结构化过滤、证据 rerank 和 Citation-grounded Answer

### 3.4 Note 沉淀层

- 作为阶段性理解、人工整理和设计取舍的承载层
- 支持从 Ask、Deep Research、产物结果回写
- 可被问答、Wiki、产物生成复用
- 可作为用户偏好、整理习惯和项目口径信号的来源之一

### 3.5 Wiki 链路

- 页面创建与编辑
- 页面版本管理
- 页面关系、链接与反向链接
- 页面引用支撑
- 缺口分析与结构化维护

### 3.6 Note 链路

- 资料树 / 文件夹浏览
- 资料元数据检索与浏览
- 候选资料卡列表
- 原文窗口
- 摘录卡片 / 批注片段沉淀
- 结构化笔记生成与回写

### 3.7 全局深度研究入口

- 提供独立的 `Deep Research` 按钮
- 可以从问答、Note、Wiki 或资料多选上下文发起
- 自动创建 `Research Run`
- 结果可回流到问答、Note、Wiki 或 Artifact

### 3.8 Deep Research Engine

- 创建 Research Run
- 生成研究计划
- 持久化 Research Table
- 行 / 单元格状态管理
- 证据绑定
- Search -> Read -> Extract -> Verify loop
- 冲突标记与低置信结果保留
- 研究轨迹、预算、状态、恢复能力
- 支持 stop contract、局部修复和必要时的分支探索
- 最终报告写入 Artifact

这条链路的设计要求是：

- Deep Research 必须是显式长任务
- 必须有外部状态
- 必须有预算 / 状态 / trace
- 不等同于一次性 Prompt
- 在升级口径下，应逐步向 `TAS-Informed Verification-Centric Research Harness` 演进

### 3.9 右侧产物栏

- 在阅读 / 对话主区右侧提供固定产物栏
- 默认基于当前研究工作台资料池触发生成
- 默认提供报告、测验、学习指南、FAQ 等高频按钮
- 支持扩展到 Wiki 页面、视频总结、会议纪要整理等动作
- 支持产物生成进度、版本与结果回看

### 3.10 Artifact Runtime

- 固定主链路的受控生成流程
- Artifact Job 异步执行
- Versioned Artifact 输出
- 支持默认 Production Action 集合与扩展动作
- 支持 Style Profile、Skill Graph 和按需 MCP capability 加载
- 支持 Skill / MCP 能力接入

推荐默认 Action：

- 研究报告
- 测验
- 学习指南
- FAQ
- Wiki 页面

### 3.11 Agent / Skill / MCP 能力栈

- Agent 用于受控决策、规划、验证与修复
- Skill 用于沉淀可复用生成能力
- MCP 用于接入外部读取、搜索、转写、解析等能力
- Action 能显式声明自己依赖的 Skill / MCP 能力

这里的重点不是做一个独立 Agent 平台，而是让 Deep Research 和右侧产物栏具备可扩展但仍然可控的能力底座。

### 3.12 Graduated Memory + Task-Neighborhood Memory Compiler

- 用户反馈、项目口径、表达偏好和禁用路径可抽取为 `Memory Signal`
- 支持 `Graduated Memory` 的门控式写入晋升
- 支持 `Semantic Neighborhood Modeling` 判断记忆适用任务邻域
- 支持 `Marginal Utility Scoring` 判断跨任务复用价值
- 支持 `Negative Memory` 记录用户明确否定过的方案、表达和结构
- 支持 `Staleness Guard` 防止旧记忆污染新决策
- 支持 `Memory Ledger` 记录来源、适用范围、使用历史和失效原因
- 支持 `Memory Compiler` 将记忆编译为风格约束、结构约束、禁用路径和交互策略

这套记忆层的设计要求是：

- Memory 不作为事实来源
- Memory 不参与资料检索排序
- Memory 不替代工作台资料池、原文窗口和 Wiki 页面
- Memory 只服务跨会话、跨链路、跨任务的个性化行为一致性

### 3.13 统一回写链路

- Ask -> Note
- Deep Research -> 研究报告 / 结构化笔记
- Deep Research -> Artifact
- Artifact -> 结构化笔记 / Wiki 页面 / Artifact 保留

所有回写必须显式确认，不允许静默写入稳定知识。

## 4. 明确不追求的方向

为了保证架构聚焦，以下方向不作为当前设计的主目标：

1. 脱离具体产品场景的通用 Agent 平台
2. 无门控的全局自治记忆治理
3. 以 benchmark 为导向的 Research Agent 比赛型优化
4. 一上来就做完整 Claim / Entity / Knowledge Graph 推理层
5. 一上来就支持非常重的企业级审批与组织流程
6. 无约束的自由自治 Agent 编排
7. 为了“显得完整”而额外引入与核心亮点无关的平台层

## 5. 任务边界

### 5.1 问答任务

- 低延迟
- 检索增强回答
- 结果可保存
- 默认不升级为深度研究

### 5.2 Note 任务

- 轻量记录与整理
- 面向中间理解
- 可晋升但不自动规范化

### 5.3 Wiki 任务

- 面向长期知识编织
- 强调页面维护与关系组织
- 生命周期严格于 Note

### 5.4 深度研究任务

- 面向开放式、多步骤研究
- 通过独立按钮显式触发
- 显式异步状态
- 具备 Table、Trace、Budget、Verification
- 最终输出是报告或草稿，而不是静默注入真值

### 5.5 产物任务

- 由右侧产物栏或系统动作触发
- 受控生成
- 结果带版本
- 输出可复用
- 需经过确认后才能回写为更稳定知识

### 5.7 记忆任务

- 面向长期可复用知识的门控晋升
- 会话、研究轨迹、产物都可提供信号
- 只有通过门控验证的内容才进入长期记忆
- 默认服务问答与右侧产物生成，不直接干预 Deep Research 主 loop

## 6. 建设顺序建议

### 6.1 统一底座

- 创建 Workspace 与 Topic Scope
- 创建资料模型
- 创建 Citation / Evidence 基础能力
- 创建 Async Task 基础能力

### 6.2 问答与 Note

- 实现 Ask 模式
- 实现问答 RAG 链路
- 实现 Conversation
- 实现 Note 保存与检索复用
- 实现右侧产物栏基础 UI

### 6.3 Wiki 链路

- 实现 Wiki Page 与 Version
- 打通链接、反向链接与引用
- 统一 Note / Wiki 存储规则

### 6.4 Note 链路

- 实现资料树与元数据检索入口
- 实现 候选资料卡 列表
- 实现 原文窗口 原文阅读
- 实现摘录卡片 / 批注片段沉淀
- 实现 结构化笔记沉淀

### 6.5 Deep Research 引擎

- 实现 Deep Research 按钮入口
- 实现 Research Run
- 实现 Research Table 与 Trace
- 跑通 Search -> Read -> Extract -> Verify loop
- 产出研究报告 Artifact

### 6.6 Artifact Runtime 与回写

- 实现 Artifact Job
- 实现默认 Production Action、Style Profile 与 Prompt Recipe
- 接入默认 Skill / MCP 能力声明
- 实现 Artifact Version
- 打通保存为结构化笔记 / Wiki 页面

### 6.7 Graduated Memory + Task-Neighborhood Memory Compiler

- 实现 Memory Signal 抽取
- 实现 Memory Candidate、Graduated Memory Gates、Negative Memory 与 Staleness Guard
- 实现 Task-Neighborhood Memory Compiler
- 在问答、Note、Wiki、产物生成和 Deep Research 中接入差异化编译策略
- 展示 Memory 来源、适用任务邻域、使用历史与失效原因

### 6.8 前端打磨与演示闭环

- 统一工作台导航
- 对齐模式切换体验
- 展示进度、证据和版本链路
- 让整套系统可演示、可说明、可写入简历

## 7. 架构评审检查清单

在正式实现前，建议先确认以下问题：

1. `Topic Scope` 是否作为主题聚合边界落地
2. `Knowledge Item` 是否作为 Note / Wiki 的共享存储基础
3. Note 链路与 Deep Research 的升级边界是否明确
4. 默认支持哪些 `Production Action`
5. 右侧产物栏的默认按钮集合是否锁定为报告 / 测验 / 学习指南 / FAQ
6. `Skill` 与 `Production Action` 的绑定方式是否固定
7. `Claim / Entity / Concept` 是否作为增强型结构化层设计
8. 参考项目能力是数据迁移、逻辑迁移，还是仅作为设计参考

## 8. 最终总结

整套设计至少应保证以下闭环天然成立：

`资料进入工作区 -> 用户在问答 / Note / Wiki 中消费资料 -> 用户通过 Deep Research 按钮或右侧产物栏发起重型任务 -> 系统通过 Agent / Skill / MCP 能力栈生成可追溯结果 -> 结果经过确认回写为可沉淀知识 -> 用户反馈、项目口径和禁用路径通过任务邻域记忆机制编译为后续个性化控制信号。`
