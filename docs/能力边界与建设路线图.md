# 能力边界与建设路线图

## 1. 目的

这份文档用于锁定 NoteWeave v2 的目标能力边界、系统建设路线和设计取舍。

目标不是只定义一个最小原型，而是先把完整产品形态设计清楚，再决定实现顺序。

## 2. 总体使命

NoteWeave v2 要成立，核心要证明的一件事情是：

`一个统一工作区可以同时承载问答、Wiki 维护与资料调查三种工作模式，并通过深度研究、右侧产物栏与记忆晋升机制，把复杂任务沉淀为可追溯、可复用、可持续演化的知识结果。`

因此这里要设计的不是一个脱离业务场景的“大而全 Agent 平台”，而是一个围绕真实知识工作流程组织起来的统一知识工作台。

## 2.1 设计收敛原则

虽然文档采用目标态口径，但实际设计必须围绕少数高价值亮点收敛，不追求把所有能力都做成完整平台。

当前真正需要成立的主线只有五个：

1. `Deep Research 智能体`
2. `右侧产物栏 + 受控式产物生成 Agent`
3. `RAG / Wiki / Note 一体化知识工作流`
4. `Graduated Memory 记忆晋升机制`
5. `文件上传 + Kafka + MinIO` 资料基础设施

除此之外的能力都应该服务这五条主线，而不是反过来要求主线去迁就平台复杂度。

## 3. 目标能力范围

### 3.1 统一工作区底座

- Workspace 作为顶层归属边界
- Topic Scope 作为主题组织边界
- 统一权限、归属、导航与对象索引
- 统一 Evidence / Citation / Version 规则

### 3.2 Source 导入与证据底座

- 文件导入
- URL 导入
- 文本导入
- 对象存储映射
- 解析文本保存
- 原文定位与 SourceWindow
- Citation / Evidence 统一引用能力

### 3.3 问答模式

- 基于 Source / Note / Wiki / Memory 的检索问答
- 当前会话连续性
- 回答级引用展示
- 一键保存为 Note
- 与深度研究、右侧产物栏天然联动

### 3.4 Note 沉淀层

- 作为阶段性理解、人工整理和设计取舍的承载层
- 支持从 Ask、调查、产物结果回写
- 可被问答、Wiki、产物生成复用
- 可作为长期记忆晋升链路的稳定来源之一

### 3.5 Wiki 模式

- 页面创建与编辑
- 页面版本管理
- 页面关系、链接与反向链接
- 页面引用支撑
- 缺口分析与结构化维护

### 3.6 资料调查模式

- 调查主题容器
- Source metadata 浏览
- SourceCard 候选列表
- SourceWindow 原文窗口
- Investigation Note 生成与回写

### 3.7 全局深度研究入口

- 提供独立的 `Deep Research` 按钮
- 可以从问答、Wiki、调查任一上下文发起
- 自动创建 `Research Run`
- 结果可回流到问答、Wiki、调查、Note 或 Artifact

### 3.8 Deep Research Engine

- 创建 Research Run
- 生成研究计划
- 持久化 Research Table
- 行 / 单元格状态管理
- 证据绑定
- Search -> Read -> Extract -> Verify loop
- 冲突标记与低置信结果保留
- 研究轨迹、预算、状态、恢复能力
- 最终报告写入 Artifact

这条链路的设计要求是：

- Deep Research 必须是显式长任务
- 必须有外部状态
- 必须有预算 / 状态 / trace
- 不等同于一次性 Prompt
- 在升级口径下，应逐步向 `Evidence-Gated Branchable Research Harness` 演进

### 3.9 右侧产物栏

- 在阅读 / 对话主区右侧提供固定产物栏
- 针对当前上下文触发生成
- 默认提供报告、测验、学习指南、FAQ 等高频按钮
- 支持扩展到 Wiki 草稿、视频总结、会议纪要整理等动作
- 支持产物生成进度、版本与结果回看

### 3.10 Artifact Runtime

- 固定主链路的受控生成流程
- Artifact Job 异步执行
- Versioned Artifact 输出
- 支持默认 Production Action 集合与扩展动作
- 支持 Skill / MCP 能力接入

推荐默认 Action：

- 研究报告
- 测验
- 学习指南
- FAQ
- Wiki 草稿

### 3.11 Agent / Skill / MCP 能力栈

- Agent 用于受控决策、规划、验证与修复
- Skill 用于沉淀可复用生成能力
- MCP 用于接入外部读取、搜索、转写、解析等能力
- Action 能显式声明自己依赖的 Skill / MCP 能力

这里的重点不是做一个独立 Agent 平台，而是让 Deep Research 和右侧产物栏具备可扩展但仍然可控的能力底座。

### 3.12 Graduated Memory

- Conversation 可抽取轻量 `Context Signal`
- Research Trace 可抽取研究偏好与方法信号
- 被确认的 Artifact / Note / Wiki 可形成 `Memory Candidate`
- 支持 `Novelty Gate + Task Neighborhood Validation` 的门控晋升
- 长期记忆默认增强问答与产物生成，不默认污染 Deep Research 主循环
- 支持聊天、研究轨迹、已确认产物三类来源的差异化晋升
- 支持记忆来源追溯、拒绝记录、人工反馈与回读策略

这套记忆层的设计要求是：

- 聊天、研究过程、产物三类来源进入同一晋升链路
- 长期记忆不是对话历史原样堆积
- 被晋升内容必须具备来源、门控记录与可回读能力

### 3.13 统一回写链路

- Ask -> Note
- Investigation -> Investigation Note
- Deep Research -> Artifact
- Artifact -> Note 草稿 / Wiki 草稿 / Investigation Note

所有回写必须显式确认，不允许静默写入稳定知识。

## 4. 明确不追求的方向

为了保证架构聚焦，以下方向不作为当前设计的主目标：

1. 脱离具体产品场景的通用 Agent 平台
2. 无门控的全局自治记忆治理
3. 以 benchmark 为导向的 Research Agent 比赛型优化
4. 一上来就做完整 Claim / Entity / Knowledge Graph 推理层
5. 一上来就支持非常重的企业级审批与组织流程
6. 无约束的自由自治 Agent 编排
7. 为了“显得完整”而额外引入与核心亮点无关的平台层

## 5. 任务边界

### 5.1 问答任务

- 低延迟
- 检索增强回答
- 结果可保存
- 默认不升级为深度研究

### 5.2 Note 任务

- 轻量记录与整理
- 面向中间理解
- 可晋升但不自动规范化

### 5.3 Wiki 任务

- 面向长期知识编织
- 强调页面维护与关系组织
- 生命周期严格于 Note

### 5.4 调查任务

- 面向资料探索与原文阅读
- 强调 SourceCard / SourceWindow / Investigation Note
- 可以停留在人工调查，不必一定升级为深度研究

### 5.5 深度研究任务

- 面向开放式、多步骤研究
- 通过独立按钮显式触发
- 显式异步状态
- 具备 Table、Trace、Budget、Verification
- 最终输出是报告或草稿，而不是静默注入真值

### 5.6 产物任务

- 由右侧产物栏或系统动作触发
- 受控生成
- 结果带版本
- 输出可复用
- 需经过确认后才能回写为更稳定知识

### 5.7 记忆任务

- 面向长期可复用知识的门控晋升
- 会话、研究轨迹、产物都可提供信号
- 只有通过门控验证的内容才进入长期记忆
- 默认服务问答与右侧产物生成，不直接干预 Deep Research 主 loop

## 6. 建设顺序建议

### 6.1 统一底座

- 创建 Workspace 与 Topic Scope
- 创建 Source 模型
- 创建 Citation / Evidence 基础能力
- 创建 Async Task 基础能力

### 6.2 问答与 Note

- 实现 Ask 模式
- 实现 Conversation
- 实现 Note 保存与检索复用
- 实现右侧产物栏基础 UI

### 6.3 Wiki 模式

- 实现 Wiki Page 与 Version
- 打通链接、反向链接与引用
- 统一 Note / Wiki 存储规则

### 6.4 资料调查模式

- 实现调查主题容器
- 实现 SourceCard 列表
- 实现 SourceWindow 原文阅读
- 实现 Investigation Note

### 6.5 Deep Research 引擎

- 实现 Deep Research 按钮入口
- 实现 Research Run
- 实现 Research Table 与 Trace
- 跑通 Search -> Read -> Extract -> Verify loop
- 产出研究报告 Artifact

### 6.6 Artifact Runtime 与回写

- 实现 Artifact Job
- 实现默认 Production Action 与 Prompt Recipe
- 接入默认 Skill / MCP 能力声明
- 实现 Artifact Version
- 打通回写为 Note / Wiki 草稿

### 6.7 Graduated Memory

- 实现 Context Signal 抽取
- 实现 Memory Candidate 与门控晋升
- 在问答和产物生成中接入记忆回读
- 展示记忆来源、晋升记录与复用效果

### 6.8 前端打磨与演示闭环

- 统一工作台导航
- 对齐模式切换体验
- 展示进度、证据和版本链路
- 让整套系统可演示、可说明、可写入简历

## 7. 架构评审检查清单

在正式实现前，建议先确认以下问题：

1. `Topic Scope` 是否作为主题聚合边界落地
2. `Knowledge Item` 是否作为 Note / Wiki / Investigation Note 的共享存储基础
3. 调查模式与 Deep Research 的升级边界是否明确
4. 默认支持哪些 `Production Action`
5. 右侧产物栏的默认按钮集合是否锁定为报告 / 测验 / 学习指南 / FAQ
6. `Skill` 与 `Production Action` 的绑定方式是否固定
7. `Claim / Entity / Concept` 是否作为增强型结构化层设计
8. 旧项目迁移是数据迁移、逻辑迁移，还是仅作为设计参考

## 8. 最终总结

整套设计至少应保证以下闭环天然成立：

`资料进入工作区 -> 用户在问答 / Wiki / 调查中消费资料 -> 用户通过 Deep Research 按钮或右侧产物栏发起重型任务 -> 系统通过 Agent / Skill / MCP 能力栈生成可追溯结果 -> 结果经过确认回写为可沉淀知识 -> 高价值内容通过门控晋升为可复用长期记忆。`
