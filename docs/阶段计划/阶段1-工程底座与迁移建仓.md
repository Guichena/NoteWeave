# 阶段1：工程底座与迁移建仓

## 1. 阶段目标

阶段 1 不是做业务，而是把后面所有阶段都依赖的底座搭起来。

本阶段完成后，必须具备：

1. 工程可启动
2. 数据库可迁移
3. 中间件可连接
4. 最小接口可访问

## 2. 子阶段树

```text
1.1 工程初始化
1.2 数据库与中间件底座
1.3 最小接口壳子
```

## 3. 子阶段 1.1 工程初始化

### 目标

建立 `backend / frontend / workers` 的基础工程和统一启动方式。

### 优先迁移

1. 旧版 Spring Boot 基础配置
2. 旧版异常处理、日志、配置装载
3. 旧版前端基础工具链里可直接复用的环境配置

### TDD 要求

先写：

1. `backend` 启动测试
2. `frontend` 构建测试
3. `workers` 基础导入测试

再写：

1. Spring Boot 主工程
2. React + Vite 主工程
3. Python worker 基础目录与依赖

### 完成定义

1. 三端工程都能本地启动或构建
2. 基础 README 和启动命令明确

## 4. 子阶段 1.2 数据库与中间件底座

### 目标

搭好 `MySQL / Redis / Kafka / MinIO / Elasticsearch` 与 Flyway。

### 优先迁移

1. 旧版 Docker Compose 片段
2. 旧版数据库连接与存储配置
3. 旧版 Kafka / MinIO / ES client 初始化代码

### TDD 要求

先写：

1. Flyway 迁移测试
2. repository 基础集成测试
3. 中间件连接探测测试

再写：

1. `docker compose`
2. `V001-V006`
3. 基础 entity / repository

### 完成定义

1. `V001-V006` 全部可迁移
2. 基础表可增删查改
3. 本地中间件全部可连通

## 5. 子阶段 1.3 最小接口壳子

### 目标

先建可用接口壳子，为阶段 2 进入真实业务闭环做准备。

### 必须提供

1. 创建工作台
2. 创建上传事务
3. 创建会话
4. 查询任务状态

### TDD 要求

先写：

1. controller 契约测试
2. 参数校验测试
3. 基础鉴权测试

再写：

1. controller
2. request / response DTO
3. 最小 service 壳子

### 完成定义

1. 上面 4 个接口可访问
2. 返回字段符合最小接口契约

## 6. 本阶段禁止项

1. 不写真正的上传合并
2. 不写真正的问答逻辑
3. 不写 Research / Artifact 主链路
