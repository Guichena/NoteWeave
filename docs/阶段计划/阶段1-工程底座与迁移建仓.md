# 阶段1：工程底座与迁移建仓

## 1. 阶段目标

阶段 1 不是做业务，而是把后面所有阶段都依赖的底座搭起来。

本阶段完成后，必须具备：

1. 工程可启动
2. 数据库可迁移
3. 中间件可连接
4. 最小接口可访问

## 2. 与原始 NoteWeave Phase 的关系

原始 `改造计划/三模式知识工作台重构设计.md` 直接从产品能力开始写 `Phase 1：问答模式`。
当前阶段 1 属于这些产品 Phase 之前的技术预备层，作用是为后续原始 `Phase 1-4` 提供统一工程底座。

## 3. 子阶段树

```text
1.1 工程初始化
1.2 数据库与中间件底座
1.3 最小接口壳子
```

## 4. 子阶段 1.1 工程初始化

### 目标

建立 `backend / frontend / workers` 的基础工程和统一启动方式。

### 优先迁移

1. 旧版 Spring Boot 基础配置
2. 旧版异常处理、日志、配置装载
3. 旧版前端基础工具链里可直接复用的环境配置

### 推荐函数与类

Java：

1. `NoteWeaveApplication.main(args)`
2. `GlobalExceptionHandler.handleValidationException(ex)`
3. `ApiResponse.success(data)`

Frontend：

1. `App.tsx`
2. `routes.tsx`

Worker：

1. `app/main.py`
2. `app/config.py::load_settings()`

### 中间件接入

1. 当前只强依赖 `MySQL`
2. 先冻结环境变量：
   `SPRING_PROFILES_ACTIVE`
   `SPRING_DATASOURCE_URL`
   `SPRING_DATASOURCE_USERNAME`
   `SPRING_DATASOURCE_PASSWORD`

### TDD 要求

先写：

1. `backend` 启动测试
2. `frontend` 构建测试
3. `workers` 基础导入测试

再写：

1. Spring Boot 主工程
2. React + Vite 主工程
3. Python worker 基础目录与依赖

### 完成定义

1. 三端工程都能本地启动或构建
2. 基础 README 和启动命令明确

## 5. 子阶段 1.2 数据库与中间件底座

### 目标

搭好 `MySQL / Redis / Kafka / MinIO / Elasticsearch` 与 Flyway。

### 优先迁移

1. 旧版 Docker Compose 片段
2. 旧版数据库连接与存储配置
3. 旧版 Kafka / MinIO / ES client 初始化代码

2. `WorkspaceRepository.save(entity)`
3. `TaskRepository.save(entity)`
4. `OutboxRepository.save(entity)`
5. `StorageHealthIndicator.health()`

中间件连接层：

1. `KafkaProducerFactory.build()`
2. `MinioClientFactory.build()`
3. `ElasticsearchClientFactory.build()`

### 中间件接入

1. db：`noteweave`
2. user：`noteweave`
3. password：`noteweave123`
4. port：`3306`
5. 第一批 migration：`V001-V006`

Redis：

1. host：`localhost`
2. port：`6379`

Kafka：

1. broker：`localhost:9092`
2. 模式：`KRaft-only`

MinIO：

1. endpoint：`http://localhost:9000`
2. access key：`minioadmin`
3. secret key：`minioadmin`
4. bucket：
   `noteweave-source`
   `noteweave-derived`
   `noteweave-export`

Elasticsearch：

1. uri：`http://localhost:9200`
2. alias：
   `nw-source-chunk`

   `nw-artifact`

### TDD 要求

2. 基础表可增删查改
3. 本地中间件全部可连通

## 6. 子阶段 1.3 最小接口壳子

### 目标

先建可用接口壳子，为阶段 2 进入真实业务闭环做准备。

### 必须提供

1. 创建工作台
2. 创建上传事务
3. 创建会话
4. 查询任务状态
5. 查询任务事件流

### 推荐函数与类

Workspace：

1. `WorkspaceController.createWorkspace(req)`
2. `WorkspaceApplicationService.createWorkspace(cmd)`
3. `WorkspaceDomainService.newWorkspace(ownerId, name, description)`

Upload：

1. `UploadController.createUpload(req)`
2. `UploadApplicationService.createUploadSession(cmd)`

Conversation：

1. `ConversationController.createConversation(req)`
2. `ConversationApplicationService.createConversation(cmd)`

Task：

1. `TaskController.getTask(taskId)`
2. `TaskQueryService.getTaskStatus(taskId)`
3. `TaskController.streamTaskEvents(taskId)`

### 中间件接入

1. `MySQL` 承接工作台、上传事务、会话、任务基础对象
2. `Redis` 只预留幂等键和短期流状态，不在此子阶段提前实现复杂逻辑

### TDD 要求

先写：

1. controller 契约测试
2. 参数校验测试
3. 基础鉴权测试

再写：

1. controller
2. request / response DTO
3. 最小 service 壳子

### 完成定义

1. 上面 5 个接口可访问
2. 返回字段符合最小接口契约

## 7. 本阶段禁止项

1. 不写真正的上传合并
2. 不写真正的问答逻辑
3. 不写 Research / Artifact 主链路
