## 知识内容补强说明

总稿提供可直接使用的完整回答；`08-知识深挖库` 补充原理、项目落点、失败场景、Trade-off 和可验证指标。各技术主题对应的项目场景如下：

```text
Research / QA
  → LLM + RAG + Agent
资料底座
  → Kafka + Outbox + MySQL + 对象存储
任务治理
  → Java 并发 + Redis + Lease/Fencing
可靠性
  → OpenTelemetry + SLO + Replay + Fault Injection
```

## 项目的直接回答

> NoteWeave 面向个人资料研究和长期知识沉淀。我负责的核心问题，是让资料、模型生成和长任务结果都能说明来源、版本和提交条件。Java Host 保存 Workspace 权限、Source Snapshot、任务状态和最终 Version，Python Worker 主要执行 Research、Artifact 等模型与工具长任务，并提交候选。资料处理通过 Outbox 与 Kafka 异步推进，QA、Note、Wiki 分别按证据回答、连续阅读和版本化页面组织资料。Research 把开放问题收敛成逐字段可验证的 Cell，Artifact 把内容验收与文件交付分开，Memory 只提供偏好和稳定约束，不替资料事实提供引用。这样即使出现重复消息、旧 Worker 晚到、引用不足或文件上传结果不明，系统也有明确的状态、对账和恢复路径。

完整系统链路见 [总稿第 13.8 节](NoteWeave面试总稿-STAR重构版-2026.06-2026.09.md#138-完整跨模块回答从一份资料到可信的研究产物)；五条亮点各自的 5 分钟回答在总稿第 1 至 5 章。

## 统一面试口径

工程化改造、联调发现、离线回放和目标架构处在不同的证据层级。总稿分别说明每条亮点的设计动机、具体链路、失败处理、代价和迁移触发条件，不把目标方案写成当前生产能力。

简历主入口不保留未填写的百分比。只有评测 Manifest、分母和基线齐备时，数字证据卡与简历才填写结果；目前固定 Fixture 只用于消融和回归，不代表线上收益。数据对象、状态转换、幂等、权限和恢复的细节以总稿为准。

## 面试主线

一句话：

> NoteWeave 不是把大模型接到资料库，而是把资料研究拆成可追溯的事实、可恢复的长任务和受约束的模型执行，让每个产物都能解释来源、失败原因和恢复路径。

五条亮点的因果关系是：

```text
资料接入与版本化
    ↓
QA / Note / Wiki 按任务组织证据
    ↓
Research 将开放问题收敛为可验证状态
    ↓
Artifact 将模型能力收敛为 Schema 和 Skill
    ↓
Context / Memory 管理长期交互，但不污染资料证据
```
