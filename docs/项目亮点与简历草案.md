# 项目亮点与简历草案

## 1. 核心项目亮点

这版简历叙事建议优先突出几个最有辨识度的工程亮点：

1. 基于 TAS 思路的 Deep Research 智能体
2. 受控式产物生成 Agent
3. RAG / Wiki / Note 一体化知识工作流
4. Memory 化的知识沉淀闭环
5. 文件上传与存储基础设施

### 亮点 1：基于 TAS 的 Deep Research 智能体

设计 Deep Research 智能体，核心借鉴 `Table-as-Search` 思路，将开放式研究问题转化为动态表格补全任务；通过 `Research Plan -> Research Table -> Search -> Read -> Extract -> Verify -> Report` 的受控循环，把研究过程从一次性生成升级为可追踪、可验证、可沉淀的长任务系统。

这部分最值得强调的关键词：

- Table-as-Search
- Loop Engineering
- Goal-conditioned Reading
- Cell-level Evidence Verification
- Research Trace

### 亮点 2：受控式异步产物生成 Agent

设计面向报告、测验、学习指南、FAQ、Wiki 草稿、视频总结等场景的产物生成 Agent，采用 `Production Action + Prompt Recipe + Artifact Runtime` 的统一主链路，把不同类型的生成任务抽象为可配置 Action，而不是为每个功能单独写一套硬编码流程。

这部分最值得强调的关键词：

- Controlled Agentic Graph Harness
- Production Action
- Prompt Recipe
- Artifact Job / Artifact Version
- Verifier / Repair

### 亮点 3：RAG / Wiki / Note 一体化知识工作流

将日常问答 RAG、阶段性 Note 沉淀和长期 Wiki 知识编织统一到同一工作区模型下，使系统既能支持低延迟问答，也能支持结构化知识整理与后续复用，而不是把聊天、笔记、Wiki 拆成彼此割裂的三套系统。

这部分最值得强调的关键词：

- Document RAG
- Note Retrieval
- Full Wiki
- Citation-backed Knowledge
- Unified Workspace

### 亮点 4：Memory 化的知识沉淀闭环

将 Source、Citation、Artifact Version 与 Research Trace 统一为共享证据层，并进一步把结果沉淀能力升级为 `Memory` 视角：让问答结果、调查结论、研究报告和产物草稿都能在显式确认后进入长期可复用的知识记忆体系，而不是停留在一次性回答或孤立文档。

这部分最值得强调的关键词：

- Evidence-backed Writeback
- Long-term Memory
- Knowledge Promotion
- Note / Wiki / Artifact / Memory Flow

### 亮点 5：文件上传、Kafka 与 MinIO 支撑的资料基础设施

围绕知识工作台的资料底座，设计文件上传、对象存储和异步处理链路：上传阶段支持分片与状态管理，原始文件统一落到 MinIO / 对象存储，解析、索引和后处理任务通过 Kafka 一类异步消息链路解耦，使文件导入、快照保留、解析和检索准备具备更稳定的工程基础。

这部分最值得强调的关键词：

- Multipart Upload
- MinIO Object Storage
- Kafka Async Pipeline
- File Snapshot
- Parsing / Indexing Pipeline

## 2. 简历长版表述

主导新一代 AI 知识工作台的架构设计，重点实现五个方向：一是基于 Table-as-Search 思路设计 Deep Research 智能体，将开放式研究问题建模为带外部表格状态、证据绑定、字段级验证和执行轨迹的长任务系统；二是设计受控式异步产物生成 Agent，将报告、测验、学习指南、FAQ 和 Wiki 草稿等能力统一抽象为 Production Action，并通过 Artifact Runtime 完成受控生成；三是打通 Document RAG、Note Retrieval 与 Full Wiki 的一体化知识工作流；四是构建从问答、研究、产物到长期 Memory 的知识沉淀闭环；五是围绕文件上传、Kafka 异步处理链路和 MinIO 对象存储设计底层资料基础设施，支撑文件快照、解析与索引准备。

## 3. 简历中版表述

设计统一的 AI 知识工作台，核心包含五个方向：基于 TAS 的 Deep Research 智能体、受控式异步产物生成 Agent、RAG / Wiki / Note 一体化知识工作流、面向长期 Memory 的知识沉淀闭环，以及基于文件上传、Kafka、MinIO 的资料基础设施。前者负责开放式研究与结构化生成，后者负责知识组织、结果沉淀和底层资料处理链路。

## 4. 简历短版表述

设计 AI 知识工作台，重点实现基于 Table-as-Search 的 Deep Research 智能体、受控式产物生成 Agent、RAG / Wiki / Note 一体化工作流，以及基于 Kafka 和 MinIO 的文件资料处理底座。

## 5. 面试安全表述

建议优先使用以下措辞：

- `designed`
- `defined`
- `built MVP of`
- `implemented prototype for`
- `modeled as`
- `rebuilt around`

在实际实现完成前，建议避免使用以下表述：

- `fully productionized`
- `completed autonomous research system`
- `already replaced the old system in production`
- `delivers stable enterprise-grade collaboration`

## 6. 面向原型交付的目标

第一版原型至少要足以支撑下面这句描述，并且能够真实成立：

`Built a prototype of an AI knowledge workbench centered on a TAS-based Deep Research agent, a controlled artifact-generation agent, a unified RAG / Wiki / Note workflow, long-term memory-oriented knowledge writeback, and a file ingestion pipeline backed by Kafka and MinIO.`
