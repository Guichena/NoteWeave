# 项目亮点与简历草案

## 项目经历

**NoteWeave｜AI 研究与知识工作台**　　　　　　　　　　　　　　　　　　　　　　　　　**2026.01 - 2026.05**

**核心技术：** `Spring Boot` `MySQL` `Redis` `Kafka` `Elasticsearch` `MinIO` `Python` `MCP`

**项目描述：** 面向个人研究与知识沉淀场景构建 AI 工作台，覆盖多类型资料接入、场景化 RAG、Deep Research、受控内容生成与长期记忆，并以 Java 工程底座和 Python Agent Runtime 协同承载检索、研究和生成类长耗时任务。

**核心职责与贡献：**

1. **设计验证驱动的 Deep Research Agent：** 采用 `Verification-Centric Research` 架构，以 `Table-as-State` 统一组织研究对象、字段、证据与结论；当前可执行主路径由 `DEEP_CELL` 与高风险 `COUNTERFACTUAL` 任务通过 Checkpoint、Citation Audit、Cell Merge CAS 与 Fencing Token 闭环推进，Local/Global Verifier、Wide Discovery、Evidence Audit 与 Synthesis 作为受控角色契约和阶段设计逐步接入，避免把未调度角色描述成已全量生产运行。

2. **构建任务感知的场景化 RAG：** 针对快速问答、资料深读和知识沉淀分别设计 QA、Note、Wiki 三条检索链路：QA 采用 BM25、Vector、RRF 与 Rerank 多阶段排序，Note 采用资料级粗排和原文窗口精读，Wiki 结合页面关系与来源回链组织知识；在 6 条内部 Gold 样本的小型确定性 fixture 回放中，单路方案的 Recall@K 与 Citation Coverage 为 33.3% 至 66.7%，QA/Note 组合变体为 100%，Scope Violation 为 0。该数字用于回归和口径约束，不等同于当前在线 Elasticsearch / Embedding / Rerank / LLM provider 的实测指标。

3. **搭建高可靠的事件驱动资料底座：** 基于 MySQL、MinIO、Kafka 与 Elasticsearch 构建原文件、业务状态和检索索引分离的资料架构，将上传后的解析、切片、向量化与索引投影转为异步任务；通过 Transactional Outbox、幂等消费、退避重试和死信重驱保障最终一致性，支持 128 MB 单文件接入，避免大文件处理阻塞业务请求。

4. **构建工程化 Agent 执行框架：** 将报告、测验、学习指南等生成能力抽象为 Schema 驱动的 Skill Graph，以稳定输入输出契约约束 Agent 执行，并通过内置 MCP 扩展外部资料与工具能力；采用 Java Host / Python Worker 分层承载业务编排和智能执行，结合 Redis 令牌桶、并发租约与任务状态持久化，实现 Workspace 级限流、资源隔离、水平扩展和故障恢复。

5. **设计面向长任务的 Context Engineering 与 Memory 体系：** 采用 Topic-aware Window 与增量摘要压缩长会话，只重算受新增消息影响的上下文片段；通过候选提取、门控晋升和版本化管理沉淀长期 Memory，并将短期会话、用户记忆与资料证据分层隔离，在保持跨任务个性化连续性的同时，避免偏好信息进入 RAG 引用和事实证据链。
