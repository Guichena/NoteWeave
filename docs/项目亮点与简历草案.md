# 项目亮点与简历草案

## 1. 核心项目亮点

这版简历叙事建议优先突出几个最有辨识度的工程亮点：

1. Deep Research 智能体
2. 受控式产物生成 Agent
3. RAG / Wiki / Note 一体化知识工作流
4. Graduated Memory 记忆晋升机制
5. 文件上传与存储基础设施

建议控制在这五个亮点以内，不再额外展开“大而全平台能力”，否则会削弱叙事重心，也会抬高实现与面试解释成本。

### 亮点 1：Deep Research 智能体

面向复杂开放式研究任务中状态易漂移、路径易跑偏、结果难验证的问题，设计 Deep Research 智能体，提出**验证驱动的 Research Harness**，将研究、读取、验证与修正组织为受控的 **Closed-Loop Research**；系统以 `Table-as-State` 管理研究状态，以 `Dual Verifier` 控制验证闭环，并通过**反证分支**进行路径纠偏。

这部分最值得强调的关键词：

- Research Harness
- Closed-Loop Research
- Table-as-State
- Dual Verifier
- 反证分支

### 亮点 2：受控式异步产物生成 Agent

设计面向报告、测验、学习指南、FAQ、Wiki 草稿、视频总结等场景的产物生成 Agent，采用 `Production Action + Style Profile + Skill Graph + Artifact Runtime` 的统一主链路，把不同类型的生成任务抽象为可配置 Action；进一步通过 `Schema-Gated Skill Graph Runtime` 约束执行计划、通过 `Capability Union Policy` 管理用户自定义 MCP 的组合权限风险，使系统既能支持风格配置和能力扩展，又不会滑向失控的通用 Agent 平台。

这部分最值得强调的关键词：

- Controlled Agentic Graph Harness
- Schema-Gated Skill Graph Runtime
- Production Action
- Style Profile
- Skill Graph
- Capability Union Policy
- Artifact Job / Artifact Version
- Verifier / Repair

### 亮点 3：RAG / Wiki / Note 一体化知识工作流

将日常问答 RAG、阶段性 Note 沉淀和长期 Wiki 知识编织统一到同一工作区模型下，使系统既能支持低延迟问答，也能支持结构化知识整理与后续复用，而不是把聊天、笔记、Wiki 拆成彼此割裂的三套系统。

这部分最值得强调的关键词：

- Document RAG
- Source-Grounded Note Flow
- Wiki Mode
- Citation-backed Knowledge
- Unified Workspace

### 亮点 4：Graduated Memory 记忆晋升机制

设计 `Graduated Memory` 机制，把聊天记录、Deep Research 轨迹、已确认产物视为不同置信度的记忆来源：会话与研究过程先被抽取为可衰减的 `Context Signals`，用于帮助系统理解用户偏好、研究意图和当前任务背景；报告、FAQ、测验、Wiki 草稿等“已生成且被确认的产物”优先形成更稳定的 `Memory Candidates`；最终只有同时通过 `Novelty Gate` 与 `Task Neighborhood Validation` 的内容，才会被晋升为跨任务可复用的 `Memory Object`。这样系统既不会浪费聊天和研究过程里的高价值线索，也不会把未验证对话直接固化成长期知识。

这部分最值得强调的关键词：

- Graduated Memory
- Context Signals
- Memory Candidate
- Dual-Gate Promotion
- Memory Object
- Reusable Knowledge Promotion

### 亮点 5：文件上传、Kafka 与 MinIO 支撑的资料基础设施

围绕知识工作台的资料底座，设计文件上传、对象存储和异步处理链路：上传阶段支持分片与状态管理，原始文件统一落到 MinIO / 对象存储，解析、索引和后处理任务通过 Kafka 一类异步消息链路解耦，使文件导入、快照保留、解析和检索准备具备更稳定的工程基础。

这部分最值得强调的关键词：

- Multipart Upload
- MinIO Object Storage
- Kafka Async Pipeline
- File Snapshot
- Parsing / Indexing Pipeline

## 2. 简历长版表述

主导新一代 AI 知识工作台的架构设计，重点实现五个方向：一是设计 Deep Research 智能体，将开放式研究问题建模为带外部表格状态、证据绑定、分支轨迹和验证闭环的长任务系统，并以 `Verification-Centric Research Harness`、`Table-as-State`、`Dual Verifier`、`Counterfactual Branching`、`Adaptive Evidence Horizon`、`Conflict-Scoped Recovery`、`Verifier-Gated Synthesis`、`Full-Horizon Plan + Lazy Replanning`、`Premature Commitment Guard` 和 `Stop Contract` 提升长程研究任务的可靠性、可恢复性与路径控制能力；二是设计受控式异步产物生成 Agent，将报告、测验、学习指南、FAQ 和 Wiki 草稿等能力统一抽象为 Production Action，并进一步引入 `Style Profile`、`Skill Graph`、`Schema-Gated Skill Graph Runtime` 和 `Capability Union Policy`，在支持用户风格配置与用户自定义 MCP 的同时保持编排可控；三是以研究工作台为基本单位打通共享资料池、多次聊天、`Source-Grounded Note Flow` 与 Wiki-first 回答链路，让资料理解、草稿整理、正式知识沉淀与后续追问形成同一主链路；四是设计参考 UMEM、ChatGPT Memory 与 Gemini Personal Context 思路的 `Graduated Memory` 机制，让聊天和研究过程提供记忆信号、让已确认产物形成高质量记忆候选，并通过 `Novelty Gate + Task Neighborhood Validation` 控制长期记忆晋升；五是围绕文件上传、Kafka 异步处理链路和 MinIO 对象存储设计底层资料基础设施，支撑文件快照、解析与索引准备。工程实现上采用 `Java` 主系统承接研究工作台、三种聊天链路、业务真源与任务编排，并将 `Deep Research` 与受控式产物生成分别拆为独立 `Python Worker` 执行器，以兼顾主系统稳定性与智能体执行链路的实验效率。

## 3. 简历中版表述

设计统一的 AI 知识工作台，核心包含五个方向：基于 `Verification-Centric Research Harness` 的 Deep Research 智能体、采用 `Schema-Gated Skill Graph Runtime` 的受控式异步产物生成 Agent、RAG / Wiki / Note 一体化知识工作流、基于 `Graduated Memory` 的长期知识沉淀机制，以及基于文件上传、Kafka、MinIO 的资料基础设施。前者负责开放式研究与结构化生成，后者负责知识组织、结果沉淀和底层资料处理链路。

## 4. 简历短版表述

设计 AI 知识工作台，重点实现基于 `Verification-Centric Research Harness` 的 Deep Research 智能体、采用 `Schema-Gated Skill Graph Runtime` 的受控式产物生成 Agent、RAG / Wiki / Note 一体化工作流，以及基于 Kafka 和 MinIO 的文件资料处理底座。

- `designed`
- `defined`
- `built prototype of`
- `implemented prototype for`

- `fully productionized`

## 6. Memory 实现参考

如果后面真要把 Memory 这一块做出来，优先参考下面四类源码即可，不建议一开始铺得太大：

- UMEM：看“记忆提取 + 记忆管理”如何联动，适合借鉴候选记忆抽取、冲突检测和分层写入思路。`https://github.com/AIDC-AI/Marco-DeepResearch/tree/main/Marco-DeepResearch-Family/UMEM`
- A-MEM：看长期记忆如何组织、链接和演化，适合借鉴记忆对象结构设计。`https://github.com/agiresearch/A-mem`
- PlugMem：看如何把原始交互抽象成可复用知识单元，适合借鉴“不要存原始历史，要存可复用知识”的思路。`https://github.com/TIMAN-group/PlugMem`
- AWS AgentCore Memory MCP Sample：看 namespace、项目隔离和工程接入方式，适合借鉴系统落地。`https://github.com/aws-samples/sample-amazon-bedrock-agentcore-memory-mcp-server`
