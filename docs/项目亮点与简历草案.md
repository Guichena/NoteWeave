# 项目亮点与简历草案

## 1. 核心项目亮点

第一版简历叙事建议只聚焦五个最有力的系统亮点。

### 亮点 1：NotebookLM 风格的三模式统一知识工作台

将产品从原有拆分的 `team/personal` 模式重构为统一的用户工作区，并参考 NotebookLM 的产品形态，把用户可见能力收敛为 `问答`、`Full Wiki`、`资料调查` 三种工作模式，同时提供右侧产物按钮栏。

### 亮点 2：Full Wiki 知识编织体系

设计 `Full Wiki` 系统，将知识视为由页面、链接、反向链接、引用和可修复关系组成的长期维护网络，而不是扁平的笔记列表。

### 亮点 3：Deep Research 独立入口与资料调查联动

设计以 `SourceCard -> SourceWindow -> Investigation Note` 为核心的资料调查模式，并提供独立的 `Deep Research` 按钮入口，把开放式研究建模为带表格状态、证据绑定、验证循环和执行轨迹的显式任务系统，其结果可回流到问答、Wiki 与调查三种模式中。

### 亮点 4：右侧产物按钮栏与受控式异步 Artifact Runtime

构建类似 NotebookLM 的右侧产物按钮栏与受控异步生成框架，将报告、测验、学习指南、FAQ、Wiki 草稿和音视频总结等能力抽象为 `Production Action`，通过统一主链路执行而不是依赖黑盒式一次性 Prompt。

### 亮点 5：Agent / Skill / MCP 驱动的证据优先回写链路

将 Source、Citation、Artifact Version 与 Research Trace 统一为共享证据层，并通过 Agent、Skill 与 MCP 组成的能力栈驱动复杂生成与研究任务，使问答结果、调查结论和生成产物都可以通过显式确认安全回写为 Note、Wiki 草稿或调查结论。

## 2. 简历长版表述

主导新一代 AI 知识工作台的架构设计，将产品从分离的团队版与个人版体系重构为统一的用户工作区，并参考 NotebookLM 的交互形态设计主工作区与右侧产物按钮栏。新架构把用户可见能力收敛为问答、Full Wiki 与资料调查三种工作模式，同时提供独立的 Deep Research 按钮入口，并在底层接入受控式异步 Artifact Runtime 与 Agent / Skill / MCP 能力栈。系统强调 Source、Citation、Research Run、Artifact Version 与 Wiki Page 之间的证据优先链路，使复杂研究与内容生成结果能够被审计、修订并通过显式回写沉淀为稳定知识。

## 3. 简历中版表述

设计了一套统一的 AI 知识工作台，在单一用户工作区模型下整合问答、Full Wiki、资料调查、Deep Research、右侧产物按钮栏与版本化 Artifact 生成。系统将低延迟问答与长时研究任务解耦，用 Topic Scope、Evidence、Version、Async Task 和 Agent / Skill / MCP 能力栈将不同模式收拢为同一领域模型，并通过受控回写把调查与生成结果沉淀为可维护知识。

## 4. 简历短版表述

设计统一的 AI 知识工作台，围绕三模式入口、Deep Research 独立按钮、右侧产物按钮栏、受控 Artifact Runtime 和 Agent / Skill / MCP 能力栈，重构用户中心的知识沉淀体系。

## 5. 面试安全表述

建议优先使用以下措辞：

- `designed`
- `defined`
- `built MVP of`
- `implemented prototype for`
- `modeled as`
- `rebuilt around`

在实际实现完成前，建议避免使用以下表述：

- `fully productionized`
- `completed autonomous research system`
- `already replaced the old system in production`
- `delivers stable enterprise-grade collaboration`

## 6. 面向原型交付的目标

第一版原型至少要足以支撑下面这句描述，并且能够真实成立：

`Built a prototype of a unified AI knowledge workbench where ask, wiki, and investigation flows share one user workspace, one evidence layer, one async execution model, and one explicit writeback path into durable knowledge.`
