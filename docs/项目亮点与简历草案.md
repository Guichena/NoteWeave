## 1. 核心项目亮点

这版简历叙事建议优先突出几个最有辨识度的工程亮点：

1. Deep Research 智能体
2. 受控式产物生成 Agent
3. 三检索链路一体化知识工作流
4. 分层压缩与可回放的长会话上下文
5. 可治理的 Durable Memory Runtime
6. 文件上传与存储基础设施

建议围绕这六个亮点组织项目描述，不再额外展开“大而全平台能力”。实际投递时可按岗位删减到四至五项，但三检索链路、长会话治理和 Memory 不应合并成同一条。

### 亮点 1：Deep Research 智能体

面向复杂开放式研究任务中状态易漂移、路径易跑偏、结果难验证的问题，实现 verification-oriented Deep Research 工程原型：以 Research Harness 骨架组织 Planner / Search / Fetch / Read / Extract / Verify / Report，并建立结构化研究状态、分层验证和恢复决策对象。`Table-as-State` 真源、独立 `Dual Verifier` 和可裁决反证分支是当前正在完成的核心目标。

这部分最值得强调的关键词：

- Research Harness
- Closed-Loop Research
- Table-as-State
- Dual Verifier
- 反证分支

### 亮点 2：受控式异步产物生成 Agent

设计面向报告、测验、学习指南、Wiki 页面、Note 文档与课程讲义 PDF 的 Skill-first 产物生成 Agent：对外以 schema-driven Skill、Artifact Job / Version 提供稳定产品契约，对内以 `ExecutionSpec + Skill Graph + Artifact Runtime` 编译受控执行计划；通过 `Schema-Gated Skill Graph Runtime` 和 `Capability Union Policy` 约束系统内置 MCP/provider 编排，并以 owner-scoped outbox lease、dead-letter/redrive、waiting/resume、Verifier/Repair、终态幂等、同 Job 追加版本和 typed runtime trace 支撑可恢复、可审计的异步长任务。生成的 Markdown/PDF 统一归档到对象存储并记录 checksum/file metadata，Java Host 显式承接资料、Note/Wiki 写回和服务间认证边界。

这部分最值得强调的关键词：

- Controlled Agentic Graph Harness
- Schema-Gated Skill Graph Runtime
- Internal Production Action
- Internal Style Profile
- Skill Graph
- Capability Union Policy
- Artifact Job / Artifact Version
- Verifier / Repair
- Owner-scoped Outbox Lease / Dead Letter
- Typed Runtime Trace
- Object Storage File Metadata
- System MCP only

### 亮点 3：三检索链路一体化知识工作流

面向同一研究工作台中的快速证据问答、资料深读和长期知识组织，设计三条差异化检索链路：QA 链路采用 Query Rewrite、Hybrid Recall、Rerank 和 Evidence Budget 完成低延迟文档 RAG；Note 链路以资料级候选、Marginalia 式侧记召回和原文邻域窗口保留局部阅读语境；Wiki 链路围绕页面、索引、双向链接、图邻域、版本和来源回链组织全量知识网络。三条链路共用 AnswerRun、Citation 和 Retrieval Trace 契约，但分别维护检索计划、证据结构和 Token Budget，使用户在同一聊天入口切换模式时，系统不会把三类问题压成一套通用向量检索。

这部分最值得强调的关键词：

- Document RAG / Hybrid Recall / Rerank
- Evidence Budget
- Marginalia Retrieval
- Source-level Candidate / Original-text Window
- Wiki Index / Bidirectional Link / Graph Neighborhood
- Citation-backed Knowledge
- Mode-specific RetrievalPlan

### 亮点 4：分层压缩与可回放的长会话上下文

面向一个 Workspace 下多个 Conversation 及单会话百轮连续追问，设计 Raw Message Ledger、Topic-aware Segment、Segment Summary Revision 和 Recent Raw Tail 四层上下文结构。系统以 Token 水位为主触发器进行异步预压缩和请求前同步补偿，只重算受新消息影响的尾部 Segment；摘要中的决策、约束和纠正逐项绑定原始 Message 与内容哈希，Context Compiler 再按活动历史头、相关 Segment、显式 Pin 和 Token Budget 组装本轮上下文。每次执行固化 RunInputSnapshot、消息截止序号、摘要版本和实际 Token Ledger，在控制 Context Rot 与长上下文成本的同时，保留从摘要回读原文、失败降级和输入级回放能力。

这部分最值得强调的关键词：

- Raw Message Ledger
- Topic-aware Segment
- Incremental Summary Revision
- Recent Raw Tail
- Token-triggered Compaction
- Active History Head
- Context Compiler / Token Ledger
- RunInputSnapshot / Input Replay

### 亮点 5：可治理的 Durable Memory Runtime

设计独立于聊天历史和 RAG 事实库的 Durable Memory Runtime，统一承接 Answer、Research 与 Artifact 的长期行为记忆。系统按 USER / WORKSPACE 隔离偏好、规范、已确认决策、负向约束和 Episode Pointer，以 Scope-aware Slot、MemoryItem / MemoryRevision 双状态机管理写入、冲突、审核、替换和删除；通过可解释 Rank、类型化 MemoryPack 与 Token Budget 控制召回，并以 TTL / Stale、Run Feedback 离线评测、用户 Memory Inspector 和上下文投毒防护抑制陈旧记忆、错误强化与跨 Workspace 污染。三条业务链路只提交幂等 ExecutionObservation，Canonical Memory 由 MemoryRuntime 单点写入，Memory 保留 Provenance 但不进入事实引用链。

这部分最值得强调的关键词：

- Durable Memory Runtime
- USER / WORKSPACE Scope
- Scope-aware Slot
- MemoryItem / MemoryRevision
- Explainable Recall / Token Budget
- TTL / Stale / Human Review
- Observation-only Write Path
- Memory Poisoning Defense
- Memory Inspector

### 亮点 6：文件上传、Kafka 与 MinIO 支撑的资料基础设施

围绕知识工作台的资料底座，设计文件上传、对象存储和异步处理链路：上传阶段支持分片与状态管理，原始文件统一落到 MinIO / 对象存储，解析、索引和后处理任务通过 Kafka 一类异步消息链路解耦，使文件导入、快照保留、解析和检索准备具备更稳定的工程基础。

这部分最值得强调的关键词：

- Multipart Upload
- MinIO Object Storage
- Kafka Async Pipeline
- File Snapshot
- Parsing / Indexing Pipeline

## 2. 简历长版表述

> 本节 Research Agent 口径已于 2026-07-12 按 M0-M4 最终实现复审；必须保留“有界顺序反证”“内部评测”“受限混合 citation verifier”等边界，详细证据见能力覆盖文档。

主导新一代 AI 知识工作台的架构设计，重点实现六个方向：一是设计 Deep Research 智能体，将开放式研究问题建模为带外部表格状态、证据绑定、分支轨迹和验证闭环的长任务系统，并以 `Verification-Centric Research Harness`、`Table-as-State`、`Dual Verifier`、`Counterfactual Branching`、`Adaptive Evidence Horizon`、`Conflict-Scoped Recovery`、`Verifier-Gated Synthesis`、`Full-Horizon Plan + Lazy Replanning`、`Premature Commitment Guard` 和 `Stop Contract` 提升长程研究任务的可靠性、可恢复性与路径控制能力；二是实现 Skill-first 受控式异步产物生成 Agent，以稳定 Skill/Job/Version 契约承接报告、测验、学习指南、FAQ、Wiki、Note 与课程讲义 PDF，并通过 `ExecutionSpec`、`Skill Graph`、`Schema-Gated Skill Graph Runtime`、`Capability Union Policy`、owner-scoped outbox lease、dead-letter/redrive、waiting/resume、Verifier/Repair、同 Job 追加版本和 typed runtime trace 管理系统内置能力的编排风险；三是设计 QA、Note、Wiki 三条差异化检索链路，分别以 Hybrid Recall + Rerank + Evidence Budget、Marginalia 侧记召回 + 原文邻域窗口、Wiki 索引 + 双向链接 + 图邻域组织快速问答、资料深读和长期知识网络，并统一固化 RetrievalPlan、Citation 与 Retrieval Trace；四是设计面向百轮连续追问的分层上下文架构，以 Raw Message Ledger、Topic-aware Segment、增量 Summary Revision 和 Recent Raw Tail 管理长会话，通过 Token-triggered Compaction、活动历史头、显式 Pin、Context Compiler、RunInputSnapshot 与 Token Ledger 控制 Context Rot、支持原文回读和输入级回放；五是设计独立于聊天历史和 RAG 事实库的 Durable Memory Runtime，以 USER / WORKSPACE Scope、Scope-aware Slot 和 MemoryItem / MemoryRevision 双状态机治理偏好、规范、已确认决策、负向约束与 Episode Pointer，通过可解释 Rank、Token Budget、TTL / Stale、Human Review、Observation-only 写入和上下文投毒防护统一服务 Answer、Research 与 Artifact，同时保持 Memory Provenance 与事实证据链隔离；六是围绕文件上传、Kafka 异步处理链路和 MinIO 对象存储设计底层资料基础设施，支撑文件快照、解析与索引准备。工程实现上采用 `Java` 主系统承接研究工作台、聊天与 Memory 业务真源和任务编排，并将 `Deep Research` 与受控式产物生成分别拆为独立 `Python Worker` 执行器。

## 3. 简历中版表述

设计统一的 AI 知识工作台，核心包含六个方向：基于 `Verification-Centric Research Harness` 的 Deep Research 智能体、采用 `Schema-Gated Skill Graph Runtime` 的受控式异步产物生成 Agent、面向 QA / Note / Wiki 的三条差异化检索链路、采用 Segment Summary Revision + Recent Raw Tail + RunInputSnapshot 的长会话上下文治理、基于 Scope / Slot / Revision / TTL / Human Review 的 Durable Memory Runtime，以及基于文件上传、Kafka、MinIO 的资料基础设施。

## 6. Memory 实现参考

实施这次 Memory 重构时，优先参考下面四类源码，不在第一阶段扩展成通用 Memory Agent 平台：

- UMEM：看“记忆提取 + 记忆管理”如何联动，适合借鉴候选记忆抽取、冲突检测和分层写入思路。`https://github.com/AIDC-AI/Marco-DeepResearch/tree/main/Marco-DeepResearch-Family/UMEM`
- A-MEM：看长期记忆如何组织、链接和演化，适合借鉴记忆对象结构设计。`https://github.com/agiresearch/A-mem`
- PlugMem：看如何把原始交互抽象成可复用知识单元，适合借鉴“不要存原始历史，要存可复用知识”的思路。`https://github.com/TIMAN-group/PlugMem`
- AWS AgentCore Memory MCP Sample：看 namespace、项目隔离和工程接入方式，适合借鉴系统落地。`https://github.com/aws-samples/sample-amazon-bedrock-agentcore-memory-mcp-server`
