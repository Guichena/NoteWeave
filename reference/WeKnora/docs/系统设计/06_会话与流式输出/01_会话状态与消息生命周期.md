# 会话状态与消息生命周期

## 总体思路

WeKnora 的会话不仅保存聊天内容，还承载 Agent 路由、知识范围、置顶状态、清空策略和批量管理能力。

## 关键模块

- `internal/handler/session/handler.go`
  - `CreateSession()`
  - `GetSession()`
  - `GetSessionsByTenant()`
  - `UpdateSession()`
  - `DeleteSession()`
  - `ClearSessionMessages()`
  - `BatchDeleteSessions()`
  - `PinSession()`
  - `UnpinSession()`
- `internal/application/repository/session.go`
- `internal/stream/redis_manager.go`
- `internal/stream/memory_manager.go`

## 为什么这样设计

会话如果只是聊天记录，就无法支撑长任务、流式消息和可恢复对话。WeKnora 用会话把“问答上下文”变成可管理对象。

## tradeoff

- **Redis**：适合短期状态和分布式运行。
- **MySQL/持久库**：适合历史记录和稳定保存。
- **内存管理器**：简单，但不适合多实例。

## 面试追问

### 1. 为什么状态不能全放内存？

因为多实例部署和重启场景下会丢失状态。对话系统一旦丢状态，用户感知会非常差，所以必须把稳定状态落到持久层或共享状态层。

### 2. 为什么要有置顶和批量删除？

这是用户管理会话空间的基本需求。知识工作台里的会话不是聊天记录仓库，而是任务容器，应该能像文件夹一样管理。

### 3. 会话里的“摘要”有什么意义？

摘要用于延续上下文、减少 token 压力，也用于会话恢复时快速找回任务语境。它不是代替原始消息，而是对历史状态的压缩表示。
