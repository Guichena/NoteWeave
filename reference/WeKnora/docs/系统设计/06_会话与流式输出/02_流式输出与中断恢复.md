# 流式输出与中断恢复

## 总体思路

WeKnora 的流式链路不是简单把 token 往前端推，而是要把 Agent 事件、工具调用、停止信号和恢复状态统一起来处理。

## 关键模块

- `internal/handler/session/stream.go`
  - `ContinueStream()`
  - `StopSession()`
  - `handleAgentEventsForSSE()`
- `internal/stream/factory.go`
- `internal/stream/redis_manager.go`

## 为什么这样设计

用户在复杂任务中经常要中断、补充、切换话题或恢复上一段回答。没有中断恢复，流式输出只是“看起来更快”，不是“真的更好用”。

## tradeoff

- **单向流式**：实现简单，但交互能力弱。
- **可恢复流式**：状态复杂，但更接近真实工作流。
- **事件化输出**：前端实现稍复杂，但利于调试和回放。

## 面试追问

### 1. 为什么要把停止能力设计成一等公民？

因为用户在长回答里经常会发现方向不对。能停下来，说明系统不是黑盒，用户也更敢在系统里进行复杂任务。

### 2. 为什么要事件化而不是只推文本？

因为 Agent 的真实过程包括检索、工具调用、重试、失败和恢复。只推文本会丢掉这条“系统怎么想”的链路。

### 3. 如果回答被中断，怎么恢复？

不是简单续写一段文本，而是恢复会话上下文和生成状态。恢复是否成功，关键看前面是否保存了可恢复的事件和会话信息。
