# 主系统全面代码审查问题清单与修复计划

日期：2026-07-16  
范围：`NoteWeave-v2` 的 Java 主系统、前端和部署配置；覆盖 QA、Note、Wiki 三种检索链路及其共享的 Workspace、资料、会话、AnswerRun、Knowledge、Memory 主系统耦合、Research/Artifact 主系统接口。  
边界：不读取、不修改 `workers/research-worker/` 与 `workers/artifact-worker/` 内部实现；Memory 当前仅保持既有能力，不进行设计重构。

## 修复原则

1. 先修会造成数据错误、任务无法执行或用户得到错误状态的问题。
2. 不为了“生产化”叠加 cost、灰度、回切等不服务于简历展示的复杂机制。
3. Workspace 继续作为权限、资料、检索、会话、AnswerRun 与引用的隔离边界。
4. QA、Note、Wiki 保持独立检索策略；共享 AnswerRun 与证据/引用底座。
5. 前端以结果优先为准：聊天主路径简洁，Research/Artifact/Memory 作为按需进入的独立能力区。

## 执行顺序

### 阶段 A：资料与任务正确性（P0-01、P0-02）

- 防止已删除 Source 被异步链路复活。
- 让解析/切片/投影具备重投幂等性。
- 验收：删除与重投场景下，资料始终不可检索、不会新增重复 chunk，三个检索模式均不可见该资料。

### 阶段 B：异步主链路可执行（P0-03、P0-04）

- Research Run 自动发布到既有 Kafka Topic。
- AnswerRun 脱离 SSE 订阅后仍会执行并落终态。
- 验收：仅调用创建 API 并轮询状态即可得到终态；随后连接 SSE 能获得回放或 snapshot。

### 阶段 C：三模式展示可信（P1-01、P1-03）

- 使无 LLM 的演示回答仍能从证据中给出事实性回应。
- 给 QA 加最小资料范围选择；明确 Note/Wiki 的工作台级语义。
- 验收：QA/Note/Wiki 均能展示各自的回答与证据；QA scope 不会召回范围外资料。

### 阶段 D：口径与体验收口（P1-02、P2、P3）

- 收紧上传文字和文档描述。
- 修正 Wiki 开关竞态、回答失败状态与默认聊天页负担。
- 更新过期验收记录，并记录延后项。

## 不在本轮实施的事项

- 两个独立 Python worker 内部算法、工具链或运行时改造。
- Memory 候选、审核、版本、Control Pack 的设计重构。
- cost、线上灰度、回切、生产运营指标和额外的复杂管理后台。
- PDF/DOCX/OCR parser 的完整实现；当前先确保对外口径真实。
