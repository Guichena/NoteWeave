# NoteWeave-v2：简历展示说明

## 项目定位

NoteWeave-v2 是一个以 Workspace 为边界的知识工作台。用户上传资料后，系统完成解析、分块和 Elasticsearch 投影；QA、Note、Wiki 三种模式复用统一的检索计划、证据包与引用边界。普通用户直接获得回答与 citation，不需要人工审核。

当前演示主路径固定为 QA V2：

```text
Workspace / 权限隔离
  -> Source 上传、解析、Chunk 投影
  -> qa-retrieval-v2
  -> EvidenceBundle
  -> AnswerRun + SSE
  -> citation 回跳 Source / Snapshot / Chunk
```

## 可写进简历的内容

### 版本一：后端 / Java 岗位

- 基于 Java 17、Spring Boot 3、MySQL、Kafka、Redis、MinIO 与 Elasticsearch 构建 Workspace 隔离的知识工作台，覆盖资料上传、解析分块、索引投影、会话回答和引用追溯。
- 将 QA、Note、Wiki 收敛为统一 AnswerModeStrategy / RetrievalPlan / EvidenceBundle 契约；QA 主路径固定为 `qa-retrieval-v2`，避免模式分支散落在 ChatService。
- 实现 Elasticsearch 主检索与 MySQL fallback，并在 EvidenceBundle 前执行 Source scope、Passage ownership、最新 Snapshot 和 citation 一致性校验，避免跨 Workspace 或过期资料进入回答。
- 设计 AnswerRun 与 SSE 回放链路，持久化检索 plan、最终证据、执行 trace 与 citation，使回答结果可回放、可审计、可定位资料片段。
- 将 AnswerRun 从 SSE 连接生命周期中解耦，消息提交后即进入独立异步生成；SSE 只承担订阅、快照与断点恢复，并处理生成/取消并发终态。
- 为 Source 解析、索引投影和删除建立幂等与失效边界；删除提交后按引用计数回收 MinIO/本地对象并清理 Elasticsearch 文档，防止异步消息复活资料。

### 版本二：检索 / AI 应用岗位

- 构建 Workspace-scoped RAG 问答链路：V2 词法充分性判断、Source 多样性证据选择、最多 6 条/8,000 字符 EvidenceBundle 与强制 citation 边界。
- 用受控真实资料完成 8-case、5 轮离线回放评测：Recall@K `0.9306`、MRR `1.0`、NDCG@K `1.0`、citation precision `0.8889`、refusal accuracy `1.0`、scope violation `0`。
- 通过带盐假名化和 content-free receipt 保存评测 artifact 的 digest、profile、聚合指标和 ranking signature，避免把 query、正文、资源标识或盐写入验收材料。

## 三到五分钟演示顺序

1. 创建一个 Workspace，说明它是用户、资料、会话、检索和引用的隔离边界。
2. 上传一份 UTF-8 Markdown/TXT/JSON/CSV 文本资料，展示资料状态从上传到解析、Chunk 与索引完成。
3. 在 QA 会话提问，展示直接回答、引用列表和 citation 对应的资料片段。
4. 指出 QA 始终使用 `qa-retrieval-v2`，但检索仍受当前 Workspace 与可选 Source scope 约束。
5. 可选打开 Note 或 Wiki，说明它们使用同一证据模型但保留不同交互语义。
6. 最后展示 r6 receipt 或测试结果，说明检索策略有可复验的本地证据，而不是只展示页面效果。

## 面试时的边界说明

- Memory 现有能力保留，但其后续设计与重构会单独进行，不与当前 QA 展示混为一谈。
- Research 与 Artifact Worker 是独立 worker；当前主项目只展示与它们的任务、回调和结果边界，不宣称改造了其内部算法。
- 当前不宣称 vector、RRF、rerank、真实生产灰度、在线成本统计或通用 AI judge。
