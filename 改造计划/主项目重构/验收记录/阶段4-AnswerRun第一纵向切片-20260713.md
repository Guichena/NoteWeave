## 已验收能力

1. 每次 QA/Note/Wiki 发送都创建唯一 AnswerRun，并返回 `answer_run_id` 与 canonical `answer_stream_url`。
2. AnswerRun 状态使用条件更新推进，终态不能被普通迟到完成覆盖。
3. 初始 Message Revision 为 `STREAMING`，成功后成为 `FINAL`；取消后成为 `PARTIAL`。
4. Answer 关键事件使用 run 内单调序号持久化，数据库唯一约束防止重复 sequence。
5. 单实例流式 claim 使用 owner 与 lease，第二个活跃生成连接不能重复接管。
6. 首 token、完成时间、错误、模型标识和 retrieval plan version 可从 snapshot 查询。
7. canonical SSE 输出 Answer 事件；旧 Chat SSE 在 AnswerRun 完成后只回放快照，不重新执行模型。
8. 显式 DELETE 将运行推进到 `CANCELLED`，生成回调检查取消信号，完成 CAS 同时阻止迟到提交。
9. SSE 订阅者断开不再通过 consumer 异常直接中止生成；数据库终态仍是恢复真相。
10. 前端已切换 canonical AnswerRun SSE，并保留旧事件类型兼容。
11. Micrometer 暴露 AnswerRun 创建、完成、失败、取消和非法迁移计数；日志 MDC 增加 `answer_run_id`。
12. Docker 从 Nginx 入口验证 V030、AnswerRun 创建、delta、completed、FINAL revision、6 个关键事件和旧 SSE 回放，共 20 项通过。
13. Docker MySQL 额外实测取消运行最终为 `CANCELLED/PARTIAL`，`noteweave.answer.run.cancelled` Counter 增至 1。
14. `SessionEventMux` 为活动 run 提供有界内存 replay；第二个连接跟随已有生成者，不再触发第二次 LLM 或返回 409。
15. `after` 与 `Last-Event-ID` 共用同一 cursor；Docker 使用最终 cursor 重连后不重复发送 snapshot/completed。
16. 每订阅者串行有界队列保证单连接保序；慢客户端 delta 合并，非 delta 溢出会断开并增加 Counter。
17. token 按 30ms 或 512 字符合并；Docker fallback 实测由 1 个 delta batch 完成，不逐行放大 SSE 调用。
18. 生成、阻塞连接与短时分发分别使用 `answerIoExecutor`、`sseConnectionExecutor`、`sseDispatchExecutor`。
19. Mux 暴露 published、replayed、cursor expired、trim、delta coalesced、subscriber overflow、dispatch rejected 和 active subscriber 指标。

## 实测状态序列

```text
CREATED
  -> RETRIEVING
  -> GENERATING / revision=STREAMING
  -> FINALIZING
  -> COMPLETED / revision=FINAL
```

取消合同：

```text
GENERATING -> CANCELLED / revision=PARTIAL
late complete -> rejected by conditional transition
```
