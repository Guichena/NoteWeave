## 前端合同

1. 一个活跃 Conversation 只建立一条持久 SSE。
2. `ConversationStreamClient` 解析任意网络分片，保存最新 event id，断线后使用 `Last-Event-ID` 指数退避重连。
3. reducer 通过 `run_id` 更新对应助手消息，不依赖最后一条消息的位置。
4. 连接先处理 MySQL snapshot，再处理 Redis 或本机 live event。
5. POST 返回前到达的 delta 暂存在 run map，创建助手消息后立即回填。
6. Conversation 连接未就绪时继续使用 canonical AnswerRun SSE。

## 背压合同

1. 测试客户端限制为 1KB/s。
2. Redis 管道实际写入 600 条 8KB delta 和 1 条 citation，并校验 XLEN=601。
3. 服务端触发 104 次同 run delta 合并，subscriber overflow=0。
4. 压力期间健康 API P95=24.75ms，慢连接没有占用普通请求或生成线程池。
