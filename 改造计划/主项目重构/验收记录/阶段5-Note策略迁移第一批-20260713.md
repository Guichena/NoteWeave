## 本批输入边界

Note 仍接收原 builder 的同一组业务输入：Workspace、Conversation、当前 query message、用户原始问题、连续对话检索问题、问题类型、上下文窗口、主题锚点/摘要和 Chat Control Pack。输入统一放入 `AnswerContext`；Chat Control Pack 仍只控制表达，不作为事实 Evidence。

## 本批检索与证据边界

1. `NoteAnswerModeStrategy.plan` 生成 `note-marginalia-v1` RetrievalPlan。
2. `NoteEvidenceRetriever` 依次调用原 `findNoteRecallPlan`、`readEntriesMetadataForNote` 和 `openSourceWindowsForNote`。
3. 原候选配额、Journal freshness、关系扩展、verify admission、窗口 anchor/continuation 选择与排序算法未改。
4. 最终 ReadingWindow 被适配为 Passage evidence，稳定 evidence id 为 `note-window:<chunkId>:<windowNo>`。
5. 候选资料、Journal、关系扩展、验证 trace、资料元信息和原窗口列表形成 bundle 级 Note retrieval snapshot，供 strategy compose 重放原模板。

## 统一管线扩展

`EvidenceRetrievalResult` 让 retriever 除 evidence 外显式返回 bundle metadata、degraded 和 degradation reasons。`RetrievalOrchestrator` 合并这些结果并拒绝冲突 metadata；QA retriever 使用空 metadata，行为保持不变。

## Citation 与运行记录

- Note `PromptSpec.referencedEvidenceIds` 按原 ReadingWindow 顺序声明全部选中 evidence；
- `EvidenceCitationAssembler` 校验 bundle membership 后持久化 citation；
- evidence 展示标题可以包含 Research Report 来源标识，但 citation 表仍保存原 source title，事件层继续按 source metadata 生成展示标题；
- AnswerRun、message revision、retrieval summary 分别记录 `note-marginalia-v1`；
- message revision 记录 `evidence-bundle:<bundleId>`。
