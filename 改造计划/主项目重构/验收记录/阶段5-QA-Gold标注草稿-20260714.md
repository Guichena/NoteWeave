- 日期：2026-07-14
- 后端测试：174/174
- Request schema：`retrieval-qa-annotation-request-v1`
- Draft schema：`retrieval-qa-annotation-draft-v1`
- 状态：真实 Port 候选可安全生成脱敏待标注草稿；reviewed draft 编译与真实 snapshot 仍待下一切片

## 目标

此前真实 Elasticsearch 已有检索数据，但仓库中只有受控 gold fixture。直接从搜索结果自动推断 relevant evidence、expected citation 或 shouldRefuse 会把被测系统输出当作 ground truth，因此本切片只生成可人工审核的标注草稿。

## 完成内容

- 新增 `QaGoldAnnotationRequest`，输入 dataset version、candidate pool size 和一个或多个 QA case；
- 每个 case 必须提供真实 workspace、query、显式 allowed Source IDs 和 topK；
- candidate pool 限制在 1 到 100，topK 必须落在 candidate pool 内，case ID 必须唯一；
- 新增 `QaGoldAnnotationDraft`，记录 capture 时间、候选 rank/score、Source Snapshot、chunk locator、title/content/source type 和 scope 状态；
- 新增 `QaGoldAnnotationDraftCapture`，通过生产 `ChunkSearchPort.search(workspaceId, query, candidatePoolSize)` 获取候选；
- capture 不持久化 raw hit，只把完成 HMAC 假名化和敏感正文脱敏后的 draft 写盘；
- case/workspace/evidence/source/snapshot/citation ID 使用同一带盐会话稳定映射；
- email、URL、UUID、IPv4、手机号、Windows 路径和 token/API key/secret 在输出前替换；
- allowed scope 内外候选都保留，并用 `withinAllowedScope` 明确区分，便于发现线上 scope violation；
- draft 固定输出 `annotationStatus=PENDING`，`shouldRefuse=null`，相关 evidence 和期望 citation 均为空，禁止自动生成真值；
- 每个候选带一个稳定 citation 评测标签，用于后续关联标注；它不是已经写入数据库的 citation ID。

## 安全边界

- 真实 annotation request 含 workspace/query/Source ID，应作为本地受控输入，不作为脱敏产物提交或共享；
- 唯一允许共享/归档的是 `captureAndWrite` 生成的 sanitized draft；
- 盐至少 16 个字符，应继续由受控环境提供，不能写入 request 或 draft；
- out-of-scope candidate 只用于评测标注，不代表允许它进入最终 EvidenceBundle；
- 草稿未完成人工审核前不能传入 replay、shadow comparator 或质量门禁。
