# 阶段 5：QA V2 简历展示收尾验收（2026-07-16）

## 结论

QA 主路径已按“简历展示版”完成 V2-only 收口：新 QA `AnswerRun` 不再让 Workspace 历史开关选择检索算法，统一使用 `qa-retrieval-v2 / qa-passage-v2 / qa-lexical-sufficiency-v2 / qa-source-diverse-budget-v2`。Workspace 仍继续隔离资料、会话、Source scope、AnswerRun 与 citation。

本记录不把本地受控离线评测写成生产指标，也不涉及 Memory、`workers/research-worker/` 或 `workers/artifact-worker/` 的内部实现。

## 当前代码证据

| 要求 | 当前证据 |
| --- | --- |
| 单一 V2 QA profile | `QaAnswerModeStrategy`、`QaRetrievalStrategyProfile` 与 `QaEvidenceSelectionPolicy` 固定 V2 profile、plan、relevance 与 selection policy。 |
| Workspace 开关不改变 QA 算法 | `QaWorkspaceRetrievalStrategyContractTest` 为两个 Workspace 分别写入 `retrieval_strategy_v2_enabled=true/false`，断言所有新 AnswerRun 仍持久化 V2 plan/profile/prompt/summary。 |
| Evidence/citation 边界 | `QaAnswerPipelineContractTest` 验证 Prompt 引用的 evidence id 与最终 EvidenceBundle、citation 装配结果一一一致。 |
| 显式 scope 与持久化 citation | `Phase1And2ContractTest` 覆盖上传→QA→citation 以及仅从显式 Source scope 持久化 citation。 |
| Workspace 权限隔离 | `WorkspaceAccessContractTest` 覆盖成员、撤权和跨 Workspace 资源访问拒绝。 |

`retrieval_strategy_v2_enabled` 仍保留在旧数据库/API 兼容层；它不再由 `ChatService` 或 QA strategy 读取为新 AnswerRun 做策略决策。
