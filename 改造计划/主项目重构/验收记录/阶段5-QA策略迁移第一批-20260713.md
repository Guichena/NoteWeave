## 本批输入边界

QA 仍接收原 builder 的同一组业务输入：Workspace、Conversation、当前 query message、连续对话检索问题、问题类型、上下文窗口、主题锚点/摘要和 Chat Control Pack。上述输入被整理为 `AnswerContext`；Chat Control Pack 仍是 prompt 控制信息，不进入事实 EvidenceBundle。

## 本批检索与证据边界

1. `QaAnswerModeStrategy.plan` 生成 `qa-passage-v1` RetrievalPlan。
2. `QaPassageEvidenceRetriever` 调用原 `RetrievalService.retrieveForQa`，保持 ES 优先、MySQL fallback、原打分和来源多样性算法不变。
3. 原 `RetrievedChunk` 被一对一适配为 Passage evidence，保留 source、snapshot、chunk、标题、摘录、位置、score、match reason 和 Research Report 来源信息。
4. `RetrievalOrchestrator` 产出带稳定 evidence id 的 EvidenceBundle，QA compose 只声明 bundle 内 evidence id。

## 本批 citation 持久化边界

`EvidenceCitationAssembler` 以 `EvidenceBundle + PromptSpec.referencedEvidenceIds` 为唯一 QA citation 输入：

- prompt 引用 bundle 外 evidence 时拒绝；
- bundle evidence id 重复时拒绝；
- prompt 重复声明同一 evidence id 时拒绝；
- 非 Passage 或缺少 source/snapshot/passage 主键时拒绝；
- citation 和 message_citation 按 prompt 声明顺序持久化；
- Note/Wiki 暂时保留旧 citation 路径，待各自策略迁移时切换。

## 行为兼容证据

- QA 可见回答保留迁移前的模板文案、问题分类、连续对话说明、检索边界、检索策略、证据编号、Chat Control 区块和后续操作顺序；
- Research Agent 保存报告仍显示 `Research Report(runId)` 来源标识；
- citation 事件和 source/snapshot/chunk 回跳保持不变；
- AnswerRun `retrieval_plan_version`、message revision `prompt_version` 和 retrieval summary 均记录 `qa-passage-v1`；
- message revision 记录 `evidence-bundle:<bundleId>`。
