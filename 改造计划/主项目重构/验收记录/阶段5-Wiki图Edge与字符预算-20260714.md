# 阶段 5：Wiki 图 Edge 与字符预算验收

- 日期：2026-07-14
- Retrieval Plan：`wiki-page-graph-v1`
- 默认图预算：`maxGraphHops=1`、`maxGraphNodes=30`、`maxGraphEdges=60`、`maxGraphCharacters=4000`
- 状态：Wiki graph expansion 已同时服从 hop/node/edge/character budget，原页面召回、排序、正文、citation 和回答模板算法未改

## 原缺口

前一批 `WikiGraphBudgeter` 已执行 hop/node budget，但仍存在两个成本边界：

- 指向 seed page 或已接纳 node 的重复关系边不再消耗 node budget，可能继续累积任意数量 edge；
- 图关系最终会被渲染进旧 Wiki 回答模板，只限制 edge 数量无法稳定约束 prompt 中关系文本体积；
- 阶段计划要求 graph expansion 服从 hop/node/edge/token budget，原 plan、trace 和验收只覆盖前两项。

## 完成内容

### RetrievalPlan 契约

- `RetrievalPlan.Budget` 新增 `maxGraphEdges` 与 `maxGraphCharacters`；
- 保留原四参数构造器，兼容既有 QA/Note/Wiki 测试和调用点，默认补入 `60` edge、`4000` character；
- `WikiAnswerModeStrategy` 显式声明六项预算，不提升 `wiki-page-graph-v1`，因为召回、排序和回答算法未变化；
- `AnswerStrategyContractValidator` 拒绝负数 edge/character budget。

### WikiGraphBudgeter 执行语义

- 保持 seed context 顺序，并按每个 root 的 outgoing、backlink 顺序确定性遍历；
- 只有真正入选的关系才消耗 edge 与 character budget；
- 新 node 同时受全局 node budget 约束；指向 seed 或既有 node 的关系不重复消耗 node，但仍消耗 edge/character；
- 任一关系越过 edge、character 或新 node 上限时跳过该关系，继续以相同稳定顺序检查后续关系；
- `maxGraphHops=0` 仍清空所有 outgoing/backlink，四项 usage 均为 0；
- root Wiki 页面、Knowledge Version evidence、summary/content、来源 citation 与 citation 顺序不受图关系预算影响。

### Character budget 定义

`maxGraphCharacters` 使用关系渲染成本的确定性、token-safe proxy：基于关系标题、状态、mention count 和固定格式开销计算，只统计真正入选的关系。该值用于在模型调用前稳定限制图关系体积，但不宣称等同于 tokenizer 的精确 token 数，也不包含页面正文、summary 或 citation 文本。

### Trace 与持久化

`WikiEvidenceRetriever` 在 metadata 和 `retrieval-execution-trace-v1.steps[].measurements` 中新增：

- `graph_edges_used`、`graph_characters_used`；
- `graph_edge_limit`、`graph_character_limit`。

这些字段只记录计数和上限，不复制页面标题、关系正文或资源标识符；它们随既有 `retrieval.summary` 和 AnswerRun 审计链路持久化。

## 数据与算法边界

- 本次只补齐预算执行和可观测性，不改变 Wiki 页面召回上限、score、关系来源、citation 查询或旧模板输出结构；
