# 阶段 5 Wiki 图预算执行验收

- 日期：2026-07-14
- 后端测试：195/195
- Retrieval Plan：`wiki-page-graph-v1`
- 图预算：`maxGraphHops=1`、`maxGraphNodes=30`
- 状态：Wiki graph hop/node budget 已成为可执行契约，页面召回、评分和来源 citation 算法未改

## 原问题

- Wiki plan 已声明 `maxGraphHops` 和 `maxGraphNodes`；
- `EvidenceRetriever` 只接收 `AnswerContext + Step`，具体 retriever 无法读取全局 plan budget；
- `KnowledgeService.findRelevantWikiPageContexts` 最多返回 5 个页面，每页再携带最多 5 个出链和 5 个反链；
- 多页面命中时，关系扩展可能越过 plan 声明的 30-node 上限；
- `RetrievalOrchestrator` 只能限制 evidence 数量/字符，无法从 Knowledge Version evidence 推断并安全裁剪 snapshot 内部图关系。

## 完成内容

- `EvidenceRetriever.retrieve` 扩展为接收完整 `RetrievalPlan` 和当前 `Step`；
- QA 与 Note retriever 保持原行为，仅使用已有 step/evidence budget；
- 新增 `WikiGraphBudgeter`，在 Wiki retriever 内、snapshot 编码前执行图预算；
- `maxGraphHops=0`：
  - 保留命中的正式 Wiki 页面；
  - 清空页面的 outgoing links 与 backlinks；
  - 保留页面绑定的来源 citations；
- `maxGraphHops>=1`：
  - 当前算法仍只读取一跳直接关系，不虚构二跳扩展；
  - 按命中页面顺序、每页 outgoing 后 backlink 的稳定顺序遍历；
  - 对扩展页面使用全局唯一 node 集计数；
  - 指向 seed page 或已经接纳页面的关系边不重复消耗 node budget；
  - 达到 `maxGraphNodes` 后跳过需要引入新页面的后续关系边；
- 图预算不修改 root Knowledge Version evidence 数量、页面 score、页面 summary/content 或 citation 查询；
- 预算后的 contexts 同时用于：
  - `WikiRetrievalSnapshot`；
  - Knowledge Version evidence 的 outgoing/backlink count metadata；
  - Wiki 旧模板的页面关系和反向引用展示；
- `EvidenceRetrievalResult` 新增独立数值 measurements，避免把包含正文的 snapshot metadata 复制进在线 trace；
- Wiki measurements 包含 hop/node 使用量与上限，并进入 `retrieval-execution-trace-v1` 的 step trace。

  - 指向另一个 seed 页面和已接纳节点的关系仍保留；
  - 达到 node limit 后，新节点关系被稳定跳过；

## 后续边界

- 当前 Wiki 检索算法只执行一跳关系读取，因此即使未来 plan 配置大于 1，也不会在没有二跳 retriever 的情况下伪造更深图扩展；
- 后续若引入二跳或独立 RelationGraphRetriever，必须复用同一 hop/node budget 和 measurements 契约；
- 当前没有独立 edge budget，重复指向已计数节点的关系边允许保留；若真实 benchmark 证明边数成为成本瓶颈，再通过新 plan version 增加 edge budget。
