- 日期：2026-07-13

- 状态：QA、Note、Wiki 三模式统一策略迁移完成；Retriever/Hydrator 拆分待施工

## Wiki 证据边界

1. `WikiAnswerModeStrategy.plan` 生成 `wiki-page-graph-v1` RetrievalPlan，声明 page graph channel、5 个页面证据、1 hop 和 30 node 预算。
2. `WikiEvidenceRetriever` 调用原 `findRelevantWikiPageContexts` 与 `citationIdsForWikiPages`，不改变页面召回、链接、反链和 provenance 算法。
3. 每个命中页面的 latest Knowledge Version 转为 `KNOWLEDGE_VERSION` evidence，稳定 evidence id 为 `knowledge-version:<versionId>`。
4. 页面正文/摘要、version no、出链、反链、citation 数量和 source citation IDs 保留在 evidence 与 Wiki retrieval snapshot。

## Citation 边界

- `PromptSpec` 引用 Knowledge Version evidence，`EvidenceCitationAssembler` 校验 item/version id；
- Knowledge Version evidence 不伪造 `source_chunk_id`，因此不新增 Passage citation；
- 浏览器 citation 事件继续复用该 Knowledge Version 已绑定的原始 citation IDs；
- 原 citation IDs 的顺序与重复语义保持不变，绑定 offset 使用实际新建 citation 数计算；
- Wiki 无页面时 evidence/citation 为空，且明确不退回普通资料 RAG。

## 统一分派完成

- `ChatService` 只构造一次统一 `AnswerContext`；

- `ChatService` 不再依赖 `RetrievalService`、`KnowledgeService` 或具体 retriever；
- ArchUnit 新增门禁防止上述依赖回流。
