# 阶段 5 检索执行 Trace 与指标闭环验收

- 日期：2026-07-14
- 后端测试：193/193
- Trace schema：`retrieval-execution-trace-v1`
- 持久化载体：AnswerRun `retrieval.summary` / MySQL `answer_event`
- 状态：检索执行 trace、事件持久化和低基数 Micrometer 指标已闭环；真实数据质量阈值仍待校准

## 原问题

- `EvidenceBundle` 没有结构化执行 trace；
- `RetrievalOrchestrator` 未记录各 channel latency 和预算前后候选数；
- AnswerRun 的 `retrieval.summary` 只记录 plan version 和 selected evidence count；
- 旧 selected evidence count 来自 prompt evidence 数量加 Wiki existing citation 数量，语义实际是 citation count，不是 EvidenceBundle 大小；
- 无法从持久化事件还原某次检索执行了哪些 step、是否降级、候选如何经过预算以及最终 evidence 的 rank/score；
- 将正文直接放入事件或指标又会扩大敏感信息暴露面。

## 完成内容

- 新增 `RetrievalExecutionTrace`，schema 固定为 `retrieval-execution-trace-v1`；
- bundle trace 记录：
  - plan version 与总耗时；
  - raw、admitted、selected evidence 数量；
  - selected evidence 总字符成本；
  - 每个 step 的 index、channel、candidate limit、raw/admitted count、latency、degradation 和安全数值 measurements；
  - 最终入选 evidence 的 rank、evidence ID、kind、raw/fused/rerank score 和 character cost；
- `EvidenceBundle` 新增不可空 trace，同时保留旧构造入口并为测试/兼容调用生成空 trace；
- `RetrievalOrchestrator` 在同一次执行中采集 step 与 bundle 级 trace，不依赖日志反推；
- `AnswerSubmissionService` 将 bundle trace 原样传递到 `AnswerRunService.prepareGeneration`；
- `retrieval.summary` 在顶层提供常用计数和耗时，并在 `execution_trace` 中持久化完整 trace；
- selected evidence count 直接取 `trace.selectedEvidenceCount()`，不再混入 Wiki existing citation；
- 复用现有 `answer_event` 表完成持久化，没有修改 V030 历史迁移，也不新增重复的 trace 表。

## 指标

- `noteweave.retrieval.step.latency`
  - tags：`channel`、`degraded`；
- `noteweave.retrieval.step.candidates`
  - tags：`channel`、`stage=raw|admitted`；
- `noteweave.retrieval.bundle.selected_evidence`
  - tag：`mode`；
- `noteweave.retrieval.bundle.selected_characters`
  - tag：`mode`；
- `noteweave.retrieval.bundle.degraded`
  - tag：`mode`。

指标 tag 不包含 workspace、query、Source、evidence ID、用户 ID 或其他高基数值。

## 安全边界

- trace 和 `retrieval.summary` 不包含 query、title、excerpt、content 或 Source 正文；
- selected evidence 只记录内部 evidence ID、kind、rank、score 与字符成本；
- 事件仍受 AnswerRun workspace 权限和既有 MySQL 恢复边界约束；
- 离线 sanitized shadow/gold 继续使用独立带盐假名化流程，不能用在线 trace 替代外发脱敏数据。
