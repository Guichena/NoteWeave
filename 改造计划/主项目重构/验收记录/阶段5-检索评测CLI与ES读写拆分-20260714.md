## 完成内容

- 新增 `ElasticsearchChunkSearchAdapter`，独立实现 `ChunkSearchPort`，承接在线 QA 和离线评测 CLI 的 Elasticsearch 读侧；
- `ElasticsearchIndexer` 不再实现检索 Port，只保留 Kafka 驱动的索引写入、删除与投影确认职责；
- 写侧增加 `noteweave.elasticsearch.enabled=true` 条件装配，关闭 Elasticsearch 时不创建依赖 client/JDBC/Kafka 的 indexer；
- 新增 `RetrievalEvaluationCliConfiguration`，显式装配 `NoteWeaveProperties`、Elasticsearch client、读侧 adapter、`RetrievalSnapshotSanitizer`、`QaGoldAnnotationDraftCapture` 和 `QaGoldAnnotationCompiler`；
- CLI 使用 `WebApplicationType.NONE`，不启动 Web server；配置测试固定验证不装配 `JdbcTemplate`、Flyway 和 `KafkaListenerEndpointRegistry`；
- 配置类和入口使用专用 `retrieval-evaluation-cli` Profile。第一版 CLI 配置曾被主应用 component scan 加载，使 CLI ObjectMapper 覆盖在线 snake_case ObjectMapper 并造成 API 契约回归；Profile 隔离后主应用不再加载 CLI Bean；
- `capture-draft <request.json> <draft.json>` 使用生产 `ChunkSearchPort` 捕获候选并在落盘前假名化 ID、脱敏正文，输出固定为 `PENDING`；
- `compile-reviewed <request.json> <reviewed.json> <gold.json> <shadow.json> <snapshot-version>` 重新捕获当前候选、校验漂移与人工标签，并只输出 sanitized `retrieval-gold-v1` 和 `retrieval-shadow-v1`；
- 盐只从 `NOTEWEAVE_RETRIEVAL_EXPORT_SALT` 读取，CLI 的结构化成功输出不回显 raw request 内容或盐。

## SessionEventMux 回归修复

完整回归曾偶发缺失 `answer.delta` 或 `citation.upsert`。根因是 `SessionEventMux.follow()` 先注册 subscriber，再在 channel 锁外逐条 enqueue replay；live terminal 可能先进入队列并关闭 subscriber，随后清空尚未交付的 replay/citation。

修复后：

- 在 channel 临界区内完成 subscriber 注册与 `prime(replay)`；
- 解锁后调用 `startDrain()`，再启动 bridge pump；
- subscriber 将 replay 装载、drain 调度与普通 live enqueue 分离，同时保持原有有界队列和 delta 合并语义；
- 新增 `shouldPrimeReplayBeforeLiveTerminalCanCloseSubscriber`，使用阻塞 bridge executor 确定性复现竞态，验证 replay delta、live citation、terminal 的序号和类型完整有序。

## 安全与后续边界

- raw annotation request 可能包含真实 workspace/query/Source ID，必须只保存在受控本地目录并禁止提交；
- salt 不写文件、不提交，并需在 capture 与 compile 期间保持一致；
- reviewed、gold 与 shadow 只能包含假名化 ID 和脱敏文本；
- 下一步需先导入或由用户指定包含真实内容的 workspace、query 与 allowed Source，再执行首批 capture/review/compile，并积累多轮真实 snapshot；
- 在真实样本和多轮延迟/质量数据完成前，不校准或启用生产 `retrieval-quality-gate-v1`，也不引入 vector、RRF 或 rerank。
