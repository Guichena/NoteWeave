## 原缺口

此前 QA annotation CLI 只完成了空 Workspace smoke：

- 本地 Elasticsearch 中 20 个 Source 均为单 chunk、59–101 字符的 smoke 文档；
- 空候选草稿只能证明 CLI、连接、HMAC 和落盘链路，不能进入人工相关性标注；
- 缺少可重复的真实内容 Workspace/allowed Source 准备流程；
- 现有 sanitizer 的 Windows 路径规则只识别 `D:\\...`，不能识别 Markdown 链接常见的 `D:/...`。

## 已完成实现

### 真实内容准备脚本

新增 `scripts/prepare-stage5-qa-annotation.ps1`：

- 保持 PowerShell 5/7 可解析的纯 ASCII 脚本源；
- 通过公开 API 创建专用 Workspace；
- 通过真实 multipart 兼容上传接口导入 `README.md`、`backend/README.md` 和 `docs/ResearchAgent-Capability-Coverage.md`；
- 等待 parse task `COMPLETED` 与 Source `READY/INDEXED`；
- 使用实际返回的 Workspace/Source ID 生成 3-case `retrieval-qa-annotation-request-v1`；
- raw request 只写入被忽略的 `backend/target/retrieval-eval`，不提交仓库；
- 不生成审核标签、gold set、shadow 质量结论或 gate policy。

### 路径脱敏修复

真实 draft 暴露出 Markdown 链接里的 `D:/java-projects/...` 会绕过旧 `D:\\...` 规则。`RetrievalSnapshotSanitizer` 现统一识别两种 Windows 分隔符，并在 Markdown `)`、`]`、`}`、`>`、反引号、引号和常见标点前停止，避免把包围语法吞入路径占位符。

测试同时固定：

- `D:\\private\\note.txt` 被替换为 `[PATH]`；
- `D:/java-projects/NoteWeave-v2/docs/README.md` 被替换为 `[PATH]`；
- raw 路径不能出现在 sanitized gold 或 annotation draft 文件中；
- path redaction 计数覆盖 query 与 candidate content。
