# 阶段 5 策略契约与输出 Token 预算闭环验收

- 日期：2026-07-14
- 后端测试：206/206
- 数据库版本：V031
- 错误码：`ANSWER_RETRIEVAL_PLAN_INVALID`、`ANSWER_PROMPT_POLICY_INVALID`
- 状态：RetrievalPlan、PromptSpec、AnswerPolicy 已进入统一运行时校验；输出 token budget 已持久化并传递到 LLM 请求

## 原问题

- `AnswerModeStrategy.policy()` 从未被 pipeline 调用；
- `minimumEvidence`、`allowNoEvidenceAnswer`、`citationRequired` 和 `maximumOutputTokens` 只是 DTO 字段；
- RetrievalPlan 未统一验证 mode、workspace filter、Source scope、step 参数和 budget；
- Prompt version 可以与 plan version 不一致；
- Prompt evidence IDs 是否属于 bundle，主要等到 citation assembler 才校验；
- Wiki Knowledge Version 不产生新 Passage citation，单靠 citation assembler 无法覆盖全部 Prompt policy；
- 无证据拒答通过中文文案表达，没有结构化 refusal 状态；
- AnswerRun 和生成网关不知道策略声明的最大输出 token；
- OpenAI-compatible 请求没有发送 `max_tokens`。

## RetrievalPlan 校验

新增 `AnswerStrategyContractValidator.validatePlan`，在 Orchestrator 执行前检查：

- strategy 期望 mode 与 `plan.mode` 必须一致；
- plan version 非空；
- 至少包含一个 step；
- `maxEvidence` 与 `maxEvidenceCharacters` 必须为正；
- graph hop/node budget 不得为负；
- step channel 非空；
- candidate limit 必须为正；
- weight 必须为有限正数，拒绝 NaN/Infinity/非正值；
- 每个 step 的 `workspace_id` filter 必须等于当前 AnswerContext workspace；
- 无显式 Source scope 时不允许策略偷偷加入 `source_ids`；
- 有显式 Source scope 时只允许 QA，且必须存在与排序后 scope 精确一致的 `source_ids` filter；
- 任一条件失败返回 `ANSWER_RETRIEVAL_PLAN_INVALID`，不执行 retriever。

## Prompt 与 Policy 校验

`validatePromptAndPolicy` 在 strategy compose 后、消息与 citation 持久化前检查：

- system/user prompt 非空；
- prompt version、bundle retrieval plan version 与 plan version 完全一致；
- bundle evidence IDs 非空且唯一；
- Prompt evidence IDs 非空、唯一并全部属于 bundle；
- Policy minimum evidence 不得为负；
- maximum output tokens 必须为正；
- 显式 refusal 不得引用 evidence；
- 非 refusal 且 evidence 为空时，必须由 `allowNoEvidenceAnswer` 明确允许；
- evidence 数量必须达到 minimum evidence；
- citation required 时，Prompt 引用数量必须至少达到 minimum evidence；
- 任一条件失败返回 `ANSWER_PROMPT_POLICY_INVALID`。

## 显式 Refusal

- `PromptSpec` 新增 `refusal` 字段；
- 保留原四参数构造入口，默认 `refusal=false`；
- QA 无 Passage、Note 无已验证阅读窗口、Wiki 无正式页面时均返回 `refusal=true`；
- 三种拒答仍保持原中文模板和可见行为；
- refusal 必须具有空 evidence 引用，因此不会伪造 citation。

## 输出 Token Budget

- 新增 V031，只追加 `answer_run.maximum_output_tokens int null`，未修改任何历史迁移；
- ChatService 在一次 strategy 调用中取得并校验 AnswerPolicy，然后把 `maximumOutputTokens` 写入 AnswerDraft；
- AnswerSubmissionService/AnswerRunService 将预算持久化到 AnswerRun；
- AnswerRun GET/list snapshot 返回 `maximum_output_tokens`；
- `retrieval.summary` 顶层同步记录该预算，便于事件审计；
- ChatAnswerGenerationAdapter 加载 AnswerRun 的预算，并通过 `AnswerGenerationMaterial` 交给 Orchestrator；
- `AnswerGenerationGateway.generate` 显式接收 maximum output tokens；
- `ChatLlmClient` 增加带 token budget 的兼容重载；
- `HttpChatLlmClient` 在 OpenAI-compatible chat.completions body 中发送 `max_tokens`；
- LLM 未启用时，template fallback 仍重放既有模板，不裁剪正文，因此本切片不改变当前可见回答算法。

## 后续边界

- 当前 token budget 对启用的 OpenAI-compatible LLM 是实际请求上限；
- template fallback 不是模型生成，不按 token 截断，避免破坏旧模板算法；
- 未来接入其他模型 provider 时必须实现带 maximumOutputTokens 的 ChatLlmClient 重载，不能静默忽略策略预算；
- 真实 gold/shadow 与生产质量阈值仍需真实资料集，策略契约闭环不能替代质量标注。
