# 阶段 6：Knowledge 查询边界第一批验收

- 日期：2026-07-14
- 范围：Wiki Answer 页面检索、页面关系与 citation 只读边界
- 状态：`KnowledgeQueryService + WikiRetrievalQueryPort` 已进入真实 Answer 链路
- 算法约束：保留原 Wiki 页面召回、评分、fallback、关系顺序和 citation 顺序

## 原问题

`KnowledgeService` 达到 1928 行，同时承载：

- Knowledge CRUD 与 immutable version；
- Wiki 页面搜索与回答召回；
- graph overview/ego traversal；
- outgoing/backlink 和 citation read model；
- link rebuild、auto-fix、lint、统计与治理；
- Wiki ingest/upsert 写路径。

阶段 5 虽已把 Wiki 回答包装为 `AnswerModeStrategy`，但 `WikiEvidenceRetriever` 仍直接依赖巨型 `KnowledgeService`，并导入其嵌套 `KnowledgePageHit/WikiPageContext`。这使 Answer 模块仍与 Knowledge facade 的内部结构耦合，也无法独立替换 read model 或缓存实现。

## 已完成实现

### 独立 Port 与 read model

- 新增 `WikiRetrievalQueryPort`：只暴露 `findRelevantWikiPageContexts` 与 `citationIdsForWikiPages`；
- 新增顶层 `KnowledgePageHit` 与 `WikiPageContext`；
- `WikiEvidenceRetriever` 构造依赖改为 `WikiRetrievalQueryPort`；
- Wiki snapshot、graph budgeter、strategy 与测试统一使用顶层 read model，不再引用 `KnowledgeService.*` 嵌套类型。

### KnowledgeQueryService

`KnowledgeQueryService` 负责：

- Wiki API 的搜索 read model；
- Answer retrieval 的最多 5 个相关 Knowledge Version；
- 每页最多 5 个 outgoing、5 个 backlink、5 个 citation；
- 多页面既有 citation ID 的原 sort-order 查询。

Workspace 不存在或没有页面时仍保持原空列表语义；该切片没有在读路径新增异常或 fallback 到普通 Source RAG。

### 共享搜索引擎

新增包内 `KnowledgeWikiSearchEngine`，避免 API search 与 Answer retrieval 出现两套排序：

- term 提取规则保持 `Han/a-z/A-Z/0-9`；
- title、summary、content 权重保持 `6/3/2`；
- title 全词 bonus `24`、summary 全词 bonus `6`；
- graph、citation、version、page kind bonus 与 unresolved penalty 保持不变；
- tie-break 继续按 score、citation count、backlink count、updated-at；
- Answer retrieval 有相关结果时最多取 5 个；无结果时按原 updated-at 顺序回退最多 5 个零分页面；
- API search 无匹配时仍返回空列表，不套用 Answer fallback。

`KnowledgeService.searchWikiPages` 委托查询服务；graph/list read model 直接复用同一搜索引擎加载的 `WikiSearchRow`，避免复制聚合 SQL。

## 结构变化
