# 阶段 6 Redis ACL 缓存生产化第一批验收

## 1. 本批范围

- 日期：2026-07-14
- 范围：Workspace ACL cache namespace/version、正向与拒绝 TTL+jitter、Redis 故障回源、数据库 load 指标和权限矩阵回归
- 状态：ACL cache 第一批生产化已完成；Source/Wiki/Memory cache 与 rate/concurrency quota 尚未开始

本批只优化 Workspace 授权缓存，不改变 WorkspaceRole/WorkspacePermission 矩阵、资源归属查询、成员状态判定或 `aclVersion` 失效语义。MySQL 仍是授权真源，Redis 只减少重复读取。

## 2. Key namespace 与版本

ACL key 固定为：

```text
noteweave:v1:cache:acl:{workspaceId}:{userId}:{aclVersion}
```

性质：

- `noteweave:v1` 明确应用和序列化 namespace/version；
- `cache:acl` 与 Streams、后续 quota key 分离；
- key 只包含 Workspace/User ID 和单调递增 ACL version，不包含用户名、token、角色描述或其他原始敏感文本；
- 成员新增、角色/状态修改和移除继续由 `WorkspaceMembershipService` 递增 `workspace.acl_version`；旧 key 无需扫描删除，新请求自然切换到新版本。

读取兼容旧的纯 role value，并将新 value 写为：

```text
ROLE:OWNER
ROLE:EDITOR
ROLE:VIEWER
DENIED
```

## 3. TTL 与防穿透

默认配置：

| 配置 | 默认值 | 用途 |
| --- | ---: | --- |
| `NOTEWEAVE_ACL_CACHE_TTL_SECONDS` | 300 | active role 正向缓存 |
| `NOTEWEAVE_ACL_NEGATIVE_CACHE_TTL_SECONDS` | 30 | 无 active membership 的短拒绝缓存 |
| `NOTEWEAVE_ACL_CACHE_JITTER_SECONDS` | 60 | 正向/拒绝 TTL 随机抖动 |

所有 TTL 最低收敛为 1 秒，jitter 最低为 0。拒绝缓存显著短于正向缓存，用于降低不存在用户/成员的重复数据库穿透；正常成员变更仍依赖 `aclVersion` 立即切换版本，不等待 TTL。

## 4. 授权与降级语义

`WorkspaceAclCache.get` 返回三态：

- role hit：使用缓存角色继续 permission check；
- explicit denied hit：直接拒绝；
- miss：回源 MySQL。

下列情况全部按 miss 处理：

- cache 配置关闭；
- `StringRedisTemplate` bean 不存在；
- key 不存在；
- value 非法；
- Redis command 抛出运行时异常。

MySQL fallback 仍验证：

- Workspace 存在且 `ACTIVE`；
- `workspace_member.status=ACTIVE`；
- `users.status=ACTIVE`；
- role 能映射为已知 `WorkspaceRole`。

数据库查不到 active membership 或 role 非法时默认拒绝，并尝试写入短 `DENIED` 缓存。Redis 写失败不会把拒绝改成允许；Redis 读失败也不会直接拒绝合法成员，而是回源数据库。

## 5. 指标

保留原专用计数：

```text
noteweave.security.acl.cache{result=*}
```

新增统一 cache 计数：

```text
noteweave.cache.requests{cache=workspace_acl,result=*}
```

低基数 result 包含：`hit`、`negative_hit`、`miss`、`load`、`negative_load`、`disabled`、`invalid`、`error`。

数据库 fallback 增加 timer：

```text
noteweave.security.acl.db.load{result=granted|denied|invalid_role|error}
```

指标不携带 workspace/user/key 等高基数或敏感 tag。

## 6. 测试覆盖

新增 `WorkspaceAclCacheTest` 固定：

1. versioned namespace 与 300 秒正向 TTL；
2. `DENIED` 使用独立短 TTL；
3. namespaced role 和旧纯 role value 均可读取；
4. Redis error 返回 miss，允许 Guard 回源数据库；
5. Redis bean 缺失时 cache disabled，不直接拒绝访问。

既有 `WorkspaceAccessContractTest` 继续固定 OWNER/EDITOR/VIEWER、inactive membership、成员角色变更、移除和 `aclVersion + 1` 行为。
