## 2. API 与模型 Owner

`MemoryApi` 持有：

- `GET memory/reviews?kind=ALL|CANDIDATE|OBJECT&limit=1..200`；
- `POST memory/reviews/{kind}/{id}/decisions`；
- object version list/detail/append；
- object revoke。

全部 read/mutation 可透传 `AbortSignal` 到 shared API transport。模型完整保留 review priority、risk/utility、policy、conflict/evidence/lifecycle 状态、promoted object、revoked object ids、version provenance、compile hints 与 supersede/valid window。

## 3. Server-State 与竞态

`useMemoryReview` 是唯一 server-state owner，持有 queue、selection、versions、独立 queue/versions loading、mutating/error 和 last decision。`LatestMemoryRequestGate` 提供：

- workspace 切换取消全部在途请求并清空旧投影；
- kind 切换立即清空旧 queue，再加载新 queue；
- queue、versions 与 mutation 独立 channel；
- 重选 Object 取消旧版本请求；
- 从 Object 切到 Candidate 立即取消 versions channel；
- 决策/版本追加后 refetch queue，已完成 review 的对象从 selection 中移除。

## 4. 人工审核工作台

三栏组件提供：

- 左栏：ALL/CANDIDATE/OBJECT 筛选、priority、risk、utility、review/lifecycle 状态；
- 中栏：statement、task neighborhood、policy/evidence/conflict 解释、审计理由和决策；
- 右栏：Object immutable version 链、compile hints 和 append 修正版表单。

决策集合严格匹配后端：

| Review kind | 可见决策 |
| --- | --- |
| 普通 Candidate | `APPROVE`、`REJECT` |
| 冲突 Candidate | `REPLACE_EXISTING`、`REJECT` |
| Object | `APPROVE`、`REVOKE` |

冲突 Candidate 不显示普通 `APPROVE`，避免触发已知的 `MEMORY_REVIEW_CONFLICT_RESOLUTION_REQUIRED`。版本追加要求 canonical statement 和至少一个 task neighborhood，旧版本不覆盖。

## 5. App 与架构门禁

`App.tsx` 只增加：

- `memory` shell view；
- `MemoryReviewWorkbench` 组件分支；
- “打开 Memory 审核”入口。

Memory endpoint、queue/version state、request timer 和 decision algorithm 均未进入 App。`ui-contract-check.mjs` 禁止 `/memory` API query、object endpoint、`memoryApi` 或 review state 回流，并要求真实 view/component/入口接线。
