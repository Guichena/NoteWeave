# 阶段 6 前端 Research 模型与动态控制台边界验收

- 验收日期：2026-07-15
- 范围：Research read model、具体 API/hook 类型、左侧控制台组件抽取、动态 import、架构门禁与 bundle 验证
- 状态：本批完成；主报告、详情 overlay 和审计面板继续在下一批抽离

## 1. Read Model Owner

此前 Research API 和 state hook 使用调用侧泛型，`App.tsx` 同时保留完整 run/detail/checkpoint/intent/counterfactual response type。该模式容易产生第二套近似 JSON 投影。

本批将以下类型统一迁入 `src/features/research/model.ts`：

- run summary/detail、source scope、intent/completion contract、recovery targets；
- row/final answer/report structure、counterfactual、closed-loop state、trace/process summary；
- checkpoint/list/snapshot、timeline、signal 和历史筛选模型。

`ResearchApi.listRuns/getRun/getCheckpoint` 与 `useResearchState` 均改为返回和持有具体 feature model，不再提供调用侧泛型入口。

## 2. 真实动态组件边界

新增 `src/features/research/ResearchSidebar.tsx`，承接原 Research 左侧控制台的完整 JSX：

- 显式问题、目标、profile、交付格式、时间范围、深度、类型和约束；
- Deep Research 启动与历史刷新；
- 显式 source scope、报告写回来源标记与定位；
- history filter、关键转折时间线、闭环路径摘要和 run history 卡片。

组件通过显式 props 接收页面表单值、server-state、派生视图、回调与展示 helper，不引入第二套 Research state，也不从聊天上下文隐式取研究输入。

`App.tsx` 使用：

```tsx
const LazyResearchSidebar = lazy(() => import("./features/research/ResearchSidebar")
  .then((module) => ({ default: module.ResearchSidebar })));
```

并以 `Suspense` 加载 fallback。动态组件是实际工作台控制台，不是空壳占位；原 `<h2>独立研究工作台</h2>` 已不在 App。
