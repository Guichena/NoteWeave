# NoteWeave 受控式异步产物生成智能体架构设计

## 1. 设计目标

NoteWeave 的产物生成模块面向报告、学习指南、FAQ、知识页草稿、自定义 Prompt 生成，以及视频总结、音频纪要、课程笔记等场景。它在产品上对应右侧固定的 `Artifact Actions Rail`，是类似 NotebookLM 右侧按钮区的核心生成入口。

本模块不是单纯的 Prompt 模板库，也不是完全自主的开放式 Agent，而是设计为一个 受控式 Agentic Graph Harness：

- 固定主链路，保证稳定性
- 局部 Agent 节点保留智能决策能力
- Prompt Recipe 支持用户配置
- Artifact Commit 负责版本化沉淀
- MCP 模块负责外部资料接入

整体目标是：

用一套统一链路承载多种产物生成能力。

避免为每类产物维护一套硬编码流程。

保留 Agent 在意图识别、内容规划、生成修复等节点的能力。

支持视频、音频、文档、URL、文本、知识卡片等多类型输入。

支持用户自定义 Prompt 和产物按钮。

支持生成产物版本化保存，并回流检索链路形成知识闭环。
支持与 `Graduated Memory` 机制对接，让已确认产物成为长期复用知识的重要晋升来源。

## 2. 总体架构

用户输入 / 点击产物按钮        ↓Production Action Resolver        ↓ArtifactJob 异步任务        ↓Universal Artifact Graph Harness        ↓Input Adapter        ↓Agentic Content Planner        ↓Content Acquisition        ↓Canonical Content Object        ↓Context Compiler        ↓Prompt Recipe Runner        ↓Verifier / Repair Agent        ↓Artifact Commit        ↓ArtifactVersion        ↓Artifact-Derived Retrieval

整体分为六层：

1. Production Action Layer：产物能力抽象层
2. Agentic Harness Layer：受控 Agent 编排层
3. Content Normalization Layer：内容归一化层
4. Prompt Recipe Layer：可配置生成层
5. Artifact Commit Layer：版本化落库层
6. Retrieval Feedback Layer：检索回流层

## 3. 核心设计思想

### 3.1 不是完全自主 Agent

完全自主 Agent 容易出现以下问题：

- 步骤不可控
- 工具调用不可控
- 生成结果不可追踪
- 失败原因难定位
- 知识库写入存在污染风险

因此 NoteWeave 不让 Agent 自由规划完整流程，而是采用固定主链路。

### 3.2 不是完全固定 Workflow

完全固定流程又会导致：

- 新增功能需要写新流程
- 视频、音频、文档、URL 等输入难以复用
- 用户自定义能力受限
- 系统扩展成本高

因此系统在局部节点保留 Agent 能力。

### 3.3 采用受控式 Agentic Graph Harness

系统采用折中方案：

- 主链路固定
- 节点边界清晰
- 局部 Agent 决策
- 所有结果可追踪
- 所有产物版本化保存

即：

Controlled Agentic Graph Harness

### 3.4 向 2026 编排思想升级

在保留 `Controlled Agentic Graph Harness` 主骨架的前提下，推荐再吸收 2026 年更成熟的几条编排思想：

- `Style Profile`
  把“用户风格设置”从 Prompt 文本里独立出来

- `Skill Graph`
  不把 skill 当成平铺列表，而是当成可组合的技能子图

- `Schema Gate`
  不是想到什么就直接执行，而是先把本次产物任务编译成结构化执行计划，再校验后运行

- `Lazy Capability Loading`
  不把全部 MCP 工具一次性暴露给模型，而是按 action 和 skill graph 只加载本次需要的能力

- `Capability Union Policy`
  不只检查单个 MCP 工具是否安全，还检查它和当前 Action、Skill、Workspace 组合起来是否越权

因此升级后的定位可以理解为：

`Schema-Gated Skill Graph Runtime on top of a Controlled Artifact Harness`

## 4. Production Action：产物能力抽象

系统将不同产物生成能力统一抽象为 Production Action。

例如：

- 报告生成
- 学习指南生成
- FAQ 生成
- 知识页草稿生成
- 自定义 Prompt 生成
- 视频总结
- 音频纪要
- 课程笔记

每个 Production Action 描述：

- 输入类型
- 目标产物类型
- 默认 Style Profile
- 默认 Skill Graph
- 内容获取策略
- Prompt Recipe
- 输出结构要求
- 是否允许外部能力
- 是否允许回流检索

示例：

视频总结 Action

- 输入：B 站链接 / 视频文件 / 字幕文件
- 内容获取：字幕提取或音频转写
- 输出：视频总结 Artifact
- 生成方式：视频总结 Prompt Recipe
- 可选能力：MCP 字幕提取、音频转写

学习指南 Action

- 输入：文档 / 文本 / Card / 视频转写
- 内容获取：文档解析或内容读取
- 输出：学习指南 Artifact
- 生成方式：学习指南 Prompt Recipe

自定义 Prompt Action

- 输入：文本 / 文件 / URL / Card
- 内容获取：自动识别
- 输出：Custom Artifact
- 生成方式：用户自定义 Prompt Recipe

新增功能时，不新增完整流程，而是新增一个 Production Action 配置。

新增功能 ≠ 新增一套 Graph  
新增功能 = 新增 Production Action + Prompt Recipe

进一步升级后可以表达为：

新增功能 = 新增 `Production Action + Style Profile + Skill Graph Template`

## 5. Universal Artifact Graph Harness：统一产物生成主链路

系统内部保留一套通用产物生成 Graph。

Validate Input        ↓Resolve Action        ↓Normalize Input        ↓Plan Content Acquisition        ↓Acquire Content        ↓Build Canonical Content        ↓Compile Context        ↓Run Prompt Recipe        ↓Verify / Repair        ↓Commit Artifact        ↓Index Artifact

这套 Graph 的特点是：

- 主流程固定，保证可控
- 局部节点允许 Agent 决策，保证灵活
- 每一步都有输入输出边界，便于追踪
- 所有生成结果都进入 Artifact 版本体系

不同产物的差异主要体现在：

- 输入类型不同
- 内容获取方式不同
- Prompt Recipe 不同
- 输出 Artifact 类型不同
- 是否需要外部能力不同
- 验证规则不同

Graph 主干保持一致。

如果采用 2026 风格的编排增强，那么 `Run Prompt Recipe` 这一段建议进一步展开为：

Build Execution Plan  
↓Schema Gate  
↓Expand Skill Graph  
↓Resolve Needed Capabilities  
↓Execute Skill Nodes  
↓Node-Level Verify  
↓Local Repair  
↓Commit Artifact

这样系统既保留一条稳定主链路，又不需要把所有灵活性都塞进一个大 Prompt。

## 6. Agent 能力保留的位置

系统保留 Agent 能力，但限制 Agent 的边界。

### 6.1 Action Resolver Agent

负责理解用户意图，并选择合适的 Production Action。

例如用户输入：

帮我总结这个 B 站视频

系统判断：

输入类型：URL来源类型：Bilibili目标产物：视频总结选择 Action：Video Summary Action

用户输入：

把这段会议录音整理成纪要

系统判断：

输入类型：音频文件目标产物：音频纪要选择 Action：Meeting Minutes Action

### 6.2 Content Planner Agent

负责判断当前输入需要如何获取内容。

例如：

B 站链接  → 优先尝试字幕提取  → 如果无字幕，则尝试音频转写视频文件  → 提取音轨  → 调用音频转写能力PDF 文档  → 文档解析  → 分段清洗Card  → 读取卡片内容  → 可选加载关联上下文

Content Planner Agent 只能在系统允许的能力范围内做选择，不能自行调用未授权工具。

### 6.3 Generation Agent

Generation Agent 负责根据 Prompt Recipe 生成 Artifact 草稿。

它不决定整个任务怎么执行，只负责在约束内完成内容生成。

输入：

Context PackPrompt RecipeOutput Contract

输出：

Artifact Draft

### 6.4 Verifier / Repair Agent

负责检查生成结果是否符合要求，并在必要时做一次修复。

检查内容包括：

输出是否为空是否过短是否包含必要章节是否符合目标产物结构是否保留来源信息

如果失败：

触发一次 Repair Prompt

如果仍失败：

标记为 WARN 或 FAILED

## 7. Canonical Content Object：内容归一化

为了统一处理视频、音频、文档、网页、文本、Card 等输入，系统引入：

Canonical Content Object，简称 CCO

CCO 是所有输入进入生成链路前的标准内容对象。

视频 / 音频 → TRANSCRIPT CCOPDF / Word / Markdown → DOCUMENT_TEXT CCO普通文本 → RAW_TEXT CCO知识卡片 → CARD_CONTEXT CCO多个输入 → MIXED_CONTEXT CCO

CCO 中包含：

标题正文分段内容时间戳来源类型元信息来源追踪

示例：

Canonical Content Object- kind: TRANSCRIPT- title: 视频标题- plainText: 完整字幕或转写文本- segments:  - 00:00 - 01:20 第一段内容  - 01:20 - 03:40 第二段内容- sourceTrace:  - 输入来源  - 字幕来源  - 转写来源  - 外部能力调用记录

通过 CCO，后续的 Context Compiler 和 Prompt Recipe Runner 不需要关心原始输入来自哪里。

## 8. Context Compiler：上下文编译

Context Compiler 负责将 CCO、用户偏好、Action 配置和 Prompt Recipe 组织为模型可消费的上下文包。

它解决的问题是：

避免直接拼接超长 Prompt统一不同来源内容的上下文结构保留来源追踪控制上下文长度支持后续回放和重新生成

输入：

Canonical Content ObjectProduction ActionPrompt Recipe用户偏好可选知识库上下文

输出：

Context Pack- taskBrief- mainContent- segments- userPreference- outputContract- sourceTrace

## 9. Style Profile 与 Prompt Recipe：用户可配置生成层

Prompt Recipe 仍然保留，但不建议单独承担“风格、结构、篇幅、受众”全部配置。

更合理的拆法是：

- `Style Profile`
  负责“怎么写”

- `Prompt Recipe`
  负责“这一类产物按什么结构生成”

Style Profile 推荐包含：

- 语气：学术 / 教学 / 咨询 / 简洁
- 结构：先结论 / 先背景 / 问答式 / 大纲式
- 篇幅：短 / 中 / 长
- 证据密度：高 / 中 / 低
- 面向对象：自己 / 团队 / 面试汇报 / 对外客户

Prompt Recipe 则更适合负责：

- 必须出现哪些章节
- 哪些内容可以表格化
- 是否生成行动项
- 是否生成复习题
- 是否输出 FAQ / Wiki 草稿等固定结构

用户可以调整：

输出风格章节结构长度要求是否生成表格是否生成行动项是否生成复习题是否面向课程、会议、论文或项目文档

示例：视频总结 Prompt Recipe

请基于视频转写内容生成结构化总结，包括：
1. 一句话总结
2. 时间线摘要
3. 核心观点
4. 关键概念
5. 可沉淀为知识卡片的要点

示例：音频纪要 Prompt Recipe

请基于音频转写内容生成会议纪要，包括：
1. 总体摘要
2. 主要议题
3. 关键结论
4. 行动项
5. 待确认问题

用户可以复制默认 Action，并修改 Style Profile 或 Prompt Recipe，形成自己的产物生成按钮。

## 10. MCP 多媒体能力接入

MCP 能力接入作为独立模块存在，重点服务视频、音频、网页等外部资料输入。

它负责：

接入用户 MCP Server发现 MCP 工具保存工具描述映射为标准 Capability执行字幕提取、音频转写、网页读取等外部能力将结果转为 External Content Snapshot再交给 CCO 构建流程

主产物生成链路不直接依赖具体 MCP 工具，而是只申请标准能力。

同时不建议把全部 MCP 工具一次性暴露给模型，而是采用：

- capability 摘要先注册
- runtime 按 action 和 skill graph 选择能力
- 只把本次真正需要的 tool schema 加载进上下文

这样可以降低上下文长度、工具干扰和用户自定义 MCP 带来的失控风险。

例如：

需要字幕提取能力：EXTRACT_TRANSCRIPT需要音频转写能力：TRANSCRIBE_AUDIO需要网页读取能力：READ_WEB_PAGE

MCP 模块内部完成映射：

Bilibili MCP get_subtitle  → EXTRACT_TRANSCRIPTASR MCP transcribe  → TRANSCRIBE_AUDIOWeb Reader MCP read_page  → READ_WEB_PAGE

## 11. 视频 / 音频接入流程

### 11.1 B 站链接流程

用户输入 B 站链接        ↓Input Adapter 识别平台        ↓Content Planner 判断需要字幕        ↓申请 EXTRACT_TRANSCRIPT 能力        ↓MCP 获取字幕和元信息        ↓生成 External Content Snapshot        ↓构建 TRANSCRIPT 类型 CCO        ↓进入产物生成主链路        ↓生成视频总结 / 课程笔记 / 学习指南

如果没有字幕：

尝试 TRANSCRIBE_AUDIO

如果能力缺失：

任务进入 WAITING_FOR_CAPABILITY提示用户配置 MCP 或上传字幕 / 音频文件

### 11.2 视频文件流程

用户上传视频文件        ↓Input Adapter 识别视频文件        ↓提取音轨        ↓申请 TRANSCRIBE_AUDIO 能力        ↓完成音频转写        ↓生成 TRANSCRIPT CCO        ↓进入产物生成主链路

### 11.3 音频文件流程

用户上传音频文件        ↓Input Adapter 识别音频        ↓申请 TRANSCRIBE_AUDIO 能力        ↓获取转写文本        ↓按时间或语义切分        ↓生成 TRANSCRIPT CCO        ↓生成音频纪要 / 访谈总结 / 课程笔记

## 12. Artifact Commit：版本化产物落库

生成结果不会作为一次性聊天回复结束，而是保存为 ArtifactVersion。

每次 Artifact Commit 记录：

产物内容使用的 Production Action使用的 Prompt Recipe输入快照CCO 快照外部能力调用记录生成结果校验结果父版本生成时间

同一个输入可以形成多个版本：

v1 默认视频总结v2 课程笔记风格v3 精简版v4 表格版

这让产物具有：

可追踪可回滚可比较可重新生成可检索复用

## 13. Artifact-Derived Retrieval：产物回流检索

生成产物可以回流到检索链路，参与后续问答、二次生成和知识沉淀。

但生成产物不是原始资料，因此进入检索索引时需要标记为：

ARTIFACT_DERIVED

推荐检索权重：

Original Source > User Card > Pinned Artifact > Indexed Artifact > Draft Artifact

回流状态：

DRAFT：刚生成，可编辑，默认不进入正式检索INDEXED：用户允许进入检索PINNED：用户确认质量较高，提升检索权重

回流后可以支持：

基于视频总结继续问答基于多个音频纪要生成阶段总结基于学习指南生成 FAQ将稳定内容人工确认发布为 Wiki

最终形成：

生成 → 版本化 → 检索 → 复用 → Wiki 沉淀

## 13.1 产物到长期记忆的晋升

在当前架构口径下，Artifact 不应默认等同于长期知识，但它是 `Graduated Memory` 最稳定的上游来源之一。

推荐链路：

```text
ArtifactVersion
  -> 用户确认有效
  -> 抽取 Memory Candidate
  -> 通过 Novelty Gate
  -> 通过 Task Neighborhood Validation
  -> 晋升为 Memory Object
```

这样系统长期复用的不是原始对话，而是被确认、可追溯、可复用的产物结构和知识单元。

## 14. 异步任务机制

所有产物生成都以 ArtifactJob 异步执行。

状态包括：

CREATEDQUEUEDRUNNINGWAITING_FOR_CAPABILITYVERIFYINGCOMMITTINGCOMPLETEDFAILEDCANCELLED

示例：B 站视频总结任务进度

10% 校验输入20% 识别 B 站链接35% 获取视频元信息50% 提取字幕65% 构建 CCO80% 生成总结90% 校验结果100% 保存 ArtifactVersion

异步任务机制保证：

长任务不阻塞用户界面可以展示进度可以失败重试可以等待外部能力配置可以追踪每一步产物来源

## 15. 用户自定义能力

用户可以新增产物功能，但不需要自己搭建完整 Agent 流程。

用户新增的是：

Production Action

但从 2026 的编排思想看，用户真正可配置的应该分成四类：

- Production Action
- Style Profile
- Prompt Recipe
- MCP Capability Binding

用户可以配置：

Action 名称输入类型输出类型Prompt Recipe是否使用外部能力是否回流检索输出结构要求

如果允许用户自定义 MCP，建议采用三段式：

1. 接入
   配置 server，做健康检查、工具发现和风险标记

2. 授权
   勾选 allowed tools，配置 approval mode、workspace scope、action scope

3. 绑定
   把工具能力绑定到标准 capability，再绑定到具体 Action 或 Skill Graph

这样用户添加的是“能力来源”，不是直接给模型一整套万能工具。

另外建议加入一层 `Capability Union Policy`：

- 不只判断单个 MCP 工具是否可用
- 还判断它与当前 Action、Skill、Workspace 数据组合后是否可能越权

示例：课程视频笔记 Action

输入：B 站链接 / 视频文件内容获取：字幕或转写输出：课程笔记Prompt：提取知识点、重点难点、复习题

示例：组会纪要 Action

输入：音频文件 / 转写文本内容获取：音频转写输出：会议纪要Prompt：总结进展、问题、老师建议、下一步计划

用户不需要修改主 Graph，系统仍然复用 Universal Artifact Graph Harness。

## 16. 设计亮点

### 16.1 保留 Agent 能力，但限制 Agent 边界

系统不是完全固定流程，而是在 Action 选择、内容规划、生成和修复节点保留 Agent 决策能力。

但 Agent 不能随意修改主流程、绕过权限或直接写入知识库。

### 16.2 一套 Graph 支撑多种产物

通过 Production Action 和 Prompt Recipe，将不同产物生成能力统一到一套 Graph Harness 中，避免多套硬编码流程。

### 16.2.1 Skill Graph 与局部修复

在升级版设计里，Graph 内部不再只是单段 Prompt，而是可以展开为一个小型 `Skill Graph`：

- 结构规划
- 内容合成
- 引用检查
- 风格改写
- 局部修复

这样失败时可以只修局部节点，而不需要整条任务全量重跑。

### 16.3 多类型输入统一归一化

通过 Canonical Content Object，将视频、音频、文档、URL、文本和 Card 统一为标准内容对象。

### 16.4 MCP 多媒体接入独立解耦

MCP 负责外部能力，主链路只感知标准 Capability。

这样既能支持 B 站链接、音视频文件等复杂输入，又不会让产物生成流程直接依赖具体工具实现。

### 16.4.1 Lazy Capability Loading 与权限门控

MCP 能力不应一次性全量暴露，而应根据当前 Action 和 Skill Graph 按需加载。

同时建议增加：

- Schema Gate
- Approval Gate
- Capability Union Policy

让用户自定义 MCP 在可扩展的同时保持边界清晰。

### 16.5 产物可版本化、可检索、可沉淀

Artifact Commit、Artifact-Derived Retrieval 和后续的 Memory Promotion Hook 让生成结果不只是临时回答，而是可以沉淀、复用、继续检索并晋升为长期知识的对象。

## 17. 简历表述

### 17.1 产物生成 Agent 主链路

实现 Universal Artifact Graph Harness 异步产物生产机制：将报告、学习指南、FAQ、知识页草稿、自定义 Prompt 生成等能力抽象为可配置 Production Action，通过通用 Graph 主干编排输入适配、内容归一化、上下文构建、Prompt Recipe 生成、结果校验与 Artifact 版本落库，并在 Action 选择、内容规划和结果修复等节点保留受控 Agent 能力；进一步引入 `Style Profile`、`Skill Graph`、`Schema Gate` 与按需能力加载机制，使系统能够在不演化为通用 Agent 平台的前提下支持用户风格配置和用户自定义 MCP；将生成产物作为派生知识对象回流检索索引，形成“生成—版本化—检索—复用”的知识闭环。

### 17.2 MCP 视频 / 音频能力实现

设计并实现基于 MCP 的视频 / 音频资料接入与产物生成链路：支持用户输入 B 站链接、视频文件、音频文件等多模态资料，通过 MCP 工具发现与 Capability Mapping 将字幕提取、音频转写、网页读取等能力抽象为统一外部能力，并将获取到的字幕 / 转写结果归一化为 Canonical Content Object，接入异步产物生产流程，自动生成视频总结、音频纪要、课程笔记等结构化 Artifact。

## 18. 最终定位

NoteWeave 的产物生成模块采用 `Controlled Agentic Graph Harness + Schema-Gated Skill Graph Runtime` 的组合架构。

它不是完全自主 Agent，也不是简单 Prompt 模板库，而是在统一 Graph 主干中保留轻量 Agent 决策能力，将不同产物生成能力抽象为 Production Action，并通过 `Style Profile`、`Skill Graph`、Canonical Content Object、Prompt Recipe、Artifact Commit 和 Artifact-Derived Retrieval 实现可配置、可追踪、可版本化、可沉淀的知识产物生成闭环。

MCP 多媒体接入模块作为外部能力层，负责将 B 站链接、视频文件、音频文件等资料转化为标准内容对象，并通过标准 Capability、Lazy Capability Loading 和 Capability Union Policy 约束外部能力接入，使视频总结、音频纪要和课程笔记等复杂场景可以复用同一套产物生成主链路。
