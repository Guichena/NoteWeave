# NoteWeave 面试准备使用说明

## 0. 本篇定位

这份文件是整个 `面试准备` 目录的入口。它只解决四件事：

1. 先看哪些文件。
2. 每类文件怎么用。
3. 当前主口径和边界是什么。
4. 不同准备时间下应该怎么复习。

统一改造标准见 `NoteWeave学习文档改造方案.md`。后续新增或改写资料，都按“问题驱动、可直接复述、结合 NoteWeave 真实链路、说明边界和追问”的方式写。

## 1. 当前总口径

NoteWeave 现阶段可以讲成一个本地可运行、链路可验收的 AI 知识工作台，而不是只停在方案层的 demo。

可以坚定主讲的已验收能力包括：

- `TEAM / PERSONAL` 双空间和权限边界。
- `Task + Attempt + Event + Outbox + Kafka + Worker` 统一异步底座。
- 团队文档上传、解析、chunk、索引、Hybrid RAG、Citation 和 RetrievalTrace。
- WebSocket Runtime、stop/resume、DRAFT/FORMAL、Redis runtime state。
- 个人 Source、Card、Artifact、Methodology、Synthesis 和长期 Memory。
- PromptVersion、LLMCallLog、RagEvalRun、SystemHealth、Cleanup、AuditLog、Admin/Ops。
- 静态前端工作台的主要本地验收入口。

需要额外收住的一点：

- 当前后端主链路已经验收到 `Phase 15`；`Phase 16 Frontend Workspace` 在 `docs/PROJECT_STATUS.md` 里仍是 `PENDING`。
- 这不等于“前端还不能讲”。更准确的口径是：静态前端工作台已经能覆盖登录、Space、Chat、Artifact、Wiki、Graph、Memory、Admin 等主要本地验收入口，并且已有 smoke 跑通；但完整前端工作区仍属于继续完善中的阶段能力。

仍然不要讲成当前主链路事实的内容：

- 真实生产 QPS、P99、token/day、线上准确率数字。
- 完整开放式 MCP 平台已经做完，或者 MCP 已成为所有主链路强依赖。
- Bibtex 已端到端落地。
- GraphRAG 是当前主检索链路。
- 完整开放 Agent 平台已经实现。
- 微服务拆分、注册中心、配置中心、分库分表已经落地。
- Redis 是主异步任务队列或主业务事实源。

## 2. 文件怎么分工

这个目录里的资料可以按下面方式理解：

- `00-使用说明.md` 和 `NoteWeave学习文档改造方案.md`：入口和标准，解决怎么学、怎么改、哪些边界不能踩。
- `01-项目主述题.md`：准备“介绍项目”“价值是什么”“是不是 demo”“你负责什么”。
- `02-模块深问题.md`：根目录最核心的技术主文档，准备权限、任务、上传、RAG、Runtime、Artifact、Memory、Observability 等模块级深挖，也承接最高频技术题的标准答。
- `09-重点系统功能QA深入版.md`：系统设计总串讲主文档，负责把团队链路、个人链路、可靠性和可观测串成一条完整故事。
- `03-追问题库.md`、`05-mock-面试记录.md`、`实际问题.md`：做一问多追训练和真实面试复盘。
- `04-简历风险点与优化口径.md`：统一简历关键词、风险词和边界表达。
- `中间件专项`：补 MySQL、Redis、MinIO、Elasticsearch、Kafka 的项目化讲法。
- `重点系统功能链路/11_中间件RAGAgent系统设计映射/README.md`：把项目自然接到中间件八股、RAG 系统设计和 Agent / Workflow trade-off。
- `rag专项题 (1).md`、`07-个人链路升级与竞品思考.md`、`08-牛客RAG帖子与评论总结.md`：补 RAG 原理、个人链路和产品思考。
- `大厂深挖题库`：准备压力题、系统设计题和连续深挖题。

## 3. 推荐使用顺序

### 30 分钟速过

适合临时面试前快速拉主线。

1. 读 `00-使用说明.md`，统一总口径和边界。
2. 背 `01-项目主述题.md` 的 1 分钟和 3 分钟版本。
3. 刷 `02-模块深问题.md` 里的 Q1、Q2、Q4、Q7、Q10。
4. 看 `09-重点系统功能QA深入版.md` 最后的 30 秒、2 分钟和三个亮点。
5. 看 `04-简历风险点与优化口径.md`，避免把关键词讲过头。

### 2 小时系统准备

适合把主线、模块和风险口径串起来。

1. 先读 `00-使用说明.md` 和 `NoteWeave学习文档改造方案.md`。
2. 背 `01-项目主述题.md`，形成项目开场。
3. 精读 `02-模块深问题.md`，把核心链路讲顺。
4. 再读 `09-重点系统功能QA深入版.md`，把系统故事串成一条线。
5. 用 `02-模块深问题.md` 里的高频问题清单压成能直接复述的答案。
6. 补 `04-简历风险点与优化口径.md` 和 `03-追问题库.md`。

### 1 天完整准备

适合准备深挖、压力题和系统设计题。

1. 完成 2 小时路径。
2. 看 `重点系统功能链路/11_中间件RAGAgent系统设计映射/README.md`，把项目接到中间件八股和 system design。
3. 看 `中间件专项/00_使用说明与总览.md` 和 5 篇专项文档。
4. 看 `rag专项题 (1).md`、`07-个人链路升级与竞品思考.md`、`08-牛客RAG帖子与评论总结.md`。
5. 刷 `实际问题.md` 和 `03-追问题库.md`，做真实问答转答训练。
6. 最后刷 `大厂深挖题库`，补压力题、排障题和系统设计题。

## 4. 回答统一骨架

每道项目题尽量按下面顺序讲：

```text
场景：这个模块解决什么真实问题。
结论：第一句话直接回答，不绕。
链路：请求、任务、状态、存储、检索或生成怎么流转。
证据：对应哪些类、表、接口、测试或验收入口。
取舍：为什么这样设计，不用更简单方案的原因是什么。
边界：哪些是已验收事实，哪些只是扩展方向。
追问：失败、重复、越权、无证据、断线、脏数据时怎么办。
```

如果一个答案只有“用了什么技术”，没有“为什么、怎么落地、边界在哪”，那就还不能算准备完成。

## 5. 最推荐主打的三条故事

第一条是统一异步骨架：上传解析、Source 编译、Artifact 生成、Wiki 入索引、Eval 和 Cleanup 都复用 `Task + Outbox + Kafka + Worker`，不是每个模块各写一套后台任务。

第二条是 evidence-first RAG：团队问答不是直接问模型，而是权限约束下的 BM25、向量召回、Wiki recall、Weighted RRF、EvidencePostProcessor、Citation 和 RetrievalTrace 闭环。

第三条是生成和沉淀分层：Artifact 是版本化工作产物，Wiki 和 Synthesis 才是确认后的长期知识，这能避免 LLM 生成内容自动污染知识库。

## 6. 训练方式

训练不要按“读完一个文件就结束”，而要按下面闭环做：

1. 先用 `01`、`02`、`06` 形成标准答法。
2. 再用 `03-追问题库.md` 做一问多追。
3. 把暴露的问题记录到 `05-mock-面试记录.md`。
4. 如果遇到真实杂问题，就回填到 `实际问题.md`。
5. 如果发现某个专题回答发虚，再去 `中间件专项`、`rag专项题 (1).md` 或 `大厂深挖题库` 补细节。

## 7. 面试前自查

- 我能否用 1 分钟讲清 NoteWeave 是什么。
- 我能否用 3 到 5 分钟讲清团队和个人两条主链路。
- 我能否说出至少 5 个真实实现锚点，比如 `TaskService`、`HybridRetriever`、`ChatRuntimeService`、`PersonalGenerationService`、`AdminObservabilityController`。
- 我能否解释为什么不是普通 RAG demo。
- 我能否诚实回答没有生产 QPS/P99，而是说明如何通过 Eval、Trace、Log 和压测验证。
- 我能否区分已验收事实和扩展方向，而不是把未来规划讲成当前能力。
