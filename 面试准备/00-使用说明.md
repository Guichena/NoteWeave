# NoteWeave 面试准备使用说明

> 本文件为 2026-06-01 重构版，依据当前代码、测试和 Flyway 迁移整理。不要再按旧阶段计划或旧题库口径背。

## 0. 当前总口径
- NoteWeave 当前可以讲成一个 AI 知识工作台，不是普通接大模型 Demo。核心是把资料进入、检索问答、证据追踪、成果生成、知识沉淀和运营排障做成闭环。
- 主边界是 PERSONAL 和 TEAM 两类 Space。TEAM 侧负责团队知识库、RAG Chat、Wiki、Graph 和 Admin/Ops；PERSONAL 侧负责 ResearchProject、Source、ArticleCard、ConceptCard、SynthesisCard、Artifact 和 Methodology。
- 主技术骨架是 Java 17、Spring Boot 3.3、MySQL、Redis、MinIO、Elasticsearch、Kafka、WebSocket、Flyway、JUnit/Testcontainers 和静态 HTML/CSS/ESM 前端。
- 后台长任务统一走 Task、TaskAttempt、TaskEvent、TaskOutbox、Kafka、Worker。Redis 主要承担 WebSocket runtime state、ticket、stop/resume 和短期状态，不要说成主任务队列。
- 表结构要按生命周期讲：Space/Member 管边界，Task/Outbox 管异步，Document/Chunk 管摄取，Citation/Trace/LLMLog 管证据，Artifact/Methodology/Wiki/Synthesis/Memory 管生成和沉淀，Eval/Ops 管运营。
- RAG 不是只把问题扔给 LLM，而是先做权限过滤、BM25/向量/Wiki 混合召回、Weighted RRF、EvidencePostProcessor、PromptBuilder、Citation 持久化和 RetrievalTrace。
- Artifact 和 Wiki 分离。Artifact 是可版本化的阶段性成果，只有人工确认后才发布为团队 Wiki 或沉淀为个人 SynthesisCard。
- 长期记忆包含 session summary、space memory、user memory，并通过 MemoryWritebackStrategy 过滤 DRAFT、短问候和敏感内容。
- 近期新增能力在当前代码中已经覆盖 WikiGraph、AutoWikiMaintenance、Admin Observability、RAG Eval、cleanup、health、audit、task 管理等实现。部分旧文档如果还说待做，以当前代码为准。
- 不要编造线上 QPS、token/day、P99、真实用户规模、生产准确率。可以说已有 LLM 日志、RetrievalTrace、RAG Eval 和 task event，能支撑后续度量。
- 如果面试官追问“怎么证明不是纸上谈兵”，按分层验证答：纯逻辑看单测，跨组件看 `MockMvc` + `ContainerizedIntegrationTest`，异步链路看 `Task/TaskAttempt/TaskEvent/TaskOutbox`，RAG 看 `Citation/Trace/Eval`，外部工具看 `SkillExecutionLog` 和失败状态。

## 1. 推荐复习顺序
### 30 分钟速过
1. 读 `01-项目主述题.md`，背下 1 分钟和 2 分钟项目介绍。
2. 读 `04-简历风险点与优化口径.md`，把 Hybrid RAG、Memory、Skill、MCP、Bibtex 的口径校准。
3. 读 `03-追问题库.md`，每个题组至少能接 3 个追问，尤其补上“表结构与中间件落位”。

### 2 小时系统准备
1. 先读根目录 00 到 04。
2. 再读 `09-重点系统功能QA深入版.md`，按“边界、一致性、证据、沉淀、工具、运营、表结构、中间件、扩展”这些相似问题题组复习。
3. 最后挑 `重点系统功能链路`、`中间件专项` 和 `大厂深挖题库` 里和简历最相关的文件补细节。

### 1 天完整准备
1. 上午先背项目总述，再按“权限边界、一致性、证据追溯”三组练追问。
2. 下午按“生成沉淀、工具接入、可观测运维、扩展排障”四组继续练。
3. 晚上用 `实际问题.md` 和 `05-mock-面试记录.md` 做模拟面试。

## 2. 回答统一骨架
1. 场景：这类问题解决什么实际风险。
2. 方案：NoteWeave 当前真实怎么实现。
3. 收益：为什么这个方案比简单做法更稳。
4. 权衡：牺牲了什么复杂度，换来了什么能力。
5. 追问：失败、重试、权限、删除、恢复、指标怎么回答。

## 3. 目录分工
- `01-项目主述题.md`：项目介绍和 ownership。
- `02-模块深问题.md`：代码锚点和模块索引，练习时要回到题组。
- `03-追问题库.md`：按相似问题组织的连续追问路径。
- `04-简历风险点与优化口径.md`：避免夸大或说错。
- `中间件专项`：把 MySQL 表结构、Redis key、MinIO object、ES index、Kafka topic/Outbox 映射到项目。
- `重点系统功能链路`：作为链路和代码锚点补细节，不要孤立背。
- `大厂深挖题库`：按面试官意图和题组准备。
- `通用问题分主题深答` 与 `加深版`：把通用八股转成 NoteWeave 项目题组深答。

## 4. 面试前自查
- 能否在 2 分钟内讲清 TEAM/PERSONAL 双空间。
- 能否讲清 Task/Outbox/Kafka 为什么存在。
- 能否画出 upload -> parse -> chunk -> index -> RAG -> citation。
- 能否讲清 `users/space/task/document_chunk/citation/retrieval_trace/artifact_version/methodology_card/wiki_page_version/artifact_distillation_proposal/rag_eval_result` 这些表为什么存在。
- 能否说明 MySQL、Redis、MinIO、ES、Kafka 各自为什么不能互相替代。
- 能否解释 Artifact 为什么不自动进入 Wiki。
- 能否说明单元测试、集成测试、RAG Eval、Admin/Ops 分别证明什么，哪些不是线上压测。
- 能否诚实说明哪些是已实现，哪些是可扩展。

## 6. 10 轮精修应该怎么练
1. 项目定位与知识闭环。
2. 整体架构与职责拆分。
3. 为什么不用 grep / LIKE 直接做检索。
4. BM25、向量、Hybrid、RRF 的取舍。
5. 上传、解析、Chunk、索引与异步恢复。
6. Chunk 与 Evidence Context 的边界。
7. Citation / Evidence 的回溯与权限校验。
8. Wiki 与 Artifact 的长期知识分层。
9. 权限隔离、越权检索与引用漂移排查。
10. RAG 评测、问题排查与项目优势表达。

## 7. 面试时的统一答题顺序
1. 先讲这个模块解决什么问题。
2. 再讲为什么不能用更简单的办法。
3. 再讲 NoteWeave 当前怎么做。
4. 再讲当前方案的优缺点。
5. 再讲如果出问题怎么查。
6. 最后讲后续怎么演进。

## 8. 现在最该记住的几个事实
- RAG 的核心不是“调用模型”，而是“检索、证据、权限、评测”。
- Upload 的核心不是“传上去”，而是“可恢复、可重试、可追踪”。
- Wiki 的核心不是“又一份文档”，而是“人工确认后的长期知识层”。
- Artifact 的核心不是“消息结果”，而是“可版本化的阶段性产物”。
- Redis 主要承载短期运行态和上传 bitmap，不是主任务队列。

## 5. 加深版使用原则
- 不再把新增特性拆成一堆孤立模块背。
- 相似问题放在同一组里练：例如 Bilibili MCP、URL Source、上传都属于“外部输入怎么受控进入系统”；Artifact、Wiki、Synthesis、Memory 都属于“临时内容怎么变成长期知识”。
- 回答时先讲共性设计，再举当前项目里的 1 到 2 个具体例子。
- 遇到新问题时先判断它属于哪一组，再套“边界、状态、证据、失败、验证、不能说满”的框架。
