# NoteWeave 深问题题组与代码锚点

> 本文件为 2026-06-01 题组版，依据当前代码、测试和 Flyway 迁移整理。文件名沿用旧目录，但内容不再按模块单独背诵，而是按相似问题题组组织，并给出对应代码锚点。

## 0. 使用方式

面试练习顺序：

1. 先选题组：边界、一致性、外部输入、证据、沉淀、工具、表结构、中间件、运营、扩展。
2. 再练 2 分钟回答：场景 -> 方案 -> 收益 -> 失败 -> 验证 -> 不能说满。
3. 最后回到代码锚点：用类名、任务类型、测试和迁移证明不是空讲。

## 1. 边界与隔离题组

面试先说：

> NoteWeave 把 Space 作为最高业务容器，区分 PERSONAL 和 TEAM，并把系统角色、空间角色和资源访问拆开，避免 AI 生成、检索、引用和运维链路串数据。

重点问题：
- 为什么要有 TEAM/PERSONAL 双空间？
- systemRole 和 SpaceMember.role 为什么不能混在一起？
- Citation 返回前为什么还要二次权限校验？
- Admin 能否直接看个人 Memory 或团队私有文档？
- Artifact 同时引用团队和个人资料时，可见性怎么判断？

追问：
- Controller 做过权限校验后，Service 层还要不要校验？
- ES 里还有旧 chunk 时，权限过滤怎么兜底？
- 用户退出 Space 后，历史引用还能展示吗？

## 3. 一致性与恢复题组

面试先说：

> NoteWeave 用统一 Task/Outbox/Kafka/Worker 骨架承接长任务，把 DB 内事务和跨系统执行拆开，用最终一致、幂等和可观测事件处理失败恢复。

重点问题：
- 为什么不直接在业务事务里发 Kafka？
- Outbox 保证的是什么一致性？
- Worker 重复消费怎么保证幂等？
- 任务取消为什么用 cancel_requested？
- WIKI_INDEX、RAG_EVAL_RUN、CLEANUP_RESOURCE 失败怎么办？

追问：
- Kafka 已投递但 Worker 执行失败，如何重试？
- 重试是复用原 Task 还是新建 Task？
- Admin mark-failed 和业务失败有什么区别？

## 8. 表结构、索引与中间件落位题组

面试先说：

> NoteWeave 的数据设计不是一张大 JSON 表，而是按生命周期拆分：MySQL 存事实和状态，Redis 存短期运行态，MinIO 存大对象，ES 存检索读模型，Kafka 触发异步任务。

重点问题：
- 这个项目核心表结构怎么设计？
- 为什么不用一张 message JSON 表保存所有 AI 结果？
- 为什么 `space_id/status`、`task_type/task_status`、`document_id/index_version` 这些索引重要？
- MySQL、Redis、MinIO、ES、Kafka 分别承担什么，为什么不能互相替代？
- ES 和 MySQL 不一致、MinIO 有残留、Kafka 重复消费、Redis 丢运行态分别怎么兜底？

追问：
- 当前迁移里为什么很少显式 foreign key？
- `citation`、`retrieval_trace`、`llm_call_log`、`answer_feedback` 为什么要分表？
- `artifact_version`、`wiki_page_version`、`artifact_distillation_proposal` 为什么都要绑定版本？
- Kafka 换 RabbitMQ、ES 换 OpenSearch/Milvus、MinIO 换 OSS/S3 会影响哪些抽象？

## 10. 不能说满清单

- 不要说 Redis 是主任务队列。
- 不要说当前是完整开放 Agent 平台。
- 不要说当前 WikiGraph 是完整 GraphRAG 主线。
- 不要说 Artifact 会自动进入 Wiki、Memory 或 ConceptCard。
- 不要说 Admin 可以绕过所有数据边界。
- 不要说当前已经做了分库分表、读写分离或真实生产压测。
- 不要说 Kafka/ES/Redis 任一组件能替代 MySQL 事实源。
- 不要编造 QPS、P99、token/day、生产准确率或真实用户规模。
