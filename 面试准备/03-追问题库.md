# NoteWeave 追问题库

## 使用方式

这份文件适合做 mock interview。每次先问一个主问题，再从后面挑 1 到 3 个追问。

## 1. 项目总述追问

主问题：

- 你先介绍一下 NoteWeave。

追问：

- 你刚才说它不是简单的 RAG demo，那你觉得最能证明这一点的是哪个工程模块？
- 你为什么把团队知识空间和个人研究空间拆开？
- 如果只能保留一个亮点模块，你保留哪个？

## 2. Task / Outbox 追问

主问题：

- 你讲讲这个项目的异步任务底座。

追问：

- 幂等是怎么设计的？
- 重试时为什么还能复用同一个 task，而不是新建一个概念完全不同的对象？
- 为什么 cancel 不做强中断？
- 如果 Kafka 已经收到消息，但任务状态还没变，怎么处理？

## 3. 上传处理链路追问

主问题：

- 你讲讲文档上传到可检索的完整链路。

追问：

- 为什么 chunk 状态要用 Redis bitmap 跟踪？
- 为什么内容去重只在同 space 内做？
- 为什么 merge 后不直接同步解析，而要异步？
- 为什么 reindex 要有 active version 的概念？

## 4. Hybrid RAG 追问

主问题：

- 你讲讲团队侧 Hybrid RAG 是怎么做的。

追问：

- Weighted RRF 为什么比简单拼接结果更好？
- EvidencePostProcessor 解决的真实问题是什么？
- 为什么 citation 要和 retrieval trace 分开？
- 如果面试官说“这不就是 ES + 向量一起查吗”，你怎么反驳这句话过于简化？

## 5. WebSocket Runtime 追问

主问题：

- 你讲讲会话执行框架为什么要用 WebSocket。

追问：

- stop / resume 具体怎么保证状态一致？
- 为什么 runtime state 放 Redis？
- 如果用户断线重连，系统怎么恢复？
- 为什么 DRAFT 不写长期 memory？

## 6. 个人研究主线追问

主问题：

- 你讲讲个人研究链路。

追问：

- 为什么 URL 抓取要做安全限制？
- ConceptCard 为什么还要 alias 和 relation？
- evidence backtrace 这层如果去掉，会出什么问题？
- MethodologyCard 在个人生成里到底带来了什么价值？

## 7. Artifact / Wiki 追问

主问题：

- 为什么 Artifact 和 Wiki 要分离？

追问：

- 为什么要有 ArtifactVersion？
- 为什么 distill 要绑定 artifactVersionId？
- 为什么先沉淀成 SynthesisCard，而不是直接修改已有 ConceptCard？
- 为什么用户确认是必要步骤？

## 8. Observability / Eval / Admin 追问

主问题：

- 你讲讲项目里的可观测性和后台能力。

追问：

- 如果一次回答不准，你会从哪几层往回查？
- Eval 为什么要和正式聊天隔离？
- cleanup scan/execute 为什么分两步？
- Audit log 在什么情况下最有用？

## 9. 简历风险词追问

主问题：

- 你简历里写了 `Hybrid RAG / 长期记忆 / Skill / MCP / Redis runtime state`，分别是什么意思？

追问：

- 你说的 Skill 是开放插件生态，还是受控生成流水线？
- 你说的 Redis runtime state 具体承载了哪些会话执行状态？
- 你说的 MCP 是已经落在主链路里了吗？
- 哪些点是当前已实现，哪些点是已有骨架、容易补齐？
