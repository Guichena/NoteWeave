# NoteWeave 追问题库

## 0. 本篇定位

这份文件不是“把题看一遍就算学过”，而是用来做连续追问训练。目标是把自己从“会背标准答案”推进到“能解释链路、取舍、失败处理和边界”。

所有问题都默认按 NoteWeave 当前已验收口径回答。遇到 MCP、Bibtex、真实生产指标、完整开放 Agent、微服务拆分等问题时，要先分清哪些已经落地、哪些仍是扩展方向。当前 MCP 不能再一概讲成“未落地”，更准确的说法是：B 站解析已经拆成远程 MCP tool service，并接入产物入口和对话触发；但完整开放平台、广义多工具自治调用仍然不是当前主链路事实。

训练时建议直接开口说，不要只在脑子里过。每个主题至少练一轮“主问题 + 3 个追问”，回答必须包含一句结论、一个链路、一个 trade-off 和一个边界提醒。

## 1. 使用方法

每次训练只选一个主题，不要一轮里横跳多个模块。建议按下面顺序练：

1. 先从 `01-项目主述题.md` 或 `02-模块深问题.md` 选一个主问题。
2. 用本文件给自己连续追 2 到 4 个问题。
3. 每次回答都按“场景 -> 结论 -> 链路 -> 证据 -> 取舍 -> 边界 -> 失败处理”组织。
4. 训练完把暴露问题记录到 `05-mock-面试记录.md`。
5. 如果发现某个主题经常答虚，就回到对应专项文档补课。

可直接开口模板：

```text
我的结论是……
在 NoteWeave 里对应的是……链路。
这里的 trade-off 是……
如果失败或被追问边界，我会这样收口……
```

## 2. 项目总述追问

### 起手问题

你先介绍一下 NoteWeave。

### 推荐回答方向

先用一句话定义产品，再讲 `TEAM / PERSONAL` 双空间，然后讲团队和个人两条主链路，最后落到统一任务、证据链、运行态和可观测底座。

### NoteWeave 锚点

- `com.noteweave.space`
- `com.noteweave.task`
- `com.noteweave.team.rag`
- `com.noteweave.chat.runtime`
- `com.noteweave.personal.generation`
- `Phase15AdminOpsIntegrationTest`

### 连续追问路径

1. 你说它不是简单 RAG demo，最能证明这一点的是哪个工程模块？
2. 如果只能保留一个亮点，你会讲任务底座、RAG 证据链还是个人研究链路？为什么？
3. 现阶段哪些核心链路已经验收、哪些还在继续完善，你怎么说明这个边界，而不是夸成生产上线？
4. 如果要真正上线，第一批还要补哪些能力？

### 坑点

- 不要只说“上传文档后问答”。
- 不要把“本地可验收”说成“已有真实生产流量”。

## 3. 权限与空间追问

### 起手问题

为什么要把 `TEAM` 和 `PERSONAL` 做成一级空间边界？

### 推荐回答方向

先讲权限模型和知识生命周期不同，再讲底层复用、上层分治。重点不是“页面分两个菜单”，而是避免权限串线和知识污染。

### NoteWeave 锚点

- `com.noteweave.space`
- `com.noteweave.permission`
- `ResourceAccessService`
- `Space.type`
- `SpaceMember.role`

### 连续追问路径

1. 如果一开始共用一套内容模型，后面会出什么问题？
2. `systemRole` 和 `space role` 为什么不能合并？
3. Citation、Trace、Memory 为什么也要受权限边界约束？
4. 如果个人研究成果要共享给团队，你会怎么做确认和权限迁移？

### 坑点

- 不要把 `PERSONAL` 讲成普通私有文件夹。
- 不要忽略 Memory 和 Citation 的跨边界风险。

## 4. Task / Outbox / Kafka 追问

### 起手问题

你讲讲 NoteWeave 的统一异步任务底座。

### 推荐回答方向

先讲为什么长任务必须统一治理，再讲 `Task + Attempt + Event + Outbox + Kafka + Worker` 各自职责，最后补最终一致、补偿投递和消费侧幂等。

### NoteWeave 锚点

- `TaskService`
- `TaskOutboxService`
- `TaskKafkaPublisher`
- `TaskKafkaConsumer`
- `TaskExecutionCoordinator`
- `TaskServiceIntegrationTest`

### 连续追问路径

1. 为什么不直接在业务事务里发 Kafka？
2. Outbox 能不能保证绝不重复？
3. Worker 重复消费同一个 task 怎么办？
4. 任务取消为什么是 `cancel_requested`，而不是强杀线程？
5. Kafka 投递失败但业务记录已经提交，怎么补偿？

### 坑点

- 不要把 Outbox 讲成强一致。
- 不要把 Redis 讲成主任务队列。

## 5. 上传、解析、索引追问

### 起手问题

团队文档从上传到可检索完整链路怎么走？

### 推荐回答方向

按 `init upload -> chunk upload -> merge -> DOCUMENT_PROCESS -> parse -> chunk -> index -> active version` 讲，重点放在上传态和处理态分离、对象复用边界、索引版本切换和权限过滤。

### NoteWeave 锚点

- `DocumentUploadService`
- `DocumentProcessingService`
- `ChunkService`
- `VectorIndexerService`
- `Phase2UploadFlowIntegrationTest`
- `Phase3DocumentProcessingIntegrationTest`

### 连续追问路径

1. 为什么上传要支持分片、断点续传和 cancel？
2. 为什么 `FileObject` 复用限制在同一个 `spaceId`？
3. merge 后为什么不直接同步解析？
4. 为什么要保存 parsed text object？
5. 为什么 reindex 要有 `activeIndexVersion`？
6. 文档 soft delete 后，怎么避免旧 chunk 被召回？

### 坑点

- 不要说跨空间按 hash 直接复用权限。
- 不要说重建索引时直接覆盖旧版本。

## 6. Hybrid RAG / Citation 追问

### 起手问题

你讲讲团队侧 Hybrid RAG 是怎么做的。

### 推荐回答方向

先讲权限和 scope，再讲多路召回、Weighted RRF、证据后处理、PromptBuilder、Citation 和 RetrievalTrace。重点不是“拼几路检索”，而是让证据、来源和排障闭环成立。

### NoteWeave 锚点

- `HybridRetriever`
- `EvidencePostProcessor`
- `TeamRagPromptBuilder`
- `CitationService`
- `RetrievalTrace`
- `Phase9HybridRetrievalIntegrationTest`

### 连续追问路径

1. BM25、向量召回、Wiki recall 各自补什么短板？
2. Weighted RRF 为什么比简单拼接或分数相加更稳？
3. `EvidencePostProcessor` 解决的真实问题是什么？
4. 无证据时为什么要明确兜底？
5. Citation 和 RetrievalTrace 分别回答什么问题？
6. citation 不准时，你会从哪几层排查？

### 坑点

- 不要把 Citation 讲成答案一定正确。
- 不要让模型在无证据时自由发挥。

## 7. WebSocket Runtime / Memory 追问

### 起手问题

HTTP 问答已经能用，为什么还要 WebSocket Runtime？

### 推荐回答方向

先讲流式交互只是表层需求，再讲 runtime state、stop/resume、partial content、断线恢复和 Memory 写回策略。Redis 只负责短期运行态，不是主事实源。

### NoteWeave 锚点

- `ChatRuntimeService`
- `ChatRuntimeStateStore`
- `MemoryWritebackService`
- `MemoryWritebackStrategy`
- `ContextReadRouter`
- `Phase12LongTermMemoryIntegrationTest`

### 连续追问路径

1. stop / resume 怎么保证状态一致？
2. Redis runtime state 具体存什么？
3. 为什么 runtime state 不全部落 MySQL？
4. DRAFT 和 FORMAL 为什么要区分？
5. 哪些内容不应该写入长期 Memory？
6. Memory 写多了怎么避免噪声污染？

### 坑点

- 不要把 Redis 讲成主队列。
- 不要说 DRAFT 会无差别写入长期记忆。

## 8. 个人研究 / Artifact / Methodology 追问

### 起手问题

个人研究链路为什么做成 `Source -> Card -> Artifact -> Synthesis`？

### 推荐回答方向

先讲“结构化加工”和“长期沉淀”不是一回事，再讲可追踪证据、版本化产物和确认后沉淀。Skill 要讲成受控生成流水线，不讲成完整开放 Agent 平台。

### NoteWeave 锚点

- `PersonalGenerationService`
- `PersonalArtifactDistillationService`
- `MethodologyMatcher`
- `ArtifactPlanExecutor`
- `SkillExecutionLog`
- `SynthesisCard`

### 连续追问路径

1. URL 导入为什么要做安全限制？
2. `importStatus=READY` 为什么必须有可读文本？
3. Evidence backtrace 如果去掉，会出什么问题？
4. ConceptCard 为什么需要 alias 和 relation？
5. MethodologyCard 为什么不直接硬编码在 prompt 里？
6. Artifact 为什么不自动写入个人 Wiki？
7. Distillation 为什么要绑定 `artifactVersionId`？

### 坑点

- 不要把 Artifact 讲成生成后自动进入长期知识。
- 不要把 Skill 讲成开放插件生态。

## 9. Observability / Eval / Admin 追问

### 起手问题

为什么 AI 项目还要做 Observability、Eval 和 Admin/Ops？

### 推荐回答方向

重点讲“出了问题能定位、能复现、能治理”。日志、trace、评测、健康检查、清理和审计各自负责不同层，不要混成一团。

### NoteWeave 锚点

- `AdminObservabilityController`
- `AdminOpsController`
- `SystemHealthService`
- `RagEvalRun`
- `AuditLog`
- `Phase14ObservabilityEvaluationIntegrationTest`
- `Phase15AdminOpsIntegrationTest`

### 连续追问路径

1. 一次坏回答出现后，你会从哪几层反查？
2. Eval 为什么不能污染正式聊天和长期 Memory？
3. PromptVersion 管理有什么价值？
4. Health 为什么拆成 MySQL、Redis、MinIO、Kafka、ES、LLM Provider？
5. Cleanup 为什么要 scan/execute 两步？
6. AuditLog 在哪些场景最有价值？

### 坑点

- 不要把日志等同于评测。
- 不要编造生产准确率和线上效果数字。

## 10. 简历风险词追问

### 起手问题

你简历里写了 `Hybrid RAG / 长期记忆 / Skill / MCP / Redis runtime state`，分别是什么意思？

### 推荐回答方向

分成“已验收可主讲”“已做但要讲清边界”“只能作为扩展方向”三层回答，避免把所有词都说满。

### NoteWeave 锚点

- `HybridRetriever`
- `MemoryWritebackService`
- `SkillExecutionLog`
- `ChatRuntimeStateStore`
- `04-简历风险点与优化口径.md`

### 连续追问路径

1. `Hybrid RAG` 是不是只是几种召回拼一起？
2. `长期记忆` 怎么避免写脏？
3. `Skill` 是开放插件生态，还是受控生成流水线？
4. `MCP` 已经落到主链路了吗？
5. `Bibtex` 当前是已实现还是后续扩展？
6. Redis 在项目里到底承担缓存、运行态还是队列？

### 坑点

- `Bibtex` 仍然是扩展方向；`MCP` 要讲成“已有远程 B 站 tool service 落地，但不是完整开放平台”。
- 不要让简历关键词超出仓库和验收能支撑的范围。

## 11. 指标与压力题追问

### 起手问题

没有生产 QPS、P99、准确率数字时，你怎么证明项目价值？

### 推荐回答方向

先明确当前没有真实生产指标，再讲已有观测面和会怎么设计压测与评测。重点是诚实、可验证，而不是“现场编一个数字”。

### NoteWeave 锚点

- `TaskEvent`
- `RetrievalTrace`
- `LLMCallLog`
- `RagEvalRun`
- `SystemHealth`
- `AuditLog`

### 连续追问路径

1. 如果面试官一定让你说 QPS，你怎么回答？
2. 你会怎么设计压测？
3. RAG 效果看哪些指标？
4. citation coverage 高是否等于回答正确？
5. 文档量上升一个数量级，哪里先瓶颈？
6. 如果要拆微服务，第一刀切在哪里？

### 坑点

- 不要编造“92% 准确率”或 “P99 xx ms”。
- 不要把 citation coverage 当成唯一效果指标。
