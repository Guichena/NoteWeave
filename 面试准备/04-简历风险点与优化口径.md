# NoteWeave 简历风险点与优化口径

## 目标

这份文件专门解决一个问题：

面试时哪些词可以大胆讲，哪些词要换一种更稳的讲法。

## 一、强实现，可作为主亮点

- `Hybrid RAG`
- `长期记忆`
- `Artifact / Wiki 分层`
- `Task / Outbox / Kafka`
- `WebSocket 会话执行`
- `个人 Source -> Card -> Artifact -> Synthesis`
- `PromptVersion / LLM 日志 / RetrievalTrace / Eval / Admin Ops`

推荐讲法：

- 这些能力不是只在文档里，而是有 controller、service、migration、integration test 支撑的。
- 面试时可以直接当成当前主线能力来讲，再补一句“这块还有优化空间”。

## 二、已做但更适合讲成“受控能力”

### 1. Skill

不要讲成：

- “我们做了一个完全开放的 agent skill 平台。”

推荐讲法：

- “这里的 Skill 更接近受控的生成步骤编排。系统会按 artifactType 选择一组固定技能步骤去加载上下文、选证据、生成内容、保存产物，同时记录 SkillExecutionLog，便于排查和审计。”

### 2. Redis runtime state

不要讲成：

- “我们主链路是 Redis 在跑异步任务队列。”

推荐讲法：

- “主异步任务统一还是 Task/Outbox/Kafka。Redis 这块我主要用来承载 WebSocket runtime state，比如会话执行态、stop/resume 控制、断线恢复相关状态，而不是主任务队列。”

## 三、已有骨架，可说成“容易补齐的下一步”

### 1. MCP

当前仓库里没有把 MCP 做成主链路强实现。

推荐讲法：

- “我对 MCP 这类工具协议比较熟，项目在 Studio/Skill/任务编排这块也有比较清晰的扩展位。如果要继续做，MCP 很适合作为工具接入协议层，但当前仓库的主链路重点还是在知识工作台本身，不是在完整 MCP 平台化。”

### 2. Bibtex

当前仓库主输入还是 file/text/url/source。

推荐讲法：

- “如果往学术研究场景继续延伸，Bibtex 很自然会补在个人 Source 导入层，用来解析元数据、作者、年份和引用关系。但当前主实现还没把它做成正式输入类型。”

## 四、当前不适合讲得太满

- “完全自治 Agent 编辑器”
- “成熟的 MCP 工具生态”
- “Bibtex 已完整落地”
- “生产级线上指标我有真实数据”

原因：

- 这些点一旦被追问到 controller、service、数据结构、测试覆盖，很容易口径虚。

## 五、最稳的总原则

能讲优化，但不要跳过当前事实。

最安全的说法是：

- 这块已经有实现
- 当前做到什么程度
- 还可以怎么继续优化

而不是：

- 这块很容易做，所以等于已经做了
