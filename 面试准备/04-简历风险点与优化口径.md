# NoteWeave 简历风险点与优化口径

> 本文件为 2026-06-01 重构版，依据当前代码、测试和 Flyway 迁移整理。不要再按旧阶段计划或旧题库口径背。

## 0. 原则
- 简历上可以写强，但面试回答必须能落到代码和测试。
- 已实现能力要讲成你做过的工程闭环。
- 部分实现或扩展方向要主动降级为“预留方向”或“下一步会这样做”。

## 1. Hybrid RAG
安全口径：我做的是权限约束下的混合检索链路，核心包括 Elasticsearch BM25、向量召回、Wiki recall、Weighted RRF、EvidencePostProcessor、Citation 和 RetrievalTrace。

不能说：已经有生产级 GraphRAG、真实线上准确率、复杂 query rewriting 全套平台。

## 2. 长期记忆
安全口径：当前实现包含 SessionSummary、MemoryItem、SpaceMemory、UserMemory、MemoryWritebackStrategy 和 ContextReadRouter，重点是 DRAFT 不写入、敏感内容过滤、分层上下文加载。

不能说：已经有个性化推荐系统、知识图谱记忆或自动学习用户所有行为。

## 3. Redis runtime state
安全口径：Redis 主要承载 WebSocket ticket、runtime state、partial content、stop/resume 和短期状态。主后台任务仍是 Task/Outbox/Kafka。

不能说：Redis 是项目主消息队列或业务事实源。

## 4. Skill / Agent
安全口径：Skill 在当前项目里更像可控生成流水线、工具注册和执行日志，和 Artifact generation 结合。它不是完全开放式多 Agent 自主平台。

不能说：已经实现自主规划、复杂多 Agent 协作、RL 训练。

## 5. MCP / Bibtex
MCP 安全口径：项目有 Studio MCP/Bilibili 工具扩展相关代码，但主面试回答应放在 Studio 可扩展工具层，不要说成所有核心链路都依赖 MCP。

Bibtex 安全口径：学术资料导入可以作为 Source 导入的自然扩展，但当前主链路还是 FILE/URL/TEXT Source、卡片编译和证据回溯。

## 6. 指标数字
- 不要编造 QPS、P99、token/day、线上用户数。
- 可以说已有 LLMCallLog、RetrievalTrace、RagEvalRun、TaskEvent，后续会用 recall@k、MRR、citationCoverage、latency、failure rate 验证。
- 如果面试官要数字，先说明当前是本地可验证工程原型，不是线上压测报告。

## 7. Rerank / Query Rewrite / GraphRAG
Rerank 安全口径：当前主链路使用 Weighted RRF 做多路召回融合，rerank 可以作为后续高价值场景的增强。不要说当前已经有独立 rerank 模型或在线 rerank 平台。

Query rewrite 安全口径：当前可以从 Prompt、Retriever、Trace 和 Eval 的角度说明未来会补 query rewrite，但不要把它说成已落地的主能力。

GraphRAG 安全口径：当前有 WikiGraph、WikiRelation 和 KnowledgeGraph 展示/维护能力，但 RAG 主链路仍是 BM25、向量、Wiki recall 和 RRF，不要说成完整 GraphRAG。

## 8. 面试时主动澄清边界
- `已实现`：双空间、权限、上传处理、Task/Outbox/Kafka、Hybrid RAG、Citation、Wiki、Artifact、Memory、Eval/Ops。
- `当前暂未实现或不应说满`：生产级指标、复杂审批流、完整 GraphRAG、开放式 Agent 平台、完整 Bibtex 主链路、复杂 query rewrite / rerank 平台。
- `后续优化`：更强 rerank、query rewrite、索引 alias 灰度、Prompt 注入防护、更多文档类型、线上指标体系。
