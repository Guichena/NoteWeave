# 文件：00_面试官可问点总览.md

## 1. 面试官视角下这个项目最值得问什么

NoteWeave 最强的面试价值不是“用了大模型”，而是把 AI 知识系统里最容易被忽略的工程问题做成了闭环：权限、异步、检索、证据、运行态、记忆、成果沉淀、可观测和后台运维。面试官通常会从“你做了什么”快速推进到“为什么这么设计、失败怎么办、边界在哪里、如何扩展”。

## 2. 项目的核心可问点地图

### 业务与架构边界

- 为什么 NoteWeave 不是普通 RAG Demo？
- 为什么要设计 `TEAM` 和 `PERSONAL` 双空间？
- 团队知识、个人研究、Artifact、Wiki、Memory 的边界是什么？
- 当前哪些能力已实现，哪些是未来扩展？

### 权限与安全

- `systemRole` 和 `space role` 为什么分离？
- Citation 返回前为什么要二次权限校验？
- ES 检索 filter 之外为什么还要 MySQL 状态复核？
- URL Source 导入如何防 SSRF？
- Admin 能力如何避免越权和敏感日志泄露？

### 异步任务与一致性

- 为什么统一成 `Task + Attempt + Event + Outbox + Kafka + Worker`？
- 为什么不直接在业务事务里发 Kafka？
- Worker 重复消费如何幂等？
- RUNNING 任务为什么用 `cancel_requested`？
- outbox 投递失败如何补偿？

### 文档处理与索引

- 分片上传、断点续传、秒传、cancel、cleanup 怎么设计？
- FileObject 为什么按 `spaceId + contentHash` 复用？
- parsed text 为什么保留？
- `activeIndexVersion` 如何保证重建失败时旧索引可用？
- 文档删除后如何避免旧 chunk 被召回？

### RAG 与证据链

- BM25、Vector、Wiki recall 各自解决什么？
- Weighted RRF 为什么比直接加权分数更稳？
- `EvidencePostProcessor` 为什么要做去重、相邻合并、同文档限流？
- 无证据时为什么要明确兜底？
- Citation 和 RetrievalTrace 的区别是什么？

### WebSocket Runtime 与长期记忆

- HTTP 已经能问答，为什么还要 WebSocket？
- stop/resume/partial content/ack 如何设计？
- Redis runtime state 和 MySQL 持久化如何分工？
- DRAFT 为什么不写长期 memory？
- MemoryWriteback 如何过滤敏感内容和低价值内容？

### 个人研究与 Artifact

- Source 到 ArticleCard/ConceptCard 的链路怎么走？
- 为什么 evidence backtrace 不能只相信 LLM quote？
- Artifact 为什么不等于 ChatMessage？
- MethodologyCard 为什么不写死在 prompt 里？
- Skill 是受控 pipeline，不是完整开放 Agent，这个边界如何解释？
- Artifact 为什么确认后才沉淀为 SynthesisCard？

### 可观测、评测与运维

- 一次坏回答如何从 answer 反查到 retrieval、citation、prompt、LLM log？
- RAG Eval 如何隔离正式会话和 Memory？
- System health 为什么拆 MySQL、Redis、MinIO、Kafka、ES、LLM Provider？
- cleanup 为什么先 scan 再 execute？
- AuditLog 记录什么价值？

### 扩展性与压力追问

- 文档量扩大一个数量级哪里先瓶颈？
- 如果拆微服务先拆哪里？
- 如果 Citation 不准如何定位？
- 如果要支持 DOCX、扫描 PDF、Bibtex、MCP，该接在哪些扩展点？
- 如何诚实回答没有生产 QPS/P99？

## 4. 面试表达总原则

- 先讲业务问题，再讲架构方案，不要先报技术栈。
- 每个亮点都按“场景、方案、收益、取舍、失败处理”组织。
- 对已实现能力可以坚定讲，对未来能力要明确说是扩展方向。
- 不编造 QPS、P99、token/day、生产规模等仓库没有的数据。
- `MCP`、`Bibtex`、完整开放 Agent、多服务拆分只能作为扩展方向，不能说成当前主链路。

## 5. 最推荐主打的三个故事

### 故事 1：统一异步骨架

场景：上传解析、Source 编译、Artifact 生成、Wiki 入索引、Eval 和 cleanup 都是长任务。

方案：统一为 `Task + Attempt + Event + Outbox + Kafka + Worker`。

收益：状态、重试、取消、审计、前端进度和后台运维复用一套模型。

### 故事 2：Evidence-first RAG

场景：AI 问答必须可信、可追踪、可排障。

方案：BM25/Vector/Wiki recall + Weighted RRF + EvidencePostProcessor + Citation + RetrievalTrace。

收益：答案不只是生成文本，而能回到 source、chunk、version 和 snapshot。

### 故事 3：生成成果和长期知识分层

场景：LLM 生成结果不一定天然可信，不能自动污染知识库。

方案：Artifact 独立版本化；团队侧人工发布 Wiki；个人侧 proposal/confirm 后沉淀 SynthesisCard。

收益：保留生成效率，同时控制长期知识质量和证据边界。

## 6. 面试前自查清单

- 我是否能从 1 分钟项目介绍自然过渡到一个核心模块深挖？
- 我是否能说出至少 3 个真实类名或服务名作为实现锚点？
- 我是否能解释设计取舍，而不是只说“为了性能”或“为了安全”？
- 我是否能承认当前没有生产指标，并说明会如何测？
- 我是否能把简历风险词解释到和仓库事实一致？

## 7. 新版深度材料怎么用

每个主题文件现在都补充了三个更深的复习区：

- `整条链路深讲`：用于回答“你把这个功能完整讲一下”的问题，重点是按步骤讲清输入、处理、状态变化、依赖组件、落库和失败边界。
- `原理与设计原因速查`：用于回答“为什么这么设计、不这么做会怎样”的追问，重点是把设计选择背后的工程原理说清楚。
- `3 到 5 分钟深答模板`：用于面试现场直接复述，适合面试官说“展开讲讲”时使用。

推荐复习顺序：

1. 先读 `00_面试官可问点总览.md`，建立项目可问点地图。
2. 每个主题先读 `整条链路深讲`，确保你能画出链路。
3. 再读 `问答与讲解`，练习面试官具体问题怎么回答。
4. 最后背 `3 到 5 分钟深答模板`，形成可以自然说出口的版本。

## 8. 大厂面试官最喜欢的追问方式

面试官通常不会停在“这个功能是什么”，而会按下面路径推进：

```text
功能是什么
-> 整条链路怎么走
-> 中间状态怎么流转
-> 为什么不用更简单方案
-> 失败、重复、取消、越权怎么办
-> 如何观测和排障
-> 数据量变大以后哪里先瓶颈
```

所以回答时不要只给结论。比如讲 RAG，不要只说“用了 Hybrid RAG”，要讲：权限校验、session scope、BM25/vector/wiki recall、RRF、EvidencePostProcessor、PromptBuilder、LLMCallLog、Citation、RetrievalTrace、无证据兜底和 memory writeback。这样的回答才像真实做过系统。

## 9. 面试现场通用表达骨架

遇到任何模块深挖题，可以套这个结构：

```text
这个模块解决的是 xxx 场景下的 xxx 问题。
完整链路是：A -> B -> C -> D。
其中关键状态有 xxx，关键表/类有 xxx。
我这么设计主要是为了解决 xxx，例如一致性/权限/可追踪/失败恢复。
不用简单方案的原因是 xxx。
如果失败或重复，会通过 xxx 兜底。
如果后续规模变大，我会先看 xxx 指标，再优化 xxx。
```

## 10. 必须守住的事实边界

- 可以坚定说已实现：双空间、权限、Task/Outbox/Kafka Worker、上传解析索引、团队 RAG/Citation、WebSocket Runtime、个人 Source/Card、Artifact/Synthesis、Memory、Methodology、Eval/Observability、Admin/Ops。
- 可以作为优化说：更复杂的 query rewrite、reranker、更完整 prompt governance、更丰富 eval 指标、更多文档类型、个人成果共享团队。
- 只能作为扩展方向说：MCP 主链路、Bibtex 端到端、完整开放 Agent、多服务生产拆分、真实生产 QPS/P99。
