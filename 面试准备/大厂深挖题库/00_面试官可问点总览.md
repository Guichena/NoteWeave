# 大厂深挖题库总览

> 本文件为 2026-06-01 题组版，依据当前代码、测试和 Flyway 迁移整理。复习时不要把新增特性孤立成单点背诵，要把相似问题合并成一类面试官意图来回答。

## 0. 面试官真正想确认什么

大厂面试不会只顺着模块列表问。更常见的方式是从一个现象切入，然后连续追问边界、链路、失败、验证和演进。所以准备时按下面八类题组练：

1. 边界与隔离：系统会不会串数据，权限是否只靠前端，Admin、Space、Citation、Memory、Artifact、Wiki 的边界是否讲得清。
2. 一致性与恢复：长任务为什么能重试，Kafka/Outbox/Worker 怎么协作，删除、取消、重建索引、断线恢复会不会留下脏状态。
3. 证据与防幻觉：RAG 是不是只调模型，BM25/向量/Wiki recall 如何融合，Citation 和 RetrievalTrace 如何支撑排障。
4. 生成与沉淀：ChatMessage、Artifact、Wiki、SynthesisCard、Memory 哪些是临时结果，哪些是长期知识，为什么需要人工确认。
5. 工具与 Agent 边界：MCP、Bilibili tool、SkillExecutionLog、ArtifactPlanExecutor 能讲成受控工具链，但不要讲成完整开放 Agent 平台。
6. 数据模型与中间件落位：表结构、索引、MySQL/Redis/MinIO/ES/Kafka 分工是否能讲清，跨组件失败是否能对齐。
7. 自动化与运营：AutoWikiMaintenance、WikiGraph、RAG Eval、PromptVersion、LLMCallLog、AnswerFeedback、Admin/Ops 如何让系统可评测、可排障、可治理；单测、MockMvc、ContainerizedIntegrationTest 如何证明关键链路可回归。
8. 性能与扩展：瓶颈怎么找，哪些地方最终一致，哪些组件能替换，哪些指标现在能采集，哪些不能编造成生产数据。

## 1. 题组到真实能力的映射

### 边界与隔离题组

常见问法：
- 为什么要有 TEAM/PERSONAL 双空间？
- systemRole 和 SpaceMember.role 为什么分开？
- Citation 返回前还要不要做权限校验？
- Admin 能不能直接绕过所有空间边界？

回答锚点：
- Space 是最高业务容器，PERSONAL 和 TEAM 的资源归属不同。
- SpacePermissionService、ResourceAccessService、SpaceMember、users.system_role 分工不同。
- Citation、Trace、Artifact、Memory 这类二次读取链路也必须回到资源权限判断。
- Admin 是运维角色，不等于可以无边界读取所有私有知识。

### 一致性与恢复题组

常见问法：
- 为什么不在业务事务里直接发 Kafka？
- Outbox 解决的是强一致还是最终一致？
- Worker 重复消费、任务取消、任务重试怎么处理？
- ES 写成功但 DB 状态没切怎么办？

回答锚点：
- 业务事务先落 Task 和 TaskOutbox，调度器再投递 Kafka。
- Consumer 只信 taskId，执行前回查 DB，Worker 通过 TaskExecutionCoordinator 记录 attempt/event/status。
- 上传解析、WIKI_INDEX、RAG_EVAL_RUN、CLEANUP_RESOURCE 都复用这套骨架。
- 失败排查时看 TaskEvent、Outbox、Kafka 消费、业务表状态和外部组件状态。

### 证据与防幻觉题组

常见问法：
- Hybrid RAG 具体 hybrid 在哪里？
- Weighted RRF 为什么比简单拼接稳？
- 没有证据为什么不能硬答？
- 用户质疑引用不准，怎么查？

回答锚点：
- HybridRetriever 组合 BM25、向量和 Wiki recall。
- WeightedReciprocalRankFusion 做多路排序融合，EvidencePostProcessor 做去重、相邻合并、限流和截断。
- TeamRagPromptBuilder 约束模型基于证据回答，CitationService 持久化引用，RetrievalTrace 记录召回和后处理过程。
- RAG Eval 可以用 case/run/result 验证 recallAtK、MRR、citationCoverage，但不能包装成真实线上准确率。

### 生成与沉淀题组

常见问法：
- Artifact 为什么不直接放进 ChatMessage？
- Artifact 为什么不能自动进入 Wiki 或 Memory？
- SynthesisCard 为什么要 proposal/confirm？
- MethodologyCard 是模板、Prompt 还是训练？

回答锚点：
- Artifact 是版本化产物，ArtifactVersion、ArtifactSource、ArtifactCitation 保留生成历史和证据。
- MethodologyCard 管 workflow、outputStructure、qualityChecklist，是可管理的方法论输入，不是模型训练。
- 团队 Wiki 是人工确认后的长期知识，个人 SynthesisCard 也要用户确认后沉淀。
- MemoryWritebackStrategy 会过滤 DRAFT、短问候和敏感内容，避免把临时探索污染长期记忆。

### 工具与 Agent 边界题组

常见问法：
- 你说 MCP，当前到底实现了什么？
- Bilibili MCP 怎么进入 Chat 或 Artifact 生成？
- SkillExecutionLog 记录什么价值？
- 为什么不能把它说成完整 Agent 平台？

回答锚点：
- 当前是受控工具扩展：StudioMcpToolRegistry 注册工具，Local/RemoteBilibiliMcpToolService 负责本地或远程调用，BilibiliMcpCoreService 生成结构化上下文。
- Chat 可通过 `/mcp bilibili <url>` 触发，ArtifactPlanExecutor 可在有工具参数时加入 LoadMcpToolContextSkill。
- SkillExecutionLog 记录 skillName、input/output、status、promptVersion 等执行过程，便于追踪工具和生成步骤。
- 现在不是开放式 Agent marketplace，也不是自主多 Agent 编排平台。

### 自动化与运营题组

常见问法：
- 坏答案怎么排查？
- PromptVersion 为什么重要？
- AutoWikiMaintenance 和 WikiGraph 有什么实际作用？
- cleanup 为什么先 scan 再 execute？
- 你怎么证明异步、RAG、MCP、Admin/Ops 不是只靠手测？

回答锚点：
- PromptVersion、LLMCallLog、RetrievalTrace、AnswerFeedback 用来定位模型输入、输出、召回证据和用户反馈。
- AdminRagEvalController/RagEvaluationService 管 eval case/run/result，评测任务走 Task 骨架。
- WikiGraphService、WikiGraphSyncService、AutoWikiMaintenanceService 让长期知识能被链接、检查和维护。
- Admin/Ops 的 cleanup、health、audit、task 管理让残留资源和失败任务可见、可审计、可人工介入。
- 验证要分层讲：单测覆盖 RRF、EvidencePostProcessor、PromptBuilder、SafeUrlContentFetcher 等纯逻辑；容器化集成测试覆盖 MySQL、Redis、Kafka、MinIO、ES 的状态协作；RAG Eval 做离线质量回归。

### 数据模型与中间件落位题组

常见问法：
- 你这个项目核心表结构怎么设计？
- 为什么 Citation、Trace、LLMLog、Feedback 不放在同一张表？
- MySQL、Redis、MinIO、ES、Kafka 分别承担什么职责？
- 如果 ES 和 MySQL 状态不一致，哪个是事实源？

回答锚点：
- 表结构按生命周期拆：Space/Member、Task/Outbox、Document/Chunk、Citation/Trace、Artifact/Version、Wiki/Version、Memory、Eval/Ops。
- 索引按访问路径讲：空间过滤、任务积压、版本切换、trace 排障、eval/ops 时间序列。
- 中间件按数据形态讲：MySQL 事实源，Redis 短期状态，MinIO 大对象，ES 检索读模型，Kafka 任务消息通道。
- 跨组件失败回到 TaskEvent、Outbox、RetrievalTrace、Citation、cleanup 和 Admin/Ops。

### 性能与扩展题组

常见问法：
- 如果并发上来，先哪里会成为瓶颈？
- Kafka、ES、LLM、MinIO 任何一个挂了怎么降级？
- 单体项目怎么演进成更大规模？
- 没有生产指标时怎么回答性能？

回答锚点：
- 不编造 QPS/P99/token/day，只讲现有日志、Trace、TaskEvent、RAG Eval 能采什么指标。
- 扩展先按边界拆：文档处理 Worker、检索/RAG、LLM 调用、Artifact 生成、Admin Eval/Ops。
- MySQL 是业务事实源，Redis 是短期运行态，ES 是检索索引，Kafka 是后台任务通道，LLM 不做权限判断。
- 降级要讲具体场景：ES 失败可提示检索不可用或退化到有限上下文，Kafka 堆积看 Task/Outbox，MinIO 丢对象会影响原文和 Citation 展示。

## 2. 面试前必须避开的口径

- 不要把 Redis 说成主任务队列。
- 不要把当前 WikiGraph 说成完整 GraphRAG 主链路。
- 不要把 Skill/MCP 说成完整开放 Agent 平台。
- 不要说 Artifact 会自动进入 Wiki、Memory 或 ConceptCard。
- 不要说 Admin 可以无边界绕过所有数据权限。
- 不要编造线上规模、P99、QPS、生产准确率或 token 成本。

## 3. 推荐练习方式

每次练一组，不练一个模块。比如先练“外部输入怎么受控进入系统”，把上传、URL Source、Bilibili MCP、用户 prompt 放在一起讲；再练“临时内容怎么变长期知识”，把 ChatMessage、Artifact、Wiki、SynthesisCard、Memory 放在一起讲。能把一组问题讲成端到端闭环，比背 10 个孤立模块更能抗追问。
