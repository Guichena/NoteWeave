# 通用问题分主题深答使用说明

> 本文件为 2026-06-01 题组版。这个目录仍保留若干主题文件，方便查答案和代码锚点；真正练习时不要按文件名孤立背，要把相似问题合并成题组。

## 0. 先把通用题翻译成 NoteWeave 题组

- 项目介绍、架构设计、模块边界：合并成“边界与闭环”题组，回答 TEAM/PERSONAL、Space 权限、资料进入、RAG、Artifact、Wiki、Admin/Ops。
- MQ、Outbox、幂等、分布式事务：合并成“一致性与恢复”题组，回答 Task、TaskAttempt、TaskEvent、TaskOutbox、Kafka、Worker。
- Redis、缓存、运行态、会话恢复：合并成“短期状态与事实源边界”题组，回答 WebSocket runtime、ticket、stop/resume、DRAFT/FORMAL，不把 Redis 说成主队列。
- 表结构、索引、数据库设计：合并成“数据模型与中间件落位”题组，回答 Space/Task/Document/Citation/Artifact/Wiki/Memory/Eval/Ops 表为什么这样拆。
- RAG、向量检索、Prompt、幻觉治理：合并成“证据可信”题组，回答 BM25/向量/Wiki recall、Weighted RRF、EvidencePostProcessor、Citation、RetrievalTrace、RAG Eval。
- Artifact、Skill、Agent：合并成“生成与工具边界”题组，回答 ArtifactPlanExecutor、SkillExecutionLog、MethodologyCard、Bilibili MCP、SynthesisCard。
- 指标、压测、排障、沟通：合并成“可观测与演进”题组，回答 PromptVersion、LLMCallLog、AnswerFeedback、Admin/Ops、cleanup、health、audit。

## 1. 推荐练习顺序

1. 先读 `../00_面试官可问点总览.md` 和 `../11_通用问题按NoteWeave深答.md`，把题组口径背熟。
2. 再按需要打开本目录的具体主题文件，拿里面的代码锚点和可复述答案补细节。
3. 每个主题回答都补一句“这类问题还会牵到哪个题组”，例如 RAG 会牵到权限、Citation、Trace、Eval，Artifact 会牵到 Skill、MCP、Synthesis 和 Wiki。

## 3. 每题必带的三层边界

1. 已实现：只讲当前代码、测试、迁移能支撑的能力。
2. 设计目标：讲为什么这样设计，解决什么工程问题。
3. 后续可扩展：讲未来可以怎么做，但不要冒充已经落地。

## 4. 面试前自查

- 能否把类似问题归到题组，而不是翻目录找单个模块背。
- 能否自然带出新增特性：Bilibili MCP、ArtifactPlanExecutor、SkillExecutionLog、MethodologyCard、AutoWikiMaintenance、WikiGraph、PromptVersion、RAG Eval、Admin/Ops。
- 能否避开夸大：不说完整 Agent 平台、不说完整 GraphRAG、不说 Redis 主队列、不说自动沉淀、不编造生产指标。
- 能否补上表结构和中间件深挖：核心表、组合索引、Redis key、MinIO object_key、ES index、Kafka topic/Outbox。
