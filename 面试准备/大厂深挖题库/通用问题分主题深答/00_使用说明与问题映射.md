# 文件：00_使用说明与问题映射.md

## 1. 这组文档解决什么问题

这组文档是对 `11_通用问题按NoteWeave深答.md` 的分主题深化版。原文是一份完整长答，适合集中阅读；本目录按大厂面试常见追问方向拆开，适合逐主题背诵、模拟面试和快速定位薄弱点。

每个主题都按同一套结构组织：

- `本主题覆盖的通用问题`：把原始清单里的重复问法归并。
- `架构视角怎么切入`：先从 NoteWeave 整体系统回答，不陷入单点功能。
- `完整链路深讲`：讲清输入、处理、状态、存储、异步、失败和观测。
- `关键实现锚点`：列出可以在面试中说出口的类、表、组件或状态。
- `为什么这么设计`：解释设计原因、替代方案和取舍。
- `可直接复述的深答`：给 2 到 5 分钟可直接说的版本。
- `追问兜底`：面试官继续追时怎么守住事实边界。

## 3. 推荐复习顺序

1. 先读 `01`，把项目主线讲顺。
2. 再读 `03` 和 `05`，这是最容易体现技术深度的两条链路。
3. 然后读 `06` 和 `07`，补上 AI 系统的记忆、运行态和 Agent 边界。
4. 最后读 `08` 和 `09`，准备压力题、指标题和开放题。

## 4. 统一回答骨架

遇到通用问题时，可以套这个结构：

```text
我先从整体架构讲这个问题。
在 NoteWeave 里，这个能力服务于 xxx 闭环。
完整链路是 A -> B -> C -> D。
关键实现上，用到了 xxx 类/表/状态。
这么设计是因为 xxx；如果用更简单方案，会有 xxx 风险。
当前已经实现的是 xxx；未来可以扩展的是 xxx。
如果面试官关心指标，我会用 xxx 观测，而不会编造生产数字。
```

## 5. 必须守住的边界

- 当前项目不是完整开放 Agent 平台，而是受控 Skill pipeline。
- 当前主链路不是 GraphRAG，不要把 Wiki/Concept relation 夸成 GraphRAG 主链路。
- 当前 MCP、Bibtex 是扩展方向，不是已实现主链路。
- 当前没有生产 QPS、P99、token/day、线上准确率数字。
- 当前没有分库分表、本地缓存 + Redis 二级缓存、微服务注册中心主链路。
