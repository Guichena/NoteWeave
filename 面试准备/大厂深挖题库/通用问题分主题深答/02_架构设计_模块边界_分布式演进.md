## 0. 通用问题如何转成项目深答
先把通用八股问题落到 NoteWeave 的真实模块，再回答场景、方案、收益、权衡、故障和指标。下面是本主题的项目化深答。

## 1. 本篇定位
这个主题用于把八股中间件、RAG 和 Agent 追问映射回真实项目，避免答成脱离项目的背诵。

## 2. 面试先说版
如果面试官问中间件或 Agent，我会先把它落到 NoteWeave。MySQL 是业务事实源，保存用户、空间、任务、文档、卡片、Artifact、Citation、Memory、Eval、Admin 状态。Redis 是短期状态，主要用于 WebSocket ticket、runtime、stop/resume，不是主任务队列。MinIO 保存上传对象、解析文本、citation snapshot 和 artifact 相关对象。Elasticsearch 承担 BM25、向量和 Wiki 索引，不做权限事实源，所以检索前后都要带 DB 权限或状态校验。Kafka 承担后台任务消息，配合 TaskOutbox 做最终一致。Agent 方面当前更适合讲为可控的生成工作流和 Skill 执行日志，而不是完全自主多 Agent。

## 3. 当前真实口径
MySQL 存业务事实，Redis 存短期运行态，MinIO 存文件和快照，Elasticsearch 存检索索引，Kafka 承载后台任务，LLM/Skill 只在受控编排里执行。

### 已实现
- docker-compose.yml 提供 MySQL、Redis、MinIO、Elasticsearch、Kafka。
- Task/Outbox/Kafka 是主异步骨架。
- Redis 在 chat runtime 和 upload runtime state 中承担短期状态。
- StudioMcpToolRegistry、RemoteBilibiliMcpToolService 等说明有工具扩展尝试，但主链路不要夸成完整 MCP 平台。

### 设计目标
- 先讲每个中间件在 NoteWeave 的职责，再讲为什么不用它承担不适合的职责，例如 Redis 不做主任务队列、ES 不做业务事实源、LLM 不做权限判断。
- 中间件问题可以自然回到项目链路，并且体现工程边界感。

### 后续可扩展
- 如果 Kafka 换成 RabbitMQ，会影响哪些抽象？
- 如果 ES 挂了，团队问答如何降级？
- 如果 MinIO 对象丢失，Citation 怎么表现？
