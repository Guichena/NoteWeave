# 文件：00_使用说明_如何从初学者讲到大厂深挖.md

## 1. 这版材料和上一版有什么区别

上一版 `通用问题分主题深答` 主要解决“怎么按主题回答”。这一版是加深版，目标是让你回答时既能让初学者听懂，又能经得住大厂面试官继续追问。

这版每个主题都会尽量按下面顺序展开：

1. `先讲业务`：这个能力在 NoteWeave 里解决什么业务问题。
2. `再讲概念`：对应的八股知识点是什么。
3. `解释原因`：为什么需要这个设计，不做会有什么问题。
4. `讲怎么做`：具体链路、状态、表、类、组件怎么配合。
5. `讲内部原理`：涉及哪些数据结构、算法、协议、事务或存储机制。
6. `讲取舍`：有没有替代方案，为什么当前项目选这个。
7. `讲追问`：面试官可能继续怎么问，应该怎么接。

## 2. 面试回答的层次感

很多同学回答项目题的问题是：上来就堆技术名词，比如“用了 Redis、Kafka、ES、RAG”。这会让面试官觉得你只会背技术栈。更好的方式是由浅入深：

```text
业务问题
-> 架构设计
-> 核心链路
-> 关键技术点
-> 底层原理
-> 失败场景
-> 指标和扩展
```

例如问“为什么用 Kafka”，不要直接说“削峰、异步、解耦”。这三个词太八股，面试官会继续追。你应该结合 NoteWeave 说：

```text
NoteWeave 有文档解析、Source 编译、Artifact 生成、Eval、Cleanup 等长任务。
这些任务耗时长、依赖 MinIO/ES/LLM、失败概率比普通 DB 写入高。
所以同步 HTTP 不合适，我们把它们抽象成 Task。
Task 创建和 Outbox 写入在同一个 MySQL 事务里，Kafka 只负责分发。
Worker 消费时回查 DB 状态，保证重复消费不会重复执行。
```

这样就从业务说到了架构，再进入 MQ、事务消息、幂等这些八股知识。

## 4. 背诵建议

初学者可以先背每个主题的“业务解释”和“可直接复述”。准备大厂深挖时，再重点看“八股知识点”和“追问兜底”。

如果时间有限，优先掌握：

- `03_MQ_Outbox_事务一致性_幂等加深版.md`
- `05_RAG_ES_向量检索_Prompt幻觉治理加深版.md`
- `06_WebSocket_Memory_会话恢复加深版.md`

这三篇最容易体现技术深度。
