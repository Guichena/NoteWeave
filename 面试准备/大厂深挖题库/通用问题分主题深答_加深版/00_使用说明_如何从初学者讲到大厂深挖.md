# 如何从初学者讲到大厂深挖

> 本文件为 2026-06-01 题组版。加深版不是给每个模块再堆一遍内容，而是训练你把相似问题合并回答，并能接住连续追问。

## 0. 初学者最容易错在哪里

- 只会按模块背：问 RAG 就只讲 RAG，问 Redis 就只讲 Redis，听起来像八股拼贴。
- 只讲功能不讲边界：没有说清 TEAM/PERSONAL、权限、Citation、Memory、Admin 的隔离。
- 只讲业务不讲表结构：说不清 `task_outbox`、`document_chunk`、`retrieval_trace_item`、`artifact_version`、`wiki_page_version` 为什么存在。
- 只讲成功链路不讲失败：没有 Task、Outbox、Kafka、Worker、Trace、Admin/Ops。
- 只讲 AI 不讲证据：没有 BM25/向量/Wiki recall、Weighted RRF、EvidencePostProcessor、Citation、RetrievalTrace。
- 看到 MCP、Skill、Agent 就说满：容易把受控 Bilibili MCP 工具链讲成完整开放 Agent 平台。

## 1. 题组化训练法

### 第一步：把问题归类

看到题目先判断它属于哪类：

- 边界与隔离：Space、Permission、Citation、Artifact、Wiki、Memory、Admin。
- 一致性与恢复：Task、Outbox、Kafka、Worker、WIKI_INDEX、RAG_EVAL_RUN、CLEANUP_RESOURCE。
- 外部输入受控：上传文件、URL Source、Bilibili MCP、用户 prompt。
- 证据可信：Hybrid RAG、Wiki recall、EvidencePostProcessor、PromptBuilder、Citation、RetrievalTrace、RAG Eval。
- 生成与沉淀：ChatMessage、Artifact、Methodology、SynthesisCard、Wiki、AutoWikiMaintenance、Memory。
- 工具与 Agent 边界：StudioMcpToolRegistry、Local/RemoteBilibiliMcpToolService、ArtifactPlanExecutor、SkillExecutionLog。
- 表结构与中间件落位：MySQL 表、Redis key、MinIO object、ES index、Kafka topic/Outbox。
- 可观测与扩展：PromptVersion、LLMCallLog、AnswerFeedback、Admin/Ops、cleanup、health、audit、压测方案。

### 第二步：按五句话展开

1. 这个问题本质上在考什么风险。
2. NoteWeave 现在怎么做。
3. 这样做比简单方案好在哪里。
4. 失败、重试、权限、证据怎么兜底。
5. 如果继续扩展，下一步会做什么，但当前不能说满什么。

### 第三步：每组准备一个 2 分钟回答

不要给每个新增特性单独准备一段孤立答案。比如 Bilibili MCP 应该放进“外部输入受控”和“工具与 Agent 边界”两组里；AutoWikiMaintenance 应该放进“生成沉淀”和“可观测运营”两组里；RAG Eval 应该放进“证据可信”和“可观测扩展”两组里。表结构问题不要单独背 SQL，要放进“数据生命周期”和“中间件职责边界”两组里。

## 2. 加深版目录怎么用

- `01_业务闭环与项目主述加深版.md`：先练项目总述，再把所有新增能力归入闭环。
- `02_整体架构与分布式演进加深版.md`：练边界、事实源、中间件职责和未来拆分。
- `03_MQ_Outbox_事务一致性_幂等加深版.md`：练长任务一致性和失败恢复。
- `04_Redis_缓存_运行态_数据结构加深版.md`：练 Redis 作为运行态而不是主事实源。
- `05_RAG_ES_向量检索_Prompt幻觉治理加深版.md`：练证据可信和 RAG 排障。
- `06_WebSocket_Memory_会话恢复加深版.md`：练 DRAFT/FORMAL、stop/resume、长期记忆边界。
- `07_Artifact_Skill_Agent边界加深版.md`：练 ArtifactPlanExecutor、SkillExecutionLog、Methodology、Bilibili MCP、Agent 边界。
- `08_指标压测排障沟通加深版.md`：练 PromptVersion、LLMCallLog、RAG Eval、Admin/Ops、cleanup、health、audit。

## 3. 新增特性应该怎么融进去

- Bilibili MCP：不要单独吹工具，放到“外部输入怎么受控进入系统”和“工具失败怎么追踪”里讲。
- MethodologyCard：不要说成训练模型，放到“生成质量怎么稳定”和“Artifact 输出结构怎么管理”里讲。
- ArtifactPlanExecutor：不要说成全自动 Agent，放到“生成步骤怎么可控编排、怎么留 SkillExecutionLog”里讲。
- SkillExecutionLog：放到“坏结果怎么排查”和“工具执行怎么审计”里讲。
- AutoWikiMaintenance/WikiGraph：放到“长期知识怎么维护”和“自动化不能替代人工确认”里讲。
- PromptVersion/LLMCallLog/RetrievalTrace/AnswerFeedback：放到“坏答案怎么查、效果怎么评”里讲。
- Admin/Ops/RAG Eval/cleanup/health/audit：放到“运营、排障、评测、资源治理”里讲。
- MySQL/Redis/MinIO/ES/Kafka：放到“数据形态怎么落位”里讲，重点是事实源、短期状态、大对象、读模型、消息通道。

## 4. 终极检查

一段回答如果没有出现“边界、状态、证据、失败、验证、不能说满”中的至少四个点，就还不够大厂深挖。读完本目录后，目标不是记住更多标题，而是能把一个问题自然扩展成一条完整工程链路。
