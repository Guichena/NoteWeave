## 2. 没有生产数据时，正确姿势不是沉默，而是换成验证设计

很多候选人一被问到 QPS / P99，就只剩一句“现在没有生产数据”。这句必须说，但还不够。

更稳的回答结构是：

```text
当前没有真实线上指标
-> 所以我不会编数字
-> 但我已经把验证拆成几层来设计
-> 每层看什么指标、用什么 case、怎么判断是否过关
```

这样面试官会感觉你不是没准备，而是知道工程验证应该怎么搭。

## 3. 压测设计为什么要按链路拆，而不是只给一个总 QPS

NoteWeave 不是单一 CRUD 系统，一个总 QPS 数字解释力很差。更合理的设计是分层压：

### 3.1 上传链路

关注：

- chunk 上传并发。
- merge latency。
- MinIO 写入稳定性。
- bitmap 更新和清理。

### 3.2 异步任务链路

关注：

- Task pending / running / failed 分布。
- TaskAttempt latency。
- Kafka lag。
- outbox 补发情况。

### 3.3 检索链路

关注：

- BM25 / 向量 / Wiki recall 延迟。
- RRF 和后处理耗时。
- no-evidence rate。

### 3.4 生成链路

关注：

- provider latency。
- token 消耗。
- timeout / error rate。

### 3.5 Runtime 链路

关注：

- active session。
- stop / resume 成功率。
- event buffer 压力。

这样回答时，面试官会更容易相信你理解系统瓶颈不会只出现在“接口平均耗时”。

## 4. 排障为什么不能只说“我先看日志”

“看日志”不是错，但太粗。更成熟的表达是先做归因分层：

### 4.1 任务没跑起来

看 Task / Outbox / Kafka / Worker。

### 4.2 任务跑了，但输出不对

看业务状态、版本号、下游组件写入结果。

### 4.3 检索不对

看 RetrievalTrace、召回数量、排序、evidence 后处理。

### 4.4 生成不忠实

看 PromptVersion、LLMCallLog、Citation 绑定。

### 4.5 用户体验不对

看 WebSocket runtime、resume、partialContent、前后端事件对齐。

这种分层方式比“先查日志”更像系统性排障。

## 5. 技术沟通的关键不是降智，而是翻译目标和代价

给业务或产品讲方案时，最怕直接报中间件和模式名。因为对方真正在乎的是：

- 为什么要做这件事。
- 不做会有什么风险。
- 做了能带来什么可见收益。
- 会不会影响交付节奏。

所以技术沟通更稳的做法是：

```text
先讲业务目标
-> 再讲当前风险
-> 再讲为什么这个设计能降低风险
-> 最后讲实现成本和可回滚性
```

例如 Citation，不是“我要建 citation 表”，而是“我需要让回答有依据、坏回答能反查、权限变化后还能重新校验”。

## 6. AI Coding 真正的风险点不在“写得快”，而在“你是否理解副作用”

AI Coding 最容易出事的地方通常不是代码风格，而是：

- 权限语义被改坏。
- 事务边界被破坏。
- 幂等或状态机被偷懒简化。
- 异常和补偿路径被漏掉。
- 看起来通过编译，但链路语义悄悄变了。

所以更成熟的口径不是“我会用 AI 提效”，而是：

```text
我让 AI 帮我阅读、对比、补测试、给小步 patch
-> 但涉及权限、一致性、异常和安全的地方必须自己核链路
```

这会和 NoteWeave 自己对 AI 输出的治理逻辑形成一致性。

## 7. 没有生产事故，也能讲“如何面对事故”

面试官有时并不一定要你真经历过线上事故，而是看你有没有事故意识。稳的讲法可以是：

- 先明确当前没有真实生产事故数据，不虚构。
- 再说明如果出现坏回答、任务堆积、恢复失败，你会沿哪条链路定位。
- 最后说明已有的 Trace、Event、Log、Eval、Audit 能支撑哪类回溯。

这样你表达的是“我有处理框架”，而不是“我一定经历过生产事故”。

## 8. 边界、不能说满和扩展方向

- 这篇只补验证设计、分层排障、业务翻译和 AI Coding 风险控制，不再重复标准版主答。
- 当前可以坚定讲：没有生产指标但有可观测面和验证方案；坏回答可以按链路归因；AI Coding 只能辅助不能替代验证。
- 当前不要讲成：已有真实生产容量、事故复盘指标、完善线上 SLA；AI 生成代码可以无 review 直接进主链路。
- 扩展方向可以讲：后续如果进入真实生产环境，再逐步补压测基线、告警阈值、灰度验证和正式回归 case 集。

## 9. 继续追问怎么接

如果面试官继续往下压，这一题最稳的承接顺序是：

```text
先承认没有生产数字
-> 再讲验证方案如何按链路拆
-> 再讲坏回答 / 坏链路如何分层排障
-> 最后讲业务沟通和 AI Coding 的治理意识
```

这样既诚实，也不会显得你在回避工程问题。
