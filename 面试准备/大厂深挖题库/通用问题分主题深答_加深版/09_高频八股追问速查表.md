# 文件：09_高频八股追问速查表.md

## 1. MQ / Kafka / Outbox

### Q：MQ 的作用是什么

异步、削峰、解耦、重试。结合 NoteWeave，要说文档解析、Source 编译、Artifact 生成这些长任务不适合同步 HTTP。

### Q：Outbox 解决什么问题

解决业务 DB 提交和 MQ 发送之间的不一致。Task 和 TaskOutbox 同事务落库，dispatcher 后续补偿发送。

### Q：Outbox 会不会重复发

会，所以消费者必须幂等。NoteWeave Worker 回查 Task 状态，只有 PENDING 才执行。

### Q：Kafka 消费为什么会重复

处理成功但 offset 未提交、rebalance、网络异常都可能导致重复。业务必须按至少一次语义设计。

## 2. Redis / 缓存

### Q：Redis 为什么快

主要基于内存读写，单线程事件循环避免大量锁竞争，使用高效数据结构和 IO 多路复用。

### Q：Redis 常见数据结构

String、Hash、List、Set、Sorted Set、Bitmap、HyperLogLog、Stream。

### Q：NoteWeave 用 Redis 存什么

上传 bitmap、WebSocket ticket、runtime state、partialContent、event buffer。长期事实不只放 Redis。

### Q：缓存穿透、击穿、雪崩

穿透是查不存在数据；击穿是热点 key 过期；雪崩是大量 key 同时失效或 Redis 整体不可用。

## 3. Elasticsearch / RAG

### Q：倒排索引是什么

从“词 -> 文档列表”的索引结构，适合全文检索。

### Q：BM25 是什么

基于词频、逆文档频率和文档长度归一的相关性算法。适合关键词和术语匹配。

### Q：向量检索解决什么

解决语义相似召回。文本转 embedding，比较向量相似度。

### Q：为什么 Hybrid RAG

BM25 精确，向量语义强，Wiki 稳定。混合召回更稳。

### Q：RRF 为什么有用

不同召回器分数不可比，RRF 基于排名融合，更鲁棒。

## 4. WebSocket / Runtime

### Q：WebSocket 和 HTTP 区别

HTTP 是请求响应，WebSocket 是长连接双向通信。

### Q：为什么不用 SSE

SSE 适合服务端单向推送；NoteWeave 需要 stop、resume、ack 等双向控制。

### Q：ack 有什么用

客户端确认收到的事件序号，服务端 resume 时只重放未确认事件。

## 5. Memory / 上下文工程

### Q：为什么不把历史全塞 prompt

token 成本高、噪声大、隐私风险高、错误历史可能误导模型。

### Q：长期记忆写入要过滤什么

DRAFT、短问候、空轮次、敏感信息、低价值内容。

### Q：summary 的作用

压缩历史上下文，保留主线，减少 token。

## 6. Agent / Workflow

### Q：Workflow 和 Agent 区别

Workflow 是固定步骤，Agent 是模型自主规划和工具调用。NoteWeave 当前是受控 workflow。

### Q：开放 Agent 难点

工具权限、schema、沙箱、预算、循环终止、tool log、eval、失败回滚。

### Q：MCP 怎么回答

当前不是主链路，未来可接 Tool/Source import 层。

## 7. 指标 / 压测

### Q：QPS、P95、P99 是什么

QPS 是每秒请求数。P95/P99 是 95%/99% 请求的响应时间上界。

### Q：没有生产指标怎么回答

不编造。说已有观测面和未来压测方案。

### Q：RAG 效果看什么

recall@k、MRR、citation coverage、no-evidence rate、answer feedback、bad case。

### Q：citation coverage 高代表正确吗

不一定。还要看 citation 是否真正支撑 claim。
