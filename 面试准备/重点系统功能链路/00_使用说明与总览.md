# 重点系统功能链路使用说明

> 本文件为 2026-06-01 题组版，依据当前代码、测试和 Flyway 迁移整理。这个目录里的 README 可以作为代码锚点，但复习时不要按模块孤立背，要先按相似问题题组组织回答。

## 0. 当前总口径

- NoteWeave 当前可以讲成一个 AI 知识工作台，不是普通接大模型 Demo。核心闭环是资料进入、可信问答、证据追踪、成果生成、长期知识沉淀和运营排障。
- 主边界是 PERSONAL 和 TEAM 两类 Space。TEAM 侧负责团队知识库、RAG Chat、Wiki、Graph、Admin/Ops；PERSONAL 侧负责 ResearchProject、Source、ArticleCard、ConceptCard、SynthesisCard、Artifact、Methodology。
- 后台长任务统一走 Task、TaskAttempt、TaskEvent、TaskOutbox、Kafka、Worker。Redis 主要承担 WebSocket runtime state、ticket、stop/resume 和短期状态，不要说成主任务队列。
- 表结构要按生命周期讲：Space/Member、Task/Outbox、Document/Chunk、Citation/Trace、Artifact/Wiki/Synthesis/Memory、Eval/Ops，而不是按页面背表名。
- RAG 不是只把问题扔给 LLM，而是权限过滤、BM25/向量/Wiki 混合召回、Weighted RRF、EvidencePostProcessor、PromptBuilder、Citation 持久化和 RetrievalTrace。
- 新增工具能力要放在“受控外部输入”题组里讲：Bilibili MCP 通过 StudioMcpToolRegistry、Local/RemoteBilibiliMcpToolService、BilibiliMcpCoreService、LoadMcpToolContextSkill 进入 Chat 或 Artifact，而不是开放式 Agent 平台。
- Artifact 和 Wiki 分离。Artifact 是可版本化阶段性成果，只有人工确认后才发布为团队 Wiki 或沉淀为个人 SynthesisCard。
- AutoWikiMaintenance、WikiGraph、PromptVersion、LLMCallLog、RAG Eval、AnswerFeedback、Admin/Ops 用来讲自动化、评测、可观测和运维，不要包装成已经有线上生产指标。

## 1. 先按题组练，再回链路文档

### 30 分钟速过
1. 读根目录 `01-项目主述题.md` 和 `04-简历风险点与优化口径.md`，先把总口径和不能说满的点校准。
2. 读 `03-追问题库.md` 的题组入口，挑“边界、一致性、证据、沉淀、工具、运营、扩展”各说 1 分钟。
3. 回到本目录，只看每条链路的“请求怎么进、状态落哪里、失败怎么查、证据怎么追”。

### 2 小时系统准备
1. 边界题组：读 01、02、06、07、08，重点讲 TEAM/PERSONAL、Citation、Memory、Artifact、Wiki 的隔离。
2. 一致性题组：读 03、04、09、10，重点讲 Task/Outbox/Kafka、索引版本、cleanup、Admin task。
3. 证据题组：读 04、05、08、09，重点讲 Hybrid RAG、Wiki recall、Citation、RetrievalTrace、RAG Eval。
4. 沉淀题组：读 06、07、08，重点讲 ChatMessage、Artifact、SynthesisCard、Wiki、Memory 的生命周期差异。
5. 工具题组：读 07、11，并结合当前代码里的 Bilibili MCP、ArtifactPlanExecutor、SkillExecutionLog。
6. 表结构和中间件题组：读 `中间件专项/01` 到 `06`，重点讲 MySQL 表结构、Redis key、MinIO object、ES index 和 Kafka topic/outbox。

## 2. 回答统一骨架

1. 场景：这类问题在 AI 知识系统里为什么重要。
2. 方案：NoteWeave 当前真实怎么实现，落到类名、表、任务类型或测试。
3. 收益：为什么比简单同步调用、直接写 JSON、直接信模型更稳。
4. 权衡：增加了哪些状态、任务和运维复杂度。
5. 追问：失败、重试、权限、删除、恢复、指标怎么回答。
