# NoteWeave 重点系统功能链路使用说明

## 0. 本篇定位

本目录按“系统链路”拆分 NoteWeave 的深挖材料。它和根目录里的 `01-项目主述题.md`、`02-模块深问题.md` 不是重复关系，而是分工关系：

- 根目录主答材料负责“先把题答出来”。
- 本目录链路材料负责“把整条系统链路讲深、讲稳、讲到能扛住连续追问”。

总入口汇总版见：

```text
面试准备/09-重点系统功能QA深入版.md
```

中间件、RAG、Agent 和 system design 映射主文档见：

```text
面试准备/重点系统功能链路/11_中间件RAGAgent系统设计映射/README.md
```

目录版更适合长期维护。后续遇到新问题时，优先补到对应链路文件夹，而不是继续把所有内容堆回一个总文档。

## 1. 这组材料和其它文件怎么配合

建议这样理解三层资料：

- `01-项目主述题.md`、`02-模块深问题.md`：
  标准答法层，解决“怎么答”。
- `09-重点系统功能QA深入版.md`：
  总览深挖层，解决“如果按系统设计角度展开，主线怎么讲”。
- `重点系统功能链路/*`：
  链路细化层，解决“某条链路完整怎么走、失败怎么办、边界在哪、能对应哪些中间件/RAG/Agent/system design 追问”。

如果面试准备时间不多，先背主答材料；如果面试官喜欢连续深挖，再进入本目录。

## 3. 推荐复习顺序

### 短时间准备

1. 先读 `09-重点系统功能QA深入版.md` 的 30 秒、2 分钟和三个亮点。
2. 再读 `11_中间件RAGAgent系统设计映射`，练“面试官问 X，我怎么自然接到八股和 trade-off”。
3. `01_总体主线与Austin映射`
4. `03_异步任务OutboxKafka链路`
5. `05_HybridRAG与Citation证据链`
6. `07_个人研究ArtifactSynthesis链路`
7. `09_ObservabilityEvalAdminOps链路`

### 完整准备

1. 先读 `01`，建立项目主线。
2. 再读 `02` 和 `03`，掌握系统底座和权限边界。
3. 接着读 `04`、`05`、`08`，掌握团队知识链路。
4. 再读 `06`、`07`，掌握运行态、记忆和个人研究链路。
5. 再读 `11`，把项目映射到中间件、RAG、Agent 和 system design。
6. 最后读 `09`、`10`，准备可观测、可靠性和压力追问。

## 4. 每条链路的统一写法

当前每个链路目录最少有一个 `README.md`。后续如果题目变多，可以继续拆成：

```text
README.md
01_主链路QA.md
02_失败场景与排障.md
03_实现锚点与测试锚点.md
04_面试追问补充.md
```

每条链路尽量保持下面结构：

```text
0. 本篇定位
1. 这条链路解决什么问题
2. 高频问题清单
3. 问答与讲解
4. 实现兜底锚点
5. 3 到 5 分钟深答
6. 边界和不能说满的地方
```

## 5. 统一回答骨架

每个系统链路回答尽量按下面顺序组织：

```text
场景：这条链路解决什么问题。
结论：第一句话直接回答，不绕。
链路：请求、任务、状态、存储、检索或生成如何流转。
证据：优先讲中间件职责、状态流转、设计取舍；实现名称只作为追问兜底。
取舍：为什么不用更简单或更重的方案。
边界：哪些是已实现，哪些不能夸大。
追问：失败、重复、越权、无证据、断线、依赖异常怎么办。
```

## 6. 事实边界

可以作为已实现主线讲：

- `TEAM / PERSONAL` 双空间与权限边界。
- `Task + Attempt + Event + Outbox + Kafka + Worker`。
- 团队文档上传、解析、chunk、BM25 / vector / Wiki recall、Weighted RRF、Citation、RetrievalTrace。
- WebSocket Runtime、stop/resume、DRAFT/FORMAL、Redis runtime state。
- 个人 Source、ArticleCard、ConceptCard、Artifact、MethodologyCard、SynthesisCard。
- Long-term Memory、PromptVersion、LLMCallLog、RAG Eval、Admin/Ops、Health、Cleanup、AuditLog。

不要讲成已落地事实：

- 真实生产 QPS、P99、token/day 或线上准确率。
- 完整开放式 MCP 平台已经做完，或者 MCP 已成为所有主链路强依赖。
- Bibtex 已端到端落地。
- 完整开放 Agent 平台。
- GraphRAG 是当前主检索链路。
- 微服务拆分、注册中心、配置中心、分库分表。
- Redis 是主后台任务队列或主业务事实源。

## 7. 怎么判断一条链路准备好了

至少要满足下面五点：

1. 能用 1 段话说清这条链路解决什么问题。
2. 能画出输入到输出的完整链路。
3. 被追问实现时，能给出 2 到 3 个真实锚点证明项目不是空讲。
4. 能回答至少 2 个失败或边界追问。
5. 不会把扩展方向说成当前事实。
